请严格执行以下步骤，不得跳过任何一步（唯一的例外是步骤 5 的「短路分支」）。

> 若当前工作区包含多个 git 仓库（并列的多个仓库，而非单仓多模块），对每个仓库依次执行步骤 1-9，最后在步骤 10 合并汇总。每个仓库**独立记录** `$BRANCH` 与 `$BEFORE`，不得跨仓库复用。

## 步骤 1：暂存本地未提交的修改
执行 `git stash push -m "temp: before pull"`

## 步骤 2：获取当前分支名
执行 `git branch --show-current`，记录为 $BRANCH

## 步骤 3：记录拉取前的 HEAD
执行 `git log --oneline -1`，记录 commit hash 为 $BEFORE

## 步骤 4：拉取最新代码
执行 `git pull origin $BRANCH`。

**退出码校验（硬约束）**：`git pull` 退出码非 0（冲突、网络、权限、无跟踪分支等）时**立即中止**并报告原始错误，**不得**继续进入步骤 5——否则拉取失败会因 `git log` 无输出被误判为「远程已是最新」。

## 步骤 5：展示新拉取的 commits（含短路判断）
执行 `git log $BEFORE..HEAD --oneline --no-merges`。

- **有输出** → 走完整流程，继续步骤 6、7。
- **无输出且步骤 4 退出码为 0** → 触发短路：跳过步骤 6、7，直接进入步骤 8；步骤 9 改用「报告 + 询问」模式；步骤 10 只需一段话说明「远程已是最新」。

## 步骤 6：展示变更文件统计（仅完整流程）
执行 `git diff --stat $BEFORE..HEAD`

## 步骤 7：读取每个新 commit 的详细 diff（仅完整流程，禁止跳过的核心步骤）
逐个执行 `git show <commit-hash> --no-color` 阅读所有新拉取 commits 的实际改动。

**硬约束**：
- 禁止只凭 commit 标题（步骤 5 的 oneline）或文件统计（步骤 6 的 stat）推断改动内容——标题是作者写的摘要，stat 只有行数，都不是代码事实
- 必须从 diff 中提取**具体内容**：改动的函数名、新增/修改的配置项、行为变化的机制（如 "readModelAliases 改读项目根 opencode.json"、"新增 BUILTIN_MODEL_ALIASES 兜底映射"）
- 每次 `git show` 一个 commit，记录其关键改动点，最后汇总

若本地有未提交修改（步骤 1 stash 了内容），注意：新拉取的 commits 用 `git show <hash>` 查看不受影响（只读）。

## 步骤 8：恢复本地修改
**仅当步骤 1 确实创建了临时 stash 时才恢复**：

```bash
git stash list          # 确认栈顶第一条是 "temp: before pull"
git stash pop           # 仅当上一步匹配时才执行
```

**禁止**无条件执行 `git stash pop`：工作区干净时步骤 1 的 `stash push` 会输出 "No local changes to save" 而不建栈，此时 pop 会弹出并删除**用户此前遗留的无关 stash**，污染工作区且丢失该 stash。

## 步骤 9：检查未推送 commits
执行 `git log origin/$BRANCH..HEAD --oneline` 检查当前分支是否有未推送的 commits。

- **完整流程（有新拉取）**：若同时满足以下两个条件，则自动执行 `git push origin $BRANCH`：
  - 步骤 1 的 stash 实际未保存任何内容（本地无未提交修改）
  - 当前分支存在未推送的 commits

  否则跳过推送，记录跳过原因（"存在本地修改" / "无需推送"）。
- **短路流程（远端无新提交）**：**不自动推送**。列出未推送的 commits 并询问用户是否推送——远端没有新代码时，本地提交推不推是独立决策，不应随「拉取」动作顺带发生。

## 步骤 10：总结
用中文汇总本次操作结果，分两部分：

### 拉取内容
- **完整流程**：基于**步骤 7 的 diff 阅读结果**（不是标题/统计），按以下维度总结：
  - **新增功能**：新 feature、新模块
  - **修复**：bug 修复、问题修正
  - **重构/优化**：代码重构、性能优化
  - **其他**：文档、配置、依赖更新等

  每个维度下的条目必须包含**具体改动**（函数名、配置项、机制变化），禁止只写 commit 标题。
- **短路流程**：一段话说明「远程已是最新，无新提交」，并列出当前 HEAD。

### 推送结果
- 若执行了推送，列出推送的 commits 及数量
- 若跳过推送，说明原因（"存在本地修改，跳过自动 push" / "无需推送" / "远端无新提交，已询问用户"）
