# 记忆新鲜度对照与借鉴（2026-09-23）

> 问题：Aik358 的记忆插件（`@a9i5k4/dsh-auto-memory` 3.1.4）怎么保持记忆新鲜度？我们能借鉴什么？
> 方法：对方派专项读码（七问，**每条均带 `文件:行号` 与代码原文**）；我方逐处核对 `max-null-plugins/dsh-memory` 源码。

## 一、它的新鲜度机制（七条）

| # | 机制 | 怎么做 | 关键限定 |
|---|---|---|---|
| 1 | **重要度** | 六类证据计数 + distinctSessions 进 `0.5+0.3×pos−0.5×correctionRate`，值域 [0,0.8]（`memory-importance.js:48-61`） | **唯一消费点是 dense 臂的乘性因子**（`index.js:6737` `c.sem * (0.5 + 0.5 * imp)`）——中性 0.75 是**等比缩放、不改序**；**不参与淘汰**（淘汰在 `fact-store.js:688-722`，与 importance 无关） |
| 2 | **时间感知检索** | `temporal-parse.js:94-162` 解析「昨天/上周/最近N天」→ `[startMs,endMs)`；命中者打 `temp=1` → **第三臂 rank-space RRF**（`recall-fusion.js:118-155`） | **只提升、不硬过滤**；**只对 label 含日期的来源**（日志/反思）可算——`MEMORY.md`／用户级／白板**永远是 undefined** |
| 2b | **独立 recency** | `recency = 2^(-ageDays/30)`（`shadow-retrieval.js:546`），半衰期 30 天 | **只占总分 0.05**、**仅 `workspace-log` 来源**；另有 future-dated 丢弃（`:544`） |
| 3 | **三态作废** | `current` / `superseded` / `retracted`，载体是正文末尾的 HTML 注释（`note-status.js:43,52`）；**触发者只有模型**（`memory_note` 的 `supersedes` / `retract` / `restore`，`index.js:6468-6492`） | **自动检测未接线**（`note-status.js:178` 自述）。作废后**检索放行 + 加 ⚠ 后缀与原因**（`l0-extract.js:269-311`，接线 `index.js:6610,6622`），**注入侧挡下**（`isCurrentPre` → `tier-layer-inject.js:503`）——**两个判据不同是有意的**（`l0-extract.js:261-264`） |
| 4 | **蒸馏归档** | 定时（10:00）或 `memory_maintain`：cutoff 取零点 → 日志截 2000 → subagent 蒸馏截 3000 → **原文整份写 `archive/`** → 要点 append 进 MEMORY.md → 删活跃日志（`index.js:8750-8841`） | **归档原文不可检索**——检索语料只有活跃日志/反思/MEMORY.md/用户级/白板（`:6626-6640`），**`archive/` 不在任何检索源** |
| 5 | **证据与统计** | `evidence-store` append-only JSONL 六类、保留 30 天/32 MiB、rebuild 出 fresh/stale/unknown；`evidence-agg` 近 7 天 + 每文件末 400 行；`recall-stats` 三通道分账 | 反向影响仅三处：evidence→importance、技能晋升门限、90 天老化时钟。**`recall-stats` 明确不加权**（用户拍板「先只记录」） |
| 6 | **配额与降级** | `deriveQuotaVerdictPre` 判 `under-quota` / `over-quota` / `balanced`（`degrade.js:307-384`） | **只出报告**：唯一调用点是 `index.js:7488` 的快照 → 落盘 + 面板；**全仓无任何分支读 verdict 去调配额** |
| 7 | **记忆日** | 默认 450 分钟（7:30 日界）：本地时刻 < 7:30 则日期减 1（`index.js:5165-5171`）；日志/沉淀/反思/问候/预算全按它切日 | 目的是**跨午夜连续工作不被劈成两天**；蒸馏 cutoff 取零点正是防这个窗口（`:8754-8756` 有实测记录） |

## 二、哪些真闭环，哪些停在「记录」

**先修正一个直觉**：这不是"一套新鲜度机制"，而是**四套互不连通的机制**——检索侧的三态标记（**不降权**）、注入侧只放 `current`、shadow 侧的连续 recency 衰减、证据侧的 importance 乘性因子。

**"不连通"有具体后果**：一条被标 `superseded` 的记忆在**检索排序里不降权**（只加 ⚠ 后缀），它可能排得比有效记忆更靠前；而 `importance` 只看证据计数，**不知道这条已被作废**。也就是说，作废这件事**只在注入侧真的生效**（挡下），在检索侧只是"告知"。

**闭环的（机制彼此接上）**：三态作废（触发 → 标记 → 注入挡下 / 检索放行带标注）、自动升降、记忆日。

**停在记录的**（读码确认，且作者自己记在 BUGLIST/注释里）：

1. **技能 90 天归档**：实现存在（`procedure-store.js:309-327`，`PROCEDURE_ARCHIVE_AFTER_DAYS_V1 = 90`）但**零调用**——`index.js:627` 与 `procedure-switch.js:18` 自述「只导出、零调用」。而 README 仍在承诺它。
2. **配额 verdict 无消费闭环**：阈值与 caps 不联动——**科学测量止于看板**。
3. **`deriveArmsHealthPre` 是死 import**（`index.js:36` 引入，全仓无调用）。
4. **evidence 的 freshness 算了**（`evidence-store.js:267-272`）**但没有消费者**。
5. **自动 supersede 检测未接线**（`note-status.js:178`）。
6. **`archive/` 不在检索源**——「原文保底」是**文件系统保底，不是检索保底**。

这些**不是疏忽**（作者自己标了），而是一个功能极多的项目自然留下的待接线项。但对我们，它们构成一组**现成的反面教材**：**只测量不消费 = 白测**。

## 三、逐条对照：我们有什么、缺什么

| 维度 | 它的做法 | 我们的现状 | 判断 |
|---|---|---|---|
| 环境失效 | （无对应；它没有环境值绑定） | 锚点三型 → `stale` + 撤常驻 + 不排除检索（`engine.ts:1248-1277`） | **我们这边更强**：它能自动探测环境变化，我们靠人/模型 |
| 语义失效 | 三态 + 检索放行/注入挡下 | **无**（只有 `memory_update` 覆盖） | **可借鉴，且成本低**——见 §四 1 |
| 检索放行 / 注入挡下 | ✓ 有意的双判据 | **已有同样的形状**（撤常驻 + 检索带 `staleReason`） | **我们对齐了**，只差来源 |
| 时间感知 | temp 臂 + recency 因子 | **无**（检索纯 BM25 + 可选语义） | 可借鉴，注意它的限定与权重 |
| 记忆日 | 7:30 日界 | **无** | 可借鉴（跨午夜场景真实存在） |
| 归档层 | 有，但**不可检索** | **无**（只有隔离区） | 要做就得**可检索**，否则重演它的坑 |
| 使用统计 | 六类证据、三通道分账 | `lastUsedAt` / `hitCount`（只记 BM25 前 N 名） | 够用；**别学它算了不用** |

## 四、可借鉴清单（按性价比排序）

### 1. 语义作废接进既有的 `stale` 路径（低成本，最高性价比）

`stale` + `staleReason` **已经预留了扩展位**：字段不限定来源，`staleReason` 是自由文本。最小改动是**加一个工具动作**（`memory_update` 加 `supersedes` / `retract`，或新增一个工具），把目标条目标成 `stale: true` + `staleReason: '被 mem_xxx 取代'`。

**下游一行不用改**：撤常驻、检索带标注、等核对后回写——这三个行为已经在 `stale` 这条路径上跑着了。

更上层的判据：**失效应该是一个维度、多种来源**（环境变了 / 被取代 / 当时就错了），而不是每种来源各开一个字段。

### 2. 时间感知：只提升不硬过滤 + 全等不建秩

它最值得学的不是"能按时间找"，而是**它的守卫方式**：`temp` 全等时不建秩，于是**没有时间词的查询逐字节行为不变**（`recall-fusion.js:5-15`）。这让新能力**可守卫、可回滚**——与我们 `mutate-check` 想达到的效果是同一类保障。

同时注意它的**限定**：只对带日期的来源有效。日志/反思天然带日期，`MEMORY.md` 这类不带——**所以"时间感知"只在有日期标签的语料上成立**。

### 3. recency 权重必须小

它给 recency 的权重是 **0.05**、半衰期 **30 天**。这个量级本身就是答案：**新近只该是微小的加成，不该压倒"对不对"**。

### 4. 记忆日（日界可配）

跨午夜连续工作时，"今天"该从几点算——它默认 7:30，而且蒸馏 cutoff 取零点正是为了防这个窗口（有实测记录）。我们要做任何按日切分的东西（归档、统计、反思提示）时，这个坑是现成的。

### 5. 归档层——**要做就必须可检索**

它把原文整份写进 `archive/`，文档说「原文归档保底，**绝不丢一个字**」。**字确实没丢**（文件还在），但 **`archive/` 不在任何检索源里**——30 天前的东西只能靠 MEMORY.md 里那段蒸馏间接命中，**原文再也搜不回来**。

**「保底」有两种含义**：文件系统保底（不删）与检索保底（还能找到）。它做到的是前者，而用户读到"绝不丢一个字"时理解的多半是后者。我们若做归档，**必须让归档可检索**（哪怕是一个低权重的检索源），否则就是同一个坑。

## 五、两条要警惕的

1. **`archive/` 不在检索源**——见上。
2. **只测量不消费**：配额 verdict、evidence freshness、技能归档时钟全都"算了但没人读"。测量本身的成本（采样、落盘、面板）**只有在有消费者时才划算**。

## 附：它的硬编码常量（我们要调时可以参考的量级）

蒸馏输出 3000 字符、digest 2000 字符、recency 半衰期 30 天 / 权重 0.05、RRF k=60、记忆日 450 分钟、技能归档 90 天、evidence 保留 30 天 / 32 MiB、`fact-store` 上限。
