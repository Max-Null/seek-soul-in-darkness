# OpenClaw 2.0 调查报告

> 日期：2026-09-01
> 调研人：MaxNull（经 DeepSeek Harness 会话调研）
> 调研目的：为 SSiD 记忆机制改造（自动生效 + 后审核）提供外部参照；顺带覆盖 AI 中台（多人一 Agent）记忆治理的行业现状
> 性质：公开信息调研。所有关键数字标注验证来源（**API 核实** = GitHub REST API 直接读取；**媒体转述** = 新闻稿/博客，未经一手验证）

---

## 一、结论先行

1. **OpenClaw 是当前最大的开源个人 Agent 项目**（仓库 2025-11-24 创建，至今约 38.8 万 Star，[API 核实](https://github.com/openclaw/openclaw)），2026 年初爆发、夏季降温，2.0（v2026.8.1）于 2026-08-31 发布，是"热度退潮后的正名之战"。
2. **2.0 的三大主题——安装门槛、记忆连续性、安全权限——与 SSiD/AI 中台的核心课题同构**，其中记忆机制最具参照价值。
3. **OpenClaw 1.0 的记忆设计 = md 明文存储 + 人工审核**（用户陈述 + PR #87900 的 body 内容佐证，[GitHub PR](https://github.com/openclaw/openclaw/pull/87900)）。**2.0 将人工审核替换为自动化 + 机器安全检查**，但**主线至今没有人工记忆队列**——社区有人提案加回（见第七节），提案被挂起。
4. **对 SSiD 的意义**：SSiD 现设计（人工闸门）≈ OpenClaw 1.0 同源；我们的改造方向（自动生效 + 人工后置审计 + 可逆回滚）联盟内无人实现，属于差异化领先位。
5. **对 AI 中台的意义**：多人共享会话（Shared Cloud Sessions）2.0 已做，但记忆的**归属隔离/跨用户泄漏治理官方未答**——这是企业级场景的空白，正是我们可提前布局的点。

## 五、2.0 三大核心改进

### 5.1 安装部署：面向非技术用户降门槛

- 引导式安装：自动扫描本机已有 AI 订阅、API 密钥、本地模型，自动处理能处理的配置；暂时用不到的设置移出初始安装
- 剩余配置交给用户在日常对话中逐步完善（"越聊越配"）
- 浏览器应用重构为一等公民：随时返回设置、续接未完成任务
- 默认 GPT-5.6；`node-llama-cpp` → 托管 `llama-server`；上下文默认 64K

来源：[品玩](https://www.pingwest.com/w/316931)、[界面新闻](https://www.jiemian.com/article/15037208.html)

### 5.2 记忆系统：从"健忘症"到主动学习（本报告重点，详见第六节）

- **Active Memory**：符合条件时调用过去会话的相关上下文（跨会话连续性）
- **Grounded Dreaming / Background Memory Consolidation**：后台处理历史会话，把值得保留的信息整理进长期记忆；留"梦境日记"（Dream Diary，来源记录），比喻为"Agent 睡觉时整理白天的记忆"
- **Automatic Self-learning**：任务完成后总结可复用经验，**通过安全检查后**形成新 Skill 或改进已有 Skill

来源：[界面新闻](https://www.jiemian.com/article/15037208.html)、[积墨 AI](http://www.jimo.studio/blog/openclaw-20-unveils-largest-update-yet-targeting-three-core-agent-challenges/)

### 5.3 安全与权限：高权限 Agent 的补课

- **Private Credential Request**：需要密码/Token 时遮罩输入，敏感信息不进入聊天记录和模型上下文
- **自动化审批细分**：周期性任务仅对获批的具体操作复用授权；任务/操作变化后需重新审批
- **插件治理**：安装前展示能力/来源/版本；未知来源且可执行代码的插件需额外审批
- 其余：Session Permission Mode、Shared Credential Store、更明确的 Sandbox 策略、`openclaw security audit` 命令（检查入站访问、工具影响半径、网络暴露、插件白名单）

来源：[界面新闻](https://www.jiemian.com/article/15037208.html)、[积墨 AI](http://www.jimo.studio/blog/openclaw-20-unveils-largest-update-yet-targeting-three-core-agent-challenges/)

## 六、记忆机制专题（对照 SSiD/AI 中台的关键）

### 6.1 三代演进

| 代 | 存储 | 审核 | 自动化 | 备注 |
|---|---|---|---|---|
| 1.0 | **md 明文**（AGENTS.md 等） | **人工审核**（用户陈述；SSiD 同源设计来自 oc-plus/fractal 时代） | 无 | 高频但"隔几天就忘"，记忆混乱 |
| 2.0 | md 明文（PR #87900 佐证，主线未见结构化存储迁移） | **无人工**；机检前置（Self-learning 须过安全检查） | Active Memory / Dreaming / Self-learning | "越用越不懂"的痛点缓解，但无人审，风险后置 |
| 社区提案 | md 明文 | 人工审核（**前置**：stage → apply/reject） | 保留 Dreaming 并行 | 见 6.2，提出但被挂起 |

### 6.2 社区"回拉人工审核"的提案（本次调研验证重点）

**PR #87900 — feat(memory): add Memory Audit review queue**（[GitHub](https://github.com/openclaw/openclaw/pull/87900)，GitHub REST API 核实，2026-09-01 查询）：

- 作者：外部贡献者 SYU8384；**状态：draft、closed（2026-07-24）、未合并**
- 标签：stale（不活跃）、triage: mock-only-proof（仅测试/模拟证据）、rating: 🧂 unranked（未达合并标准）、merge-risk: 🚨 compatibility / session-state / security-boundary（三重大风险）、status: needs proof
- **审核语义：前置**——LLM 检查可写记忆目标 + 每日记忆 + 会话日志证据，stage 出 add/edit/delete/move 建议，**最终 apply/reject 由人决定**；daily memory 与会话日志只读；cron 异步收集，不阻塞
- 作者自评："Memory Audit is the safer alternative for memory quality work"（相比 Dreaming）
- 未验证项：官方对该 PR 的维护者评审意见（CI/讨论未读取）

**结论**：OpenClaw 主线至今**没有**人工记忆审核队列；"人工审核回加"仅停留在被挂起的社区提案。自学习/记忆的"人参与"问题，官方并未接管。

### 6.3 审核门位置的三分类（SSiD 借鉴模型）

| 模式 | 时序 | 代表 | 自动 | 阻塞 | 风险 |
|---|---|---|---|---|---|
| 前置人审 | 写前逐条确认 | SSiD 现状；PR #87900 | 否 | 高 | 审核即流程，体验重 |
| 前置机检 | 写前规则检查 | OpenClaw 2.0 | 检查后 | 中 | 机检漏网=固化放大 |
| **后置审计** | 先生效、后扫描+回滚 | **SSiD 目标** | 是 | 零 | 依赖可逆性 + 守卫主动性 |

### 6.4 对 SSiD 的映射结论

1. SSiD 现设计（JSON + 人工闸门）与 1.0 同源，但 **JSON 结构化 + 两层存储已比 md 更适合 provenance/版本化/隔离**，这是改造的既有优势。
2. SSiD 目标模式（自动生效 + 后审核）不在 OpenClaw 三家之列：2.0 是"机检前置"、PR #87900 是"人审前置"。**SSiD 是独立第四种，且三硬条件（可逆性/高危影子模式/守卫主动）尚未见任何项目完整落地。**
3. `dsh-guardian`（2026-08-16 设计稿已定，未实现）的"确定性监控"职责恰好是后审核的守卫骨架，当前缺记忆维度扩展（冲突/来源/预算/泄漏检测）。

### 6.5 对 AI 中台的映射结论

- 2.0 的 Shared Cloud Sessions 解决"多人与多 Agent 协同 + 上下文不丢失"，但**未解决记忆归属与跨用户隔离**（官方来源未见相关设计）。
- 企业级场景的记忆治理（scope 分层、owner-signed、组织级批准）无成熟开源参照——**空白即机会**，但需独立立项（本次改造计划仅覆盖 SSiD 单人场景）。
