### 1.2 修复：`dsh-memory` 的 <code>&#123;&#123;</code> 缺陷（0.11.1）

调查中顺带发现的一个真实缺陷，走完了「发现 → 复现 → 修复 → 验证」全程：

- **机制**：DSH 的系统提示词走严格插值，section/context 文本里出现 <code>&#123;&#123;name}}</code> 会当场抛错（未注册 → `unknown`；名字不合 `/^[a-z][a-z0-9_]*$/` → `malformed`）。组装发生在模型调用之前，所以**该会话的全部模型请求一起失败**。
- **可达**：`memory:recall` 的注入行取自记忆正文首行（`deriveSummary`），四条子路径都承载模型或用户可写的文本。
- **复现**：真栈（`Context` + `Storage` + `SystemPrompt` + `ToolRegistry` + 插件）写入常驻记忆后 assemble，含 <code>&#123;&#123; count }}</code> 的正文让 `renderContextSections` 抛 `malformed`，含 <code>&#123;&#123;footer}}</code> 抛 `unknown`；对照组正常。
- **修复**：`src/injection.ts` 新增 `neutralizeBraces`（循环替换至稳定），`src/index.ts` 的 `recallText` 出口统一中和——四条子路径的唯一汇合点，只动注入副本，存储与面板保留原文。
- **验证**：typecheck 干净；全量 **13 文件 / 138 用例全绿**；**反证成立**（拿掉那一行调用，装配用例立刻红）。

## 二、查出来的东西（摘要，详情见上述文档）

- **Aik358 不是恶意软件**：无遥测、无数据外发（四处联网全是固定 URL 裸 GET）、Python 侧车 argv + `shell:false` + 纯标准库。
- **但它在宿主边界上动作很大**：改 profile 依赖、移动 `~/.dsh/sessions` 下的会话目录、读主目录里其他 AI 工具的记忆、默认采集思维链；另有一整套默认开启的常驻任务（每轮自动沉淀、每小时拉远端通知并自动弹窗、15 秒心跳、每分钟主线程同步读 hub）。
- **可借鉴的机制**（七条，见清单文档）：注入分项账本 + `must` 优先级、构建-投递一致性校验（exactDigest）、用真值实测注入成本、记忆写入卫生闸门、分层配额 + 配额健康度自诊断、子代理痕迹回收、测试按来源命名。
- **反面参照**：它的规则段不参与裁剪 → 每轮固定注入实测 **18291 字符 = 预算的 228.6%**。对照我们 1500 字符的预算 + 超预算诊断行，我们这一点更克制。

## 三、对话中得出的判断

### 3.1 书记员、秘书、与「她」

- **书记员**（对当前窗口）：只记录、不介入。这件事**必须交给子代理**——主对话的模型身在局中，让它同时评估"这轮值不值得记"既占上下文又抢注意力；子代理旁观，价值来自不介入。
- **秘书**（用户的原始设计）是一个**闭环**：记录建立基线 → 依据这份记录监督 → 偏离时提醒。三者必须同一个 agent，因为**它记下的就是它要守的约**。
- **「她」是谁**：作者说"用她称呼这个插件"，但所有有人味的输出都是模型产出的。准确的关系是——**插件写人格剧本，模型当演员**。用户给出的读法更贴近体验：**"她"是通过插件与记忆构建起来的、那个在对话里的存在**。这与 `dsh-tone-layer` 自己的原则（"不写人格，性格与关系由记忆生长"）是同一件事的两面。

### 3.2 自记 vs 他记

`dsh-memory` 选了**自记**（主对话模型自己调 `memory_save`），自动化只覆盖治理（命中常驻 / 30 天撤下 / 锚点失效），不覆盖写入。Aik358 是**两条路并行**（模型自记 + 子代理兜底），理由是"记忆无法被绕过，也不依赖自觉"。我们放弃他记的理由与代价写在决策文档里；**重估判据是"观察到反复漏记的实例"，不是"他记更好"这个一般判断**。

### 3.3 脑干型 vs 记忆型（用户给的划分判据）

| | 脑干型（插件 / 反射） | 记忆型（生长） |
|---|---|---|
| 判据 | 边界明确、应对固定、**需要每步都做** | 需要理解、会变、从相处里长出来 |
| 例子 | `dsh-allostasis`、`dsh-guardian` | 人格、偏好、约定 |
| 放错位置的后果 | 放进记忆 → 变成"请模型每轮自查"——回到"依赖自觉"那个它要解决的问题 | 放进插件（硬编码）→ 与"记忆决定人格"的方向打架 |

这条划分也解释了 `dsh-allostasis` 为什么必须存在：语言漂移要**每 step** 检查，模型做不到这个频率。

### 3.4 多插件 vs 单体；SSiD 是那个"Plus 版"

- 曾做过单体（oc-plus），与 DSH 磨合后改为**拆成多个插件各自演进**。
- 而 SSiD 把"整合"上提到了壳层——**功能拆开、体验合起**。实证：同一批插件此刻分别跑在 `ssid`（19 个 `@max-null/*`）与 `web`（17 个）两个 profile 里。**换一种体验只需换壳。**
- 连"盒"本身也是插件：`ssid-panels`、`quick-toolbar`、`ssid-zh-ui`、`node-appearance`、`achievements` 全在同一个 `dependencies` 里。

## 四、全家桶升级方向建议

### 4.1 立即可做（低成本、独立价值）

**① `dsh-memory` 补"人格类 / 约定类"的写入引导。**

证据：`GUIDANCE`（`src/index.ts:167`）第一句就提了这类内容——"Use memory tools for cross-session **preferences, habits**, and project conventions"——但后面每一条具体判据都往**可判定 / 可执行**上走（"换个项目还成立吗"、"这条没人想起来搜也必须生效"、"记结论要记出处"），**没有一句在教"记他是谁"**，而人格类恰好不吃这三条判据。

做法：加一段引导 + 一个类型（格式照 Aik358 的 `feedback`：正文带 `Why:` 与 `How to apply:`——前者让它能推广到新场景，后者把抽象偏好压成可执行动作）。

**独立价值**：不加读取端也能用——记下的人格类记忆会走**现有的常驻注入**，进动态段。

**② 用一个最小实验回答"知道够不够"。**

记一条**可观察**的人格记忆（例如「结论放第一句」），观察一个会话的语体。

- 挑了可观察的，是因为要能干净分辨"变了 / 没变"——这是 allostasis 的教训（它先否掉了"中文字符占比""最长连续英文游程"两个看着直观、实际分不开的指标，才找到功能词密度）。
- **变了** → `tone-layer` 不需要接读取，保持"手段库"角色即可（零缓存代价）。
- **没变**（知道却做不到）→ 才做 ③。

**③（条件性）`tone-layer` 接固定前缀。**

只在 ② 判定"知道不够"时做。代价要预先认下：**缓存**（tone 段在固定前缀里，一改就整段重编码，所以生长只能低频）+ **生长频率受限**。实现上要解决同步段读异步数据：照抄 `dsh-memory` 自己的模式（同步 provider 只读已打开的表 + `ensureProjectOpen` 预热 + assemble waterfall 补渲染）。

**不要**为它单独建一套存储或一套记忆工具——那是双状态源。判据是「**数据合、行为分**」：存储必须一份（否则无法统一检索、互相引用、一起治理），而通路、频率、失效方式本来就各不相同。

### 4.2 基础设施（来自 Aik358，全家族受益）

**① 注入成本实测。** 我们现在有五个往 system prompt 里注入的插件（`chinese-thinking`、`tone-layer`、`dsh-memory`、`dsh-guardian`、`dsh-allostasis`），**但从没测过每轮实际花了多少**。方法现成：直接从真实会话日志里把注入段切出来量真值字节（注意日志是多帧 zstd，`zstdDecompressSync` 只解第一帧——我们自己的 `scripts/unzstd-frames.mjs` 已经在处理这个）。产出一张"谁在什么位置、占了多少"的表，之后所有预算决策都有依据。

**② 动态段的分项账本与优先级。** 目前只有 `dsh-memory` 有注入预算，`dsh-guardian` 的三条提醒没有。可借 Aik358 的做法：每段带分项与优先级，超额时先丢 `low`，`must`（规则类）永不丢。

**③ 文档-测试互锁 + 变异演示。** 文档里的数值与路径由守卫从代码重推（不硬编码）；批次名与测试文件名同号；基线数字写死。另加**变异演示**：用一次故意的失败证明守卫会红（本次修 <code>&#123;&#123;</code> 时就做了一回，但没制度化）。这两条**不依赖多代理**，单人项目同样成立，性价比最高。

### 4.3 结构性的（值得沉淀成规范）

**① 把"五层"写进手册。** 这次对话实际上给全家桶做了一次分类，它是自然长出来的、不是设计的：

| 层 | 判据 | 现成成员 |
|---|---|---|
| **基线层** | 固定前缀、常驻、cache 锚；"每轮都该生效且内容稳定" | `dsh-chinese-thinking`(-90)、`dsh-tone-layer`(-85) |
| **反射层** | 近因注入、触发式；"边界明确、要每步检查、不能靠自觉" | `dsh-allostasis`、`dsh-guardian` |
| **记忆层** | 存储与检索；"会生长、需理解" | `dsh-memory` |
| **壳层** | 跨插件的统一体验 | `ssid-panels`、`quick-toolbar`、`ssid-zh-ui`、`node-appearance`、`achievements` |
| **工具层** | 开发与运维 | `plugin-center`、`skill-mcp-center`、`skills`、`capture`、`chat-rail`、`draft-polish`、`habit`、`ssid-env`、`ssid-pwsh-retry` |

用处有二：**新插件该放哪层**有了判据；**缺哪一层**一眼可见。

**② 它立刻暴露了一个缺口：基线层有 2 条，反射层只守着其中 1 条。** `dsh-allostasis` 守语言，**语气这条基线目前是裸的**。而语气的判据比语言难——语言漂移是二值的（中文 vs 英文），语气漂移的表现是**"变干"（缺席）**，且"同一个没有语气助词的信号，在 debug 场景是正确行为，在日常寒暄里才是漂移"。也就是说它的判据必须**带上场景**，而场景本身就是语义判断。

**③ 注入层的预算纪律。** 固定前缀的改动要慎重（一改就破缓存）——只有"稳定设定"配放这里；动态段应该有一条**总额度**，而不是只有 `dsh-memory` 一家有预算。这条纪律在 4.2 的实测数据出来之后才谈得上执行。

### 4.4 那个"秘书"闭环的现状与岔路口

| 环 | 现状 |
|---|---|
| 记录 | **有**（`dsh-memory`），但缺人格类引导（见 4.1 ①） |
| 判据 | **部分有**：`dsh-allostasis` 一条（语言漂移）、`dsh-guardian` 三条（断言计数、编辑队列、无反馈环）——**全部是手写的** |
| 干预 | 机制有（`agent/pre-step` 追加近因消息），缺的是"从记录里读约定"这一环 |

**岔路口**：记录是自然语言（"以后都用 PowerShell 7"），判据是形式化的（指标 / 阈值 / 正则 / 计数）。中间那层谁填——

- **人填**：每条约定手写一个检测器（现在就是这样）——准，但不 scale；
- **LLM 填**：让它读约定 + 对话判断是否守约——scale，但**不可复现**（同段对话两次判断可能不同），而一个不可复现的监督者很难证明它比没有更好。

**把一条模糊约定炼成一个能干净分离"守约 / 违约"的可测指标，是这里面最难的一步，且不可省略、不可自动。** `dsh-allostasis` 的设计文档（`max-null-plugins/dsh-allostasis/docs/设计/2026-09-20-应变-设计方案.md`）是这一步的范本。
