# 明瞳（制图师）kimi k3 配置指南

> 状态：key 用户已有（分形项目在用的同一把），待写入 `~/.dsh/.credentials.yaml`；
> 模型 id 已由分形实测确认（`moonshotai-cn/kimi-k3`，即 API id `kimi-k3`）

## 现状

- pi-ai 内置 moonshotai provider，但 catalog 只有 kimi-k2 系列（pi-ai 0.82 落后于模型发布）
- **catalog 缺失不阻塞**：`dsh-llm-pi-ai` 的 `catalog.ts` 契约支持"目录没有的模型在 settings.yaml 完全手写声明"
  （id/contextWindow/maxTokens/input/api/baseURL），pi-ai 只充当通用 OpenAI 兼容网关的调用壳
- kimi-k3 已发布且有 vision 能力（[Kimi 视觉模型文档](https://platform.kimi.com/docs/guide/use-kimi-vision-model)）
- preset 的明瞳行已挂好（`subagent_cartographer`，persona + toolFilter 就位），只差模型路由

## 你需要做的（一步）

把分形项目正在用的同一把 Moonshot key 写入凭据（key 不经过对话，你自己写）：

```sh
# 编辑 ~/.dsh/.credentials.yaml，加一行：
MOONSHOT_API_KEY: sk-你的key
```

## 我来做的（key 就位后）

### 1. 配置 pi-ai 路由 + 给明瞳接上模型

`~/.dsh/settings.yaml` 加 pi-ai section（显式声明 kimi-k3，含 vision 输入模态）：

```yaml
llm-pi-ai:
  providers:
    moonshotai:
      apiKeyEnv: MOONSHOT_API_KEY
      models:
        - id: kimi-k3
          name: Kimi K3
          input: [text, image]
          contextWindow: 262144
          maxTokens: 32768
```

然后 `presets/ssid-double-star/agent.cordis.yml` 的明瞳行补模型路由：

```yaml
- id: tool-subagent-cartographer
  config:
    provider: spawn
    toolName: subagent_cartographer
    agentOptions:
      provider: moonshotai
      model: kimi-k3
    persona: |-
      你是「明瞳」…
    toolFilter:
      allow: [read, read_image]
```

### 3. 重启 SSiD 验证

让双星委派明瞳读一张图（如 UI 截图分析），确认：
- 子会话模型路由 = moonshotai/kimi-k3
- read_image 工具可用（图片进入视觉上下文）
- 视觉分析输出正常

## 验证脚本（配置完成后跑）

沿用 `_eval-roles.ts` 模式：驱动双星委派 `subagent_cartographer` 分析一张测试图片，检查子会话的 `request/header` 路由与输出质量。

## 注意事项

- **kimi-k3 的 API id 已确认**：分形项目实测跑通的 id 是 `kimi-k3`（models.dev 前缀写法
  `moonshotai-cn/kimi-k3`），SSiD 声明直接用 `kimi-k3`，无需再猜日期后缀
- **vision 输入模态**：`input: [text, image]` 是声明；kimi-k3 为多模态模型，符合官方文档
- 成本纪律不变：明瞳单次给到位、只喂图、实现交给巧匠。
