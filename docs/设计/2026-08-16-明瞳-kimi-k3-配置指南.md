# 明瞳（制图师）kimi k3 配置指南

> 状态：待用户提供 Moonshot API key（明瞳是唯一卡在用户资源上的角色）

## 现状

- pi-ai 内置 moonshotai provider，但 catalog 只有 kimi-k2 系列（pi-ai 0.82 落后于模型发布）
- kimi-k3 已发布且有 vision 能力（[Kimi 视觉模型文档](https://platform.kimi.com/docs/guide/use-kimi-vision-model)）
- preset 的明瞳行已挂好（`subagent_cartographer`，persona + toolFilter 就位），只差模型路由

## 你需要做的（两步）

### 1. 拿 Moonshot API key

到 [platform.kimi.com](https://platform.kimi.com) 申请，然后写入凭据：

```sh
# 编辑 ~/.dsh/.credentials.yaml，加一行：
MOONSHOT_API_KEY: sk-你的key
```

### 2. 配置 pi-ai 路由 + 给明瞳接上模型

`~/.dsh/settings.yaml` 加 pi-ai section（显式声明 kimi-k3，含 vision 输入模态）：

```yaml
llm-pi-ai:
  providers:
    moonshotai:
      apiKeyEnv: MOONSHOT_API_KEY
      models:
        - id: kimi-k3
          name: Kimi K3
          input: [text, image]
          contextWindow: 262144
          maxTokens: 32768
```

然后 `presets/ssid-double-star/agent.cordis.yml` 的明瞳行补模型路由：

```yaml
- id: tool-subagent-cartographer
  config:
    provider: spawn
    toolName: subagent_cartographer
    agentOptions:
      provider: moonshotai
      model: kimi-k3
    persona: |-
      你是「明瞳」…
    toolFilter:
      allow: [read, read_image]
```

### 3. 重启 SSiD 验证

让双星委派明瞳读一张图（如 UI 截图分析），确认：
- 子会话模型路由 = moonshotai/kimi-k3
- read_image 工具可用（图片进入视觉上下文）
- 视觉分析输出正常

## 验证脚本（配置完成后跑）

沿用 `_eval-roles.ts` 模式：驱动双星委派 `subagent_cartographer` 分析一张测试图片，检查子会话的 `request/header` 路由与输出质量。

## 注意事项

- **kimi-k3 的确切模型 id 需确认**：Moonshot 官方 API 的模型 id 可能是 `kimi-k3` 或带日期后缀（如 k2 是 `kimi-k2-0905-preview`）。配好后第一次委派若报 model not found，查官方模型列表改 id。
- **vision 输入模态**：`input: [text, image]` 是声明；若官方 API 的 vision 模型 id 不同，一并调整。
- 成本纪律不变：明瞳单次给到位、只喂图、实现交给巧匠。
