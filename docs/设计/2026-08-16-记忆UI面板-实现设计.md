# 设计：dsh-memory 记忆 UI 面板实现方案

> 日期：2026-08-16
> 状态：设计草案（待 MaxNull 拍板）
> 目标：把 fractal 的「🧠 记忆面板」体验搬到 SSiD（DSH 基座），补上 dsh-memory 目前「只有工具、无 UI」的缺口
> 关联：`../决策/2026-08-16-分形DSH迁移-重评估映射表.md`（3.6 节「记忆面板」）

## 一、现状盘点

dsh-memory（`@max-null/dsh-memory@0.2.0`）现有：

| 能力 | 现状 |
|---|---|
| host 服务 `ctx.memory`（`MemoryEngine`） | ✅ `remember/list/search/forget/setStatus` |
| 模型工具 | ✅ `memory_save/list/search/forget/confirm`（5 个） |
| system-prompt 注入 | ✅ `tool:memory` section + `memory:recall` context |
| 存储 | ✅ 两层 JSON（global `$DSH_HOME/storages/memory.json` / project `<cwd>/.dsh/storages/memory_project.json`） |
| **Typert remote（client 可调的服务面）** | ❌ **缺失** |
| **Web UI 面板（浏览/搜索/确认/删除）** | ❌ **缺失** |

**缺口结论**：模型能通过工具读写记忆，但**人**没有一个图形界面浏览/确认/删除记忆——这正是 fractal 记忆面板的价值，也是本设计的交付物。

## 二、架构设计

### 2.1 数据流

```
浏览器 UI 面板（新 client 插件）
   │  ctx.remote.memory.list() / search() / confirm() / forget()
   ▼
Typert RPC（host ↔ client 的 remote 通道）
   ▼
host 侧 MemoryGateway（新，dsh-memory 内）
   │  继承 TypertRemoteService，@Remote 暴露 4 个方法
   ▼
ctx.memory（MemoryEngine，已有）
   ▼
storage（两层 JSON，已有）
```

### 2.2 两层改动

| 层 | 改动 | 归属 |
|---|---|---|
| host | 新增 `MemoryGateway extends TypertRemoteService`，暴露 `list/search/confirm/forget` | dsh-memory 包内 |
| client | 新增 UI 插件，注册到设置页 tab，消费 `remote.memory` | dsh-memory 包内（`src/client/`）或独立 client 包 |

## 三、关键机制（已核实，附源码证据）

### 3.1 Typert remote（host 侧暴露服务）

参考 `dsh-host-plugin-inventory` 的 `PluginInventoryGateway`（`packages/host/plugin-inventory/src/index.ts`）：

```ts
import { TypertRemoteService, Remote } from '@deepseek-ai/dsh-typert-protocol'

export class MemoryGateway extends TypertRemoteService {
  static inject = ['memory']            // 依赖 ctx.memory 服务
  constructor(ctx: Context) {
    super(ctx, 'memory')                 // 注册 remote 命名空间 'memory'
  }
  @Remote('list')
  list(filter: MemoryFilter): MemoryRecord[] { return this.ctx.memory.list(filter) }
  @Remote('search')
  search(query: string, filter: MemoryFilter): MemoryHit[] { return this.ctx.memory.search(query, filter) }
  @Remote('confirm')
  confirm(id: string): MemoryRecord { return this.ctx.memory.setStatus(id as never, 'auto') }
  @Remote('forget')
  forget(id: string): boolean { return this.ctx.memory.forget(id as never) }
}
```

要点：
- `TypertRemoteService` + `@Remote('name')` 是 DSH 暴露 client 可调服务面的**唯一标准机制**（`ui-settings-plugin-inventory` 消费的 `remote.pluginInventory` 同源）。
- remote 方法的参数/返回值必须是 JSON-compatible 类型（`MemoryRecord`/`MemoryHit` 已是纯对象，满足）。
- 构建时 Typert 生成 `typert.host.js`（host 用）+ `typert.remote-client.js`（client 用），package.json 需加 `./typert`、`./remote` 两个 export。

### 3.2 slot 注册（client 侧挂面板）

参考 `ui-settings-plugin-inventory/src/client/index.ts`：

```ts
export const inject = ['slots', 'locale', 'remote', 'remote.memory']

export function apply(ctx: ClientContext): void {
  ctx.slots.inject('settings.plugins.tab', () => ctx.slots.register({
    name: 'settings.plugins.tab',
    id: 'memory',
    order: 20,
    label: () => t('tab'),
    locale: NS,
    inject: () => ({ list, search, confirm, forget }),
  }, MemorySettingsTab))
}
```

要点（slot 系统标准，`2026-07-22-slot-type-chain-implementation.md`）：
- 插件只通过 `ctx.slots.register({ name, children, store, inject }, Component)` 组合 UI；`children` 同时声明并授权子 slot。
- 组件是纯函数，props 走四个 shares：`runtime`（owner 参数 + `useSession` 等）、`renderSlots`（子 slot）、`store`（`useStore` + `actions.*`）、`inject`（业务 face，这里放 `list/search/confirm/forget` 回调）。
- 业务 live-data 走 declared store（`createXXXStore()` 工厂），组件不自己写订阅。

### 3.3 组件形态

参考 `PluginInventorySettingsTab.tsx`（`packages/client/ui-settings-plugin-inventory/src/client/`）：
- `ViewState = loading | error | ready` 三态；
- `useEffect` 里 `list()` 拉数据，`useMemo` 过滤；
- 搜索框 + 卡片列表 + 展开详情；
- 记忆面板在其上加「确认（suggested→auto）」「删除」两个操作按钮，走 `confirm()`/`forget()`。

## 四、实现步骤

### 阶段 1：host 侧 remote（dsh-memory）

1. `package.json` 加 peerDependency `@deepseek-ai/dsh-typert-protocol`；加 export `./typert`、`./remote`。
2. 新增 `src/remote.ts`：`MemoryGateway extends TypertRemoteService`，暴露 4 个方法。
3. `src/index.ts` 的 `apply` 里 `ctx.plugin(MemoryGateway)`（在 MemoryEngine 之后，满足 `inject: ['memory']`）。
4. 构建生成 Typert 产物，验证 `remote.memory.list()` 可被 client 调通。

### 阶段 2：client 侧 UI（dsh-memory 内 `src/client/`）

1. 新增 `src/client/index.ts`：`inject = ['slots','locale','remote','remote.memory']`，`slots.inject('settings.plugins.tab', ...)` 注册 `MemorySettingsTab`。
2. 新增 `src/client/MemorySettingsTab.tsx`：三态 + 搜索 + 卡片列表 + 确认/删除按钮。
3. 新增 `src/client/locales.ts`：中英文案（沿用「思灵」品牌文案，如「黑暗中未见灵光」空状态）。
4. `package.json` 加 `dsh.client` manifest（`platform: 'web'`），bundle 注册。

### 阶段 3：验证

- `pnpm run test:gui`（组件单测）+ 手工在 dsh web 设置页看到「记忆」tab，能列表/搜索/确认/删除。

## 六、技术难点与风险

1. **Typert 接入独立插件的可行性**：已核实可行——`@deepseek-ai/dsh-typert-protocol`（`TypertRemoteService` + `@Remote`）、`@deepseek-ai/dsh-typert-generator`（代码生成）、`@deepseek-ai/dsh-typert-registry` 三个包**均在 npm 公开可获取**（rc 版本）。generator 导出 `WorkspaceAnalyzer`（可独立调用）与 `./tsdown` 插件（可集成构建），README 明示「Static consumers can still call WorkspaceAnalyzer directly」。因此 dsh-memory 可在包内完成 Typert remote 接入。备选（若嫌 Typert 接入繁琐）：把 `MemoryGateway` 做成 SSiD profile 行内插件，借用宿主构建。
2. **slot 位置待确认**：本设计暂定「设置页 tab」（`settings.plugins.tab` 已有先例、最稳）；但 fractal 记忆面板是「右侧 tab」，若 SSiD 想要同样体验，需先确认 DSH 是否有会话侧栏面板 slot（`SlotMap` 待查），没有则退居设置页。
3. **remote 类型必须 JSON-compatible**：`MemoryRecord`/`MemoryHit` 已是纯对象 + 字符串 id，满足；`MemoryId` 是 branded 类型，序列化时需转 `String(id)`（dsh-memory 工具层已有 `recordValue` 先例）。
