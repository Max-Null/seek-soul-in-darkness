## 一、anywhere-labs 的架构骨架（已读源码）

三层分工，清晰可复用：

| 层 | 文件 | 职责 |
|---|---|---|
| Electron bootstrap | `main.ts` | 单实例锁 → `app.whenReady` → `boot()` 启动 DSH Host → `provide()` 注入桌面能力 |
| 桌面运行时 | `electron-runtime.ts` | 托盘 / 窗口 / 更新的原生 Electron 实现 |
| 壳插件 | `index.ts`（`desktop-shell`） | 消费 `desktopRuntime`，构造 loopback URL，调度 BrowserWindow |

## 二、关键机制（自研壳的骨架）

### 1. 用 `boot()` 在 Electron main 里启动 DSH Host

```ts
// main.ts 核心（约 50 行）
const ctx = await boot(BIN_NAME, rootConfig, patches, async (hostCtx) => {
  hostCtx.provide('desktopRuntime', runtime)          // 注入托盘/窗口能力
  hostCtx.provide('desktopPnpmBootstrap', ...)        // 注入 pnpm 能力
  await hostCtx.plugin(DesktopProfileService, {...})  // 注册 desktopProfiles 服务
  provideCmdline(hostCtx, { args: ['--host', '127.0.0.1', '--port', '0'] })  // loopback web
})
```

- `boot()` 来自 `@deepseek-ai/dsh-app-boot`——**Electron 只做 bootstrap，DSH Host 在 main 进程里正常 boot**。
- 桌面能力通过 `hostCtx.provide()` 注入 Host context，壳插件通过 `inject` 消费——这就是我之前设计的「`ctx.desktop` 壳级服务」的落地方式。

### 2. desktop-shell 插件调度 BrowserWindow 加载官方 UI

```ts
// index.ts 核心
export const inject = ['desktopRuntime', 'webServer', 'webRuntime', 'appExit', 'settings']
export function apply(ctx: Context, config: Config): void {
  ctx.effect(() => ctx.desktopRuntime.schedule({
    url: desktopRendererUrl(ctx.webServer.port, ...),  // http://127.0.0.1:<port>/
    productName: 'DSH Desktop',
    windowTitle: 'DeepSeek Harness Desktop',
    iconPath, trayIcons,
  }), 'native shell generation')
}
```

- 窗口加载的是 **loopback 官方 Web UI 本体**（`http://127.0.0.1:<port>/`），非仿制。
- `desktopRuntime.schedule()` 是壳插件和原生运行时的唯一桥。

### 3. 托盘/窗口/更新在 electron-runtime.ts

`ElectronDesktopRuntime` 暴露：`schedule()`（创建窗口）、`show()`、`prepareToQuit()`、`requestRestart()`、`setThemeSource()`、`configureTerminal()`、`updates.notify()` 等。

## 五、结论

**自研壳的路径清晰、工作量可控**：复用「boot + provide 注入 + loopback UI」三件套思路（这些是 DSH 官方提供的通用机制，不是 anywhere-labs 的私有资产），自研 `electron-runtime`（托盘/窗口/通知）+ `ssid-shell` 插件（加载官方 UI + 品牌）+ `ctx.desktop` 服务（壳级能力）。

关键：**这套架构的核心（`boot()`、`provide()`、loopback web server）全是 DSH 官方的公开能力**，anywhere-labs 只是把它们组装起来了。所以自研壳不涉及"抄 anywhere-labs 的私有代码"，而是"用 DSH 官方机制重新组装 + 换品牌"。
