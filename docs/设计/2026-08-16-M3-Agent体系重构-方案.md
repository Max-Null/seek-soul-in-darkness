# M3 · Agent 体系重构方案（2026-08-16）

> 状态：方案草案（对齐后动手）
> 范围：协作编排 + 角色体系 + 模型路由 + 底层机制，四层全重构
> 调研来源：oc-plus 双星系统 agents/*.md 原始设计 + DSH agent/subagent/tool-subagent 源码实测

## 一、调研结论（决定方案的事实）

| # | 事实 | 来源 |
|---|---|---|
| 1 | DSH 子 agent 的角色声明 = preset 里一行 `tool-subagent`：`persona`（per-child 覆盖）+ `toolFilter`（allow/deny）+ `agentOptions`（provider/model/maxTokens）+ `backgroundMode` | tool-subagent Config 实测 |
| 2 | **DSH 无 temperature 透传**：AgentOptions 只有 provider/model/maxTokens。oc-plus 的 0.1/0.3 维度必须放弃，用 persona 纪律替代 | agent/runtime-types.ts 实测 |
| 3 | `backgroundMode: continuable` = oc-plus 的 task_id 续接机制（可续接子 agent） | tool-subagent Config |
| 4 | `fork` provider 继承父上下文（研究型子任务）、`spawn` 干净上下文（执行型） | preset 现状 |
| 5 | 子 agent 模型路由：`agentOptions.model` 每角色独立可配（工匠 flash、制图师 vision） | tool-subagent Config |
| 6 | 制图师的 vision 模型（kimi k3）走 `llm-pi-ai` 多 provider 插件（settings `llm-pi-ai` section） | llm-pi-ai 源码 |
| 7 | 主 agent = agent-presets（ssid-double-star 已就位，含四阶段纪律 + compaction + guardian 提醒） | 现有资产 |

## 二、角色体系：7 → 4

| 角色 | 去留 | 理由 |
|---|---|---|
| 双星 | **主 agent（preset）** | 编排者，四阶段纪律保留 |
| 工匠 | **保留**（continuable + flash） | 阶段 3 执行者，续接刚需 |
| 军师 | **保留**（one-shot + 只读） | 阶段 4 审查，12 异味清单 |
| 制图师 | **保留**（one-shot + kimi k3） | 看图刚需，成本纪律保留 |
| 参谋 | **退役** | 价值 =「方向偏离检查」，并入四阶段自检纪律 + 军师职责（军师审查时问「规格是否偏离用户目标」） |
| 助理 | **退役** | 与工匠重叠（都是执行者），oc-plus 里就是低频角色 |
| 侦查兵 | 已退役 | DSH 原生 web_search 替代 |

> 7→4 的理由：oc-plus 的 7 角色是 OC 时代的产物（OC 子 agent 无 person/toolFilter/模型独立路由，角色被迫用多个 agent 表达）。DSH 一行配置就能表达一个角色，角色应收敛到「职责不重叠的最小集」。参谋/助理的功能由纪律和工具替代，不是砍功能。

## 三、底层机制：agent-presets + 每角色一行 tool-subagent

不用 workflow（那是工具编排不是 agent 协作）、不用 ralph（那是循环迭代）。子 agent 角色直接声明在 `ssid-double-star/agent.cordis.yml`：

```yaml
# 工匠：continuable + flash + 编辑工具集
- id: tool-subagent-artisan
  name: '@deepseek-ai/dsh-tool-subagent'
  config:
    provider: spawn
    toolName: subagent_artisan
    backgroundMode: continuable
    agentOptions: { provider: deepseek-official, model: deepseek-v4-flash }
    persona: <工匠 persona>
    toolFilter: { allow: [read, edit, write, glob, grep, bash, pwsh, todo_write] }

# 军师：one-shot + 只读 + 继承主模型（pro）
- id: tool-subagent-strategist
  name: '@deepseek-ai/dsh-tool-subagent'
  config:
    provider: fork          # 继承父上下文才能审全局
    toolName: subagent_strategist
    persona: <军师 persona>
    toolFilter: { allow: [read, glob, grep, web_search] }

# 制图师：one-shot + kimi k3 + 只读
- id: tool-subagent-cartographer
  name: '@deepseek-ai/dsh-tool-subagent'
  config:
    provider: spawn
    toolName: subagent_cartographer
    agentOptions: { provider: pi-ai, model: kimi-k3 }
    persona: <制图师 persona>
    toolFilter: { allow: [read] }
```

（toolName 用 `subagent_<角色>` 而非 `subagent`：每个角色一个独立工具，模型能按名委派，语义清晰。）

## 四、协作编排：四阶段纪律保留，机制映射到 DSH 原生

| oc-plus 四阶段 | DSH 落点 |
|---|---|
| 阶段 1 研究（并行工匠探索） | 并行 `subagent_artisan`（continuable，研究完续接实现）或 `fork` 只读探索 |
| 阶段 2 综合（规格落盘） | 主 agent 写 `docs/设计/` 或 `docs/计划/`；自检「规格已落盘」 |
| 阶段 3 实现 | `subagent_artisan` continuable 续接（对应 task_id 续接：同一子会话、保留上下文） |
| 阶段 4 验证 | `subagent_strategist` 审查 + 主 agent 亲自 `git diff`（双星纪律原样保留） |

双星 persona 的「子 agent 续接机制」段改写：task_id → `subagent_id`（continuable 的 durable child id），规则不变（不转发确认问题给用户、不新建任务、不接手剩余工作）。

## 五、模型路由（成本分层）

| 角色 | 模型 | 理由 |
|---|---|---|
| 双星（主） | deepseek-v4-pro | 已有（settings.yaml agent-default-model） |
| 工匠 | deepseek-v4-flash | 执行不需要深度思考，flash 便宜 |
| 军师 | 继承（pro） | 审查需要全局视野，值得 pro |
| 制图师 | kimi-k3（pi-ai） | vision 刚需，单次给到位控成本 |

待办：配置 `llm-pi-ai` settings section 挂 kimi k3（M3 首个任务，先确认 kimi 的 pi-ai 兼容性）。

## 六、temperature 维度的替代

DSH 无 temperature 透传。替代方案 = persona 纪律收紧：
- 工匠（原 0.1）：「执行者，不思考；输出=文件+改动+测试结果，不总结不提议」
- 军师（原 0.3）：「输出 3-5 句；没问题说『审查通过』」
- 主 agent 的 reasoningEffort 已在 settings（max）——思考深度由这个维度控制。

## 七、验收标准

1. preset 里三个子 agent 角色可被主 agent 按名委派（`subagent_artisan`/`subagent_strategist`/`subagent_cartographer`）
2. 复杂编码任务走完整四阶段：研究→综合→实现→验证
3. 工匠可续接（同子会话连续修改，不丢上下文）
4. 制图师用 kimi k3 看图（读图工具验证）
5. 模型路由正确：工匠请求路由到 flash、制图师到 kimi
6. 真实端到端：一个跨文件改动任务完整跑四阶段

## 八、风险与护栏

- **kimi k3 的 pi-ai 兼容性未验证**：若 pi-ai 不兼容，制图师改用 deepseek 官方 vision（若有）或暂缓（M3 其他部分不阻塞）。
- **continuable 子 agent 的资源管理**：DSH continuation manager 持有 handle，长会话需确认 idle 回收。
- **fork vs spawn**：军师用 fork 继承上下文（审全局），但 fork 的子会话会携带完整前缀（token 成本）——若成本过高改 spawn + persona 指令「先读相关文件」。
- **四阶段纪律靠 persona**（提示词工程），不是硬约束——这正是 Guardian 断言触发线的用武之地（阶段 4 自检可接入 guardian 状态）。
