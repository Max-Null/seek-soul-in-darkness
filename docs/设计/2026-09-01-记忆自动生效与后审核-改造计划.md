## 一、背景与目标

### 1.1 调研结论（一句话）

OpenClaw 1.0 的记忆设计（md 明文 + 人工审核）与 SSiD 现设计同源；2.0 走了"自动化 + 前置机检、去掉人工"的路，但**主线至今没有人工记忆队列**（社区提案 PR #87900 已被挂起）。SSiD 要走的是**第四种**：全自动生效，人工退到门后做审计——与 OpenClaw 2.0 的区别不在"要不要自动"，而在**审核门的位置**：他们前置（机检/人审均前置），我们后置（守卫扫描 + 人只审标记项 + 可回滚）。

### 1.2 项目侧目标

1. **写入自动生效**：`memory_save` 不再默认落在"待审核→等人工确认"的冷路径；低风险记忆直接生效并参与注入/检索。
2. **人工不缺席但后置**：人工从"批准者"变"审计者"——守卫主动扫描、标记异常、自动降权；人只处理标记清单。
3. **可逆性先行**：所有记忆带 provenance（来源会话/轮次/触发者）与版本快照；回滚 = 切换版本，不是删除恢复。
4. **守卫主动**：补上记忆维度的守卫（冲突/来源缺失/注入预算异常/危险内容），复用 dsh-guardian 的事件链。
5. **习惯沉淀全自动闭环**：habit 从"两级闸门"调整为"自动沉淀 + 守卫复检"，保留高风险批准。

### 1.3 边界声明

- 本计划仅覆盖 **SSiD 单人场景**。AI 中台（多人一 Agent）的记忆治理（scope 分层、owner-signed、组织级前置批准）需另行立项，与本计划共享"自动+后审+可逆"理念但实现不同。
- 敏感凭证类内容**一律不入记忆库**（延续 OpenClaw 2.0 的 Private Credential 原则与 SSiD 现状纪律）；守卫的"危险内容"检测作为兜底而非依赖机制。

## 三、目标模式

### 3.1 三件套职责

| 组件 | 职责 | 是否 LLM | 时间尺度 |
|---|---|---|---|
| **memory**（dsh-memory） | 记忆存储/检索/注入/版本链 | 否（检索有 BM25） | 常驻 |
| **habit**（dsh-habit） | 跨会话行为信号 → 经验/习惯沉淀（自动，flash 低频） | 是（flash 批量） | 跨会话 |
| **guard**（dsh-guardian 扩展） | 写后扫描、异常标记、自动降权、回滚建议 | 否（确定性）→ 可选 LLM 冲突检测（低频） | 实时/会话末 |

### 3.2 写入路径（改造后）

```
模型 memory_save / habit 沉淀
  → 路由判定（risk 分级）
      low   → status=approved, autoEffective=true, 直接生效 → 守卫异步扫描
      med   → autoEffective=true 但标记「观察期」→ 守卫扫描 → 无异常自动转正
      high  → 影子模式：仅检索不注入+入审计清单 → 人工放行 或 N 天后自动转正
  → 全程 provenance + 版本快照写入
  → 守卫扫描（冲突/来源/预算/危险）→ 命中 → 降权/标记 → 入审计面板
```

### 3.3 与三个既有设计的衔接

| 既有设计 | 衔接方式 |
|---|---|
| 08-19 解耦 | **直接前置实施**（P0）；本计划在其二维模型上增加 risk/provenance/version 字段 |
| 08-16 habit 两级闸门 | **闸门节奏调整**："候选确认 + memory 确认" 两级前置闸门 → "自动沉淀 + 守卫复检 + 审计面板兜底"；LLM 输出无人工确认直接生效的**高风险候选仍走人工**（保留纪律：自学习不自我污染，污染防线从"人工"转移为"守卫扫描 + 可回滚"） |
| 08-16 guardian 三触发线 | **扩展第四维度**：记忆守卫（新 engine 模块），复用 session/event + storage 骨架；单测覆盖 |

## 四、记录模型（schema 增量）

> 现状 + 解耦方案：`{ id, namespace, status: suggested|approved, injected, content, keywords, createdAt, updatedAt }`

增量字段：

```jsonc
{
  "risk": "low|medium|high",              // 写路径分级（决定生效策略）
  "provenance": {                          // 来源链（可逆性基础）
    "sourceSession": "…", "sourceTurn": 123,
    "trigger": "memory_save|habit|consolidate",
    "generatedAt": "…"
  },
  "version": 3,
  "history": [ /* 前 N 版内容快照，滚动保留 */ ],
  "flagged": [ /* 守卫标记：{at, check, level, detail, status: open|ack|cleared} */ ],
  "shadowUntil": "… | null"               // 影子模式到期时间（high 风险项）
}
```

**守卫标记状态机**：`open`（待处理）→ `cleared`（人工确认无误）/ `ack`（已知悉，保留降权）。标记不删除记忆，只影响注入/检索权重。

## 五、守卫记忆维度（dsh-guardian 扩展）

| 检测 | 方式 | 动作 |
|---|---|---|
| 冲突 | 新记忆语义与既有 approved 记忆矛盾（BM25 高相似 + LLM 低频复核） | 标记 open → 人审（采纳新/保留旧/合并） |
| 来源缺失 | provenance 缺关键字段（非 memory_save 通道写入） | 直接降权 + 标记 |
| 注入预算 | 新记忆加入后高频记忆被挤出注入（对照注入预览） | 降权（新记忆 injected=false） |
| 危险内容 | 命中密钥/Token/密码模式（正则 + 敏感词） | 隔离（不注入不检索）+ 标记 open |
| 语义重复 | 与既有记忆相似度过高 | 候选合并项 → 人审 | 

原则：**守卫只降权/标记，不删除**；删除权只在审计面板人工操作。

## 六、分期实施

| 期 | 内容 | 验收 |
|---|---|---|
| **P0**（前置） | 实施 08-19 解耦：二维 schema + 迁移 + 面板三组 + 注入开关 | 旧 8 条记忆迁移后注入行为不变；开关生效 |
| **P1** | 记录模型增量：risk/provenance/version/history/flagged/shadowUntil；`memory_save` 路由（低危 direct approve，高危 suggested+影子） | 写入自动生效；每条新记忆带 provenance 与快照；回滚可恢复前一版 |
| **P2** | guard 记忆维度（五项检测）+ 审计面板（记忆 tab 增"守卫标记/影子期"分组） | 五检测各自命中 → 正确降权/标记并可见 |
| **P3** | habit 自动沉淀改造（闸门后置）+ 影子模式到期转正（cron） | 3 次纠正 → 候选自动沉淀 low/med 生效；high 走影子 → N 天后转正 |
| **P4** | 回滚演练 + 全量回归（memory/habit/guardian 三插件联动） | 模拟坏记忆写入 → 守卫标记 → 一键回滚到前版本，主流程不受影响 |

**依赖顺序**：P0 → P1 → P2 可并行（guard 骨架已定稿）→ P3 依赖 P1/P2 → P4 收尾。
**先例复用**：habit 的 flash 批量分析通道（阈值 3、串行队列）直接复用于"冲突复核"；guardian 的 sessionId 分桶、两层 storage 直接复用。

## 七、风险与护栏

| 风险 | 护栏 |
|---|---|
| 自动生效引入坏记忆（错误被固化放大） | 可逆：版本快照 + 回滚；守卫标记 open 即影响注入；高危必须影子期 |
| 守卫误报导致合法记忆被降权 | 检测动作是"标记 + 降权"，人工可 cleared 恢复；冲突检测须 LLM 复核而非纯相似度 |
| 自动失效后"从不审" | 审计面板强制：open 标记未处理时状态 tab 常驻提示（复用 guardian 注入提醒） |
| habit 自动沉淀污染 | 高风险候选保留人工；LLM 判断纪律（证据不足 skip）不变；守卫复检兜底 |
| 与注入预算/现有记忆处理冲突 | 保持注入预算机制不变，只增加"降权"动作；回归用例覆盖 |
| 迁移兼容 | P0 已含迁移规则；P1 仅增量字段，旧记录缺失字段按默认值（low/无 provenance/无历史） |
