## 一、问题背景

### 1.1 现状机制（读代码实证）

`dsh-memory` 的注入通道与检索通道是**两条独立设计**：

| 通道 | 机制 | 代码位置 |
|---|---|---|
| 注入 | `auto` 状态记忆 → `systemPrompt.context` **无条件全量注入**（无检索、无条数限制） | `dist/index.js:54-60` `recallText()` |
| 检索 | `memory_search` 工具 → BM25 评分，模型主动调用才触发 | `dist/engine.js:114-121` `search()` |
| 状态 | `suggested`/`suggest` 不注入；`auto` 每轮全量注入 | `index.js:55` 只取 auto |

隐藏细节：
- `list` 不传 namespace 时 **global + project 的 auto 都注入**（`engine.js:158-161`）
- 引擎 `setStatus(id, status)` **双向支持**（可 auto→suggested 降级），但工具/UI 只暴露 confirm（单向 suggested→auto）

### 1.2 问题：语义绑定错误

**`auto` 一个状态同时承担两个维度**：
1. 「该记忆经人工审核通过」（用户原本意图的审核机制）
2. 「该记忆每轮常驻注入」（实现的实际效果）

用户确认记忆（`memory_confirm` → `setStatus(id, 'auto')`）时触发的其实是②，但本意是①——导致**办公文档类方法论记忆（低频场景）确认后也被全量注入**，浪费上下文。「auto」状态名 + 面板 tab 英文原值 + 英文工具描述进一步误导了语义理解。

### 1.3 目标

- 审核（内容认可）与注入（常驻/按需）**解耦为两个独立维度**
- 审核通过 ≠ 默认常驻注入；注入与否由用户显式开关
- UI 文案中文化并与 DSH 语言切换联动（client 侧 `ctx.get('locale')` + `locale/change`，插件中心已有先例）

## 二、方案：二维模型

### 2.1 存储层（schema 变更）

```
现状：{ id, namespace, status: suggested|auto|suggest, content, keywords, createdAt, updatedAt }
新设：{ id, namespace, status: suggested|approved,  // 审核维度
        injected: boolean,                          // 注入维度（常驻开关）
        content, keywords, createdAt, updatedAt }
```

| status × injected | 语义 | 注入行为 |
|---|---|---|
| `suggested` + false | 待审核（默认） | 不注入，可检索 |
| `approved` + false | 已审核，按需 | 不注入，`memory_search` 检索 |
| `approved` + true | 已审核，常驻 | **每轮全量注入** |
| `suggested` + true | 非法组合 | UI 禁用开关（未审核不可开） |

**迁移规则**（一次性，读旧 schema 时兼容转换）：
- 旧 `auto` → `{ status: 'approved', injected: true }`（行为不变，不丢记忆）
- 旧 `suggest` → `{ status: 'suggested', injected: false }`
- 旧 `suggested` → `{ status: 'suggested', injected: false }`

### 2.2 注入逻辑（`dist/index.js` recallText 一处改动）

```js
function recallText(memory) {
    // 只注入「已审核 + 常驻开关打开」的记忆
    const auto = memory.list({ status: 'approved', injected: true });
    ...
}
```

`engine.list()` 需支持按 injected 过滤（filter 增加 `injected` 字段）。

### 2.3 工具层（dsh-memory `dist/index.js`）

- `memory_confirm`：语义改为「审核通过」（suggested → approved），**不再直接触发注入**。描述同步改：
  - 现状（英文）：`Confirm a suggested memory so it becomes effective (auto).`
  - 改后（审核语义）：中英双语，明确「标记为已审核；是否常驻注入由用户决定」
- **不新增模型工具**（如 memory_pin/unpin）：模型工具 schema 占上下文，注入开关是低频人工决策，由 UI 承担
- host RPC（`dist/remote.js`）新增 `memory.setInjected(id, boolean)`（供面板开关调用），或复用现有 gateway 加方法

### 2.4 UI 层（dsh-ssid-panels 记忆 tab）

- **卡片新增「常驻注入」开关**：`approved` 可切换，`suggested` 禁用（带提示「审核通过后可常驻注入」）
- **状态名中文化**（i18n 联动，复用 `STRINGS[localeId]` + locale/change）：
  - `suggested` → 待审核
  - `approved` → 已审核
  - 注入开关 → 常驻注入
- **分组**：三组——待审核 / 按需（已审核未注入）/ 常驻注入；组间分隔
- **筛选**：namespace 筛选（全部/global/project）
- **排序**：组内默认 updatedAt 降序（最新在前）；开关操作后即时重排到对应组

## 三、已确认决策（2026-08-19）

1. **审核通过后默认不注入**（injected=false）；现有 8 条 `auto` 迁移时置 true 保持现状，用户可手动关
2. **memory_search 检索范围含 `suggested`**（待审核记忆也能搜到，确认前可评估内容）
3. **分组维度 = 按状态三组 + namespace 筛选**
4. **本方案同时重写 GUIDANCE 文案**（审核语义 + 中英双语）

## 四、一键整理记忆按钮（本轮实施）

> 用户决策（2026-08-19）：按钮在**记忆 tab 头部工具栏**；**一点即发**（建会话+预填+自动提交）；**本轮做**。

### 4.1 交互

```
点击「整理记忆」按钮
 → ctx.sessions.create({ workspaceId, cwd }) 继承当前工作区
 → ctx.sessions.open(sessionId) 切换到新会话
 → 新会话 input 就绪后 setDraft(整理指令) → submit()
 → 新会话中 LLM 收到指令，用 memory_list/memory_search + memory_save/memory_forget 执行整理
```

### 4.2 预填指令（草案）

> 请整理我的记忆库：用 memory_list 查看全部记忆，合并重复或可归并的条目，精简冗长内容，为每条补充或修正 keywords（仅用 memory_save 新增、memory_forget 删除，改动全部落在 suggested 等待审核，不要调用 memory_confirm）。完成后用一句话汇报整理结果。

### 4.3 实现要点（DSH 原生机制，已查证）

| 能力 | 机制 | 位置 |
|---|---|---|
| 建会话 | `ctx.sessions.create({ workspaceId, cwd })` | `client/runtime/sessions/service.ts:485` |
| 切会话 | `ctx.sessions.open(sessionId)` | service.ts |
| 预填 | 会话 input `setDraft(text)`（会话 bind 后） | `ui-conversation/input/contract.ts:35` |
| 提交 | `SessionInput.submit(mode)` 或 `InputActions.submit()` | `contract.ts:46,83` |

**待验证项（实施时）**：
- 新会话 open 后 input 何时可 bind（等 `input` 就绪再 setDraft，避免 draft 写入失败）
- `submit()` 的调用入口在面板上下文如何拿到（ui-conversation input facade/hub vs sessions service）
- workspaceId/cwd 未选定时 create 的默认行为（hero 页场景）

### 4.4 与解耦的关系

整理流程**不依赖**解耦（injected 不影响整理）；但解耦后「整理」可顺带把高频记忆的 injected 开关置 true 写进指令（可选增强，本期不做）。先做整理按钮 = 立刻收敛现有 8 条大段记忆。

## 六、风险与注意

| 项 | 说明 |
|---|---|
| 旧数据兼容 | 迁移逻辑要兼容旧 schema 缺 injected 字段的情况（undefined → 按旧 status 推断：auto=true，其他=false） |
| host 侧 GUIDANCE 双语 | system prompt 是 host 侧，DSH locale 是 client 侧——动态切换不可行，采用**中英双语都写**（模型自取），面板文案走 client 双语 |
| 面板开关与工具一致性 | 面板 setInjected 走 RPC，与引擎状态一致；外部直接改 JSON 不被 watch（现有已知边界，面板刷新可见） |
