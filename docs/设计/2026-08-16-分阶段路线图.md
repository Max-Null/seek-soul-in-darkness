## M0 · 闭环验证

**目标**：确认「DSH 官方 GUI + anywhere-labs 壳 + dsh-memory + dsh-chinese-thinking」能一起跑。

**任务**：
1. 路径 A 下载 anywhere-labs 安装包（不构建）。
2. `dsh plugin --profile desktop add @max-null/dsh-memory @max-null/dsh-chinese-thinking`。
3. 重启应用验证。

**验收标准**：
- [ ] Electron 窗口内是官方 DSH Web UI（非仿制）。
- [ ] 中文思考生效（首轮即中文）。
- [ ] `memory_save/list/search/confirm/forget` 五个工具可被模型调用。

## M1 · 记忆 UI 面板

**目标**：补上 dsh-memory 目前「只有工具、无 UI」的缺口，人在图形界面浏览/搜索/确认/删除记忆。

**前置**：确认 Typert 是否支持仓库外独立插件接入（见记忆 UI 面板设计文档「待确认项」）。

**任务**（按设计文档）：
1. host 侧：dsh-memory 加 `MemoryGateway`（`TypertRemoteService`，暴露 `list/search/confirm/forget`）。
2. client 侧：注册设置页 tab，`MemorySettingsTab` 组件（三态 + 搜索 + 卡片 + 确认/删除）。
3. 中英文案（沿用思灵品牌：「黑暗中未见灵光」空状态）。

**验收标准**：
- [ ] dsh web 设置页出现「记忆」tab。
- [ ] 能列出 global/project 两层记忆，按 status 过滤。
- [ ] 能搜索、确认（suggested→auto）、删除。
- [ ] `pnpm run test:gui` 组件单测通过。

## M2 · Guardian 状态引擎

**目标**：把 fractal 的「📊 状态面板」（触发线监控：断言计数、编辑审查队列、无反馈环轮次）搬到 DSH。

**前置**：M1 跑通（积累了 remote + UI 的完整经验）。

**任务**：
1. 把 Guardian 的触发线逻辑映射到 DSH 的 `session/event` 事件源。
2. 自建状态存储（复用 dsh-memory 的两层 storage 思路）。
3. 状态面板 UI（参照 M1 的 remote + slot 模式）。

**验收标准**：
- [ ] 断言计数、编辑审查队列、无反馈环轮次可视化。
- [ ] 状态随会话事件实时更新。

> 本里程碑是 fractal 差异化里「需要重做」的最大块，建议拆成 2-3 个子任务逐块落地。

## M3 · 四 agent 编排

**目标**：把 oc-plus 的双星/工匠/参谋/军师四 agent 协作，用 DSH 的 `agent-presets` + `subagent` 重写。

**任务**：
1. 定义四个 agent preset（persona + 工具范围 + 权限）。
2. 用 subagent 编排协作流程（主 agent 委派 + 汇报）。

**验收标准**：
- [ ] 四个 agent 可按预设分工协作。
- [ ] 复杂任务能「主 agent 拆解 → 子 agent 执行 → 汇报」。

> 可并行于 M2。DSH 的 subagent 是原生能力，此里程碑主要是「编排配置」，非底层开发。

## M4 · 品牌壳

**目标**：fork anywhere-labs，替换为 SSiD（思灵）品牌，产出「思灵」exe。

**任务**：
1. 换应用图标 / 托盘图标为 Si 原子 + 瞳孔 logo。
2. 窗口标题「思灵」+ 主题命名对齐品牌手册（深渊 / 巨鲸之眼）。
3. `dist:win` 打包。

**验收标准**：
- [ ] 产出「思灵」品牌安装包。
- [ ] 图标 / 标题 / 主题命名与品牌手册一致。
