## 三、B 块：余额查询面板

分形机制照搬（`fractal/electron/main/ipc.ts` 计费迭代），SSiD 侧：

- **DeepSeek**：`GET https://api.deepseek.com/user/balance`，
  `Authorization: Bearer <DEEPSEEK_API_KEY>`，
  响应 `{ is_available, balance_infos: [{currency, total_balance, …}] }`
- **Kimi**：`GET https://api.moonshot.cn/v1/users/me/balance`，
  响应 `{ code: 0, data: { available_balance, voucher_balance, cash_balance } }`，
  `isAvailable = available_balance > 0`
- 归一化返回（两 provider 对称）：`{ ok, isAvailable, balanceInfos: [{currency, totalBalance}], message? }`
- key 由主进程读（渲染层零接触）：main.mjs IPC handler 从 DSH credentials
  服务（`ctx.get('credentials')`）解析 `DEEPSEEK_API_KEY` / `MOONSHOT_API_KEY`
- 侧栏加第 4 tab「余额」：两条余额卡 + 刷新按钮 + 轮询（可选，默认手动刷新）

### B 验收

- [ ] 侧栏余额 tab 显示 DS/K3 两条余额与可用状态
- [ ] key 缺失时显示明确提示（不 500）
- [ ] 渲染层零接触 key（IPC 只传归一化结果）

## 四、C 块：文件预览面板（壳级）

### 现状与决策

- DSH 官方 UI 附件预览仅图片（`dsh-client-ui-attachment`："Images only"），
  非图片预览空白——插件清单已列 `@max-null/dsh-preview` 为 M4 后项
- **第三方 client 插件路线否决**（决策记录）：DSH client 插件的构建链是
  `tsdown clientBundle()` + `modules` 静态模块表（`seed.ts`），均属 DSH 仓库
  内设施；独立仓库没有可用的 client 构建出口。按原则「不改 DSH 代码」，
  文件预览走**壳级**：SSiD 侧栏内嵌预览面板，不触碰 DSH 前端
- 文件来源：会话产出的文件列表（write/edit 工具结果 / ui-deliverables
  同源数据），由 host 侧 session projection 读出，IPC 传给侧栏

### 实现（侧栏「文件」tab）

1. 主进程：读当前活跃会话的 produced files（session projection 的
   deliverables 键，host 同进程可直接调 projection 服务）
2. IPC：`ssid:files:list`（文件列表）、`ssid:files:read`（读文件内容，
   文本传 string、二进制按格式约定）、`ssid:files:open`（系统默认程序打开）
3. 侧栏渲染：md（marked）、html（sanitize 后 iframe）、docx（mammoth）、
   xlsx（SheetJS 表格视图）、pdf（pdf.js 逐页渲染）、图片（img）、
   其余格式显示元信息 + 「系统打开」按钮

### C 验收

- [ ] 会话产出 .md 文件在侧栏预览渲染（标题/代码块正常）
- [ ] docx/xlsx/pdf 至少各一种可预览
- [ ] 未知格式降级为元信息 + 系统打开

## 五、风险与护栏

- 打包涉及下载 electron 发行版/electron-builder（网络）；失败不阻塞 A1/A2 手动验证
- C 块的 session projection 读取若 host 侧接口不直接可用，回退：扫描
  会话日志的 tool/result 事件提取文件路径（已有 zstd 扫描能力）
- 任何一步卡住按路线图「退出/回退」护栏处理，不留半截代码进 main
