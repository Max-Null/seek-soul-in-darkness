## 一、rc.8 关键事实（已查证）

| 项 | 结论 |
|---|---|
| web-react | 已删除，React bindings 并入 ui-renderer；我们插件均不直接 import |
| 新增包 | ui-brand-official / ui-reference / file-reference(-local) / agent-team（experimental）/ tool-pwsh-persistent |
| verify-client-packages | rc.8 新门禁：Cordis 必须 peer+dev 配对、动态包内部依赖 peer+dev（仓库内检查，语义为插件最佳实践） |
| 多模态 | 仅 API 管线（image_url data-URL），官方 DeepSeek 模型无视觉；UI 展示图片与模型能力无关 |
| 文件引用 | `fileReferences` 服务：`@path`/`@"path with spaces"` 光标解析，`FileReferenceCandidate[]` 返回 |

## 二、升级方向清单

### 高价值（必做）

#### H1. dsh-skill-mcp-center：SKILL.md 正文文件引用可点击

- **现状**：0.2.0 已有 `readSkill` RPC 展示 SKILL.md 原文（纯文本）
- **升级**：client 侧解析正文中的 `@路径`/`@"带空格路径"`，调 `fileReferences` 服务解析候选，渲染为可点击链接（点击打开/定位文件）
- **改动面**：client/index.tsx（SkillView md 区块）+ 类型定义；host 无需改动
- **验收**：SKILL.md 中写 `@docs/pitfalls.md`，面板中可点击跳转

#### H2. dsh-memory：记忆内容文件引用可点击

- **现状**：0.3.8 记忆卡片纯文本展示 content
- **升级**：与 H1 同一机制——记忆正文中的 `@路径` 渲染为可点击链接
- **改动面**：client 记忆卡片渲染 + fileReferences 调用
- **验收**：记忆内容含 `@src/xxx.ts` 时可点击

#### H3. 全家桶依赖声明规范（对齐 verify-client-packages 语义）

- **现状**：部分插件 peer/dev 配对不齐（如 chat-rail peer 有 `@deepseek-ai/cordis` 但 dev 缺配对；node-appearance 需确认 dev 配对）
- **升级**：10 个插件逐一扫描，补全 Cordis 及各 `@deepseek-ai/*` 的 peer+dev 配对；`files` 字段覆盖检查
- **改动面**：各 package.json（纯声明，无代码）
- **验收**：`pnpm install` 无 peer 告警；若未来入 DSH 官方体系可过 verify-client-packages

### 中价值（按需做）

#### M1. dsh-ssid-panels：品牌槽位对齐

- **现状**：SSiD 品牌（Si 瞳孔 logo）通过 CSS/自绘实现
- **升级**：用 rc.8 `ui-brand-official` 同款槽位机制（`sidebar.brand.mark` / `conversation.hero.brand.mark`）注册品牌标记，与官方品牌机制对齐
- **注意**：槽位为官方包注册，需确认第三方注册同名槽位是否冲突（先查 ui-brand-official 的声明方式）

#### M2. dsh-chat-rail：含图消息缩略标记

- **现状**：指示点/预览为文本导向
- **升级**：识别含图片内容块的消息，指示点加图片标记 + 预览显示缩略图
- **背景**：rc.8 多模态管线使图片附件进入会话成为可能（模型是否看是另一回事，UI 展示独立成立）
- **改动面**：client 消息解析 + 指示点渲染

#### M3. dsh-node-appearance：新节点类型着色覆盖

- **现状**：按类别/工具名着色（search/agent/execute/file/task/command/thinking/context/other）
- **升级**：覆盖 rc.8 新增节点形态（附件节点、file-reference 引用节点等）
- **前置**：先确认 rc.8 会话事件中这些新节点的事件类型与外观标识
