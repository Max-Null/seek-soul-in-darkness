# M2 · Guardian 状态引擎——DSH 移植设计（2026-08-16）

> 状态：设计稿（动手实现前落盘）
> 来源：fractal 三代资产（`fractal/electron/resources/preset/plugins/fractal-guardian.js`）+ 路线图 M2
> 原则：独立 npm 插件（dsh-memory 同款模式），DSH 内核零改动，SSiD 壳补 UI

## 一、目标

把 fractal 的「📊 状态面板」三个触发线搬到 DSH：

| 触发线 | fractal 定义 | 一句话 |
|---|---|---|
| 断言计数 | `ASSERTION_RE` 匹配模型输出的「不支持/做不到/只有 N 种/不存在/无法 X/远低于/过于 X」 | 模型凭空下断言，计数并提醒 |
| 编辑审查队列 | 文件编辑攒队列（filePath + trigger + relatedDocs/Tests + sessionID，≤20），会话结束 flush | 改完不审查，队列追账 |
| 无反馈环 | 连续 N 轮「改代码但没跑测试」（编辑+1、bash 清零），阈值 3 注入警告 | 没有反馈环的修改是在瞎跑 |

## 二、DSH 事件源映射

| fractal hook | DSH 事件 |
|---|---|
| `experimental.chat.system.transform`（每轮开头注入） | `systemPrompt.context`（动态 text 函数，每轮重算） |
| assistant 消息内容扫描 | `session/event` → `assistant/message`，扫描 `message.content` 的 text 块 |
| 工具调用识别 | `session/event` → `tool/call`（name 判 write/edit/bash/pwsh） |
| 轮次结算 | `session/event` → `turn/end` |
| 会话隔离 | state key = sessionId（`session/end-seed` 后清零不适用——按 sessionId 分桶即可） |

## 三、插件形态：`@max-null/dsh-guardian`（独立 npm，bundle）

对齐 dsh-memory：`dsh.bundle.patch` 声明 + `cordis.patch.yml` 一行 insert + peerDeps。

```
dsh-guardian/
├── package.json          # @max-null/dsh-guardian, bundle manifest
├── cordis.patch.yml      # insert: id=guardian, name='@max-null/dsh-guardian'
├── src/
│   ├── index.ts          # apply：ctx.plugin(GuardianEngine) + systemPrompt 注入
│   ├── engine.ts         # GuardianEngine Service('guardian')：监听 + 状态
│   ├── assertions.ts     # 断言检测（正则 + 计数 + 衰减 + 等级）
│   ├── no-feedback.ts    # 无反馈环（编辑/bash 统计 + 阈值）
│   ├── review-queue.ts   # 编辑审查队列
│   └── types.ts          # 共享类型
└── tests/
```

## 四、状态存储

复用 dsh-memory 的两层 JsonStorageBackend 思路：
- global root：`$DSH_HOME/storages/guardian`
- project root：`<cwd>/.dsh/storages/guardian`（编辑审查队列跟项目走）

单 key 状态文档（`state.json` 表，非每事件一条）：三个触发线的状态小、变化快，整读整写。

## 五、三个触发线的 DSH 版规则

### 1. 断言计数

- 扫描：`assistant/message` 的 text 块跑 `ASSERTION_RE`
- 计数：per-session，检测到 +1；**衰减**：每 3 个「无断言」的 turn -1（COUNTER_DECAY_TURNS=3）
- 等级：thresholds [1, 3] → count≤1 一级、2-3 二级、>3 三级
- 注入：count≥1 时 `systemPrompt.context` 提醒「禁止凭空断言，先查证」

### 2. 编辑审查队列

- 入队：`tool/result` 且 tool 名为 write/edit（str_replace_editor），结果成功 → push `{filePath, sessionId, turn, time}`
- 上限 20（FIFO 淘汰）
- 会话结束（`turn/end` reason=completed 且该轮有入队）→ 注入审查提醒（最多 4 条 pending warnings）
- UI 可读队列（侧栏状态 tab）

### 3. 无反馈环

- 每轮统计：`tool/call` 里 write/edit 出现 → `editsThisTurn+1`；bash/pwsh 出现 → `bashCalledThisTurn=true`
- 结算：`turn/end` 时，edits>0 且无 bash → consecutiveTurns+1；有 bash → 清零
- 阈值 3：consecutiveTurns≥3 → 注入「⚠️ 分形：缺乏反馈环」警告（下轮改代码前先跑测试）
- 会话切换（sessionId 变化）→ 清零

## 六、SSiD 侧栏 UI（M2b）

侧栏现有「记忆」tab + 收起按钮；加「状态」tab：

- 断言卡片：当前计数 + 等级（1/2/3 级色阶）
- 无反馈环卡片：consecutiveTurns / 3 + 警告态
- 审查队列卡片：N 条待审查（filePath 列表）
- 数据通道：同进程 `kernel.get('guardian')` → IPC（`ssid:guardian:*`）

## 七、验收标准

1. 三触发线可视化：断言计数、审查队列、无反馈环轮次 ✅
2. 状态随会话事件实时更新（同进程 event → IPC push）✅
3. 提醒注入生效：断言等级 / 无反馈环警告出现在 system prompt ✅
4. 插件独立 npm 包 + `dsh plugin --profile ssid add @max-null/dsh-guardian` 安装 ✅
5. 单测覆盖三触发线 + 存储 ✅

## 八、风险与护栏

- `session/event` 是 cordis 全局事件，GuardianEngine 监听要 `ctx.on` 而非 scope——注意多 session 并发（DSH web 多 session 同 host），状态按 sessionId 分桶。
- 断言正则是启发式（会误报「不存在」的客观陈述），提醒文案用「先查证」而非「你错了」。
- 若 storage 写入性能成为瓶颈（每事件整读整写），降级为内存态 + 定时 flush。
