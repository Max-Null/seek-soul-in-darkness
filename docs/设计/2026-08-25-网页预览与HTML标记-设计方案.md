# 网页预览与 HTML 标记 —— 设计方案

> 状态：设计评审（未开发）
> 日期：2026-08-25（v2：方向修订为「基于 better-sidebar 生态做」）
> 背景：SSiD「网页预览 + HTML 选取发送会话」能力建设。**方向（用户拍板）：不
> 做独立右浮层面板，基于现有侧边栏插件（dsh-better-sidebar，本仓库是
> Max-Null/DSH-better-sidebar fork）开发一个外部消费插件，替换其内置 html
> 预览子插件（registerFileViewer 覆盖），在预览内实现分形式 HTML 标记。**
> 本文档记录调研结论、实测证据、用户反馈映射与设计决策。

---

## 1. 背景与目标

### 1.1 目标

1. **HTML 预览子插件替换**：better-sidebar 打开 `.html/.htm` 文件时，命中我们
   注册的高优先级 viewer，预览渲染 + **分形式标记能力**（检查模式开关、hover
   高亮、点选、浮动 tip、批注）。
2. **结构化发送**：选中元素 → 生成带 `selector` 的 **HTML 快照** + 批注 → 待发送
   列表 → 一键送入对话（model 可精确定位、可复现、可编程）。
3. 与截图互补：截图是像素级通用兜底，HTML 标记是结构化精准增强。

### 1.2 定位（非目标）

- 不替代截图插件（两者互补）。
- 不做浏览器级远程调试（仅同源本地内容可标记；远程 URL/跨域 iframe 提示
  「跨域无法标记」）。
- 不重新发明侧边栏：面板/文件树/会话隔离/主题/设置全部继承 better-sidebar。

### 1.3 为什么之前放弃过，现在重提

历史：`dsh-sidebar-preview-select`（自家早期实现）因**适配 bug 多**（iframe 选取
与页面交互冲突、跨域限制、布局不稳）而放弃，转向截图插件。本轮现状：

- 截图 + 标注 + 原图预览编辑闭环已上线（dsh-capture），像素级诉求已满足。
- 开源 `dsh-web-preview-panel` 已把当年踩坑点攻克，但用户实测判定
  「交互不丝滑、与导航条插件冲突、待发送标记错位、大尺寸 HTML 不适配、
  文件管理混乱」——**独立面板形态与 SSiD 现有布局不相容**。
- **改用 better-sidebar 生态**：面板、文件树、打开链路、会话隔离全都现成，
  冲突与错位问题从架构上消失（同容器，无「两个右侧面板」）。

## 2. 调研结果

### 2.1 开源蓝本：dsh-web-preview-panel（zoumutou/dsh-web-preview）

- 仓库：`https://github.com/zoumutou/dsh-web-preview`；npm：`dsh-web-preview-panel@0.2.4`；
  peer 仅 `@deepseek-ai/cordis` + `react`。
- 功能全量：侧边玻璃面板（会话隔离）、本地静态托管（`/__dsh-preview/<sid>/...`）、
  Markdown/代码/图片/HTML 渲染、项目运行（日志滚动 + 「日志→对话」）、
  **元素标记**（🖉 hover 高亮 → 点选 → outerHTML 快照（剥离内部标记类，截
  3000 字符）+ 自动 selector → 锚点批注输入 → 待发送 chip →
  `conversation.input.dock`）、链接点击接管、文件拖入（`.dsh-drops/`）、
  `conversation.session.header.utilities` ▶ 入口。
- 关键实现（源码 `src/client.js`，本地 clone `dsh-web-preview-learn`）：
  - `attachMarking(doc)` 直接在同源 iframe 文档内加类/监听
    （`wvp-mark-hover`/`wvp-mark-active`/`wvp-note`）；`selectElement(el, doc)`
    生成 `{ selector, tag, text, html, rect }`。→ **标记逻辑可整体平移**。
  - 静态托管 = 同源保证；**标记前提前置即同源**。

### 2.2 分形（fractal）参考实现 —— 交互标准

- `src/renderer/src/lib/inspector-script.ts`（`buildInspectorScript(enabled)`）：
  注入 iframe 的**检查模式**脚本 —— 模式开关（`__inspectEnabled`）、hover 蓝色
  高亮框、点击拦截 → `postMessage` 上传 `{tag, id, classes, text, attrs, rect}`；
  **模式关闭时页面完全可交互**（设计动因：**HTML 是交互式的，有些 DOM 要先
  操作（展开菜单/触底加载/切换 tab）才会出现**：关闭检查 → 操作页面 → 再开
  检查 → 选取新出现的元素）。
- `src/renderer/src/composables/useSelectionTip.ts`：**浮动 tip** 交互（选区尾侧
  定位、超视口自动翻转、tab 内摘要 + 完整文本）。
- 结论：fractal 交互 + dsh-web-preview 载荷（HTML 快照）合并使用。

### 2.3 better-sidebar 生态（新基座，查证结论）

- 扩展形态：外部插件 client half `inject = ['betterSidebar']` →
  `ctx.betterSidebar.registerFileViewer(...)` / `registerTab(...)`（disposer 由
  Cordis fiber 管理；HMR-safe）；peer 声明 `dsh-better-sidebar`（optional）。
- **内置 html viewer**（`src/client/builtins/viewers.tsx`）：
  `id: 'html'`、`exts: ['html','htm']`、`fetchStrategy: 'fsRead'`、
  component = `LazyTextEditor`（`TextEditor.tsx`：预览态渲染
  **route-src iframe**（`htmlUrl(scope, path)` → better-sidebar 宿主路由，
  跨源构造，非 srcdoc）+ `sandbox` 默认开启（`HTML_IFRAME_SANDBOX`）；
  设置键 `htmlViewerNoSandbox`/`htmlViewerDefaultUnsafe`（Side card 设置
  卡片行，含警告/解锁流）。
- **覆盖方式**：外部权限完全对等——注册同 `exts` + `priority > 0` 即覆盖内置
  html viewer（匹配算法 priority 降序单趟）；`priority: 10` 即可。
- 保留内置文本编辑（源码/编辑模式）不受影响，我们只需接管「预览」渲染。
- 面板几何/主题/文件树/搜索/会话隔离/声明式设置全继承，**无独立面板宽度问题**
  （F2 从根上消失）；待发送不再用 `conversation.input.dock`（F3 从根上消失）。

### 2.4 社区横向

- awesome-dsh 600+ 插件中**无同类（HTML 预览 + 标记）**；`BrambleXu/dsh-annotate`
  （浏览器元素 → 结构化反馈，无预览面板）为最相近形态；`paicat1/dsh-screenshot`
  为截图 + agent tool。业界参照：ChatGPT Images 圈选编辑（交互手感，非标注式）。

### 2.5 自家现状（dsh-capture，已上线）

- 标注绘制内核（矩形/椭圆/箭头/文字 + 8 色）、原图预览编辑闭环、投递（delivery
  合成 drop）、playwright + 真实 SSiD 页面 e2e 套路——均可复用。

## 4. 关键事实与约束（实测证据）

- 冲突实测（2026-08-25，SSiD，viewport 1280×800）：web-preview 独立面板
  `x=788, w=482` 与 better-sidebar 面板 `x=1289, w=449` 同屏 → better-sidebar
  被挤出视口——**独立面板形态与 SSiD 不相容，是本轮换基座的决定性证据**。
- better-sidebar `--dsh-sidebar-width/--dsh-sidebar-height` 是布局联动标准
  通道（chat-rail 已联动证实）——本方案不再需要（同容器）。
- **沙箱约束**：内置 html viewer 默认 `sandbox` 打开（无 `allow-same-origin`
  则 iframe origin 为 null，父窗口无法操作其 DOM = **标记不可用**）。我们的
  viewer 不自带沙箱（由 host 静态托管路由保证跨源只读），标记注入采用与
  dsh-web-preview 相同的「同源静态托管 → 直接操作 iframe」模型，跨域/沙箱
  场景在 UI 提示「跨域无法标记」（蓝本已有文案）。
- 内置 html viewer 的编辑/保存链路（TextEditor 编辑态 + CodeMirror + `fs.write`）
  保留不动；标记只作用于预览态。
- 会话隔离/主题 token/声明式设置（Side card 卡片 + 齿轮行）继承。

## 5. 设计

### 5.1 形态

- 新外部插件：`@max-null/dsh-html-mark`（名称待定），
  **host half**（静态托管路由：以文件所在目录为根的 `/__html-mark/<sid>/<path>`
  同源 serve，保证相对资源可加载；复用蓝本静态托管逻辑）
  + **client half**（`inject = ['betterSidebar']`，注册高优先级 html viewer）。
- 未安装 better-sidebar 时插件照常加载（optional peer），viewer 不注册、标记
  能力整体隐藏——零侵入。

### 5.2 HTML 预览（viewer 替换）

- viewer：`id: 'html-mark'`、`exts: ['html', 'htm']`、`priority: 10`（覆盖内置
  html——内置入口/编辑流不受影响，预览由我们渲染）、
  `fetchStrategy: 'none'`（预览经 host 路由，字节由 iframe 自取）。
- 预览渲染：工具条（检查模式开关 🖉（默认开）/ 刷新 / 缩放三档 / 发送标记）
  + `iframe`（route-src 同源；随编辑器窗口 `ResizeObserver` 重排）。
- **不同尺寸适配（F4）**：三档缩放（宽度适配（默认）/ 实际宽度 / 100%）；
  深色主题跟随 `--dsw-alias-*`。

### 5.3 标记与批注（F1 核心，fractal 交互）

- **检查模式常驻开关**（动因见 §2.2）：打开时页面只读（点击=选取），
  关闭时页面完全交互（可操作动态元素）；状态不持久化。
- 交互：hover 高亮（主题色描边 + 半透明填充）→ 点击定住 + 生成载荷
  `{selector, tag, text, html, attrs, rect}` → **浮动 tip**（选区尾侧，超视口
  翻转）→ tip 内输入批注（回车确认）或「加入发送」；Esc/右键取消选中。
- 载荷：outerHTML 快照（剥离标记类、截 3000 字符）+ attrs；selector 自动生成
  （id → n-th-child 兜底）。
- 发送形态：代码块（`selector` + HTML 快照 + 批注）写入输入框草稿
  （复用 dsh-capture 的 composer 插入/投递通道）。

### 5.4 待发送列表（F3 架构消除后细化）

- 渲染在 viewer 工具条第 2 行（chip 列表 + 清空/发送全部），与标记同源模型；
  **不注册任何对话槽位**。
- 标签跨会话不持久化（会话级内存）；发送后清空该会话列表。

### 5.5 其它（继承与保留）

- 文件树/打开链路/搜索/项目运行（如需要）：全部继承 better-sidebar 现有能力，
  本插件不重复实现。
- 自身设置：vía `settings.pluginToggles`（检查默认态/快照长度/缩放默认档）。

## 6. 技术方案

### 6.1 包结构与注册

- 新包 `@max-null/dsh-html-mark`：
  - `src/host.ts`：`webServer` 静态托管路由（蓝本 `serveAsset` 思路：目录根 +
    路径穿越防护）；无状态。
  - `src/client/index.ts`：`inject = ['betterSidebar']`；`ctx.effect(() =>
    registerFileViewer({...}))`（HMR-safe）；`import type {} from
    'dsh-better-sidebar'` 触发类型合并；**零 value-import**（纯度门）。
  - `src/client/HtmlMarkViewer.tsx`：工具条 + iframe + 标记状态机。
- SSiD 集成：`profile-template/vendor/dsh-html-mark` + `cordis.patch.yml` 挂载
  （vendor 目录形态，同 open-sea-skin/dsh-capture 成熟路径）。

### 6.2 关键实现点

- 同源托管：路由 `/__html-mark/<sid>/<path>` 以**文件所在目录**为静态根
  （相对引用可用）；`decodeURIComponent` + `resolve` 防穿越。
- 标记注入：iframe `load` 后 `contentDocument` 操作（同源条件满足时），
  注入 inspector 脚本（检查模式/hover/点选/postMessage），载荷经
  `postMessage` 或直接回调回组件；卸载时移除（组件卸载/切文件）。
- 发送：格式化代码块 → composer 草稿插入（复用 dsh-capture delivery 思路）。
- 性能：`visible === false` 时暂停标记监听/轮询（TabComponentProps 契约）。

### 6.3 测试

- playwright + 真实 SSiD：打开 html 文件命中新 viewer（`viewerId: html-mark`）、
  检查模式开关往返、hover/点选/批注/加入发送、发送后 composer 草稿含代码块、
  卸载无残留监听、内置编辑流不受影响。
