# 网页预览与 HTML 标记 —— 设计方案

> 状态：设计评审（未开发）
> 日期：2026-08-25
> 背景：SSiD「侧边网页预览 + HTML 选取发送会话」能力建设。选型已定：以开源
> `dsh-web-preview-panel`（zoumutou/dsh-web-preview）为底蓝本，按分形（fractal）的
> 交互标准 fork 增强，vendor 打包进 SSiD 安装版。本文档记录调研结论、实测证据、
> 用户反馈映射与设计决策，作为开发前的唯一事实来源。

---

## 1. 背景与目标

### 1.1 目标

在思灵（SSiD）内提供**网页预览 + HTML 元素标记**能力：

1. 侧边面板预览工作区内容（静态文件 / HTML / 项目运行页面）。
2. **检查模式**：点击选中页面元素 → 生成带 `selector` 的 **HTML 快照** → 批注 →
   待发送标记 → 一键送入对话（model 可精确定位、可复现、可编程）。
3. 与截图能力互补：截图是像素级通用兜底，HTML 标记是结构化精准增强。

### 1.2 定位（非目标）

- 不替代截图插件（两者互补，入口并列）。
- 不做浏览器级远程调试（仅同源本地内容可标记；跨域提示不可标记）。
- 预览面板不是 IDE 文件树（文件管理只做「够用」：页签面包屑 + 排序 + 快速打开）。

### 1.3 为什么之前放弃过，现在重提

历史：`dsh-sidebar-preview-select`（自家早期实现）因**适配 bug 多**（iframe 选取
与页面交互冲突、跨域限制、布局不稳）而放弃，转向截图插件。本轮现状：

- 截图 + 标注 + 原图预览编辑闭环已上线（dsh-capture），像素级诉求已满足。
- 开源 `dsh-web-preview-panel` 已把当年踩坑点攻克（同源静态托管 → 直接操作
  iframe DOM，标记/批注/项目运行/链接接管齐全）。
- 用户在 SSiD 实测后认为「交互不丝滑、与导航条插件冲突、待发送标记错位、
  大尺寸 HTML 不适配、文件管理混乱」——**蓝本功能全但体验未达分形标准**。

## 2. 调研结果

### 2.1 开源蓝本：dsh-web-preview-panel（zoumutou/dsh-web-preview）

- 仓库：`https://github.com/zoumutou/dsh-web-preview`；npm：`dsh-web-preview-panel@0.2.4`；
  peer 仅 `@deepseek-ai/cordis` + `react`（兼容性好，无版本冲突）。
- 功能全量：侧边玻璃面板（会话隔离）、本地静态托管（`/__dsh-preview/<sid>/...`）、
  Markdown/代码/图片/HTML 渲染、项目运行（Cargo/package.json/go.mod/Python，日志
  滚动 + 「日志→对话」）、**元素标记**（🖉 hover 高亮 → 点选 → outerHTML 快照
  （剥离内部标记类，截 3000 字符）+ 自动 selector → 锚点批注输入 → 待发送 chip →
  `conversation.input.dock` 同步进对话）、链接点击接管、文件拖入（保存到
  `.dsh-drops/` 以路径引用入草稿）、主题跟随、`conversation.session.header.utilities`
  ▶ 入口。
- 关键事实（源码 `src/client.js`）：
  - 标记实现：`attachMarking(doc)` 直接在同源 iframe 文档内加类/监听
    （`wvp-mark-hover`/`wvp-mark-active`/`wvp-note`）；`selectElement(el, doc)`
    生成 `{ selector, tag, text, html, rect }`。
  - 槽位：`conversation.session.header.utilities`（▶）、`conversation.input.dock`
    （待发送标记）、`conversation.input.overlay`、`shell.overlay`。
  - 已 clone 至本地 `H:\MaxNull\WorkStation\dsh-web-preview-learn`（源码 + 构建脚本）。

### 2.2 分形（fractal）参考实现 —— 交互标准

- `src/renderer/src/lib/inspector-script.ts`（`buildInspectorScript(enabled)`）：
  注入 iframe 的**检查模式**脚本 —— 模式开关（`__inspectEnabled`）、hover 蓝色
  高亮框、点击拦截 → `postMessage` 上传 `{tag, id, classes, text, attrs, rect}`；
  **模式关闭时页面完全可交互**（这是「检查模式开关」的设计动因：**HTML 是交互式
  的，有些 DOM 要先操作（展开菜单/触底加载/切换 tab）才会出现**，关闭检查 →
  操作页面 → 再开检查 → 选取新出现的元素）。
- `src/renderer/src/composables/useSelectionTip.ts`：**浮动 tip** 交互（选区尾侧
  定位、超视口自动翻转、tab 内摘要 + 完整文本），选中后浮层提示 + 发送。
- 对比结论：dsh-web-preview 的「🖉 进入标记 / Esc 退出」与「常驻开关」语义等价
  （退出标记 = 页面可交互），但缺少**显式常驻开关**与**tip 浮层**手感；fractal
  的 DOM 元数据较「薄」（无 outerHTML），dsh-web-preview 的 HTML 快照对 model
  更有用 —— **二者合并**：fractal 交互 + dsh-web-preview 载荷。

### 2.3 社区横向

- awesome-dsh 600+ 插件中**无同类（图片/HTML 标注编辑器）**；相近作品均不满足：
  `paicat1/dsh-screenshot`（截图 + agent tool，无标记批注）、`BrambleXu/dsh-annotate`
  （浏览器元素 → 结构化反馈，无预览面板）。
- 业界参照：ChatGPT Images 圈选编辑（生成式）——交互可借鉴「图上直接操作」，
  我们是标注式，不涉及生成模型。

### 2.4 自家现状（dsh-capture，已上线）

- 截图双侧引擎（SSiD 壳 float overlay / 浏览器 CaptureOverlay），标注
  （矩形/椭圆/箭头/文字 + 8 色）、原图+编辑图双投递（有标注时）、原图预览
  编辑闭环（ImagePreviewEdit 注入官方 ImageLightbox）。
- 经验可复用：投递（delivery 合成 drop）、标注绘制内核、主题 token 用法、
  端到端自动化测试（playwright + 真实 SSiD 页面）。

## 4. 关键事实与约束（实测证据）

- 冲突实测（SSiD 页面，viewport 1280×800，面板与 better-sidebar 同时开）：
  web-preview 面板 `x=788, w=482`；better-sidebar 面板 `x=1289, w=449` →
  **better-sidebar 被挤出视口**；两者均无宽度联动。
- SSiD 布局特殊性：主视图为 BrowserView（无自定义标题栏遮挡问题），底部输入区
  有 dsh-ssid-zh-ui/截图按钮等改造，**官方 slot 定位假设在 SSiD 上不成立**
  （dock 错位的根因）。
- better-sidebar 提供 `--dsh-sidebar-width/--dsh-sidebar-height`（chat-rail 已
  联动证实），是面板共存的**标准联动通道**。
- 标记前提前置：同源（本地静态托管页面才可以标记；远程 URL/跨域 iframe 提示
  「跨域无法标记，请预览本地页面」——蓝本已有此报错文案）。
- 会话隔离：每会话独立面板状态与根目录（蓝本规范，保留）。

## 5. 设计

### 5.1 面板与侧边栏（F2）

面板宽度 `wvp` 与 better-sidebar 联动：

- **共存**：better-sidebar 关闭时，面板占据右侧（默认 380px，可拖 280–560）；
  better-sidebar 打开时，面板**自动让位**：面板宽度 = `min(预设, 400 px)` 且
  右缘 `--dsh-sidebar-width` 对齐（挤压对话而非重叠）。
- **覆盖**：拖动超过 560px 或双击面板头 → 切换「覆盖模式」（盖住全屏右侧，
  主题一致），此时无视 better-sidebar 宽度。
- 同开判定：MutationObserver 监听 `body` 上的 `--dsh-sidebar-width` 变化
  （better-sidebar 写 CSS 变量），无需依赖对方 DOM class。

### 5.2 预览与响应式（F4）

- iframe 容器 `width: 100%` 跟随面板；面板拖宽期间节流重排（`ResizeObserver`）。
- 覆盖模式：面板宽度 = 视口 `min(100vw, 1280px)`。
- HTML 大页面：默认**缩放适配**（iframe 内容 `zoom` 或 viewport meta 提示）；
  提供「宽度适配 / 实际宽度 / 100%」三档切换；Markdown/代码/图片预览组件
  按容器宽度自适应（已有蓝本基础，补窄屏断点）。
- 深色主题：沿用蓝本 `html[data-theme]` 同步 + `--dsw-alias-*` token 兜底。

### 5.3 标记与批注（F1 核心）

- **检查模式常驻开关**（设计动因见 §2.2）：面板头按钮「🖉 检查」默认**开**；
  点击即「浏览模式」（页面完全可交互，动态元素可操作），再点返回检查。
  状态每会话独立，不持久化。
- 检查模式交互（fractal 手感）：
  1. 悬停：`wvp-mark-hover` 高亮（主题色描边 + 半透明填充）；
  2. 点击：高亮定住（`wvp-mark-active`）+ 生成载荷 `{selector, tag, text, html, rect}`；
  3. **浮动 tip** 出现（选区尾侧，超视口翻转）：「选取完成 · [批注...] » 批量记录；
  4. tip 内输入批注（回车确认）或直接「加入发送」；
  5. Esc / 右键：取消当前选中。
- 载荷：沿用蓝本 `outerHTML` 快照（剥离 `wvp-*` 标记类、截 3000 字符）+ fractal
  的 `attrs` 补充；selector 用蓝本自动生成（id → n-th-child 兜底）。
- 同一元素多次标记：批注追加列表；重复点击已选中元素 = 取消。

### 5.4 待发送标记（F3）

- 不再依赖官方 `conversation.input.dock` 槽（SSiD 上错位）：改在**面板自身**
  渲染「待发送」区域（面板底部 dock 条，chip 列表 + 清空/发送全部），与 marker
  气泡同源模型；发送时经 `deliver` 通道写入对话草稿（复用 dsh-capture delivery
  思路：合成 drop / 或官方文本插入——标记以**代码块**形式进入输入框草稿
  （`selector` + HTML 快照 + 批注），比附件更贴合结构化定位）。
- 竞态：与截图/预览编辑投递互不干扰（各自独立通道）。

### 5.5 文件管理（F5）

- 面板首页 = 工作区根：目录页签（面包屑）+ 文件列表（类型图标、按类型分组、
  名称/修改时间排序切换、搜索过滤）。
- 快速打开：路径输入框（tab 补全）+ 最近打开（会话级）。
- 拖入文件：沿用蓝本 `.dsh-drops/` + 路径引用（入草稿），UI 增加「拖入后
  文件出现在当前目录」提示与跳转。

### 5.6 项目运行（保留）

- 蓝本能力保留：项目类型检测、▶ 运行/⏹ 停止、日志滚动、「日志→对话」。
- 面板视觉与 SSiD 玻璃风对齐（`--dsw-*` token + backdrop-blur），按钮/图标
  统一 lucide 风格。

## 6. 技术方案

### 6.1 形态

- 新包（fork 蓝本）：`@max-null/dsh-web-preview`，源码 `src/host.js` + `src/client.js`；
  host 保留蓝本路由/RPC（静态托管 + `/__dsh-preview/api`），client 按 §5 重做。
- SSiD 集成：`profile-template/vendor/dsh-web-preview`（vendor 目录形态，同
  open-sea-skin/dsh-capture 成熟路径）+ `cordis.patch.yml` 挂载；本机 dev 走
  `dsh-web-preview-learn` 迭代。

### 6.2 关键实现点

- 宽度联动：`MutationObserver` 监听 `body.style` 上 `--dsh-sidebar-width`/
  `--dsh-sidebar-height`；面板宽度右缘 = sidebar 宽度。
- iframe 重排：`ResizeObserver` + `requestAnimationFrame` 节流。
- 检查模式开关：复用蓝本 `attachMarking`（同源 doc 直接操作），加开关 flag
  （移除/恢复监听与高亮）。
- 载荷与投递：`{selector, tag, text, html, attrs, rect, annotation}` →
  格式化代码块 → 写入输入框草稿（复用 dsh-capture 的 drop intake 通道或
  `conversation.input` 插入）。
- 测试：playwright + 真实 SSiD 页面（沿用 dsh-capture e2e 套路）：入口出现、
  面板打开、检查模式开关往返、标记载荷正确、批注入草稿、宽度联动（构造
  better-sidebar 打开场景断言重合为零）。
