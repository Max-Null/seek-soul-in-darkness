## 1. 背景与目标

- SSiD 是 Electron 桌面应用，Windows 版由本仓库直接构建（NSIS）。
- 开发环境是 Windows，**无法本地构建 macOS 包**（electron-builder 的 mac 目标
  需要 macOS 工具链、Xcode 生态；且运行环境归档含 per-platform 原生二进制）。
- 目标：**利用 GitHub Actions 的 macOS 云端 runner**（不需要自备 Mac）构建
  mac 版（dmg 分发 + zip 增量更新），产物回传 GitHub Release / Artifacts。

### 机制一句话版

GitHub Actions 在 GitHub 云端启动一台虚拟 Mac（`macos-latest`，预装 Xcode/
Homebrew）执行仓库内定义的流水线（`.github/workflows/*.yml`）。公共仓库免费；
本仓库 `Max-Null/seek-soul-in-darkness` 为公共仓库 → 无限分钟。

## 2. 可行性结论（本分支之前的调查）

| 项 | 结论 |
|---|---|
| Electron 对 mac 支持 | ✅ 官方支持（Windows/macOS/Linux 三桌面平台） |
| 归档（dsh-runtime.tar.gz） | ⚠️ **必须 mac 上重建**：内含 esbuild/koffi/node-pty 等 per-platform 原生二进制，Windows 产出的归档在 mac 上不可用 |
| DSH 版本来源 | ⚠️ 本地 `H:/MaxNull/WorkStation/deepseek-harness` 路径在 runner 上不存在 → workflow 完整 clone 官方仓库（**钉 `dsh-v0.1.1-rc.2` tag**，与归档版本一致防漂移）并落位于 tsconfig paths 相对位置（`$GITHUB_WORKSPACE/..`），设 `DSH_CHECKOUT`（同源逻辑不变） |
| 目录选择器 worker | ⚠️ 官方 `dsh-host-directory-picker-native` 为 **Win32 专属**（koffi COM）；mac 上走 DSH 自身跨平台回退（Electron dialog），SSiD 的 worker 分支在 mac 不触发，候选链改动仅为防御性兼容 |
| 更新链路 | ✅ `publish: { provider: github }` 已配置；mac 走 zip + latest-mac.yml（electron-updater 增量） |
| 签名 | ✅ **官方 ad-hoc**（`mac.identity: "-"`，electron-builder 26 文档明确支持；e-b 在 app 组装完整后自行 `codesign --sign -`——日志实证 `signing file=…/思灵.app`）。首次打开仍可能提示「无法验证开发者」→ 右键-打开放行一次；正式分发需 Apple Developer ID + notarize（见 §8） |

## 3. 本分支改动清单

**原则：不改 Windows 行为（所有改动以 `process.platform` 分支/候选链追加实现，
Windows 路径与逻辑保持原样），回滚安全（revert 本分支即可恢复）。**

### 3.1 `shell/main.mjs`

| 位置 | 改动 |
|---|---|
| 新增 helper（PRODUCT_NAME 后） | `platformNodeName()`（win32→`node.exe`，其他→`node`）、`nodeCandidates(extra)`、`resolveNode(extra)`——跨平台 node 候选链：打包内置 `resources/node/<name>`（afterPack 注入）→ NVM v22.22.2（win32 开发机）→ `/opt/homebrew/bin/node` + `/usr/local/bin/node`（darwin）→ PATH（`node`/`node.exe`） |
| `runWorkerMode` 候选链 | 改用 `resolveNode()`（原 `node.exe` 硬编码候选）；错误消息同步 `${platformNodeName()}` |
| `mcpNodeCandidates`（SSID_MCP_NODE） | 改用 `resolveNode()`（原 3 个 node.exe 候选） |
| `playNotificationSound` | win32 保持 PowerShell；**darwin 用 `afplay /System/Library/Sounds/Glass.aiff`**；其他平台不配音效 |
| `pnpmCandidates` 用户级 shim | win32 保持 `%APPDATA%\npm`；darwin 追加 `/usr/local/lib/node_modules`、`/opt/homebrew/lib/node_modules`（存在才 push） |

### 3.2 `shell/scripts/after-pack.cjs`

- 归档校验逻辑不变。
- `injectBundledNode(context)`：win32 注入 `resources/node/node.exe`（候选：
  NVM → electron dist node.exe → PATH via `where`）；**darwin/linux 注入
  `resources/node/node`**（候选：`/opt/homebrew/bin/node` → `/usr/local/bin/node`
  → PATH via `which`）。找不到时降级日志（不失败），运行时靠 PATH 解析。

### 3.3 `shell/scripts/prepare-runtime.mjs`

- node 候选：`DSH_NODE` env → win32 保留 `D:\Program Files\nvm\...` 硬编码 → 
  **darwin 追加 `/opt/homebrew/bin/node`、`/usr/local/bin/node`** → PATH
  （split 分隔符按平台 `;`/`:`，文件名按平台 `node.exe`/`node`）。
- pnpm 候选：`PNPM_CMD` env → node 同目录 → win32 `%APPDATA%\npm\...` →
  **darwin 追加 `/usr/local/lib/node_modules/pnpm/bin/pnpm.cjs`、
  `/opt/homebrew/lib/node_modules/pnpm/bin/pnpm.cjs`**。
- `DSH_VERSION` 来源、注入逻辑、tar 步骤不变（跨平台）。

### 3.4 `shell/package.json`

- scripts 新增 `"pack:mac": "npm run bundle-kernel && electron-builder --mac"`。
- `build.mac` 新增：`target: ["dmg", "zip"]`（dmg 分发 + zip 增量更新）、
  `icon: assets/icon.png`（512×512，electron-builder 转 icns）、
  `category: public.app-category.productivity`、`darkModeSupport: true`、
  **`identity: "-"`（官方 ad-hoc 签名，2026-08-28 实测 e-b 26.15.3 生效）**。
- `build.dmg` 新增：540×400 窗口 + contents 布局（app / Applications 链接 /
  **「打开思灵.command」诊断启动器**，见 §3.6）。

### 3.5 `.github/workflows/build-mac.yml`（新增）

流水线（2026-08-28 终局定型）：检出 SSiD → **完整 clone deepseek-harness
（`--branch dsh-v0.1.1-rc.2`，落位 `$GITHUB_WORKSPACE/..` 对齐 shell/tsconfig.json
的 paths；sparse 会缺目录导致 esbuild 解析失败——已实锤）** → Node 22 + pnpm 11 →
`pnpm install --frozen-lockfile` + `node node_modules/electron/install.js`
（pnpm 10+ 默认禁 build scripts，electron dist 需显式下载）→
`prepare-runtime.mjs`（**mac 归档重建**，`DSH_NODE`/`PNPM_CMD` 指向 runner 工具）
→ `npm run pack:mac -- --publish never`（**单步**：e-b 官方 adhoc 签名 + dmg/zip）→
`upload-artifact`（dmg/zip/latest-mac.yml/blockmap）→ tag 或手动勾选 publish 时
`softprops/action-gh-release` 上传 Release 资产。

**触发**：`workflow_dispatch`（手动，默认不发布）+ `push tags v0.1.*`（发布）。
**耗时**：约 3-4 分钟（归档重建 1 分 + 打包 2 分）。

### 3.6 诊断启动器 + dmg 集成（`shell/ssid-mac-launcher.command`）

小白分发闭环：dmg 内「打开思灵.command」一键 **自检 + 自动修复 + 启动 + 诊断报告**：

- 自检：系统/芯片（Intel vs Apple Silicon 一眼定位架构错配）、app 定位（优先
  dmg 卷内同目录 → 再全盘常见位置）、结构完整性（Info.plist/MacOS/Frameworks/
  app.asar/归档/内置 node）、可执行架构（lipo 比对）、签名状态（codesign -dv+
  verify）、隔离标记、Gatekeeper 评估（spctl）、运行日志（ssid.log/heartbeat/updater 尾部 40 行）；
- 自动修复（幂等）：`xattr -cr` 清隔离 → 签名失效则 `codesign --force --deep --sign -` → 二次校验；
- 诊断报告：`[SSID-DIAG-BEGIN]…[END]` 结构化块（每项 `[OK]/[WARN]/[FAIL]`），
  窗口展示 + 落盘桌面 `ssid-diag-<ts>.txt`——小白转发报告即可，无需描述。
- 入 dmg：`dmg.contents` 第 3 项（`type: file` path 引用 projectDir 的 command 文件，
  name 显示「打开思灵.command」；git 保留 100755 执行位）。

> 参照：anywhere-labs/deepseek-harness-desktop（DSH 官方生态桌面壳，2.0.3）——
> 其 Mac 正式发布 = Developer ID 签名+公证（release-preflight 强制）、universal
> 双架构、mac 图标生成、平台差异模块隔离（windows-subprocess 等独立导出）、
> mac smoke 测试。SSiD 当前 adhoc 阶段为无证书过渡形态（见 §8 对照表）。

## 4. 用法（如何打一个 mac 包）

1. 推送本分支到 GitHub（`git push -u origin feat/macos-packaging`）；
2. GitHub 仓库页 → **Actions → build-mac → Run workflow**（Branch 选
   `feat/macos-packaging`，不勾 publish）；
3. **约 3-4 分钟**后 run 完成，页面底部 **Artifacts → ssid-mac-dist** 下载；
4. 分发：把 dmg 发给 Mac 用户，**双击 dmg → 双击「打开思灵.command」**——
   自动修复+自检+启动一条龙（首次系统弹窗选「打开」）；报告（或桌面
   `ssid-diag-*.txt`）回传可免描述定位问题。zip + latest-mac.yml 是增量更新
   元数据（暂只存档）。

## 5. 跟随主分支迭代手册（核心：本分支如何长期存活）

> 本分支是**长期特性分支**：main 继续发 Windows 版（v0.1.15、v0.1.16…），
> 本分支定期吸收 main 的新改动，保持「Windows 行为 = main」+「mac 兼容层」。

### 5.1 每月/每次 main 发版后的同步步骤（推荐顺序）

```sh
git checkout feat/macos-packaging
git fetch origin
git log --oneline HEAD..origin/main          # 看 main 新增了哪些
git merge origin/main                        # 或 git rebase（见 5.3）
# 处理冲突（见 5.2）→ 解决后：
node --check shell/main.mjs                 # 语法冒烟
node --check shell/scripts/after-pack.cjs
node --check shell/scripts/prepare-runtime.mjs
node --test shell/updater-core.test.mjs      # 发版守卫（skill §3.5）
git commit && git push
# 有疑问的冲突：跑一次 build-mac 手动 workflow 验证产物
```

### 5.2 高冲突风险文件（main 高频改动 → 冲突概率大）

| 文件 | main 侧常见改动 | 本分支改动形态 | 冲突时以谁为准 |
|---|---|---|---|
| `shell/main.mjs` | 新功能（截图/通知/更新/快捷键…） | 顶部 helper + 4 处候选链/音效分支 | **保留双方**：main 来什么收什么；本分支的 `platformNodeName/resolveNode` 候选链是纯新增，通常自动合并 |
| `shell/package.json` | 发版 bump version / 新脚本 | scripts.pack:mac + build.mac | 版本来 main、mac 配置保留本分支 |
| `shell/scripts/prepare-runtime.mjs` | 发版调整（pin/peer/归档步骤） | 候选链 platform 分支 | 逻辑来 main、候选链保留本分支 |
| `shell/scripts/after-pack.cjs` | 归档校验/注入调整 | 注入函数 platform 分支 | 同上 |
| `.github/workflows/` | 新增 workflow（如 update-guard） | 本分支新增 build-mac | 各自独立文件，无冲突 |

### 5.3 rebase vs merge

- **推荐 `git merge origin/main`**：本分支有长期作者，merge 简单安全、可回退；
  rebase 会重写历史，分支已共享给 CI 后禁止（workflow 需要分支在远端）。
- 本分支**只在 Windows 行为不变时合回 main**（见 5.4）。

### 5.4 本分支合回 main 的条件（何时可以"毕业"）

1. mac 包实机验证通过（启动/部署/截图/通知/更新链路全绿）；
2. 签名+notarize 已配（或明确接受未签名分发）；
3. 在 macOS 上完成 ≥1 轮完整回归；
4. 评审通过 → `git rebase origin/main` 后合入（或 squash），随后本分支删除。

### 5.5 回滚安全

- 本分支所有改动含 `platform` 分支，**revert 本分支提交 = 恢复 main 行为**，无
  配置/DB/接口契约隐式依赖；workflow 文件为独立新增，删除即失效。

## 9. 踩坑与沉淀（2026-08-27~28，全部 runner 日志实证）

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| 1 | `ENOTDIR: unlink …/vendor/README.md/node_modules` | rmSync 对「文件/node_modules」：Windows 静默跳过、mac 抛错 | `isDirectory()` 守卫 |
| 2 | `pnpm: SyntaxError missing ) after argument list` | CLI 的 `.bin/pnpm` 是 bash shim，被 node 直接执行 | 按扩展名判定：cjs/mjs/js→node，其余直接 spawn |
| 3 | `esbuild: command not found` | esbuild 是 tsx 传递依赖，pnpm 严格布局 `.bin` 不暴露 | package.json 显式声明 `esbuild@0.28.2` + lockfile |
| 4 | `Could not resolve @deepseek-ai/dsh-app-boot` | esbuild 按 tsconfig paths 解析到本机 checkout；runner 无 | 完整 clone deepseek-harness 至 `$GITHUB_WORKSPACE/..`（=shell/../..）+ 钉 tag |
| 5 | `electronDist does not exist` | pnpm 10+ 默认禁依赖 build scripts → electron postinstall 未下载 dist | `node node_modules/electron/install.js` 显式下载 |
| 6 | CI 隐式 publish | e-b 检测 CI 自动发布 | `--publish never` 显式 |
| 7 | afterPack 找不到归档 | **Mac 的 Resources 在 `Electron.app/Contents/Resources`**（Windows 在 appOutDir/resources） | 平台化 resourcesDir + afterPack 兜底复制 |
| 8 | 手工重签 `bundle format unrecognized` | **mac 最终 app 名是 `思灵.app`**；`Electron.app` 是中间骨架（Contents 仅 Resources）——afterPack 时刻/dir target 均为骨架 | 放弃手工重签/`--mac dir`/`--prepackaged`，改用 **官方 `identity: "-"`** |
| 9 | 用户装包报「已损坏/不完整」 | ① identity:null → 旧 adhoc 签名失效；② prepackaged 重打产出目录级坏包 | ① `identity: "-"`；② 弃 prepackaged（单步出包） |

**方法论沉淀**：① mac 构建问题先看「文件是否真存在/路径语义平台差异」，再动代码；
② electron-builder 平台差异用官方配置（identity/ad-hoc）优先，手工 codesign 后患多；
③ CI 排障每次先拿日志（本会话曾两次因误判「未完整」查错目标——app 名差异）。
