# 405 修复的持久化与后续适配决策（2026-09-14）

> 状态：已完成（本机修复 + 模板落地 + 噪音清理）；插件侧适配记为技术债
> 关联：`2026-09-14-插件中心405诊断记录.md`（根因与机制）、工作区铁律 2.0（不改 DSH 源码）

## Problem

`connection` 的 inject 收缩（DSH 0.1.5 起）让所有用 `ctx.connection.rpc.handle` 注册通道的插件失效，
请求落 frontend-static 兜底 → 405。根因与实机验证见诊断记录第十节。修好本机之后有三件事要收：

1. 该修复只在本机 `~/.dsh/profiles/ssid/cordis.patch.yml`，重装/别人装 0.3.0 会复发；
2. 受影响的不止 plugin-center（还有 ds-harness-remote、apiProxy）；
3. `dsh-web-runtime` 长期显示 11 个 `D`，让 `git status` 看起来总是脏的。

## Decision

### 一、修复进模板（已完成）

`shell/profile-template/cordis.patch.yml` 追加 `- id: connection` + `inject: [webRuntime, webServer]`。
模板是发版基准，随归档部署进用户 profile 的「用户层保留」路径。

**不会与用户 profile 已有条目重复**：`lib/profile-merge.mjs:223,252` 按顶层 id 去重
（`tmplTopIds` / `!tmplTopIds.has(e.id)` 才追加）。实测用真实 `mergeUserPatch`（非近似实现）：
89 行用户 patch + 93 行模板 → 合并 93 行，`- id: connection` 1 次、`- insert:` 1 次、二次合并幂等。

**残留**：这条要在 `prepare-runtime.mjs` 重建归档后才进安装包。

### 二、插件侧适配（记为技术债，暂不实施）

官方范式是 `dsh-pocket@2.10.6`：插件自己 `inject ['connection','webServer']`，优先把路由挂到
webServer 上（复刻 Connection 的 `/api` 传输语义），失败才回退 `rpc.handle`。

**不实施的理由**（评估后）：该范式需要逐分支复刻传输层 —— 404/415/400、最小信封校验
（`{rpcId, method, payload}`）、`server-response` 包装、Host/Origin 栅栏、浏览器认证、
`node:http ↔ fetch` 桥接、413 与 abort。`dsh-pocket` 为此写了约 200 行。

而它换来的能力目前**无处可用**：官方桌面壳（唯一没有 webServer 的宿主）在
`apps/desktop-host/config/desktop.cordis.patch.yml` 里把 `webserver` / `web-runtime` / `web-startup`
全部 `disabled: true`，且其 profile 只含官方 51 个插件、传输走 `__DSH_TRANSPORT__.openStream`
而非 HTTP —— **第三方插件在它里面本来就跑不起来**。客户端也是 `dsh-app://` 自定义协议，
plugin-center 的浏览器半同样无法加载。

所以配置层修复已经覆盖当前全部可用场景；插件侧适配是「为将来可能的无 webServer 宿主预留」，
属于技术债而非缺陷。**若将来真要支持，再按 dsh-pocket 的范式改，且必须同时改客户端请求路径。**

### 三、`dsh-web-runtime` 的 11 个 symlink 缺失（已处理）

11 项在 HEAD 里都是 mode `120000`（symlink）：`CLAUDE.md`、`packages/CLAUDE.md`、
`.agents/notes/implemented/CLAUDE.md`、`vendor/CLAUDE.md`、`.claude/skills`、
`apps/cli/tests/profiles/acp/cordis.yml`、以及 `snapshots/**` 下几处 fixture 链接。
Windows 上没落成，于是 git 报 `D`。功能无影响（都是文档与测试 fixture）。

处理：`git update-index --assume-unchanged`（本地索引操作，不动任何源码、不入库）。
撤销：`git update-index --no-assume-unchanged -- <path>`。
**注意**：若上游后来改了这些路径（如 CLAUDE.md 从 symlink 变普通文件），需先撤销才能看到。

## Alternatives considered

- **改 DSH 源码**（在 connection 侧加 `webServerCtx` 绕过 ctx 权限）：**否决**——违反用户长期约定
  （工作区铁律 2.0：DSH 源码只引用不改），且只对 dev（tsx 跑 checkout 源码）生效、对装版无效，
  会让两个环境跑行为不同的实现。这正是本次绕圈的主因，两处补丁已还原。
- **只修本机、不进模板**：否决——重装/分发即复发。
- **给 plugin-center 保留 `connection` 失败告警**：不必要——`pluginCenter` 与 `pluginCenterRpc`
  本来就是同一个 `apply` 里 `await ctx.plugin()` 的两半，两者一起挂，没有“半死”状态。

## Consequences

- 405 在本机与后续归档中都不再复发；机制（inject 收缩）若随 DSH 版本再变，`dsh-clean` 门与
  诊断记录第十节提供了重新定位的入口。
- `dsh-web-runtime` 的 `git status` 现在只剩正常未跟踪项（`.dsh/`、`.tmp-*` 等），
  `check-dsh-checkout-clean` 门（check:rules 第 7 门）能真正反映“源码是否被改”。
- 插件侧适配作为技术债挂在本文档，触发条件是「出现一个没有 webServer 又允许第三方插件的宿主」。

## 附：给受影响第三方作者的说明（`ds-harness-remote` 等）

`ds-harness-remote` 不在本工作区的自制/第三方插件目录里，**不是我们的插件**，因此只记录发现、
不改其代码。若要与作者沟通，下面这段可直接用：

> **症状**：升级到 DSH 0.1.5+ 后，贵插件通过 `ctx.connection.rpc.handle(channel, …)` 注册的
> HTTP 通道不再生效。浏览器侧表现为 `POST /<channel>/<endpoint>` 返回 **405 Method Not Allowed**，
> 同一路径 GET 返回 404（两者都来自 `packages/host/frontend-static` 的兜底：non-GET/HEAD 且无匹配
> route 即 405）。
>
> **根因**：0.1.5 起 `@deepseek-ai/dsh-client-connection` 的 inject 由
> `['webServer','credentials']` 收缩为 `['webRuntime']`，但 `rpc.handle` 的实现仍读
> **connection 实例自己的 ctx**（`rpc-host.ts` 的 `get rpc()` 里 `const owner = this.ctx`）：
> `owner.effect(() => owner.webServer.register(route), …)`。owner 的 store 里没有 `webServer`，
> cordis 的 ctx 代理沿父链找不到（`vendor/cordis/src/reflect.ts:155-166`），抛
> `cannot get property "webServer" without inject`。
>
> **官方适配范式**（可直接参照 `dsh-pocket@2.10.6` 的 `lib/web-rpc.js`，其文件头逐字写明了这个坑）：
> 插件自己 inject `['connection','webServer']`，**优先**把路由直接挂到 webServer 上，
> 并逐分支复刻 Connection 的 `/api` 传输语义（404/415/400、`{rpcId, method, payload}` 信封校验、
> `server-response` 包装、Host/Origin 栅栏、浏览器认证、`node:http ↔ fetch` 桥接、413 与 abort），
> **失败才回退** `rpc.handle`。这样在有无 webServer 的宿主里都能工作。
>
> **也可用的替代通道**：`ctx.connection.fetch.register({ path, methods, requestBody, fetch })`
> （carrier-neutral 精确路由，路径须在 `/api` 之下）或 `@deepseek-ai/dsh-api-remotes`（Typert RPC）。
> 但前者需要同步改客户端请求路径。

**宿主侧的临时缓解**（无需改插件，我们采用的就是这条）：在 profile 的 `cordis.patch.yml` 里给
`connection` 行补回 `webServer` —— `- id: connection` + `inject: [webRuntime, webServer]`。
cordis 在 fiber 激活时会把已就绪依赖写入 `fiber.store`，于是 `owner.webServer` 沿父链可解析。
实测：inject 变为 `[credentials|webRuntime|webServer]`，相关通道全部恢复。
