## 事故 1：dsh-runtime.tar.gz 损坏（截断）

- 现象：上次会话生成的归档（125.5 MB）tar -tzf 报
  `Truncated input file (needed 20992 bytes, only 0 available)`，列表只到
  node_modules 中段（56142 项），`dsh-runtime/` 源目录残留未删。
- 根因：6:08 那次 prepare-runtime 在 tar 压缩阶段中断（源目录未删是
  脚本异常退出的标志；脚本正常路径是 [7/7] 删源目录）。
- 处置：重跑 prepare-runtime（DSH_NODE 指向 PATH 的 node v26.2.0，
  PNPM_CMD 指向全局 pnpm 11.21.0），完整归档 163.3 MB / 75104 项，重建成功。
- 教训：**发布前必须 tar -tzf 全量校验归档完整性**——只看文件大小/时间戳
  会漏掉截断归档，损坏归档会打进安装包（extraResources 原样携带）。

## 事故 2：tar 解压误落 shell 根目录（package.json 被覆盖）

- 现象：冒烟前执行 `tar -xzf dsh-runtime.tar.gz`（在 shell/ 下，无 -C），
  归档条目是 `./xxx` 前缀 → 全部解压散落到 shell/ 根目录：node_modules
  （760 MB 混入）、skills/、vendor/、pnpm-lock.yaml、.npmrc、
  cordis.patch.yml、pnpm-workspace.yaml、.runtime-version——并且
  **shell/package.json 被归档里的 profile package.json 覆盖**
  （name 变 dsh-profile-ssid、version/scripts 丢失）。
- 处置：
  1. `git show HEAD:shell/package.json` 恢复原文件，再改回 version 0.1.5
     （注意：PowerShell `ConvertTo-Json` 重写会打乱格式产生 70 行假 diff，
     必须用文本级替换只改 version 一行）。
  2. 删除 shell/ 根目录的污染文件（.npmrc/.runtime-version/cordis.patch.yml/
     pnpm-lock.yaml/pnpm-workspace.yaml/skills/vendor）。
  3. `npm ci` 干净重装 shell 依赖（混入的 1041 个归档包清除）；
     electron 二进制 postinstall 未跑，手动 `node node_modules/electron/install.js`
     补装。
- 教训：**归档解压必须 `tar -xzf dsh-runtime.tar.gz -C dsh-runtime`**
  （先建目录），绝不能在工作区根目录直接解压。boot-bundled.mjs 的
  RUNTIME_DIR 就是 shell/dsh-runtime，冒烟前解压目标必须是它。
