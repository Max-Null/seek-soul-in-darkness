# 摘除 `dsh-guardian`（2026-11-23）

> 决策：从 SSiD 出厂插件集里**整个摘掉** `@max-null/dsh-guardian`，不再注入任何断言提醒；「状态」面板一并从侧栏移除。插件源码仓库与 npm 上的已发布版本保留（撤包不可逆，也没必要）。

## 一、为什么

三条触发线各自跑了一段时间，实测（`~/.dsh/storages/guardian/guardian.json`，66 个会话记录）：

| 触发线 | 实测 | 判读 |
|---|---|---|
| 断言计数 | 66 个会话里 29 个命中过，5 个到最高档 level 3 | 在说话，但没有疗效度量 |
| 编辑审查队列 | 存储里 `global: null`；本会话改了十几个文件后仍是 null | 疑似从未入队（配对依赖 `tool/result` 的 `toolCallId`） |
| 无反馈环 | 66 条记录的 `noFeedbackTurns` 全为 0 | 从未触发 |

用户判断（2026-11-23）：**DS 版本迭代之后已经不怎么「说大话」了，而且说大话本身也不是靠一个插件能解决的**。这条是决定性的——断言提醒治的是表述习惯，而表述习惯已经随模型换代变了，插件还在按旧症状给药。

## 二、为什么不并进 `dsh-allostasis`

摘之前讨论过「砍两条留一条、把断言计数并进应变」。不采纳，理由两条：

1. **判据成熟度差一代**。应变每个阈值都有本机实测（漂移 0.15、重复率 0.5、提醒后 89% 下一步回落）；断言的阈值（`[1, 3]`、3 轮衰减）抄自 fractal，没在本机标定过，也没有疗效数据。把没标定的并进有标定的，等于让后者替前者背书，「应变的判据都验过」这条资产就没了。
2. **状态形态不兼容**。应变 `inject = ['agents']`，无 storage、无跨 turn 状态，判据都是当步可算的纯函数；断言计数要按会话持久、跨 turn 累加、加载时恢复。合并会让快判据里混进慢判据。

## 三、摘了哪些面

| 层 | 动作 |
|---|---|
| 声明 | `shell/profile-template/package.json`、运行时 `profiles/ssid/package.json`、装版 `resources/ssid-plugins/ssid-plugins.json` —— 依赖与 bundles 三处全删 |
| 实体 | 装版 `node_modules/@max-null/dsh-guardian` 移到 `.ssid-build/tmp/guardian-removed-20261123-013649/`；隔离插件集 `.ssid-iso-test/ssid-plugins-dev` 的 junction 删除 |
| 面板 | `dsh-ssid-panels` 0.2.0：删「状态」tab、`guardian.snapshot` 路由、`GuardianView`、7 个专用文案；装版实体与 `shell/profile-template/vendor/dsh-ssid-panels` 逐文件同步 |

## 四、回退

- 插件实体：从 `.ssid-build/tmp/guardian-removed-20261123-013649/dsh-guardian` 移回装版 `node_modules/@max-null/`，再在 profile 与模板里加回依赖与 bundle 条目。
- 面板：`dsh-ssid-panels` 退回 0.1.12（备份在 `.ssid-build/tmp/ssid-panels-removed-guardian-20261123-013853/packaged`）。

## 五、遗留

- `~/.dsh/storages/guardian/guardian.json`（66 条会话状态）是死数据，可删；不删也不会被读。
- 生产实例需重启一次，插件集合变更才生效（本次摘除后已重启确认：`guardian.json` 不再更新）。
- 更新日志（`release-notes.md`）不在此处补：它按首行 `# vX.Y.Z` 解析版本，写「待发布」块会让弹窗标题错乱。等下一版发版时一并写进正式条目。
