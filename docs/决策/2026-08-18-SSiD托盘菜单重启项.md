# 决策：SSiD 托盘菜单增加「重启」项

> 日期：2026-08-18
> 状态：已决策
> 决策人：MaxNull
> 触发：排查「活跃会话历史加载失败」时发现——SSiD 是 DSH 的单进程壳，DSH 内核 boot 在 Electron 主进程内，目前没有任何「重启 DSH」入口，遇到插件变更、内核卡死、状态异常只能手动关掉重开
> 关联：`shell/main.mjs`（托盘与生命周期）、`shell/kernel.ts`（bootKernel）

---

## 〇、决策

**在托盘菜单加「重启」项**（`app.relaunch()` + 优雅退出）。标题栏不加任何按钮，保持干净。

## 一、背景

SSiD 是「DSH 官方 Web GUI + Electron 壳」形态（`main.mjs`），DSH 内核由 `bootKernel()` 直接 boot 在 Electron 主进程内（单进程，见 kernel.ts 头部注释）。当前生命周期只有：

- 关闭窗口 → 隐藏到托盘（`win.on('close')` 拦截）
- 托盘「退出」→ `before-quit` → `kernel.shutdown(0)` 优雅 dispose

**没有重启入口**。而现实中反复遇到需要重启的场景：装/卸插件（如本次 dsh-chat-timeline → dsh-chat-rail 切换）、DSH 内核卡死、会话日志并发读异常、皮肤/配置热加载失败等——都要手动退出再打开，体验割裂。

## 二、方案

### 2.1 为什么不做「热重启内核」（只重启 DSH，不重启壳）

理论路径：`kernel.shutdown(0)` → 重新 `bootKernel()` → 新端口 → `mainView.loadURL(新端口)`。**否决**：

1. `installProfilePackageResolver`（kernel.ts）是**全局单次安装**的 loader 改写（bare specifier → profile 目录），dispose 后再 boot 会重复安装解析器；DSH 官方 `runProfile` 注释也明确「重启走 profile 配置重启即可」——内核热重启不是设计路径。
2. 端口每次变化（`--port 0` 随机），BrowserView 需重新 loadURL，存在空白窗口期。
3. 全局副作用（registerHooks、healProfilesModuleFallback、env）难以干净回滚。

### 2.2 采用方案：`app.relaunch()` 整壳重启

```js
{ label: '重启', click: () => {
  app.relaunch({ args: process.argv.slice(1).filter((a) => !a.endsWith('worker.cjs')) })
  quitting = true
  void kernel.shutdown(0).catch(() => app.exit(0))
} }
```

要点：

1. **`app.relaunch()` 放前面**：先设置重启标志，再走 `kernel.shutdown(0)` 优雅 dispose（`ctx.fiber.dispose()`），最后 `app.exit(0)` 退出——Electron 检测到 relaunch 标志后自动以新进程启动，完成「重启」。
2. **过滤 `worker.cjs`**：main.mjs 有 worker 模式分支（`process.argv` 含 `worker.cjs` 时 spawn 孙进程后 return）。`app.relaunch` 默认沿用原始 argv，若当前进程是 worker 模式，relaunch 会错误地再次走 worker 分支而不是启动壳。必须过滤。
3. **`quitting = true`**：避免 `before-quit` 拦截（`win.on('close')` / `before-quit` 的 quit 守卫）干扰重启流程。
4. **托盘菜单结构**：显示思灵 / **重启** / 退出（重启放中间，避免误触退出）。

### 2.3 不做的事

- 标题栏不加重启按钮（用户拍板：保持干净）
- 不做「自动重启」/「卡死检测自动拉起」（本次只做手动入口，心跳检测已有 `~/.ssid/heartbeat.log`，将来需要再扩展）

## 四、验证

1. 语法检查（`node --check main.mjs`）。
2. 开发模式启动思灵 → 托盘右键 → 点「重启」→ 进程退出并自动重新启动（观察 `~/.ssid/ssid.log` 的 phase 序列：应看到 `PROCESS_EXIT` 后新的 `single-instance` 序列）。

## 五、风险

- `app.relaunch` 在打包版（NSIS）下沿用安装路径启动，已验证为 Electron 标准行为，风险低。
- 重启瞬间有窗口消失/重现（splash 流程），可接受；不新增 UI。
