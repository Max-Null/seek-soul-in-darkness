## 一、为什么做这一个

1. **SSiD 的文档是 AI 写的，而 AI 天生带「写作会话视角」**。这不是坏习惯，是生成过程的副产品——我写 01 时就写了 §2.3「第一版我写的是……」。所以这条 skill 在 SSiD 不是锦上添花，是**针对主要生产方式**的。
2. **实测证明泄漏真实存在，且位置最要紧**（§2.2）。命中最集中的地方不在变更日志里（那里合法），而在 **`skills/*/SKILL.md`——给 agent 的指令**。
3. **它是给 agent 读的 skill**：泄漏进 skill 正文，等于让后续每个 agent 都读一段历史噪音。

## 二、SSiD 侧现状（已核实）

### 2.1 探针实测

用中文变更叙事探针（`第一版|本版|旧版|不再|曾经|原来|已改|修正了|之前是|改成了|这轮|本轮`）扫 `seek-soul-in-darkness/**/*.md`：**202 处命中**。

按位置分类——**这张表是本节的核心判断依据**：

| 位置 | 文件数 | 命中密度 | 性质 | 判断 |
|---|---:|---|---|---|
| `docs/release-notes-*.md` | 19 | 高 | **变更日志的本体** | **合法主场** |
| `docs/决策/` | 99 | 高 | 决策记录 ≈ DSH 的 Agent Notes | **合法主场** |
| `docs/设计/` | 21 | 中 | 设计记录 | **合法主场** |
| `docs/排查/` | 1 | 中 | 排查记录 | **合法主场** |
| `shell/docs/pitfalls.md` | 1 | 中 | 坑记录 | **合法主场** |
| `skills/*/SKILL.md` | 14 | **低但致命** | **给 agent 的指令** | **必须修** |
| 根 `README.md`、插件 README、`docs/SSiD开发手册.md` | — | 低 | 当前状态表面 | **应修** |

**两个结论**：

1. **SSiD 需要一份「合法主场清单」，这是上游没有的复杂度**。DSH 只有 Agent Notes 一个 sanctioned home；SSiD 有**五个**。不点名豁免，agent 会把 release notes 当泄漏来「修」——那是在破坏历史。
2. **命中密度的高低是骗人的**：release notes 里几百处没人会误判，而 `skills/*/SKILL.md` 里三处会直接污染 agent 行为。**适配版必须按「表面」而不是按「密度」定优先级。**

### 2.2 实测出的真实泄漏（抽样）

| 文件 | 行 | 现状 | 泄漏类型 |
|---|---:|---|---|
| `skills/mxy-commit-review/SKILL.md` | 117 | 「二次审查通过后，**不再**询问『是否继续提交』」 | 类 3 变更叙事 |
| `skills/mxy-upgrade-vue3/SKILL.md` | 330、359 | 「grep `proxy\.` 确认模板和脚本中**都不再有**未处理的 `proxy.` 引用」 | 类 3 |
| `shell/profile-template/vendor/README.md` | 25 | 「目录下**不再保留**该包。历史上的 vendor 固化基线 = 上游 v0.9.2 + …」 | 类 3 + 类 1 |
| 根 `README.md` | 52 | 「原 v0.1.18 未分发内容并入重打」 | 类 3（编排史） |

**共同的修法**：把「比较级」还原成「当前状态」——「不再询问 X」→「直接进入步骤 6」；「确认都不再有未处理的 X」→「确认无未处理的 X」。

> 注意第四条与前三条不同：根 README 的版本摘要**大体合法**（它答的是「当前版本是什么、有什么」），只有「编排史」那半句该走 release notes。**这条算边界情形，不应用硬规则一刀切**——正是上游 `Borderline decisions` 一节存在的原因。

### 2.3 SSiD 无文档门禁（决定适配策略的关键差异）

`shell/package.json` 的 `scripts` 全部是：`start` / `typecheck` / `smoke` / `test` / `test:profile-merge` / `test:codegraph-adapt` / `pack` / `bundle-kernel` / `pack:mac`——**没有任何文档检查**。

而 DSH 有 `doc-sync`、`verify-doc-budgets`、`verify-translation-pairing`、`verify-doc-links` 一批门禁在持续守护文档。

**这条差异直接决定架构**：DSH 靠门禁长期守住全仓库，SSiD 没有门禁 → **与其要求全仓库干净（修了没人守、必然退回），不如把 scope 收窄到对 agent 影响最大的表面**。具体方案见 §三.3。

## 三、逐条适配判断

上游共 **5 个部件**（SKILL.md 引言 + 4 个一级小节）+ **2 个 references**，共 7 个部件，逐一判断。**判定分四类**：原样保留 / 改写 / 重写 / 新增。

### 1. SKILL.md 引言（定义 + REQUIRED BACKGROUND）→ **改写**

上游定义：泄漏是「**视角属于写作会话而不是仓库**」的散文。这个定义**跨语言成立，直接保留**。

要改的是依赖声明：

- 上游：`REQUIRED BACKGROUND: dsh-prose-standard owns the complete-proposition rule this skill applies`
- 适配版：指向适配后的 `ssid-prose-standard`（03 号），**并注明两者必须同批进入 `@max-null/dsh-skills`**

**为什么这条不能省**：完整命题规则是**防过度修剪**的唯一依据。DSH 的 `examples.md` 里专门有一节 `Overcorrection traps`（四类），全部依赖「先枚举命题再删」。若 agent 只装了本 skill 没装 03，它会删掉真事实。「同批进包」不是包装细节，是**判据能否成立的前提**。

### 2. `## The one test` → **原样保留**

> 对每段可疑文字问：**一个处在 HEAD、拿不到任何会话记录、PR 讨论或未提交草稿的读者，能不能解析每一个引用、核实每一条断言？**

这条**一字不改**。它是整份 skill 的支点，且与语言无关。**它同时也是上游最漂亮的设计**：用**一个可判定的问题**取代一长串禁令——按 `writing-skills` 的「形式匹配失败」表，这属于「正面配方」，而禁令清单在实测中反而**比不给指导更差**。

### 3. `## Taxonomy`（8 类）→ **原样保留，补一条中文探针指引**

8 类（死引用 / stack 与 PR 视角 / 变更叙事与版本戳 / 评审编排 / 面向评审者的辩解 / 复述与推导记录 / 模糊措辞与规划残留 / 写作语言滑落）**全部保留**。

**唯一新增**：第 8 类「写作语言滑落」在 DSH 是「英文文档里混入中文」，在 SSiD **方向相反或不存在**（SSiD 主体就是中文）。适配版应把它改成**同语言内的滑落**（如中文文档里混入英文推导过程、或未翻译的 `---- 私有 ----` 分隔符之类的排版残留），而不是照抄「中英混排」。

### 4. `## What is not leakage`（9 条 keep rules）→ **保留 + 新增 1 条**

9 条全部保留（issue 引用 / 合并 PR 引用 / 抑制理由 / 反事实现在时回归钉 / 实测边界 / 运行时新旧状态 / 笔记变更故事段内的历史阶段名 / 仓外可解析引用 / 项目口吻与文体形制）。

**必须新增的第 10 条——SSiD 的六个合法载体**（上游只认 Agent Notes 一个）：

> **变更叙事在 SSiD 的合法主场**：`docs/release-notes-*.md`、`docs/决策/`、`docs/设计/`、`docs/排查/`、`shell/docs/pitfalls.md`。在这些文件里，变更叙事是**内容本体**，不是泄漏。修剪任务默认**不进入**这些路径；确需进入时须由用户显式指定 scope。

**这条的证据**：§2.1 的实测分布 + §2.3 的无门禁事实。**没有这一条，02 在 SSiD 上会变成一个破坏历史文档的工具**——比不做更糟。

### 5. `## Workflow`（5 步）→ **改写（scope 规则）**

5 步骨架保留（定 scope 与豁免 → 只读审计 → 按表面 owner-first 修 → 删前枚举命题 → 验证）。

**SSiD 改写点**：

| 上游步骤 | SSiD 要改成什么 |
|---|---|
| 1. scope 与豁免 | 除 `vendor/` 与归档笔记外，**新增 §4 的六个合法载体**；并默认把 scope 收窄到「指令表面」：`skills/*/SKILL.md`、`docs/SSiD开发手册.md`、插件 README、JSDoc/注释 |
| 3. 按表面 owner-first | 保留骨架，但删掉 `verify-type-equiv` / `verify-translation-pairing` 这两个 SSiD 没有的门禁，换成「改动后重跑受影响的 L1（typecheck + test）」 |
| 4. 删前枚举命题 | **保留且提高权重**——这是防过度修剪的唯一闸门 |
| 5. 验证 | 上游靠门禁，SSiD **没有** → 改成「重跑探针期望只剩合法命中 + 人工确认改动的 diff 不丢事实」。**这一条要显式写明「SSiD 没有门禁，所以验证靠重跑探针」**，否则 agent 会以为有东西替它兜底 |

### 6. `references/recall-batteries.md`（52 行）→ **重写（语言方向反转）**

上游探针集针对 DSH 的语言格局（英文为主 + `.zh.md` 对照）：英文 battery 7 条、中文 battery 4 条（全部是「在英文表面里找中文残留」）。

**SSiD 的语言格局相反**（中文为主），所以：

- 上游的中文 battery **全部失效**（它们是「英文里找中文」，不是「中文里找变更叙事」）
- 需要**新写中文探针集**（本次实测用的那 12 个词是起点）
- 英文 battery 保留（SSiD 有英文 README/JSDoc，以及 `-en` 类文档）

**必须保留的三条纪律**（它们比探针本身更值钱，逐字保留）：

1. **「零命中的模式什么也证明不了，直到它命中一个已知正例；有噪音的模式什么也证明不了，直到它拒绝一个近失负例。两者都要先校准再相信全集结果。」**
2. **「探针是探针，不是定义」**——上游原话：每一轮评审都发现了没有探针能抓到的案例，所以必须**同时无模式地读 scope 内最密的散文**。
3. **已知假阳性家族**必须随探针一起迁移（§2.2 的边界情形就是新的假阳性家族素材）。

### 7. `references/examples.md`（275 行）→ **重写**

上游 275 行是**英文校准样本**，按 8 类分节，另含 `Behavior-visible candidates`、`Keeps`、`Overcorrection traps` 三节。结构**优秀，照搬结构**；**案例全换**成 SSiD 的中文案例（§2.2 已备四个，需再补到每类 1–2 个）。

**必须保留的是 `Overcorrection traps` 四类**（把义务翻转成背书 / 把假设升格为已交付特性 / 连带删掉真事实 / 留下数字丢了出处）——这四类**跨语言成立**，且是修剪工作最危险的失败模式。
