## 一、为什么做这一个（以及一个反转的前提）

### 1.1 上游的全部逻辑建立在一句前提上

> **"Git hooks are intentionally narrow: pre-commit fixes staged lint, checks staged whitespace, and guards vendored-source metadata; pre-push runs only the incremental repository typecheck. CI owns exhaustive coverage and the platform matrix."**

也就是说上游的模型是：**本地钩子只做很小的事 → 你按变更选最小检查集 → CI 兜底穷尽覆盖与平台矩阵**。所以"选最小集"是**安全的**，因为有兜底。

### 1.2 SSiD 的这条前提**整个不存在**（已核实，见 §2.2）

- **零 git 钩子**
- **CI 只有 mac 打包，不跑任何测试**，且只在 `push tag` 时触发（推分支不触发）
- **无覆盖率配置**

**所以适配后的第一原则要反转**：

> 上游：*There is no universal local baseline beyond the hooks.*（除钩子外没有通用本地基线）
> **SSiD：没有任何本地基线，也没有 CI 兜底——你选的检查就是这次改动仅有的证据。**

这不是措辞差异，是**风险等级差异**。它抬高的是"选择"的分量：漏选一个检查不会有人替你发现。

### 1.3 一个系统性发现

把本轮与前几轮的核实拼起来，SSiD 的**质量兜底是全面缺席的**：

| 兜底机制 | DSH | SSiD | 核实处 |
|---|---|---|---|
| pre-commit / pre-push 钩子 | 有（`core.hooksPath=.git/dsh-hooks`，lefthook 管理，含 `pre-commit`/`pre-merge-commit`/`pre-push`） | **无** | 本说明 §2.2 |
| CI 跑测试 | 有（穷尽覆盖 + 平台矩阵） | **无**（只打包） | 本说明 §2.2 |
| 文档门禁 | `doc-sync` 等一批 | **无** | 02 §2.3 |
| 覆盖率配置 | per-file 100% | **无** | 本说明 §2.2 |

**这条发现不属于某个 skill**，但它决定了 01/02/06 三份适配版都要把"**没有东西替你兜底**"写进正文——否则 agent 会沿用上游的心智模型（"反正 CI 会抓"），而那个假设在 SSiD 是假的。

## 三、逐条适配判断

上游共 **7 个部件**（引言 + 6 个一级小节；另有 2 个二级小节 `### Focus unit coverage on the affected source`（挂 §2）与 `### Post-sync validation`（挂 §4））。

### 1. 引言 → **改写（前提反转）**

**保留**：*"Use this skill to run relevant local evidence **once** before a push."*（关键在 **once**——不重复已通过的）。

**改写**：把"钩子很窄 + CI 兜底"整段换成 §1.2 的反转表述。**删掉** `gh stack sync` 是唯一顺序例外那句（SSiD 不用 stacks）。

**新增**（有据）：**SSiD 的仓库根无 `package.json`，命令须在 `shell/` 下执行**——这是上游没有的操作前提。

### 2. `## Inspect the outgoing change` → **改写（基准确认换工具）**

**保留**：

- 确认 checkout 与分支（`git status --short --branch` / `git rev-parse --show-toplevel`）
- **"绝不猜测或抓取 base"** —— 上游原文 *"The command never guesses or fetches a base"*。改述为 SSiD 可执行的形式：**先确认比较基准（上次发版 tag 或目标分支的实时 ref），不要想当然用 `origin/master`**。SSiD 有 **19 个 release tag** 可作基准候选（`git tag` 实测；最近的是 `v0.2.1`）
- 合并了变化后的 base 之后：**重跑范围报告、重估合并后的范围能影响什么行为、只重跑被合并失效的检查**（逐字保留）

**替换**：`change-scope` → `git diff --stat <verified-base>..HEAD` + 受影响插件清单。**必须注明"这不是 change-scope 的等价物：它给路径，不给受影响包与脏层"**。

### 3. `## Select relevant evidence` → **改写（核心判据保留，8 类全换）**

**保留的三条核心判据**（逐字）：

1. **除钩子外没有通用本地基线** → SSiD 版：**连钩子都没有**（§1.2）
2. **每个行为变更需要最窄的、可获得的、会因该回归失败的测试或专用检查；只在 diff 真正触及的表面加更广的检查**
3. **不要因为 commit 或 push 在即就手动重复已通过的检查**（尤其不要为了重复 pre-push 钩子而在推送前跑 typecheck —— **SSiD 没有该钩子，所以这条变成"不要无理由重复"**）

**保留的入口纪律**：当改动涉及**拥有资源的或异步的测试、fixture、helper 或 CI 执行路径**时，**先读 01** 判断是否适用恢复 / 负向控制 / 静默拆除 / 并发进程证据；本 skill 仍负责选命令、并避免重复已通过的证据。

**8 类具体检查全部换成本地域**：

| 上游类型 | SSiD 对应 |
|---|---|
| 包或脚本行为：跑属主 Vitest 文件或聚焦用例名 | **跑属主测试**：`shell/` 是 node:test（`npm run test:profile-merge` 等）；插件按各自 runner（vitest 或 node:test，见 01 §2.1）。**注意 9 个插件用 `tests/`、3 个用 `test/`** |
| Remote mock 类型：跑 `pnpm run typecheck`，把异常留在 test proxy | **删**（SSiD 无 Remote mock 机制）。**但保留通用判据**：**"未构建的 `any` 是显式的本地退让，不是严格证据"** → 对应 SSiD 的 `lib/` 是派生物：改 `src/` 后要跑 `npm run typecheck` 与构建 |
| 文档 / Agent Note / 目录 / 文档链接注释：跑 `doc-sync` | **无 doc-sync** → 改为 **03** 的行文判据（人工语义核）+ 相关链接的可用性检查 |
| 模型/编辑器/CLI/终端可见输出：跑聚焦的无密钥快照或真实可运行示例 | **对应 Playwright 截图基线**（`cd shell/tests/plugin-adapt && npm test`）。**保留"基线变了要问为什么变"的纪律**（上游：*"Review expected-output diffs as behavior changes, not formatting noise"*） |
| 期望输出放置：`snapshots/` 与 `tests/expected/` 的区分 | **删**（SSiD 无该制度） |
| Profile 与配置放置：`apps/cli/tests/profiles/` | **改写**：SSiD 的对应物是 **`shell/profile-template/`**——**改它必须同时跑 `node scripts/prepare-runtime.mjs` 并核对三处 vendor 全等**（手册 §10 双处声明 + vendor 四份指纹一致） |
| 包清单 / 公开导出 / 构建配置 / worker 或 bin 入口 / 构建产物路径：跑 `build` + hygiene + built smoke | **保留并本地化**：改 `package.json` 的 `main`/`exports`/`dsh.client` → 跑 `npm run build`（tsdown）+ `npm run typecheck`；改 `cordis.patch.yml` → 核对插件在 profile 中可装载 |
| 真实 provider 或 agent 行为：跑 `test:e2e`（有凭据时），**绝不打印密钥** | **保留原则**：**"绝不打印密钥"逐字保留**；SSiD 的对应面是 MCP 服务器与真实模型调用 |

**二级小节 `### Focus unit coverage on the affected source` → 删（无覆盖率配置）**

**但必须救回两句**（它们与覆盖率机制无关）：

1. **"测试选择与覆盖率选择是两件事"** —— 一个文件过滤器决定跑哪些测试，配置决定量哪些源码
2. **"不要用 `--passWithNoTests`、降低阈值、或缩小覆盖面来**掩盖**一个未覆盖的受影响文件"** —— 这是**反作弊条款**，与有没有覆盖率配置无关

**救回的形式**：并入 §3 正文，作为"选测试时的两条禁令"。

### 4. `## Full local rehearsal` → **保留（并调整阈值说明）**

**逐字保留三种情况**：用户显式要求 / 诊断 CI 失败 / 变更横跨全仓以致没有更窄的集合可信。

**保留**：*"Use the current workflow and package scripts as the inventory; do not recreate the removed `check:pre-push` aggregate."* → SSiD 版：**以 `shell/package.json` 的 scripts 为清单，不要自造聚合命令**。

**新增（有据）**：因为**没有 CI 会替你在推送后发现问题**，SSiD 的"横跨全仓"阈值**应当比上游低**——触及**壳/内核边界**（`shell/main.mjs` ↔ `kernel.bundle.mjs` ↔ profile）或**同时改多个插件**时，倾向按全量排练处理。

### 5. `## Protect history-rewriting pushes` → **改写（保留 lease 铁律，删 stacks）**

**逐字保留的核心**（这是本 skill 最硬的一条）：

> 重写独立分支的历史前，抓取当前远端分支并**记录它的确切 OID**；用 **`--force-with-lease=<branch>:<observed-oid>`** 发布，使并发更新中止推送。**Raw `--force` 永不允许。**

**保留**：**"任何重写推送之后，重新抓取实时 head，并重新审计未解决的评审线程、批准、可合并性、检查——重写之前的 commit hash 与行内评论锚点不是当前证据。"**

**删除**：`gh stack push` / `gh stack sync` 相关（SSiD 不用 GitHub stacks），因此**二级小节 `### Post-sync validation` 整节删除**（它的 4 步与后续修复流程全部围绕 stack sync）。

### 6. `## Handle failures` → **保留**

**逐字保留**：若相关检查在普通推送前失败，**停下并修复或解释阻塞**；**不要"推上去然后指望 CI 结果不同"**（这条在 SSiD 更硬——CI 本来就不会告诉你）。

**保留环境特定失败的证明流程**：记录确切命令、失败用例与平台特定差异；确认相关的非平台证据；**该检查必需时优先修复跨平台不确定性**；**只有用户显式要求或同意时才绕过本地钩子**，并报告究竟什么失败、为什么预期 CI 会不同（SSiD 无钩子，此条改写为"绕过任何自定义检查"）。

### 7. `## Push procedure` → **改写（保留 mergeability 诊断）**

**保留四步**：跑一次选定的检查 → 正常提交并**在继续之前检查 pre-commit 修复器改过的文件**（SSiD 无 pre-commit 修复器 → 改为"检查格式化/生成步骤改过的文件"）→ 推送（或对已授权重写分支用确切 lease）→ **验证远端 ref 与本地 `HEAD` 一致**（`git rev-parse HEAD origin/$(git branch --show-current)` 逐字保留）。

**保留那段极有价值的诊断**（上游 §120-126）：当 `gh pr checks` 报 "no checks reported" 且 `/actions/runs?head_sha=<sha>` 返回 `total_count: 0` 时，**先读可合并性再怀疑推送或 GitHub 丢事件**：

```sh
gh pr view <number> --json mergeable,mergeStateStatus
```

> **GitHub 在 PR 处于 `CONFLICTING`/`DIRTY` 时不创建 `pull_request` 工作流运行，所以缺失的信号就是冲突本身，不是基础设施问题。** 解决冲突是唯一的修法；空提交、`--allow-empty` 推送、draft/ready 翻转、撤销再恢复都会让 `total_count` 保持为零并增加垃圾历史。

**这条判据的适用边界要写清**：SSiD 自己**没有 `pull_request` 工作流**（CI 只在 tag 触发），所以这段**对 SSiD 的分支不适用**；它适用于**给 DSH 或第三方提 PR 时**。

**删掉**末尾 `gh stack sync` 那句。

**自查记录（本轮踩到一个真陷阱，留痕）**：

我最初查 DSH 钩子时只看 `.git/hooks`，**得到"DSH 也没有钩子"的错误结论**——实际是 `core.hooksPath` 指向了 `.git/dsh-hooks`。

> **由此加一条写作规则（已并入 `写作规则` §三）**：**检查"某机制是否存在"时，默认位置查不到不等于不存在**。凡涉及"有没有 X"的否定结论，必须查配置解析后的**实际路径**（`git rev-parse --git-path <name>` 一类），而不是默认目录。SSiD 的"无钩子"结论是**经过这条程序**得出的（`core.hooksPath` 为空 + 默认目录零命中，两条都查了）。
