# 评测脚本子代理无模型：诊断与修复

- 日期：2026-08-16
- 触发场景：`shell/_eval-roles.ts`（M3 角色端到端评测）驱动"双星"委派灵犀时，4 次子代理委派全部失败
- 状态：已修复（`_eval-roles.ts`、`_diag-m3-roles.ts`），待下次评测运行验证

## 现象

eval 会话（`eval-lingxi-1786874923665`）中，`subagent_counselor`、`subagent_fork`、`subagent`
四次委派全部返回 `Error: subagent run failed`。4 个子会话
（`fd9f78bc`、`9ca654a3`、`63640661`、`6f2f080b`）落盘的 `turn/end` 事件记录同一错误：

```
agent "<uuid>" has no provider/model: set AgentOptions.provider and AgentOptions.model
or supply both via the agent/request waterfall
```

主 agent（双星）本身运行正常，只有子代理失败。

## 根因

DSH 子代理的模型继承链是
`resolveChildAgentOptions`（`packages/subagent/subagent/src/child-agent.ts`）：
只继承 `parent.options.provider` / `parent.options.model`——即**显式传入的
`AgentOptions`**，不继承 `installModelSelection` 挂在 agent 平面 scope 上的
waterfall 注入。

官方 headless runner（`packages/bundle/headless/src/index.ts` 第 111-119 行）创建
agent 时**两者都做**：

```ts
agentOptions: { provider: selection.provider, model: selection.model },
setup: (agentCtx) => {
  installModelSelection(agentCtx, { current: selection, assembled: undefined })
},
```

而我们的评测脚本只做了后者（只装 model selection，未传 agentOptions），于是主 agent
靠 waterfall 能跑，子代理创建时 `parent.options` 里没有 provider/model，报
"has no provider/model"。

结论：不是灵犀 persona 配置问题，不是 harness 子代理 bug，不是 API/凭证故障，
是评测脚本创建主 agent 时缺了 `agentOptions`。

## 修复

`shell/_eval-roles.ts` 与 `shell/_diag-m3-roles.ts` 的 `ctx.agents.create` 调用补上：

```ts
agentOptions: { provider: selection.provider, model: selection.model },
```

与官方 headless runner 对齐。`boot-smoke.ts` 不创建 agent，无需改。

## 验证路径

重跑 `node --import tsx/esm _eval-roles.ts`，检查 `_eval-roles.log`：
子会话段落应出现「灵犀: …」输出与「灵犀模型路由: deepseek-official/deepseek-v4-pro」，
主会话段落应出现「assistant: …」转述结论。
