# skill 适配说明 09：不适配理由（4 个）

> **本说明的地位**：对应目标 ④——**明确不适配的 skill 记录原因，而非硬造判据**。格式见 `2026-09-10-skill适配说明-写作规则.md`。
> 状态：已决策（推断 · 2026-09-12）

> 这是 8 份完整适配说明（01–08）之后的收尾；它**不生成 skill**。

---

## 一、判「不单独适配」的标准

**不是「SSiD 用不上」，而是「SSiD 没有它谈论的那个东西」。**

一个 skill 被判不单独适配，必须满足：**它的主题制度在 SSiD 不存在**——不是规模小、不是频率低，而是**被指向的对象本身缺失**。硬凑一份空壳 skill 的三重代价：

1. **它占着触发位**：agent 会为一个在 SSiD 永远不会发生的场景加载它；
2. **它携带假判据**：为了填满篇幅必然写进 SSiD 无法执行的命令与路径；
3. **它让"已适配"的意义变模糊**：以后没人分得清哪几份真能用。

**同时**：判不适用**不等于判无价值**。本说明的第二职责是**提取可搬的判据并把它们并入已有 skill**——丢掉这些才是真的浪费。

## 二、逐条理由

### 1. `dsh-doc`（861 行）→ ⛔ **不单独适配，但提取 3 组判据并入 03/05**

**上游体量**：SKILL.md 128 行 + `references/` 5 个 + `templates/` 4 个 = 861 行。

**它依赖的制度（逐条核实，SSiD 全部没有）**：

| 制度 | 上游要求 | SSiD |
|---|---|---|
| **kind 系统** | 4 个 kind（`package-group` / `package-reference` / `package-library` / `package-bundle`），**每个 kind 严格对应一个模板文件**，且"加一个新 kind 必须同时给出模板、仓库位置与专用检查" | 无 |
| **YAML 元数据** | frontmatter 的 `kind` 字段派生出期望模板；README 元数据门禁会**拒绝** `name` / `audience` / 未治理的 `tags` / README 局部 `i18n` 元数据 | 无 |
| **双语配对** | `foo.md` / `foo.zh.md` / `foo.i18n.yaml` 三件套 + **逐行对齐** + sidecar 哈希 | 无（SSiD 无双语制度） |
| **字数预算** | `pnpm run verify-doc-budgets` + `scripts/doc-budgets.manifest.json` 的天花板 + 至少 5% 余量 | 无 |
| **网站投影** | VitePress + `website/docs.ts` 显式公开白名单 + `project-doc-site.ts` 重写进 `.generated/` | 无 |
| **门禁** | `test:docs` / `doc-sync` / Summary gate（英文 Summary ≤ 100 词）/ skill 元数据检查 | 无（06 §2.2 已核） |
| **参考范例** | `session-persistence-jsonl` 的 README 对是格式样板 | 无对应物 |

**所以它不单独适配**：这份 skill 的主题是"**一套会互相校验的文档制度**"，而 SSiD 只有它的**最终产物**（13 个插件 README），没有产出它们的机器。强行适配会得到一份只讲"README 该长什么样"、却指向一堆不存在命令的 skill。

**但它有 3 组与制度无关的判据，必须提取**——**这是本次核实对清点表的更正**（清点表记为 `⛔ 现在不适用` 而未提可搬部分）：

#### (a) Fact-check procedure 的 5 条 → 并入 **03**

上游 §"Fact-check procedure: test, do not assume" 里，**5 条有 4 条不依赖任何 SSiD 缺失的制度**：

- **"对每条声称的操作，对着当前 checkout 真跑一遍"**——执行文档将展示的每个 CLI 命令、配置片段、profile/patch 示例的**原样**版本；**只写下你观察到的**，包括确切输出、警告与失败模式。若某断言依赖你没有的密钥或网络，**说明这一点并点名验证属主，而不是断言其行为**
- **★★★ "删掉你无法复现的东西"**：*"**绝不**把命令、字段、默认值或行为从**记忆、类比或邻居包的 README** 搬过来。当一条断言无法复现时，**修那条断言——而不是修测试**。"*
- **"对着最新 master 检查旧文档"**：修订既有页面之前先 `git fetch origin` 并把该节与 `origin/master` 对照；**"master 上一句陈旧的陈述仍然是错的"——要对着代码改，不是对着旧散文改**
- **"分类主题再写安装指引"**：**读事实，不要读文件夹名**（看 `package.json` 的声明与入口文件的插件形态）

> **为什么这条必须搬**：它**逐字描述了我在本系列 01–03 里犯的那 8 次错误**——把数字从记忆与类比里搬过来。DSH 早已把这条写成判据，而 SSiD 侧没有任何等价物。**不搬它，就是让同一个错误继续以"文档工作"的名义发生。**

#### (b) Voice rules 的 5 条 → 并入 **03**

5 条**全部制度无关**（它们管的是陈述方式）：

- **★★ "Summary 说的是主题能做什么"**：开篇 Summary 与用户向小节描述用户或 agent **能用它做什么**——结果、收益、何时选用、主要代价——**绝不是它的角色、类型或内部身份**。包 Summary 里的"它是什么"**仅指读者可见的能力**，不是它的 Cordis 角色、注册点或内部组件。*"'这个接缝注册 `ctx.x` 并追加 `x/event` 记录'是身份叙述；'你可以每条消息存一条笔记，重启后还在'才是它做什么。"*
  > **这条与 `writing-skills` 的「description 只写触发条件」同源**：两者都是"读者要能判断该不该用它，而不是被告知它内部走了几步"。**适配版的 description 规则应把两处合并成一条**。
- **"开发者小节解释，绝不枚举"**：折叠的实现内容覆盖整体设计概念、架构与挥手式数据流，**足够了理解它怎么工作**，并**链接代码**取确切细节；**不做完整 API 目录、穷举式字段清单、事件负载枚举或 JSDoc 复述**
- **★ "Dev Note 是唯一的草稿区"**：半成品想法、草稿、未定方向、实测产物与工作假设**只**出现在末尾的 Dev Note 里，并**显式标注非权威**；**其他每一节都是打磨过的当前状态散文**
- **★ "只讲当前状态"**：**Dev Note 之外没有兼容性垫片、迁移话术或历史**（"previously" / "now" / "no longer" / renamed）；**"今天这个代码库是唯一主题"**
  > **这条与 02 的推理痕迹修剪同源**——**03 与 02 应互相引用它**，而不是各自造一份。
- **"用受控的技术英语"**：歧义会改变行为时，让每句话有**显式 actor 与一个主要动作**；一个概念复用一个术语；优先直接动词；拆开堆叠的指令与条件；**保留情态与例外**。（上游引用一份 ASD-STE100 启发的规范，SSiD 无对应文献 → **保留判据、删引用**。）

#### (c) Quality criteria 的 6 条 → 并入 **04**（评审用）

6 条**全部通用**，且**正是评审时要问的问题**：

- **Brief**：常用路径只含其结局所需的事实；穷尽真相保持在**一个直接链接或一层细节**之外
- **Intuitive**：前置先于依赖概念；**下一步动作是显然的**；标题用读者会搜的词
- **Friendly**：读者能**识别成功**、**行动前理解风险**、**从可能的失败中恢复**、并能选择是否继续深入
- **Accurate**：每条持久断言**有一个属主**与**与其风险相称的验证路径**
- **★ Agent-readable**：元数据、稳定标题、锚点、术语、归属、当前/提议状态**支持定向检索而不必加载整个语料**
- **Newcomer-complete**：一个没有仓库上下文的专业工程师能**通过 3–5 个链接页重建相关架构或特性**

**并入方式**：03 的"必需覆盖"清单里加一节"文档质量六问"，并在 **04** 的 Manual checks 里引用它（评审新增文档时逐条过）。

**结论**：`dsh-doc` **不生成 skill**，但它的 **15 条判据**（fact-check 4 + voice 5 + quality 6）分别并入 03 与 04。**净损失为零。**

### 2. `dsh-translate-docs`（74 行）→ ⛔ **不适用**

**它是什么**：上游的**扩展双语文档工作流**——把 `foo.md ↔ foo.zh.md` 配对保持一致且两边都自然。它在 frontmatter 里就声明了调用边界：

```yaml
disable-model-invocation: true
user-invocable: true
```

即**只许用户显式点名调用**，不许从其他 skill 或"推断出的翻译需求"里被选中。

**它依赖的制度（SSiD 全部没有）**：

| 机制 | 作用 | SSiD |
|---|---|---|
| 三件套 `foo.md` / `foo.zh.md` / `foo.i18n.yaml` | 配对本体 + 一致性记录 | 无 |
| `pnpm run gen-translation-brief` | 生成简报（改动映射到最窄可安全对齐的粒度） | 无 |
| `pnpm run verify-translation-pairing --write/--list` | 重算并记录两侧 blobby 哈希 | 无 |
| `docs/i18n/terminology.md` | **双向约束**的术语表 | 无 |
| `docs/i18n/translation-rules.md` / `translation-prompt.md` / `style-samples.md` | 翻译规则、机用模板、文体样本 | 无 |
| 配对门禁 | 检查标题深度、围栏块、表格行列数、列表种类与起始、链接 locale | 无 |

**为什么不能"简化适配"**：这份 skill 的**唯一主题**就是双语配对。SSiD 是**单语（中文）仓库**——去掉配对制度后，剩下的只有"怎么把一段话翻译好"这类通用写作建议，而那已经由 **03** 覆盖。**硬适配会造出一份没有任何场景能触发的 skill。**

**唯一值得记下的一条**（不并入，仅记录）：*"**绝不**为了应用一次更新而重译整份文档——最小更新保留了所有未改动部分的已复核措辞；重译把那次复核丢掉了。"* 这条判据的**一般形式**（"最小改动保留已复核的部分"）已在 03 的"完整命题"节里隐含，无需另立。

### 3. `dsh-archive-agent-notes`（68 行）→ ⛔ **不适用（但记录为待办 #7 的参考）**

**它依赖的制度**：Agent Note 的**生命周期**（`implemented` / `proposed` / `rejected`）+ **三件套** + **`archived/<kind>/` 冻结** + **机械重录哈希** + `pnpm run verify-archived-agent-notes` 验证器 + 追加式封印（append-only seal）。

**SSiD 的现实**（03 §2.2、04 §三.3、05 §三.9 已分别核实）：`docs/决策/`（99 个文件）**无状态字段、无归档制度、无双语三件套、无验证器**——**这份 skill 要动的每一样东西都不存在**。

**两层价值，都不构成"适配"**：

1. **它是待办 #7（Agent Notes 状态机）的直接参考** —— 清点表已指出这一点。若 SSiD 将来要给 `docs/决策/` 引入状态与归档，这份 skill 的**分类判据**是现成的方法。
2. **它有一条通用的分类判据**（值得记录）：***"按未来决策价值分类——理由、备选方案、否定性保证、持久/wire 语义、归属边界、安全规则、重新引入条件——而不是按字数或年龄。**"* 并附带一条纪律：**"不要为了配额而归档。"**
   > 这条与 05 §7 的"先证明再动手"是同一个精神：**判断要基于语义，不基于可计数的表面指标。**

**为什么不并入 05**：05 已把"取代标记"压成一个动作（§三.9）。把归档生命周期塞进 05 会让它重新依赖不存在的制度——**那正是 05 §三.9 明确拒绝的做法**。

### 4. `dsh-merging-stacked-prs`（127 行）→ ⛔ **不适用**

**它依赖的制度**：**GitHub 官方堆叠 PR 对象** + `gh stack` 扩展（`--version` / `link` / `checkout` / `sync` / `rebase` / `push` / `merge`）+ GraphQL 的 `PullRequest.stack` / `stackEntry.position` + merge queue。

**SSiD 的现实**：

- **单人开发，无 PR 评审流程**（04 §一已定）；次场景（向 DSH / 第三方提 PR）也**不用 stacks**
- 上游自己写明了硬门槛：*"每个 head 分支必须位于同一仓库"*、*"跨 fork 链直接硬停"*、*"不要在官方扩展或服务端堆叠特性不可用时退回逐个手工合并与重定向"*

**它的两条通用判据已经被别处覆盖**：

- **"任何历史重写后要重新抓取确切 head，并重新审计未解决的评审线程、批准、可合并性、检查"** → **06 §三.5 已逐字保留** ✓
- **"删除分支只在对应 PR 报告 `MERGED` 之后的单独最后一遍进行；删前要求 GitHub 报告没有仍以它为 base 的开放 PR"** → 通用但 SSiD 无 PR 流程，**暂无处安放**（若将来有分支清理动作，这是判据来源）

**所以不单独适配，也不并入**——它的判据已被 06 吸收，剩下的全是 `gh stack` 机制。

## 三、这份判断的边界（什么情况下要重新评估）

**不适用是"现在"的结论，不是永久结论。** 下列任一条件出现时，对应 skill 应被重新评估：

| 触发条件 | 应重新评估 | 届时的起点 |
|---|---|---|
| SSiD 引入**双语文档**（中英对照） | `dsh-translate-docs` | 它的三路径分流（更新 / 新配对 / 删除改名）+ "最小更新而非重译" |
| SSiD 给 `docs/决策/` 引入**状态与归档** | `dsh-archive-agent-notes` | 它的按未来价值分类判据 + 追加式封印 |
| SSiD 建立**成体系的文档制度**（kind / 模板 / 预算 / 门禁） | `dsh-doc` | 它的四模板骨架 + Summary gate；**但 15 条判据届时已在 03/04 里** |
| SSiD 开始用 **GitHub 堆叠 PR**（例如长期并行多条改动线） | `dsh-merging-stacked-prs` | 它的硬门槛检查 + 官方 stack 对象作为成员资格权威 |

**写入包的方式**：`@max-null/dsh-skills` 首次发布**不含这 4 个 skill**，但包内 README 应有一段"**未包含的 4 个上游 skill 及原因**"（简短指向本说明），这样包的使用者不会以为我们漏了它们。

## 四、数字自检（命令产出，可复现）

```powershell
$root = 'DSHfork\.agents\skills'
# 行数（LF 口径，与 read 一致）
foreach ($n in @('dsh-doc','dsh-translate-docs','dsh-archive-agent-notes','dsh-merging-stacked-prs')) {
  $tot = 0
  Get-ChildItem "$root\$n" -Recurse -File | ForEach-Object {
    $tot += ([regex]::Matches([System.IO.File]::ReadAllText($_.FullName),"`n")).Count
  }
  "$n = $tot"
}
# dsh-doc = 861 ; dsh-translate-docs = 74 ; dsh-archive-agent-notes = 68 ; dsh-merging-stacked-prs = 127

# dsh-doc 的构成
@(Get-ChildItem "$root\dsh-doc\references" -File).Count   # 5
@(Get-ChildItem "$root\dsh-doc\templates" -File).Count    # 4

# SSiD 侧：本说明引用的"不存在"逐条
Test-Path 'seek-soul-in-darkness\docs\i18n'                       # False
Test-Path 'seek-soul-in-darkness\docs\cookbook'                   # False
git -C 'seek-soul-in-darkness' config --get core.hooksPath        # 空
Test-Path 'seek-soul-in-darkness\benchmarks'                      # False
(Get-Command ffmpeg -EA SilentlyContinue) -ne $null               # False
```

**自查记录**：

- 本说明引用的行数（861/74/68/127、**5** references、4 templates）来自 01–08 各轮的同一批命令，且 `dsh-doc = 861` 与清点表一致。
- **自查抓到一处错误**：第一版把 `dsh-doc` 的 `references/` 写成 **6 个**，实测为 **5 个**（`metadata-links-i18n.md` / `review.md` / `structure-hierarchy.md` / `style.md` / `website-sync.md`）。**这又是一次「我数过的」错误**——而且它就发生在我写「本说明没有引入任何新数字」的那一节里。**教训：「我引用的都是旧数字」这句话本身不构成免责**，每个数字仍要单独核对。
- 本说明**更正了清点表的一处判断**：`dsh-doc` 原记为 `⛔ 现在不适用` 而未提"可搬判据"。核实后它有 **15 条**制度无关的判据（fact-check 4 + voice 5 + quality 6）应并入 03/04。**这是第二处对清点表的更正**（第一处在 04 §2.2：Cordis 注册**不是** DSH 专有）。
- 两处更正的**方向相反**：04 是"原判不适用，实际适用"；09 是"原判纯不适用，实际**部分可搬**"。**共同点**：清点表是在**只读了一遍**的情况下做的粗分类，而适配说明是**逐条核实**——差异不出在判断力，出在**核实的深度**。
