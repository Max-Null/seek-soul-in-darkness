# 输入框命令/权限中文化：SSiD 内部插件方案

> 日期：2026-08-20
> 决策人：MaxNull（方案由 DSH 源码调研得出）
> 范围：仅 SSiD 内置（`plugins/` + `profile-template/vendor/`），不发布社区插件

## 一、背景与问题

DSH Web GUI 整体已是中文（locale 系统存在且 zh 是键集源），但**输入框两处内容仍为英文**：

| 位置 | 英文内容 | 原因 |
|---|---|---|
| 权限触发器（输入框盾牌按钮 + 菜单） | `Read Only` / `Workspace Write` / `Full access` | 客户端 `PermissionSelect.tsx` 把机器名 kebab 转 Title Case，`Full access` 为硬编码；host 端 `optionOf()` 未配置 name/description 时回退英文 |
| `/` 命令弹窗（命令行） | 命令 description（`Switch the permission preset...` 等） | 各插件注册命令时 `description` 英文硬编码，未走 locale 字典 |

目标用户：SSiD 非开发用户。命令名（`/compact` 等）是命令语法本身，不翻译；命令描述与权限展示名/描述需要中文化。

## 二、可挂载点调研结论（DSH 源码）

结论先行：**官方扩展面（slot / remote / provide 替换）均不可行，唯一可行且低侵入的挂点是 host 端包装服务实例方法**。

| 候选挂点 | 结论 | 依据 |
|---|---|---|
| 客户端 slot 替换权限触发器 | ❌ | `PermissionSelect`/命令按钮是 `ui-conversation` `InputBar.tsx` 硬编码组件，不在 slot 里；`conversation.input.left/right` 文档明言 "never replace" 内置 chrome |
| 客户端替换 `remote.commands` | ❌ | `RemoteNamespaceService` 经 `ctx.plugin` + `provide('remote.commands')` 注册，Cordis provide 唯一实现语义，重复提供抛错（`vendor/cordis/src/reflect.ts` L289） |
| host 端 `ctx.provide` 替换 services | ❌ | 同上，provide 唯一性 |
| **host 端包装服务实例方法** | ✅ | Cordis `ctx.get` 返回 traced proxy，`Symbol.for('cordis.original')` 可取原始实例（`vendor/cordis/src/utils.ts` L54/L117）；Typert gateway 每次 RPC 实时 `ctx.get(serviceKey)` 解析 receiver（`packages/api/gateway/src/index.ts` L150），`Reflect.get(receiver, method)` 实例 own 属性优先于原型（L163），`originalOf` 只用于 binding 验证（L537）——实例 `defineProperty` 包装方法对 Typert 反射无影响 |

## 三、方案

**新增 SSiD 内置插件 `@max-null/dsh-ssid-zh-ui`（纯 host 端，无 client half）**：

```
plugins/dsh-ssid-zh-ui/
├── package.json        # @max-null/dsh-ssid-zh-ui；dsh.bundle.patch
├── cordis.patch.yml    # insert 一行插件
├── lib/index.mjs       # apply：inject ['commands','permissionPresets'] → 包装实例方法
└── verify-zh-ui.cjs    # node 模拟验证（仿 verify-header-unify.cjs）
```

### 3.1 包装点

1. **`ctx.commands.list(agent)`** → 返回的 descriptor 数组逐项替换 `description`（按命令名查中文表，未收录保持原样）。
2. **`ctx.permissionPresets.optionOf(name)`** → 预设项返回中文 `name`/`description`；`custom` 分支固定中文。
   - 客户端 `displayName()` 对非 kebab 字符串原样透传（`PermissionSelect.tsx` L55-58），中文 name 可直接显示；`selectFor` 内部 `this.optionOf(...)` 会解析到实例 own 属性（包装后的方法），投影/RPC/客户端整链路生效。

### 3.2 实现要点

- 用 `ctx.inject(['commands', 'permissionPresets'], cb)` 等待服务；Cordis 服务 HMR 重载后 inject 重新执行，包装跟随新实例。
- 通过 `service[Symbol.for('cordis.original')] ?? service` 取原始实例，`Object.defineProperty` 包装（configurable: true），实例 own 属性遮蔽原型方法。
- 包装幂等（实例上挂标记符号，防重复包装）。
- 防御：包装失败 try/catch 记 `ctx.logger.warn`，绝不影响 host 启动。
- wrapper 内用 `Reflect.apply(original, this, args)` 转发，保持 `this` 语义（`list` 内部调用 `this.view()` 等私有方法）。

### 3.3 翻译表

**命令描述**（官方 6 命令全收录，未知保留）：

| 命令 | 中文描述 |
|---|---|
| `/compact` | 压缩当前会话的历史记录，释放上下文空间 |
| `/feedback` | 对当前会话或消息提交反馈 |
| `/goal` | 为当前会话设置长期执行目标 |
| `/permission` | 切换权限模式（沙箱范围 + 审批策略） |
| `/plan` | 进入或退出计划模式 |
| `/export` | 导出当前会话日志为文件 |

> hint（命令参数占位，如 `<preset>`）**不翻译**——它是命令语法提示，用户需输入机器值，避免误导。

**权限预设**（覆盖三个默认预设 + custom）：

| 预设 | name | description |
|---|---|---|
| `read-only` | 只读 | 仅允许读取与浏览，不授予文件修改或命令执行权限 |
| `workspace-write` | 工作区写入 | 允许修改当前工作区文件；敏感操作与外部命令仍需逐项确认 |
| `danger-full-access` | 完全访问 | 可直接执行敏感操作、文件修改或外部命令，不再逐项确认；仅建议在信任任务时使用 |
| `custom` | 自定义 | 当前沙箱与审批设置不匹配任何预设 |

## 三·五、演进记录（2026-08-20 实测后）

### v1（host 包装）→ v2（client 展示层翻译）决策

v1 实现为 host 端包装 `commands.list` / `permissionPresets.optionOf`，经 settings 语言开关控制翻译。**实测发现死结**：权限投影与命令目录的数据推送是事件驱动的（会话事件/`commands/change`），语言切换**不会触发数据重推**——host 翻译写入数据后，客户端缓存的中文无法切回英文，必须刷新页面才恢复。

**v2 决策：翻译整体移到 client 展示层**：

- host half 变 no-op（数据保持英文原文）。
- client half 维护**英文原文 → 中文**翻译表（`TEXT_ZH`，文本全等匹配），按 `ctx.locale`（`locale/change` 事件）即时替换/恢复；MutationObserver 兜底 React 重渲染。
- 替换范围限定 css-modules 原始段 + role 语义：`[class*="triggerLabel"]`（输入框权限/模型触发器）、`[class*="selector"]`（设置页选择器）、`[role="menuitem"]`（菜单项）、`[role="option"]`（命令/权限弹窗选项）。文本全等匹配，官方中文子串（「启用 Full access」）与消息正文不受影响。
- 权限名中客户端 `PermissionSelect.tsx` 对 `danger-full-access` 硬编码 `Full access`，host 数据无法覆盖——v2 一并由展示层替换为「完全访问」（含菜单项、弹窗选项、设置页选择器）。

**翻译表**（`TEXT_ZH`，11 条 + `ZH_TO_EN` 1 条）：

| 英文原文（rc.8） | 中文 |
|---|---|
| `Read Only` / `Workspace Write` / `Full access` / `Custom` | 只读 / 工作区写入 / 完全访问 / 自定义 |
| `Compact older conversation history` | 压缩当前会话的历史记录，释放上下文空间 |
| `set or view the goal for a long-running task` | 为当前会话设置长期执行目标 |
| `Enter or leave plan mode` | 进入或退出计划模式 |
| `Switch the permission preset (sandbox mode + approval policy)` | 切换权限模式（沙箱范围 + 审批策略） |
| `Download this Session log as a ZIP archive` | 导出当前会话日志为文件 |
| `record feedback about this session` | 对当前会话或消息提交反馈 |
| `Select the model for this conversation` ↔ `选择本会话使用的模型` | 双向（`/model` 命令描述） |

> `/model` 双向兜底：官方 `ui-model-selection` 的命令描述**注册时快照 locale，切语言不刷新**（源码注释明言）。插件用 `ZH_TO_EN` 反向表兜底：中文界面把英文快照转中文，英文界面把中文快照转英文。两表键集互斥（英文键集 vs 中文键集），restore + 正向替换顺序无冲突。

### 实测验收（用户，2026-08-20）

中文界面权限「只读/工作区写入/完全访问」、命令描述中文；切 English 全部即时恢复英文；切回中文即时恢复。`verify-zh-ui.cjs` 43 项断言全过。

## 四、装配与分发

1. 源码：`plugins/dsh-ssid-zh-ui/`（SSiD 仓库内置，仿 `dsh-header-unify`）。
2. vendor 分发：`shell/profile-template/vendor/dsh-ssid-zh-ui/`（lib 产物副本），`profile-template/package.json` dependencies + bundles 各加一行 `file:./vendor/...`。
3. 发布链：`scripts/prepare-runtime.mjs` 重跑（新归档含本插件），后续随 SSiD 版本发布。
4. 本机验证：vendor 副本 + profile `package.json` + pnpm install + 重启 dsh web。

## 五、验证计划

1. `verify-zh-ui.cjs`：node 模拟——翻译表覆盖断言、`wrapList` 翻译/未知保留、`wrapOptionOf` 预设中文/custom 中文/未知走原逻辑、实例 own 属性遮蔽断言。
2. 实机（本机 ssid profile + 3080 GUI）：权限按钮显示「工作区写入」、菜单「只读/工作区写入/Full access」、tooltip 中文描述；`/` 命令弹窗 description 中文；`/permission` 执行不受影响（机器值不变）。
3. HMR/重载：改插件重启 profile 后包装仍生效。

## 六、风险与边界

- **上游演进**：DSH 若把命令 description 接入 locale（PR 方向），本插件翻译表可能与其重叠——届时保留本插件（内部用户零感知）或移除（让位上游），二选一。
- **rc 版本差异**：本方案针对 rc.8 产物（profile 已实测）；上游 master 的 `optionOf`/`list` 签名与 rc.8 一致（源码调研）。
- **全家桶命令**：`@max-null/dsh-*` 若有自注册命令，未收录时保持英文（兜底不破坏）。
