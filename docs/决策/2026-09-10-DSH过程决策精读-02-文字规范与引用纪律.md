## 1. 具体的散文点名行为者与已记录事实

`2026-08-09-concrete-prose-names-actors-and-recorded-facts.md`

### 他们遇到的事

仓库里的散文**用了抽象类别标签，而读者需要的是不同的具体事实**。同一个标签可能指：

- 被替换掉的引用所引用的更早事件序号
- 产生某条消息的 provider 和 model
- 提供上下文的调用方
- 提供某配置行的文件
- 构建某个二进制的 CI job

结果是：**读者必须先翻代码，才能知道这句话承诺的到底是哪个事实。**

### 判断

维护中的散文要**点名**本地契约所需的确切**行为者、动作、来源、事件、字段、文件或进程**，并说明**记录了什么、以及谁或什么记录的**。

给写作者的操作方法只有一条，但很锋利：**做口语检查**——把那些你**不会用来向同事解释同一件事**的词替换掉。

适用范围明确列出：Markdown、README、活跃 Agent Note、JSDoc 和注释、提示词、诊断信息、用户可见字符串。

三条约束防止走偏：

- **逐句审查**，不做全仓库同义词替换
- 编辑后的句子要保留：行为者、动作、条件、顺序、情态、例外、归属、失败行为、后果
- 精确的代码标识符、公共 API、持久字段、协议成员、类型名、文件名**保持不变**，除非另有一次独立的协同重命名

还有一个专门针对三个高频词的判断：用 `contract` / `boundary` / `shape` 之前，先问这句话是不是其实想说更具体的规则、操作、数据结构、字段集合、校验点、时序点、API、类型或失败条件。

### 凭什么这么判断——三个被否决的方案

| 方案 | 否决理由 |
|---|---|
| **禁用一份固定的词表** | 一个词可能是精确的标识符，或在另一份契约里是最清晰的术语——调用方/被调用方的不变量**是真实的契约**，进程或线路边界**是真实的分界**。逐句审查能抓住歧义，而不会否决合法的名称 |
| **把每个抽象标签都换成 "source"/"origin"/"metadata"** | **另一个宽泛标签仍然让读者去猜**：这句话指的是文件、调用方、事件序号、provider/model 对、commit 还是构建 job |
| **连同散文一起重命名所有匹配的标识符** | 编辑上的清晰度**不足以正当化**无关的 API、协议、持久格式、类型或文件迁移；那些改动需要各自的消费者审计和独立的决策 |

第 2 条否决理由值得单独记住：**换一个宽泛的词，等于什么都没做，只是把谜题换了个面。**

### 他们承认的代价

文档和诊断信息会多用几个词；仓库范围的散文审计**需要语义分类，不能做盲目替换**。

## 2. Agent Note 的统一格式

`2026-07-05-uniform-agent-note-format.md`

### 他们遇到的事

Agent Note 的**路径**已经编码了生命周期和类别，但**文件内容**仍然混杂着各种标题风格、状态格式、ADR 模板和提案模板，甚至 implemented 记录里还留着提案期的章节。

根因一句话：**作者复制他们找到的那个邻居**。而且生命周期移动可以跳过必需的改写——因为没有门禁强制文件内的契约。

### 判断

格式契约落在 README 里，包含：头部块、各生命周期的正文骨架、**强制的 `Alternatives considered` 段**，以及规范章节词汇（在规范章节之间，定制技术章节保持自由形式）。

门禁 `verify-agent-note-format` 作为 `doc-sync` 的一部分强制执行每一条机械条款，于是**跳过硬写的生命周期移动会失败 CI，而不是依赖评审者的记忆**。

两个关键立场：

1. **整个语料在同一次变更里被规范化**——发布前的立场是"没有过渡期、没有双格式容忍"
2. **唯一的祖父条款是内容，不是格式**——alternatives 是**记录的，绝不编造**，所以无法从记录中重建 alternatives 的旧笔记，携带一行精确的注释，而门禁**只对早于本笔记日期的文件**接受它

### 凭什么这么判断——8 个被否决的方案

| 方案 | 否决理由 |
|---|---|
| **完全刚性的模板**（每个生命周期一个固定章节序列） | 大型设计笔记带 8–15 个定制的技术章节（包拓扑、线路契约、schema），它们是**承重内容而不是漂移**；刚性序列会强制破坏性重写，并从此永远与模板搏斗 |
| **只规范化头部**（H1 和 Status，正文不动） | 债务标记标出的恰恰是**正文**的体裁分裂；把 `Context`/`Decision` 与 `Problem`/`Proposal` 长期并置，什么也没解决 |
| **不要 Status 行**（文件夹本身就是状态） | 选择保留"自描述的文件"；促成删除它的那个漂移风险，通过**把该行对着文件夹把关**而被中和 |
| **带日期的状态**（`implemented (accepted YYYY-MM-DD)`） | 接受日期是**被写作规则挡在文档之外的叙述性历史**；文件名带首次提案时间、git 带其余；而且——**门禁能检查日期的格式，却永远无法检查它的真实性** |
| **裸 `# <title>`** | `Agent Note: ` 前缀让文件在被移到树外阅读时**仍然自描述体裁** |
| **用 `## What we give up` 作为 implemented 的收尾** | **它只命名代价**，而诚实的 consequences 段必须同时记录这个权衡**买到了什么** |
| **只靠约定，不设门禁** | slop 检查表已经用约定禁止了 implemented 里的 spec-speak，而**十九个文件展示了单靠约定能达成什么** |
| **独立的 `FORMAT.md` 契约文件** | 一个入口点同时携带布局、分类和格式，比两个契约文件**更容易被发现和维护** |

第 7 条是整篇最有分量的一条：**"十九个文件展示了单靠约定能达成什么"**——这句话把"我们有规范了"这种自我安慰直接击穿。

### 他们承认的代价

- 每篇 Agent Note 现在要多花一点结构成本
- **强制的 `Alternatives considered` 是刻意的摩擦**：*一个没有记录它击败了什么的决策，会招致 Agent Note 本来要防止的重新打官司*
- 无法重建 alternatives 的旧笔记**永久携带祖父注释**——这是"记录上一个诚实的空白，而不是编造理由"

## 3. 只引用已提交的产物

`2026-08-09-committed-artifact-citations.md` · **本批最重要的一篇**

### 他们遇到的事

大型设计和评审会话会留下**工作速记**：决策序号、审计项代码、计划章节号、任务和 stack 序号、评审者裁决。这些速记**在会话记录打开时读起来完全自然，会话一关就解析不到任何东西**。

一次仓库范围的审计给出了具体清单（这本身就是个好示范——不是"感觉有点乱"，而是"审计发现集中在 `packages/client`"）：

- 裸 `(decision 12/16/19/20/21)` 引用，其中**只有 decision 21 有已提交的拥有者**
- `(audit C2/S1/S3/S7)` 代码——仓库里**任何地方都没有**对应的审计文档
- `design §4.7` / `web2 §0` / `plan §1.4`——指向**未提交的草稿**
- 计划阶段标签（`T2/T5/T9`、`P-I`、`W5`）
- stack 位置（"a later PR in this stack"）出现在**持久 JSDoc** 里
- "ruling" / "design ledger" 这类词汇

同样的家族还出现在测试、CSS 注释、生成器模板、CI 注释和 Agent Note 里——包括 "this PR / branch / review round" 这种视角、评审编排式的归因，以及"deferred to a later PR"这类**过时声明（目标其实早已发布）**。

然后是最关键的一句诊断：

> The documentation standard already banned the change-history half (previously/now, PR and commit references) **but stated no counterpart rule for citations**, so unresolvable ordinals kept landing.

**文档标准早就禁止了"变更历史"那一半（previously/now、PR 和 commit 引用），但没有为"引用"这一半陈述对应规则**——所以无法解析的序号不断落地。

这是"规则有缺口"的教科书案例：**禁了一半，没管另一半，漏洞就从没管的那半漏进来。**

### 判断

持久散文（注释、JSDoc、文档、笔记、测试注释和标题）**只引用已提交的产物**，且能在仓库内解析、不需要 grep 考古：

- 可以引用：**具名的拥有者 Agent Note**（路径至少出现一次，正文里有个可搜索的名字）、**文档页路径**、**GitHub issue 号**
- 仍然禁止：PR、commit、branch、stack 位置（按文档标准）；不过 Agent Note 和事故复盘**可以引用已合并的 PR 和 issue 作为证据**
- **有已提交拥有者的序号 → 用该决策的名字替换**（"decision 21" → "the plain-text-reference decision"），序号本身在全仓删掉
- **没有拥有者的序号 → 直接删除，把它的叙事分句重述为能独立成立的陈述**
- **已修复的回归用现在时的反事实表述**（"without X, Y happens"、"a naive X would…"），**绝不用仓库历史**（"used to Y"）
- implemented 笔记陈述**已发布现实**：一条 "deferred to a later PR" 如果目标早已发布，就改成具名那篇已发布的笔记
- **豁免**：录制的 fixture、快照、归档笔记——**录制的模型输出和封存的历史保持原声**
- **召回探针使用词汇边界，并用已知正例和一个近似负例来校准**；撰写语言探针针对**相反语言的那一面**，而不是把完整的中文语料当作"未翻译残留"
- **所有者优先的编辑要追踪每一个生成的消费者**；逐字代码围栏在双语对之间逐字节复制

### 凭什么这么判断——三个被否决的方案

| 方案 | 否决理由 |
|---|---|
| **把设计账本和审计文档提交进去，让序号可解析** | 会话记录是**工作产物，不是维护中的参考**；提交它们会在 Agent Note 旁边**创造一份平行的、没有门禁的决策语料**，而且它们的内部编号**仍然会漂移** |
| **为禁用词汇做一道机械门禁** | **推迟，不是否决**——理由见下 |
| **删除那些引用了死产物的理由** | 事实分句被保留或重述；**只有引用、评审编排和推导记录被移除** |

第 3 条划出了删除的边界：**删的是引用，不是理由。**

### 为什么机械门禁被"推迟"而不是直接做

这是全篇判断力最集中的一段，值得逐句看：

> the vocabulary is unbounded natural language, and the audit's recall batteries need judgment to separate leakage from legitimate prose ("wait" the noun, contrastive "actually", runtime old/new states)

词汇是**无界的自然语言**，审计的召回电池**需要判断力**才能区分泄漏与合法散文——比如作名词的 "wait"、表对比的 "actually"、运行时的 old/new 状态。

他们给出了一份**窄的高精度候选门禁清单**，供模式复现时启用：

```
\(decision \d      \(audit [A-Z]\d      \bcut \d      this cut
\bT\d\b            P-I                  used to       \bv1\b      §\d
```

（最后一条 `§\d` 排除那些章节编号**有已提交拥有者**的引用。）

而这份清单的**来源**很讲究：*"review of the purge itself caught residuals in exactly the cases those searches missed, so they lead the candidate list"*——**对清除行动本身的评审，恰好抓到了那些搜索漏掉的情况，所以它们领跑候选清单**。

### 一次坦诚的缺口披露

Verification 段最后一句：

> Coverage gap: no gate rejects a new ordinal citation — review owns the rule.

**覆盖缺口：没有门禁拒绝新的序号引用——这条规则由评审承担。**

官方**主动写出**"这条规则靠评审而非门禁"。这一点在第 01 批的判断标准①（"可机械判定的不变量必须编码成检查"）旁边看尤其有意思：它说明**"能不能机械判定"本身就需要判断**，硬上一道会误伤合法散文的门禁，只会制造第 01 批判断标准⑦所说的坏训练。

### 他们承认的代价

- 注释里的引用通过**路径或名字**解析；读者永远不需要重建一个已关闭的会话来跟进
- **设计会话必须先把决策落到 Agent Note，持久散文才能引用它们**；序号速记留在会话内部
- 引用会变长（一个笔记路径替代 "(decision 21)"），换来的是**免 grep 的解析**

## 这批的共同判断标准

**① 换一个宽泛的词等于什么都没做。**
"把抽象标签统一换成 source/origin/metadata"被否决的理由是：**另一个宽泛标签仍然让读者去猜**。这条直接适用于任何"统一术语"的冲动——统一到一个同样模糊的术语，只是把谜题换了个面。

**② 规范只禁了一半，漏洞就从另一半漏进来。**
文档标准禁止了"变更历史"，却没管"引用"，于是序号引用不断落地。看任何规范时都该问：**与它对称的那一半在哪？**

**③ 删除时要区分"引用"与"理由"。**
死产物的引用可以删，但**事实分句要保留或重述**。删掉引用就删掉理由，是过度清除。

**④ 不能被机械判定的规则，要么推迟，要么明说缺口。**
他们对禁用词汇**推迟**了门禁，并列出高精度候选清单备用；同时**主动写出**"覆盖缺口：这条规则由评审承担"。两条路都比"假装有门禁"诚实。

**⑤ 探针必须用正例和近似负例校准。**
"用已知正例和一个近似负例校准"、"召回电池需要判断力区分泄漏与合法散文"——这是待办 #8 的直接方法论输入。近似负例（near-miss negative）是这里的关键：**只测正例的探针，无法知道自己有没有误伤。**

**⑥ 强制的摩擦可以是刻意的。**
`Alternatives considered` 是"刻意的摩擦"，理由是：**一个没记录它击败了什么的决策，会招致它本来要防止的重新打官司**。摩擦不总是坏事，要看它阻止的是哪种未来成本。

**⑦ 诚实的空白胜过编造的理由。**
无法重建 alternatives 的旧笔记，永久保留一行"此处不可重建"的注释，而不是补一段像样的理由。**这与"编造一个合理的历史"只有一线之隔，而他们选择了留白。**

**⑧ 自描述优先于依赖上下文。**
`Agent Note: ` 前缀让文件挪出树外仍能自述体裁；Status 行保留而非依赖文件夹。**假设读者在错误的上下文里读到它。**
