# 官方桌面端承载思灵插件实测（2026-09-25）

## 一句话结论

**思灵的插件家族可以直接装进 DSH 官方桌面端并全部运行；思灵的界面定制靠插件（官方前端插槽）就能复现，不需要改壳。**「以官方桌面端为基座」在技术上成立——但成立的形态不是「把官方壳改造成思灵」，而是**把思灵装进官方壳**。

## 背景

2026-09-25 官方对外发布 DSH 桌面端安装包（`0.1.7-rc.1.20260924.1`，win-x64 322 MB）。此前（0.1.5 时代）曾讨论过「要不要放弃自建壳、改以官方桌面端为基座」，当时结论是官方桌面端太初级。本轮升级 0.1.7 又付出了一次壳适配成本，因此重新评估该问题。

评估卡在一个可实测的问题上：**我们的插件装进官方桌面端能不能跑。** 本文是该实测的记录。

## 机制层面的关键发现

### 1. 官方桌面端与 SSiD 用的是同一套注册机制

官方桌面端首启生成的 `profiles/desktop/package.json`：

```json
{
  "name": "dsh-profile-desktop",
  "private": true,
  "dependencies": {},
  "dsh": { "profile": { "bundles": ["@deepseek-ai/dsh-base", "@deepseek-ai/dsh-web-app"] } }
}
```

——与 SSiD 上一轮迁移后的形态一字不差。安装插件即写 `dependencies`，启用即把名字追加进 `dsh.profile.bundles`。UI 上「已安装」分组的判据仍是 profile `dependencies`（详见 `2026-09-24-内核0.1.7适配-隔离实验台账.md` 的迁移节）。

设置同样写进 profile 的 `cordis.patch.yml`（实测该文件被官方桌面端写入了 `ui-chat` / `ui-settings` / `ui-settings-account` 三个配置覆盖）。

### 2. 界面定制靠官方前端插槽，不靠壳

`dsh-ssid-panels/lib/client.js:1505-1532` 用的是官方 DSH Web 前端的插槽：

- `ctx.slots.inject('sidebar.brand.mark')` → 换品牌图标
- `ctx.slots.inject('sidebar.brand.name')` → 换品牌名（渲染出「思灵」）
- `ctx.slots.inject('conversation.hero.brand.mark')` → 换欢迎页品牌
- `ctx.slots.inject('settings.section')` → 加「关于」设置页
- `ctx.inject(['betterSidebar'])` → 注册侧栏 tab（peer 缺失时静默）

**这些插槽是 DSH 的扩展点，不是思灵壳的。** 这解释了为什么整套界面定制能原样搬过去，也说明思灵的「样子」本来就是插件资产而非壳资产。

### 3. 本地路径安装：UI 要求绝对路径，pnpm 产出 symlink

- 输入 `file:./vendor/dsh-tone-layer` → 被拒：**`无法识别这个包名或地址：a local path must be absolute`**
- 输入绝对路径 → 成功，pnpm 写入 `"link:H:/.../vendor/dsh-tone-layer"`，`node_modules` 下是**符号链接**（不是 `file:` 的复制语义）

**symlink 安全性判断**：链接目标位于 profile 内的 `vendor/`，其向上查找链经过 `profiles/desktop/`，**该目录下有 `node_modules`**，因此 ESM 解析正常。这与 2026-09-22 桌宠 `@dsh-pet/bridge` 那次致命故障（链接目录一路上溯到 `H:\` 一个 `node_modules` 都没有）性质不同。

**含义**：思灵的 `file:./vendor/xxx` 相对路径 + 复制语义，**无法通过官方桌面端 UI 复现**；要在官方桌面端沿用该形态，只能手写 profile 的 `package.json`。

### 4. peer 依赖不兼容只警告不拦

安装日志原文：

```
[WARN] Issues with peer dependencies found. Run "pnpm peers check" to list them.
+ @max-null/dsh-chinese-thinking 0.3.0
Done in 541ms using pnpm v11.7.0
```

我们的插件 peer 声明停留在 `^0.1.1-rc.1` 一类的旧范围，与 0.1.7-rc.2 内核不完全匹配（semver 的 prerelease 匹配规则），但**不影响安装**。官方桌面端的 profile `pnpm-workspace.yaml` 带 `autoInstallPeers: false`。

### 5. 官方桌面端自带的能力（我们目前自建或缺失的）

- **原生恢复对话框**：Exit / Restart / **禁用第三方插件** / 备份 profile patch 并重启；恢复动作会把 `cordis.patch.yml` 改名为 `cordis.patch.yml.bak-<timestamp>`（README:105/111）
- **内置 pnpm v11.7.0**，包操作不需要系统 pnpm
- **内置完整 dsh runtime** + Python/Node/pnpm 发行版（`app.asar.unpacked/dsh`）
- **runtime resolution**：内置共享包 + profile 内包优先、尽量同实例（社区讨论亦提到这点）

## 实测方法的三条坑（我的操作问题，非产品缺陷）

1. **不要用后台 job 以 `&` 启动官方桌面端**：应用的 stdout 挂在 pwsh 管道上，job 结束管道关闭后应用写日志会得到 `EPIPE: broken pipe, write`，主进程抛未捕获异常卡在错误对话框（窗口标题 `Error`），CDP 随即失联。正确做法是 `Start-Process -RedirectStandardOutput/-RedirectStandardError` 指向文件，让子进程持有真实文件句柄。
2. **必须清掉继承自思灵会话的 `SSID_*` 环境变量**：从思灵会话内启动任何 DSH 实例，会继承 `SSID_PROFILE_DIR=C:\Users\MaxNull\.dsh\profiles\ssid`、`SSID_SESSION_ISOLATED_ROOT`、`SSID_SHELL_VERSION` 等一整套标识。这会让 `dsh-ssid-env` 误判（探测到标识就注入「你在 SSiD 内运行」，而实际跑在官方桌面端里），并可能影响其它读这些变量的插件。隔离三件套之外，**`SSID_*` 也要清**。
3. **UI 上定位启用开关要用完整的 `aria-label`**：列表页每个插件的开关都带唯一的 `aria-label`（形如 `启用 @max-null/dsh-memory`），但用 `/^启用/` 这样的宽松匹配会命中**第一个**（本次误开了官方的「智能体团队」，随后已撤销，`bundles` 回到 8 项）。「立即启用」按钮则是**装完那一刻的一次性入口**——它只对最近一次安装的包显示（`dsh-client-ui-plugin-manager/lib/client.js:2728` 读 `state.install` 的 activation），后续安装会把它顶掉，所以「一次只装一个、装完立刻启用」才是顺手的节奏。

## 对「要不要以官方桌面端为基座」的影响

**技术可行性：确认。** 插件可完整搬运，界面可复现，机制同源。

**但成立的形态与原先设想的不同**：

| 设想 | 实测后的判断 |
| --- | --- |
| fork 官方 `apps/desktop`，把壳改造成思灵的样子 | **不必要**——界面定制本就是插件的事，改壳是重复造轮子 |
| 把思灵插件装进官方桌面端的 `profiles/desktop` | **可行且已验证**，零壳改动即可得到「官方壳 + 思灵灵魂」 |
| 官方桌面端取代思灵壳 | **代价明确**：profile 名 `desktop` 硬编码（`apps/desktop/src/paths.ts:19`）、`productName` 硬编码（`scripts/electron-builder-config.mjs:109`）、发布需 Windows EV 签名/macOS notarize、且官方自更新会覆盖定制 |

**多开**：官方桌面端单实例锁绑 Electron userData、profile 名固定，但 `DSH_HOME` 与 `--user-data-dir` 都可替换——本次实测即以此与思灵并行运行，互不干扰。

**账号**：即使隔离了 `DSH_HOME`，官方桌面端仍读到真实 DeepSeek 账号登录态（面板显示账号与余额）。测试期间未发消息，未消耗额度。

## 复现路径

```
.dsh-desktop-test\
  dsh-desktop-win-x64.exe        安装包（322 MB）
  install\                       安装目录（NSIS 静默安装）
  home\                          DSH_HOME（profile: desktop）
  user-data\                     Electron userData
  desktop-out.log / desktop-err.log
  probe-*.js                     CDP 探针（cdp-eval.mjs 调用）
```

启动（**必须清 `SSID_*`**）：

```powershell
Get-ChildItem env: | Where-Object { $_.Name -like 'SSID_*' -or $_.Name -like 'DSH_*' } |
  ForEach-Object { Remove-Item "env:$($_.Name)" }
$env:DSH_HOME = 'H:\MaxNull\WorkStation\.dsh-desktop-test\home'
Start-Process 'H:\MaxNull\WorkStation\.dsh-desktop-test\install\DeepSeek Harness.exe' `
  -ArgumentList '--user-data-dir=H:\MaxNull\WorkStation\.dsh-desktop-test\user-data','--remote-debugging-port=9355' `
  -RedirectStandardOutput '...\desktop-out.log' -RedirectStandardError '...\desktop-err.log'
```
