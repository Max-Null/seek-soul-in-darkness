> 目的：用户背景是「用自研 SSiD 做 AI 原生中台服务开发」，学习目标有两个——① 升级个人工作方法论；② 升级 SSiD 工具本身。

> 配套：结构与规模（12 skill / 960 篇 Agent Notes / 215 脚本）见 `2026-09-10-DSH官方工程化范式调查.md`，本篇只讲**方法论与可迁移点**。

## 一、八条核心方法论（跨 skill 提炼）

| # | 原则 | 原文依据 |
|---|---|---|
| 1 | **证据驱动**：任何结论须有可复现证据 | "A suspicious loop, unused cache, or large file alone is not evidence of a bottleneck." |
| 2 | **最小必要**：最窄的测试、最小的改动、最小检查集 | "Every behavior change needs the narrowest available test or purpose-built check that would fail for its regression." |
| 3 | **一个事实一个家** | "Each fact has one home: the tier whose job it is; elsewhere, link there." |
| 4 | **决策必留替代方案** | "A decision recorded without what it beat invites re-litigation — the failure Agent Notes exist to prevent." |
| 5 | **当前状态而非变更史** | "Document current state, not change history." |
| 6 | **机器强制优于人类自觉** | Gates 体系本身（约 50 个 `verify-*` 在 CI 里拒绝违规） |
| 7 | **资源点名**：owner / 原子分配 / 就绪信号 / 清理登记 / 静默完成 | "Use the resource owner's allocator instead of checking availability and claiming it later." |
| 8 | **反模式显式化** | 明文列出"不得作为根因修复"的手段（见 §2.4） |

### 1.1 三条共享次序（三个 skill 的公共骨架）

「先证据后判断」展开成三条次序：

1. **范围报告先于阅读代码**——先跑 `change-scope`，再读 diff。
2. **call-site 先于结论**——没有生产调用方证据，就不算「可删」。
3. **最窄证据先于全量**——回归时会失败的那个测试，胜过整套跑一遍。

### 1.2 一条容易被忽略的纪律

把「必须改」与「可以不改」显式分栏，并把已被绿灯门禁覆盖的问题排除在讨论之外——重复检查不产生信息，只产生虚假确定性。

## 二、五组 skill 的方法论

### 2.1 写作：`dsh-prose-standard` + `dsh-trim-cot-leakage`

**两者关系**：前者管"写够、写在哪"，后者管"删什么"；单独用 trim 会过度删减。

**契约判据**：只写 caller **cannot infer** 的内容（义务、不变式、前后置、兼容承诺）。
**完整命题五要素**：actor and action ／ condition–timing–ordering ／ modality（must·may·never）／ negative guarantee and exception ／ ownership–side effect–failure mode–consequence。
**修剪前提**："Remove adjectives, repetition, and narration only **when every factual clause survives**"。
**六类动作**：keep / add / trim / restore / restructure / defer；"do not manufacture edits to satisfy a deletion target"。
**两条反直觉规则**：
- "A smaller word count alone is not an improvement."
- "Keep non-obvious rationale when omitting it could plausibly cause misuse or an incorrect simplification."

**CoT 泄漏的定义**："Chain-of-thought leakage is prose whose vantage is the authoring session rather than the repository"。
**单测判定**（可直接当工具用）：
> "could a reader at HEAD, with no access to any session transcript, PR thread, or uncommitted draft, resolve every reference and verify every claim?"

**修复方式不是单纯删除**："The fix is never deletion alone when a passage carries factual clauses — restate each so it stands at HEAD, then delete the transcript around it"。
**八类泄漏**：死设计会引用（`(decision 7)`、`design §4.7`、阶段标签）／stack/PR 视角／变更叙事与版本戳（used to, no longer, this cut, today）／review choreography／为评审辩解／复述与推导记录／hedges／作者语言滑落。
**keep 白名单**（不得误删）：issue 引用、`TODO(name)`、suppression 理由、**measured 界**（"the provenance word 'measured' is load-bearing"）、runtime old/new、外部标准 §、note 的 Alternatives-considered。
**边界**：`§`-ban 覆盖**未提交草稿**的编号，不覆盖已提交且自有编号的文档。

### 2.2 审查与简化：`dsh-code-review` + `dsh-find-simplifications`

**共同元原则**："This skill is guidance, not a complete checklist."（导向，不是清单）

**审查顺序**：核对 checkout/分支 → 验证 live base/head → 跑范围报告 → **再读 diff** → 按 SSoT 清单逐项过（AGENTS.md / defensive-patterns / testing / Agent Notes / i18n）。
**分级**：7 条 Blocking requirements + 一长串 Manual checks；"Separate blockers from suggestions and omit issues already enforced by a green gate."
**审查质量主张**："Prioritize correctness, lifecycle, security, and broken required behavior over style; **a short review with one substantiated blocker is better than a list of nits.**"
**两条边界**："Automated checks do not establish those properties."；"Coverage is necessary but not evidence that the scenario is correct."
**对既定决策**："Treat disagreement with an Agent Note as a design discussion, not an automatic veto."
**收到 review 时**："verify each claim and fix or rebut it on technical grounds without performative agreement."

**简化的判据**："A strong simplification removes, folds, or demotes something real and has clear evidence that the current design costs more than it buys."
**强候选**（非显而易见）：无生产消费者的公共 API/事件/配置项/包；只有测试或文档是消费者且其行为非承重；**同一事实的两份表示**（尤其是持久 session 事件与瞬态 `agent/*` 事件之间）；seam 有所有实现都必须支持却无人用的方法；独立 package 只服务测试；推测性通用性；只为保护无人调用 API 的不变量。
**反模式**："Thin candidates are not enough for an Agent Note: deleting one typo, running `knip` once, removing an intentionally documented backend/adapter, or flagging "this looks complex" without call-site proof."
**四条拒绝理由**：有生产调用方／被已实施 Note 或防御模式证成／只造成无关 churn／想法对但太小。
**替换净值**："A wrapper that relocates the same complexity is not a win."

### 2.3 提交：`dsh-pre-push-checks`

**选择律**："Every behavior change needs the narrowest available test or purpose-built check that would fail for its regression; add broader checks only for surfaces the diff actually reaches."
**为什么本地不跑全量**：hooks 故意窄，"CI owns exhaustive coverage and the platform matrix"。
**变更类型 → 证据映射**（节选）：

| 变更类型 | 应跑证据 |
|---|---|
| 包/脚本行为 | 拥有该行为的 Vitest 文件或 focused test name |
| Remote mock 类型 | `pnpm run typecheck`（unbuilt `any` 只是 "explicit local fallback, not strict evidence"） |
| 文档/Agent Note/catalog | `pnpm run doc-sync` |
| 模型/CLI/终端可见输出 | 拥有该输出的 focused keyless snapshot |
| manifest/公开导出/构建配置 | `pnpm run build` + hygiene + 构建产物 smoke |
| 真实 provider | 相关 e2e（有凭据时）；"never print secrets" |

**严禁**：重复已通过的检查（"do not run typecheck immediately before pushing solely to duplicate the pre-push hook"）；用 `--passWithNoTests`、降阈值、缩 include 掩盖未覆盖；"Raw `--force` is never allowed."（rewrite 用 `--force-with-lease=<branch>:<observed-oid>`）；"Do not push and hope CI differs."
**全量本地排练**仅三种情形：用户明确要求／诊断 CI 失败／变更广到没有更窄集合可信。

### 2.4 性能与可靠性：`dsh-speed-up-perf` + `dsh-ci-test-reliability`

**性能七步**：定范围（含**停止规则**）→ 核对确切当前 base → survey 用户路径并排序 → 先建真实合成基准 → **填 measurement card 才动手** → 先证回归 → 一次一个因果因子 + negative control。
**measurement card 七字段**：User operation（确切动作 + 外部可观测完成条件）／Workload（固定维度、分布、种子、为何覆盖常规与尾部）／Entry path／Clock（含与不含的耗费、冷热状态）／Memory（基线、GC 策略、保留 vs 瞬时）／Verdict（原始样本、聚合、标定限额、**negative control**）／Behavior（归属测试与允许差异）。
**完成判据**："the tightened assertion fails on the original implementation or a controlled reintroduction of the targeted cost."
**不算证据**：可疑循环/未用缓存/大文件；历史迭代器或 Client fold 快；"Node folds, fake DOMs, and custom heartbeat events alone cannot establish browser responsiveness."；未区分 merged/closed/superseded/estimated/newly-measured 的历史数字。
**另一条底层原则**："Faster execution with unbounded retention is not an automatic win."
**隐私红线**：不得把 prompt、输出、路径、身份、ID、凭据、录制片段写进 fixture / 日志 / 截图 / PR；基准不得依赖 home、本地仓库、网络服务或私有数据。

**CI 可靠性**：先建模拓扑（同文件／跨文件 worker／同 job 独立进程／共享宿主的多个 job），每个已获取资源点名五件东西。
**关键防护**：回环 `listen(0)` 后等 listening 再读地址（"Never scan for a free port and bind it later."）；`mkdtemp` per-test 私有根；进程全局态（env/cwd/fake timers/locale/module mocks/globalThis/global fetch）视为独占可变资源，改则 capture → 恢复 → 登记 → try/finally → afterEach 兜底。
**同步纪律**："A fixed sleep is not evidence that setup completed or cleanup settled."；"Use a timeout only to bound a wait, never as the condition that makes the assertion correct."
**可靠 ≠ 多跑几次都过**："repeated execution alone is not a race test"（要用 barrier 证重叠）；"Stress runs supplement a deterministic regression; they do not replace one."
**反模式清单**（八条禁令）："increasing a timeout without identifying the awaited state; adding retries; making all files serial; swallowing an error or unhandled rejection; weakening an assertion; normalizing away unstable behavior; adding a sleep before cleanup or assertion."
**报告纪律**："do not describe retries, skipped tests, or pending CI as passing."

### 2.5 决策记录：Agent Notes（详见调查文档 §2）

三条最值得立刻用：
1. **目录即状态机**：`{proposed,implemented,rejected,archived}/{class}/yyyy-mm-dd-title.md`，日期取主题首提日。
2. **事实就地改，决策不可改**："Rewrite stale facts in place" + "never edited into a *different decision*"。
3. **归档即冻结**：归档后不可编辑、翻译、移动，也不再是当前行为的权威。

## 三、可迁移清单

### A. 个人工作方式（12 条）

1. **砍掉强调通胀**：加粗只留给"改变行为的那一句"——我当前回复的加粗密度属于官方 slop 清单明列的反模式。
2. **不写变更叙事**：文档里禁"此前/现在/不再/已修订"，历史归 commit。
3. **不写 review choreography**：不写"我上次错了/你纠正得对"，直接陈述当前结论。
4. **注释只在 caller 推不出时写**；写就写不变式、顺序、失败模式、负向保证。
5. **性能动代码前先写停止规则 + measurement card**；一次只改一个因果因子；无 negative control 不算修好。
6. **偶发 bug 先问宿主拓扑**（固定端口、可预测路径、时钟、全局态、子进程句柄），再谈业务代码；复现用 barrier 不用 sleep。
7. **提交前按"回归时会失败的最窄测试"选证据**，不习惯性全量；不重复已通过的检查。
8. **向 AI 提需求时给约束模板**：measurement card 七字段 / "先出范围报告再读 diff" / "只保留契约删掉推导"。
9. **让 AI 审查时要求"少而实"**：blocker 与 suggestion 分栏、每条给 defect/location/impact/evidence、跳过已被绿灯覆盖者。
10. **收到 review 逐条验证**，fix or rebut on technical grounds，不做表演式同意。
11. **决策用四段模板**：Problem → Decision（现在时）→ **Alternatives considered（必填）** → Consequences。
12. **不重复讨论已决事项**：决策变更用新记录取代旧记录并双向交叉链接。

| # | 项 | 说明 | 成本 |

| 1 | **Agent Notes 状态机** | `docs/决策/` 加 `proposed/implemented/archived` 流转 + `rejected/` 目录；三行头 + `## Problem` 开头 + 强制 `## Alternatives considered` | 低 |
| 2 | **`check-rules` gate**（待办 #5） | 参考官方一脚本一职责 + 配套自测 + 统一排编器；先把既有手册规则机械化（双处声明、BOM、vendor MD5、旧名残留） | 中 |
| 3 | **CoT 泄漏探针** | 把八类泄漏做成 rg 探针批，挂 commit-msg 或 CI；**探针必须带正负例校准 + keep 白名单**，否则误报摧毁规则可信度 | 低 |
| 4 | **插件模板增两份卡** | `perf-card.md`（measurement card 七字段）+ `test-isolation.md`（资源点名五栏）；新插件入库连带隔离声明（呼应铁律 6） | 低 |
| 5 | **"消费者证据"门禁** | 新增导出/配置项/事件须能列出生产调用方，否则拒收或降级为带稳定标签的 TODO | 中 |

| 7 | **提交纪律落地** | `--force-with-lease` 强制、raw `--force` 禁；报告不把 retry/skip/pending CI 说成通过 | 低 |
| 8 | **文档字数预算** | 给手册/README 设 ceiling；超限按 relocate → condense → raise，且 raise 需说明理由 | 低 |

## 四、立即应用（本周可做）

1. **我自己**：从下一条回复起，加粗密度降到"只标改变行为的那句"；文档不写"此前/修订/我上次错了"。（§3.A.1–3）
2. **SSiD 决策目录**：建 `proposed/implemented/archived/rejected` 四目录，把现有 `docs/决策/` 按状态归档一批，并给新决策套四段模板。（§3.B.1）
3. **一条探针先跑起来**：从八类泄漏里挑最容易命中的两类（变更叙事 + 死设计会引用）写 rg 探针，带正负例校准，先手动跑。（§3.B.3）
4. **提需求模板化**：下次让我做性能或排查类任务时，直接用 measurement card 七字段当约束。（§3.A.8）
5. **提交前自检**：按"回归时会失败的最窄测试"选检查项，不跑全量。（§3.A.7）
