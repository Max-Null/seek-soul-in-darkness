## 2. 卡点：@deepseek-ai/dsh@0.1.2-alpha.1 未发布 npm

`pnpm view @deepseek-ai/dsh versions`：最新为 **0.1.1-rc.2**（0.1.2-alpha.1 是 master 源码版本，尚未发布）。SSiD 归档（`shell/scripts/prepare-runtime.mjs` 第 121 行）**从 npm 精确 pin 安装内核**，npm 没有该版本就装不上。两条路径：

### 路径 A（推荐先做）：dev 源码模式——不等 npm 发布

SSiD 壳的运行时选择（`shell/kernel.ts` 三级回退：DSH_CHECKOUT → 相邻源码 → 内置闭包）中，**未打包 dev 模式**下删除部署锚点即可回退到相邻源码：
- 部署锚点：`~/.dsh/profiles/ssid/node_modules/@deepseek-ai/dsh/package.json`（存在 → 优先用闭包）
- 操作：让内核走并列源码 = **把 `H:\MaxNull\WorkStation\deepseek-harness` 作为相邻 checkout**（它就在 SSiD 仓库旁的 WorkStation 下，且已是 master 源码）；若仍被闭包拦截，临时改名为 `node_modules/@deepseek-ai/dsh` 移到备份或设置 `DSH_CHECKOUT=H:/MaxNull/WorkStation/deepseek-harness`（注意 pitfalls #5：User 级环境变量残留会劫持，用完删除）。
- **重启 SSiD 壳后即跑 master 内核**（源码模式），然后 §3 升插件。

### 路径 B（正式发版形态，需官方发布或本地发布 alpha）

## 5. 风险与回滚

- **壳-内核兼容性（最高风险）**：SSiD 壳（Electron main.mjs/titlebar 等）此前只与 rc.2 内核验证过。master 内核改动较大（plugin-center 通道、client 模块表等）。build 失败/功能异常先记录，`main.mjs` 兼容点（插件中心 IPC、mcp 桥、BrowserView、`ssid:title` 事件）逐一排查——**这正是路径 A 先做的意义：在开发模式下低成本暴露壳兼容问题**。
- **回滚**：恢复 `package.json.pre-master-*` → `pnpm install` → 恢复 `.runtime-version`（删掉会强制下次重部署）→ 重启 SSiD 即回 rc.2 闭包；源码模式的 DSH_CHECKOUT 用完删除（pitfalls #5 幽灵依赖）。
- **BOM 陷阱**：改 profile JSON 一律用 node（`writeFileSync(p, JSON.stringify(obj, null, 2) + '\n', 'utf8')`）；PowerShell 5.1 `Set-Content -Encoding UTF8` 会写 BOM，DSH `readProfileManifest` 直接崩（2026-08-29 实测）。
- **版本声明**：保持精确 pin（无 ^），与 web 端声明形态一致。
