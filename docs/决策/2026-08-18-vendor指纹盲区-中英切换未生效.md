# vendor 更新盲区：指纹不覆盖 vendor 目录 → 老 profile 永远拿不到插件更新

日期：2026-08-18
状态：进行中

## 用户实测问题

「关于 SSiD 还是不支持中英双语」——dsh-ssid-panels 0.1.1（中英切换）已在
vendor（a81b88f，01:45），但用户 profile 里仍是 0.1.0。

## 根因链（时间戳定案）

1. 归档 `dsh-runtime.tar.gz` 生成于 **01:13:51**，早于 vendor 0.1.1 同步
   （01:45）——归档内 vendor 是 0.1.0 旧产物（tar 精确计数确认无 i18n）。
2. 上一轮 tar 检查的输出错位（PowerShell 两段输出交叠），误判归档含 i18n，
   导致未重跑 prepare-runtime。
3. **更深缺陷**：`.runtime-version` 指纹 = md5(package.json dependencies +
   pnpm-lock)——**vendor/ 目录内容不在指纹内**。即使重跑归档，指纹不变
   （6ef8f070），老 profile 判定「版本一致」跳过重部署 → vendor 更新永远
   到不了用户。

## 修复

1. **指纹覆盖 vendor**：prepare-runtime 的指纹追加 vendor 目录清单
   （相对路径+文件大小 的 md5）——vendor 任何变化都会触发重部署。
2. 重跑 prepare-runtime（vendor 0.1.1 进归档）→ 归档 boot 冒烟 → pack。

## 决策备查

- 指纹原则升级：**归档内一切「随包分发的内容」都必须参与指纹**——
  profile 文件 + node_modules（lock 已覆盖）+ vendor（本次补上）。
- 时间戳对照是唯一可靠的事实源，管道输出错位会骗人——重要验证用
  落盘计数（精确串匹配计数）而非肉眼扫输出。
