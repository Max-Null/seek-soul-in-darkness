# SSiD 预设技能包 —— 落地方案

> 日期：2026-08-19
> 状态：已定案（本期实施）
> 关联：[SSiD-插件清单](../设计/SSiD-插件清单.md) #7「14 技能包 ssid-skills（M3）」

---

## 一、需求

思灵（SSiD）安装后**开箱即用**：出厂自带 14 个技能（8 mxy + 6 omo），
无需用户手动安装。现状是仓库根 `skills/` 有技能源码，但安装包
（profile-template → dsh-runtime.tar.gz）**不含任何技能**——新用户装完
思灵，`~/.dsh/skills` 为空，一个技能都没有。MCP 预设本期不做（另议）。

## 二、机制调研（DSH 侧）

1. **技能发现**（`dsh-skill-filesystem`，standard / ssid-double-star preset
   里的 `skill-filesystem` 行，`includeDefaultRoots` 默认 true）按 rank 扫描：
   - 项目根（最近含 `.git` 的祖先）：`.dsh/skills`（100）、`.agents/skills`（200）
   - `$DSH_HOME/skills`（400，user-dsh，跳过 `.system`）、`~/.agents/skills`（500）
   - `$DSH_BUNDLED_SKILL_DIR`（bundled 只读层，trustedHost）
   - 技能格式：目录包 `<name>/SKILL.md` 或扁平 `<name>.md`，需 YAML frontmatter
     （name kebab-case + description）。
2. **skill-mcp-center UI**（`@max-null/dsh-skill-mcp-center`，已预制）扫描
   `~/.dsh/skills`、`~/.agents/skills`、会话 cwd 的 `.dsh/skills`/`.agents/skills`
   ——**bundled 层不可见、不可 toggle**。出厂技能要能在设置里管理，必须落在
   用户/工作区层。
3. **SSiD 部署链路**：`shell/profile-template/`（package.json + cordis.patch.yml
   + vendor/）→ `prepare-runtime.mjs` → `dsh-runtime.tar.gz` → 用户首启
   `main.mjs deployRuntime` 解压到 `~/.dsh/profiles/ssid/`（归档顶层 = profile
   根内容）→ `kernel.ts bootKernel` boot（DSH_HOME = `~/.dsh`）。

## 三、方案决策

**出厂技能 = 归档携带（profileDir/skills）+ 启动时非覆盖合并到用户层（`~/.dsh/skills`）。**

对比过的替代方案与否决理由：

| 方案 | 结论 | 理由 |
|---|---|---|
| 只挂 bundled 层（`DSH_BUNDLED_SKILL_DIR` 指向 profileDir/skills） | ❌ | skill-mcp-center UI 扫不到 bundled 层：出厂技能在设置里不可见、不可关；且引入新的环境变量依赖 |
| bundled + 用户层双挂 | ❌ | 同名技能两个来源，bundled rank 优先会 shadow 用户层修改（toggle 无效） |
| **用户层非覆盖复制（本期方案）** | ✅ | ①skill-mcp-center 完全可见可管理；②fractal 传统一致（「首次启动初始化，合并非覆盖」）；③用户增删改永远优先，升级补新技能不覆盖用户修改；④不改 DSH 任何机制 |

同步策略（幂等，每次启动执行）：

- 源：`<profileDir>/skills/`（随归档部署，只读出厂副本）
- 目标：`$DSH_HOME/skills/`
- 规则：遍历源下**目录条目**（技能包）；目标不存在同名条目 → 复制；存在 → 跳过。
  根级 `.md`（如 README）不复制（会被扁平技能解析器误扫）。`skipped` 目录跳过。
- 失败不阻塞 boot（try/catch + 日志）。

## 四、实施清单

| # | 改动 | 文件 |
|---|---|---|
| 1 | 14 个技能目录副本（仓库根 `skills/` 整目录复制，**不含** README.md） | `shell/profile-template/skills/`（新增） |
| 2 | 同步函数 `syncPresetSkills(sourceDir, targetDir)` + bootKernel 调用 | `shell/kernel.ts` |
| 3 | pnpm 兜底安装分支复制 skills 到 profileDir | `shell/main.mjs` |
| 4 | 归档指纹纳入 `skills/`（技能内容变化触发重部署） | `shell/scripts/prepare-runtime.mjs` |
| 5 | 注明部署副本同步关系（改技能后需同步到 profile-template/skills） | `skills/README.md` |

## 五、验证

1. `npm run typecheck`（shell）—— kernel.ts 改动编译通过
2. 同步逻辑模拟：源 = 仓库根 `skills/`、目标 = 临时目录，跑两遍（第二遍全跳过 =
   幂等）；预置同名文件验证「存在即跳过」；验证根级 .md 不被复制
3. 目录一致性：profile-template/skills 与仓库根 skills 技能条目一一对应
4. 归档指纹：prepare-runtime.mjs 改动仅影响构建产物，typecheck 覆盖不到，
   靠代码审查 + 下次构建验证

## 六、边界与后续

- 本期**不做** MCP 预设（双星 persona 引用的 GitHub MCP / Playwright MCP 另立
  方案，涉及 token 与内置 node 执行路径，需单独设计）
- 出厂技能若被用户删除，升级**不**补回（非覆盖语义，符合「用户资产」定位）
- 技能内容更新：改仓库根 `skills/` → 同步到 `profile-template/skills/` → 重建
  归档（指纹变化自动触发用户升级部署）
