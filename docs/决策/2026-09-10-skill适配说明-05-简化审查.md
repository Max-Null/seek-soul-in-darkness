## 一、为什么做这一个（以及一个必须说清的定位）

### 1.1 它是「把宽泛请求变成有证据的提案」的 skill

上游开场就定死了用途：*把这句"找找能简化的地方"变成一个**有证据支撑的 Agent Note***。所以它的真正难点**不是"怎么删代码"，而是"怎么证明该删"**：

- §2 给 **9 条** strong-candidate 判据（无生产消费者 / 只有测试和文档在用 / 两份表示镜像同一事实 / 无消费者的 seam 方法 / 只为测试存在的包 / 猜测性产品通用能力 / 只为保护未用 API 而存在的不变量与回滚路径 / 手搓了依赖已有的东西 / 简化后行为略变但更好解释）
- §7 给 **"证明或否证"** 的完整流程（先分类消费者：生产语料 / 非生产语料 / 模糊语料；再用 `rg` 找，再读调用点）
- §7 还有 **4 条拒绝条件**（生产调用方存在则这是特性决策不是清理 / 已被实现的 Agent Note 或来之不易的防御模式论证过 / 会引发无关改动却没真减少公开 API / 想法对但太小 → 加内联 TODO）

**这套"先证明再动手"的纪律，正是 SSiD 最缺的**。

### 1.2 定位：这是**引入新实践**，不是改进已有实践

实测（§2.1）：**SSiD 目前没有任何简化类决策记录，也没有任何内联 TODO 标记**。所以：

- 本 skill 的判据**来源清楚**（上游 157 行，已经过 DSH 真实历史检验）——满足三层验证规则里"未改动判据继承上游检验"
- 但它的**落地场景在 SSiD 是空的**。落地后会**开始产生** `docs/决策/` 里的简化类记录
- **因此它不能声称"改进现有流程"**。它的价值是**给 SSiD 补一套"如何证伪一个简化提案"的方法**

### 3. `## What Counts As A Strong Candidate`（9 条）→ **保留 9 条判据，删 1 个二级小节**

**9 条判据全部保留**（它们与仓库结构无关，是"什么样的东西算值得删"的定义），包括：

**需要本地化的两处**：

**二级小节 `### Audit invariant companions` → 删除**。SSiD 无 `./invariant` 机制（04 §2.1 已核）。**但它有一句通用的该救**：*"只比较**能独立分叉**的观测才算有用"* —— **并入第 3 条**（两份表示镜像同一事实），因为那是同一个判断。

**5 个域全部换成本地域**（上游是 agent loop / ACP / LLM-tools / Bash / packages）：

| # | SSiD 的域 |
|---:|---|
| 1 | **壳与内核边界**：`main.mjs` / `kernel.bundle.mjs` / profile 装载 / splash 与部署流程 |
| 2 | **插件面**：13 个插件的注册点（storage backend / webServer / tools / slots / sessionProjections）、`cordis.patch.yml`、`dsh.client` 导出面 |

### 5. `## Simplify Prose With The Code` → **保留**

**逐字保留**：注释与文档**是按面积维护的一部分**；删掉复述代码或解释别处已拥有的行为的注释；**保留必需的局部契约**；文档留在其属主层级，略去实现细节与罕见情形，除非它们改变被维护的契约。

指向改为 **03**（`ssid-prose-standard`）。

### 6. `## Audit Trust And Lifecycle Boundaries` → **保留**

**逐字保留**判断框架：对每个防御性拷贝、冻结、验证器与回调捕获，**点名值从哪来、下一个所有者是谁**；同进程的类型化 service/plugin 调用**通常借用只读值**；解析器、配置装载、队列、模型/工具 JSON、持久文件、worker、进程与 wire 解码器**拥有或验证**它们的数据。

**保留那句反直觉的**：*"围绕敌意 getter、伪造的类型化对象、回调替换、或同进程交接后突变构造的测试，是**可能存在投机契约的证据**，而不是保留它的自动理由。"*

**要改的**：上游的判据链指向 DSH 的 `defensive-patterns.md` → 改为 **01**（测试可靠性覆盖生命周期/拆除）＋ SSiD 的实际边界（Electron 主进程 ↔ 渲染进程、`kernel` ↔ 插件、MCP 传输、`webServer` 路由）。

### 7. `## Hand-Rolled Code Versus A Dependency` → **保留，政策出处换指向**

**逐字保留 4 条证明要求**：

1. 读手搓实现，**点名该包覆盖的确切表面**；包里没覆盖的残余语义**算作反对交换的依据**并留在提案里
2. **诚实检查该包的健康度**（维护、采用、传递依赖足迹）；引擎底线已有内置时优先内置
3. **先查决策记录**：已被记录结论钉住的接缝，交换它必须**胜过那份记录的理由**，而不只是引用政策
4. **算净删除量**：实现 + 专用测试 + 文档，**减去残留的胶水**；**只是把同样的复杂度搬个家的包装不算赢**

**政策出处**：上游引 `2026-07-26-dependencies-over-hand-rolling.md`（DSH 的 Agent Note）。SSiD 无对应记录 → 改指向工作区 `AGENTS.md`，并**注明"SSiD 尚无成文的依赖政策，本 skill 落地时应同步补一条"**。

**保留**：先分类消费者再动笔；先 `rg` 再读调用点；**4 条拒绝条件全部保留**（其中"想法对但太小 → 加内联 TODO"依赖 §10，见下）。

**语料三类改为 SSiD 的**：

| 上游 | SSiD |
|---|---|
| 生产语料：`packages/*/src`、`examples/*/src`、`examples/**/*.yml`、运行时脚本、loader/config 路径 | **`max-null-plugins/*/src`、`seek-soul-in-darkness/plugins/*/src`、`shell/main.mjs`、`shell/kernel.ts`、`shell/scripts/`、`shell/profile-template/`** |
| 非生产语料：tests、README/docs、Agent Notes、snapshots、生成的期望输出、注释 | **`test/` 与 `tests/`（两者都要匹配）、`lib/`（派生）、README、`docs/`、Playwright `baselines/`** |

**搜索工具**：上游用 `rg` → SSiD 同样用 ripgrep ✓（本机可用，本体已多次使用）。

### 9. `## Coalesce Superseded Agent Notes` → **大幅删改（5 步 → 1 步）**

上游 5 步（识别当前 owner → 判断完全/部分取代 → 移交独有理由 → 修入链并三件套同删 → 搜残留）**依赖一整套 SSiD 没有的制度**：状态机、`archived/` 冻结、中英对照三件套、入链门禁。

**SSiD 的对应物只有一个动作**：

> **当一条新决策记录取代了某条旧记录时，在旧记录顶部加一行"已被 `<新文件名>` 取代"，并在新记录里链接旧记录。** 不删除（`docs/决策/` 是历史，且没有归档制度来承载"冻结"语义）。

**保留上游那句边界**（逐字）：**"不要把每次代码简化普查都扩大成全仓库的笔记审计"**。

**明确不做的**：上游的"完全取代 vs 部分取代"细分、理由移交清单、入链修复、三件套同删——**SSiD 没有可移交的落点，也没有三件套**。硬搬会让 agent 去修不存在的链接。

**保留上游的一条判断（有据且通用）**：*"先移除后加回"的功能是典型的完全取代案例*——但只有当该功能确已从生产代码、配置、schema、持久或 wire 格式、迁移与兼容行为中消失时，移除记录才可以独占其历史。

### 10. `## Write The Agent Note` → **改写为「写决策记录」**

上游的落点是 `.agents/notes/<lifecycle>/<class>/yyyy-mm-dd-topic.md` + `Status: proposed` + 7 条建议结构。

**SSiD 落点**：`docs/决策/YYYY-MM-DD-<标题>.md`（无 lifecycle 目录、**无 Status 字段**）。

**7 条建议结构保留 6 条**（把 `Status: proposed` 去掉，其余照搬）：

1. `# <动作导向的标题>`
2. `## 问题`：点名当前 API、引用相关文件、陈述消费者证据；**把生产调用方与测试/文档分开**
3. `## 提案`：确切说明要**移除、折叠、降级还是换位**；相关时含测试、文档、README、JSDoc、快照与生成文件的清理
4. `## 为什么不保留它？` 或 `## 我们放弃了什么`：**让最强的反方论证可被看见**
5. `## 验收标准`：可观察的终态与门禁
6. `## 风险`：公开 API 变更、行为变更、未来产品需求，以及为何这笔权衡仍然合理

**保留上游的收尾约束**：具体到"一个实施者能顺着痕迹走下去"；**避免"简化这个包"这类含糊提案**；与既有记录重叠时，**把有用的细节并入既有记录而不是新建重复**。

### 11. `## Inline TODO Notes` → **保留判据 + 标注现状空白**

**逐字保留**：内联 TODO/FIXME/XXX **只用于小而局部、明显有用但不是持久设计决策**的清理；**用稳定标签点名异味**（如 `TODO(double-default)`、`XXX(unused-default)`）；**说明为什么可以安全重访、什么动作会简化它**；**不要为投机性抱怨或需要记录级决策的行为加 TODO**。

**必须新增的现状说明**（有据）：**SSiD 目前零 TODO 标记**，待办集中在手册的「待办清单」节。所以：

- 若采用内联 TODO，**要先定紧迫度语义**（上游有 `FIXME`/`TODO`/`XXX` by urgency 的文档，SSiD 无）——**这是落地时的一个前置决定，不是可以直接照抄的**
- 否则 §7 的"想法对但太小 → 加内联 TODO"这条拒绝条件的**出口是空的**，会变成"想法对但太小 → 忘掉它"

### 12. `## When Folding Another PR Or Branch` → **降权保留**

上游 5 条依赖 GitHub PR/stack 工作流。SSiD 无 PR（04 §一已定），**但有给上游提 PR 的真实场景**（2 次先例）。

**保留为"次场景"**：向 DSH 或第三方插件提 PR 前，diff 对照 `origin/master` 而非当前分支；移植达标的记录、把重叠材料并入既有记录、**不为凑数移植低置信度提案**、更新 PR 描述让评审者看到真实计数。

**删掉**："关闭重复 PR"（SSiD 不拥有上游仓库的 housekeeping）。

### 13. `## Validation And PR Hygiene` → **改写（门禁换名）**

上游：docs-only 至少跑 `pnpm run doc-sync` + `lint` + `git diff --check`；代码注释或 skill 改动另跑相关验证器。

**SSiD 版**：

| 上游 | SSiD |
|---|---|
| `pnpm run doc-sync` | **无** → 改为"改动文档后重跑受影响的 L1" |
| `pnpm run lint` | **无** |
| `git diff --check` | **命令可用，但没有钩子替你跑它**——本仓库**零自定义 git 钩子**（`core.hooksPath` 未配置、默认 hooks 目录零命中；06 §2.2 实测）。**要跑就手动跑** |
| pre-push hook 只贡献 typecheck | **删**（本仓库无任何钩子） |

> **更正留痕**：本节第一版写的是「`git diff --check` 有 pre-commit 钩子」与「SSiD 有 pre-commit」——**错的**。写本说明时尚未核实钩子状态，是**假设**了 DSH 的形态。06 的实测推翻它：本仓库两个钩子都没有。**这是"未核实就写"的又一例**（与 01 §三.1 的「这些文档都不存在」同类）。

**保留**：PR 摘要四要素（新增/合并/部分取代/删除的记录数、主要普查域、有意排除的内容、跑过的检查）；每个合并组要点名新旧 owner 与完全取代的证据。
