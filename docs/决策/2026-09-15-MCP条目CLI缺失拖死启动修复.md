# MCP 条目 CLI 缺失拖死内核启动（2026-09-15）

> 状态：**已修复**（壳层启停判定联动 + 模板 `disabled` 兜底 + 一键恢复脚本；随下一版出包）
> 关联：手册 §7 坑 #31、`docs/决策/2026-09-09-CodeGraph-MCP-默认索引目录修复.md`、
> `shell/fix-mcp-startup.ps1`（现网应急工具）

## 一、现象

新机器（zip 免安装版、全新用户目录）首次启动失败，splash 报：

```
ssid: plugin tree failed to load: failed to apply loader entry mcp-codegraph
(@deepseek-ai/dsh-mcp-client): invalid config:
  ... but got {"serverName":"codegraph","transport":"stdio","cwd":"D:\\AI center",
  "command":"...\\resources\\node\\node.exe",
  "args":[null,"--exclude","node_modules", ...], ...}
```

注意 `args` 的第一项是 `null`。

## 二、根因

模板 `mcp-codegraph` 的 `args[0]` 取自壳注入的 `SSID_MCP_CG_CLI`，而壳只在 CLI 实体存在时
才注入它；缺失时该表达式求值为 undefined（JS 的未定义值），JSON 里成为 `null` —— 而 `dsh-mcp-client` 的
schema 要求 `string[]`，于是**整棵插件树加载失败，思灵起不来**。

两条判定各管各的，才会组合出「条目启用、CLI 缺失」：

| 位置 | 判据 | CLI 缺失时的行为 |
|---|---|---|
| 注入 `SSID_MCP_CG_CLI` | `existsSync(<profile>/node_modules/@astudioplus/codegraph-mcp/bin/codegraph-mcp.js)` | 只写一行日志，不注入 |
| 决定 `SSID_MCP_CG_ENABLE` | 只判 `cgWorkspace === null` | 索引目录解析成功即 `'1'` → 条目启用 |

`mcp-playwright` 是同一形状（`args[0]` 取自 `SSID_MCP_PW_CLI`），且当时连 `disabled` 兜底都
没有——任一依赖没装齐都会以同样方式拖死启动。手册 §7 坑 #8 记过同一现象，但只当成 smoke
排查线索，未做兜底。

## 三、修复

1. **壳层**：新增纯函数 `resolveCodeGraphEnable(workspace, cliExists)`
   （`shell/lib/codegraph-adapt.mjs`），`main.mjs` 把 CLI 存在性并入启停判定，日志同时打印
   `cli=present|missing` 与 `enabled=`。
2. **模板层**（第二道保险，防壳被绕过或环境变量组合异常）：
   - `mcp-codegraph`：`disabled: !!js 'process.env.SSID_MCP_CG_ENABLE !== "1" || !process.env.SSID_MCP_CG_CLI'`
   - `mcp-playwright`：新增 `disabled: !!js '!process.env.SSID_MCP_PW_CLI'`
3. **回归**：`shell/tests/codegraph-adapt.spec.ts` 覆盖「目录 × CLI」四种组合。
4. **现网应急**：`shell/fix-mcp-startup.ps1`（配 `.cmd` 双击入口）——检查两个 CLI 是否在位，
   缺哪个就停用哪个条目；改动前备份、写回后用思灵自带 node + profile 的 `yaml` 包实解析校验、
   可重复运行。已装 0.3.1 的机器靠它自助恢复启动。

**降级方向的选择**：停用只让那个 MCP 不可用，内核、界面与其他插件照常；相比之下「schema
校验失败 → 整棵插件树加载失败 → 思灵起不来」是不可接受的失败模式。

## 四、CLI 为何会缺失

本案例中该 profile 的运行环境没装齐（`@astudioplus/codegraph-mcp` 不在 `node_modules` 里）。
新机部署能否稳定装上它，取决于归档闭包与部署期的 `pnpm install`；**本修复不改变这一点**，
只保证「缺包 ≠ 起不来」。缺包排查线索：`~/.ssid/ssid.log` 里
`prefab mcp codegraph cli missing` 与 `prefab mcp node=` 两行。

## 五、验证

脚本在本机用「profile 副本 + 缺 CLI」的模拟环境跑过四轮：`-DryRun` 不写盘；真实修复在系统
自带 PowerShell 5.1 下正确停用两个条目（中文输出正常）；复跑幂等（报「已经是停用状态」）；
同构环境（带 `node_modules/yaml`）走通第四步实解析，输出 `✓ YAML 合法：entries=2`。逐行比对
确认改动仅为「插入 1 行 + 替换 1 行」，无内容丢失。

演练期抓到并修掉一个真 bug：从日志提取 node 路径时，惰性正则在 `...\resources\node\node.exe`
上只匹配到目录，脚本会去执行一个目录并 `exit 1`（用户会误以为修复失败）。现改为锚定行尾 +
校验「是文件而非目录」。

## 六、遗留

- 一键脚本是一次性工具：下一版安装包带上本修复后，新用户不再需要它。
- 已装 0.3.1 的老用户需脚本或手工改 `disabled` 才能恢复启动；运行环境装齐后把备份覆盖回来即可。
