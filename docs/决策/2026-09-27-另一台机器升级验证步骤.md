# 另一台机器上的升级验证步骤（0.4.0 → 1.0.0）

**目的**：在一台**已经装了思灵 0.4.0** 的机器上，走一遍真实的升级路径，回答一个我目前只有源码推断、没有实测的问题：

> **装完 1.0.0 之后，`~/.dsh/profiles/ssid/package.json` 里的依赖是 `link:` 形式（插件集换代了），还是仍留着 `file:./vendor/…`（没换代）？**

这个答案直接决定主清单里「升级前把 profile 改名」那一步**是否必要**。

**注意**：这台机器上的思灵 0.4.0 **会被顶掉**（两者 appId 相同，NSIS 按升级处理）。动手前确认上面没有你还需要的东西。

---

## 需要准备

| 材料 | 说明 |
|---|---|
| `ssid-1.0.0-win-x64-unsigned.exe` | **439.2 MB**，SHA256 `B5AD2716C36677CC7BA65B59D7745926B6362626934F07325B501D48FFE601DC`。传到那台机器后先核对哈希 |
| `ssid-shell-setup-0.4.0.exe` | **361.3 MB**，SHA256 `64AFDA898E89AB733E033518EACB708C9A440A86C2521C4D0725E24E7575AE15`。**回滚时要用** —— 那台机器上虽然装着 0.4.0，但安装包本身未必还在 |

核对方便起见，在那台机器上跑：

```powershell
Get-FileHash "$env:USERPROFILE\Downloads\ssid-1.0.0-win-x64-unsigned.exe" -Algorithm SHA256
```

## 第一步：抄升级前基线

把下面整段复制到那台机器的 PowerShell 里跑（**不需要管理员**）。它会把结果写到桌面文件。

```powershell
$out = "$env:USERPROFILE\Desktop\ssid-升级前基线.txt"
"===== 思灵升级前基线 =====" | Out-File $out -Encoding utf8
"时间: $(Get-Date -Format 'yyyy-MM-dd HH:mm:ss')" | Out-File $out -Append -Encoding utf8

"`n--- 已安装版本 ---" | Out-File $out -Append -Encoding utf8
Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\*','HKLM:\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall\*','HKCU:\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\*' -ErrorAction SilentlyContinue |
  Where-Object { $_.DisplayName -match '思灵|SSiD' } |
  Select-Object DisplayName, DisplayVersion, Publisher |
  Format-List | Out-File $out -Append -Encoding utf8

$prof = "$env:USERPROFILE\.dsh\profiles\ssid"
$pj = Join-Path $prof 'package.json'

"`n--- profile 依赖构成 ---" | Out-File $out -Append -Encoding utf8
if (Test-Path $pj) {
  $j = Get-Content $pj -Raw | ConvertFrom-Json
  $d = @($j.dependencies.PSObject.Properties)
  "依赖总数: $($d.Count)" | Out-File $out -Append -Encoding utf8
  $d | Group-Object { if ($_.Value -like 'file:*') { 'file:./vendor/…' } elseif ($_.Value -like 'link:*') { 'link:…' } else { '版本号' } } |
    ForEach-Object { "  $($_.Name): $($_.Count)" | Out-File $out -Append -Encoding utf8 }
  "bundles 数: $(@($j.dsh.profile.bundles).Count)" | Out-File $out -Append -Encoding utf8
} else { "profile/package.json 不存在" | Out-File $out -Append -Encoding utf8 }

"`n--- node_modules ---" | Out-File $out -Append -Encoding utf8
"顶层条目: $(@(Get-ChildItem (Join-Path $prof 'node_modules') -Force -ErrorAction SilentlyContinue).Count)" | Out-File $out -Append -Encoding utf8

"`n--- 关键插件（升级前）---" | Out-File $out -Append -Encoding utf8
$na = Join-Path $prof 'node_modules\@max-null\dsh-node-appearance\package.json'
if (Test-Path $na) {
  $n = Get-Content $na -Raw | ConvertFrom-Json
  "dsh-node-appearance: version=$($n.version)  inject=$($n.dsh.client.inject -join ',')" | Out-File $out -Append -Encoding utf8
} else { "dsh-node-appearance: 未找到" | Out-File $out -Append -Encoding utf8 }

"`n--- 会话文件（升级前）---" | Out-File $out -Append -Encoding utf8
$sess = "$env:USERPROFILE\.dsh\sessions-ssid"
"v3 文件数: $(@(Get-ChildItem $sess -Recurse -File -ErrorAction SilentlyContinue | Where-Object { $_.Name -like '*v3*' }).Count)" | Out-File $out -Append -Encoding utf8
"v4 文件数: $(@(Get-ChildItem $sess -Recurse -File -ErrorAction SilentlyContinue | Where-Object { $_.Name -like '*v4*' }).Count)" | Out-File $out -Append -Encoding utf8

Write-Host "基线已写入: $out" -ForegroundColor Green
Get-Content $out
```

**顺带**（可选但有用）：如果那台机器上有你想保留的对话，记下它的会话 id（`sessions-ssid` 下某个目录名），升级后拿去验能否打开。

## 第二步：升级

1. **完全退出思灵**（托盘图标右键退出，确认任务管理器里没有 `思灵.exe`）
2. **直接双击 `ssid-1.0.0-win-x64-unsigned.exe`** —— **不要改名 profile，不要做任何清理**，就是要走真实的用户升级路径
3. 未签名构建，SmartScreen 会拦一下，选「仍要运行」
4. 装完启动思灵

**观察并记下**：
- 安装过程有没有报错或异常提示
- 启动后**窗口标题**是什么（正常是「思灵」；崩溃时是「应用无法启动或已意外停止」，并会给出一个 crash 日志路径）
- 如果弹了崩溃对话框，**把对话框内容截图或抄下来** —— 那是最有价值的信息

## 怎么判定（把两份文件发回来，我按这个判）

| 升级后 `package.json` 的形态 | 结论 | 对主清单的影响 |
|---|---|---|
| **出现 `link:` 形式**，且 `dsh-node-appearance` 是 **0.6.0** + inject 为 `…ui-plugin-manager` | **插件集换代了** | 「改名 profile」**不必要**，清单可简化 |
| **仍是 `file:./vendor/…`**，`node_modules` 条目数没变 | **没换代** | 「改名」**必要** —— 且要在清单里写明后果 |
| 启动即崩（`pending settingsScope` 或别的） | **没换代且已复发** | 「改名」**必要且紧急** |
| 装了但起不来、或安装器报错 | **安装器本身有问题** | 这是新问题，优先查它 |

**会话那一栏**：v3 文件数应该**不变**，v4 出现新文件 —— 这印证了「迁移产出新世代、原文件保留」。

## 第四步：回滚（如需）

```powershell
# 1) 卸载 1.0.0（控制面板 → 程序和功能 → 思灵 → 卸载）
# 2) 装回 0.4.0
#    Start-Process "$env:USERPROFILE\Downloads\ssid-shell-setup-0.4.0.exe"
# 3) 如果升级后 profile 被改坏了，把备份换回来（若你升级前做过改名备份）
#    Remove-Item "$env:USERPROFILE\.dsh\profiles\ssid" -Recurse -Force
#    Rename-Item "$env:USERPROFILE\.dsh\profiles\ssid.backup-0.4.0" 'ssid'
# 4) 启动，确认能读到升级前的会话
```

**卸载不会碰 profile**：`installer/uninstall.nsh` 首行注释写着 `the Harness home is never touched`，`uninstall-data.h` 也把 Harness home 列入拒绝删除名单。实际删除目标只有 `%APPDATA%\思灵` 与 updater 缓存。

## 本次验证能回答的 / 不能回答的

**能回答**：

- NSIS 安装器在真实机器上能否装、能否覆盖 0.4.0
- 旧 profile 经 `seedSsidProfile` 是否换代（**核心问题**）
- v3 会话是否被保留、v4 是否产生
- 升级后能否正常启动

**不能回答**：

- 自动更新链路（未签名构建 + 没有真实更新源）
- 从更早版本（0.3.x 等）升级的路径
- macOS 侧的任何行为
