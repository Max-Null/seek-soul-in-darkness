# 通知体系扩展：卡点通知（提问/授权）+ 通知设置面板

日期：2026-08-18
状态：进行中

## 需求（用户）

1. 卡点通知：出现提问（ask_user_question）与授权申请（approval）时，窗口
   失焦同样弹 Windows 通知 + 音效。
2. 通知设置面板：分形设置页同款——总开关 + 分场景开关。

## 事件面查证结论

- **授权**：`session/event` 的 `approval/asked`（session.append 审计事件，
  含 id/toolName）——root ctx 监听 ✓ 可靠。
- **提问**：`ctx.userQuestions.ask()` 纯服务调用（无 session 事件）——
  壳层同进程包装服务实例的 ask 方法（boot 后 ctx.get('userQuestions')），
  调用时发通知。包装是唯一可靠路径（UI DOM 轮询脆弱）。
- 会话完成：turn/end completed（已实现，本轮并入统一机制）。

## 设计

1. **配置**：`~/.ssid/notify.json`：`{ enabled, replyDone, question, approval }`；
   文件不存在 = 默认全开。壳层每次通知前同步读（文件小，性能无虞）。
2. **通知统一入口**（main.mjs）：`maybeNotify(scene, title, body)`——
   读配置 → enabled && scene 开关 → win.isFocused() 为假 → Notification
   （silent）+ Asterisk 音效 + safeLog。
3. **三场景**：
   - replyDone：turn/end completed（「会话已完成，用时 mm:ss」）
   - approval：approval/asked（「有新的授权申请」「工具 <name> 请求授权」）
   - question：userQuestions.ask 包装（「需要你的回复」「AI 向你提出了一个问题」）
4. **设置面板**（plugins/dsh-ssid-panels）：
   - host：rpc 端点 notify.get / notify.set（读写 ~/.ssid/notify.json）
   - client：新 tab「通知」——总开关 + 会话完成/提问/授权申请三开关
   - build → vendor 同步 → 归档指纹（vendor 清单）自动触发重部署
5. 双语：面板文案走 panels 既有 i18n（0.1.1 中英切换框架）。
