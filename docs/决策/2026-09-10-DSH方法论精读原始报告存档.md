## 报告 A：文档体系与 Agent Notes 机制

**源文件**：`.agents/skills/dsh-doc/SKILL.md`、`.agents/notes/README.md`、`.agents/notes/AGENTS.md`、`.agents/notes/implemented/AGENTS.md`、`docs/AGENTS.md`、`dsh-doc/references/structure-hierarchy.md`

### A.1 文档分层与职责边界

每层都明写「不收什么」：

| 层 | 职责 | 不收 |
|---|---|---|
| Root `AGENTS.md` | 常驻指令（每条 1–3 行 + 链接 home） | 故事、示例、情景流程、从 home 复述的内容 |
| 子树 `AGENTS.md` | 子树专属指令 | 根文件已有的全仓规则 |
| JSDoc / 代码注释 | 模块与导出的本地完整契约（行为、失败、时序、所有权、模态、异常、后果） | 推理过程、测试走读、评审分析、复述代码 |
| Package README | 每包契约（config、语义、limitations、扩展点、Model Experience / Known Limitations） | JSDoc 复述、生成目录复述、别的包的事 |
| Agent Note | 活跃决策记录（why、放弃了什么、必需验证） | 迁移计划、验收清单、spec-speak（"should…"） |
| 顶层 `docs/` | architecture 有序地图 / subsystems 类型定义 / cookbook 编号验证步骤 / postmortem（唯一可讲事故处）/ user 产品指南 / development 贡献者流程 | — |
| 网站 `website/` | 投影 | "The website is a tested projection, never a second copy"；`.generated/` 永不手改 |

**核心原则（逐字）**：

- "Preserve one owner per fact: source, tests, generated catalogs, package READMEs, guides, Agent Notes, and scratch each keep their own kind of truth."
- "Each fact has one home: the tier whose job it is; elsewhere, link there."
- "Document type does not widen that scope."（参考文档只对自身主题穷尽）

**映射规则（逐字）**：

> "Placement: bugs → postmortems; rationale → Agent Notes; procedures → cookbooks; type definitions → subsystems; package contracts → READMEs; standing orders → root `AGENTS.md` with a rationale link."

**kind 元数据机械映射**：package-group / package-reference / package-library / package-bundle，一 kind 一模板；"Add a new kind only together with a distinct template file, a documented repository position or declared owner, and a focused check that maps documents to it."

**硬约束**：一事实一家；重复规则用特征短语 grep 合并（"keep one home and link the rest"）；生成目录永不手改；搬迁必须原子修好所有入链。

**「受众优先层级」**：该术语仅出现在 dsh-doc 的 frontmatter description（"using audience-first hierarchy"），完整定义条目未读到。可验证支撑三条：① 分页按「一个主要 job + 一个 reader」分类；② 页内顺序固定为 用户可用 → 高级配置 → 开发者细节；③ "Organize cross-package Markdown under audience and learning intent instead of leaving unrelated pages flat at `docs/`."

### A.2 Agent Notes 机制

**触发条件（逐字）**："Every non-trivial change MUST add or update at least one Agent Note in the same PR."

非平凡 = 改变行为、架构、跨文件/跨包契约、流程或工具、测试策略、磁盘/wire/配置格式，或维护者可能重新审视的其他决策。豁免仅限纯机械、无行为/契约/结构/流程/理由变化的局部编辑。更新既有归属 note 即算满足，禁止另建重复。新增 note 必触发一次 supersession 检查（同 PR 归档合格 triplet，部分取代则双向交叉链接）。

**生命周期（目录即状态）**：

| 目录 | 含义 | 备注 |
|---|---|---|
| `proposed/` | 实施前评审的提案，尚未或仅部分构建 | "Never archive a proposed note: reject an obsolete proposal." |
| `implemented/` | 决策已 ship | 随实际发布同步更新——"facts only — paths, names, structure — not the decision itself" |
| `rejected/` | 已考虑后拒绝 | 仅当理由还能防住一个诱人错误时保留，否则中/英 + sidecar 三件套一起删 |
| `archived/` | 冻结历史 | 仅 implemented 可进 |

**归档判据**：shipped 决策已完成且理由不太可能指导未来工作。仍活跃的判据（任一成立即保留）：alternatives、ownership boundary、negative guarantee、durable/wire semantics、security rule、reintroduction condition。且 "word count and age are discovery aids, never archive criteria."、"Do not archive toward a quota."

**为什么归档不可编辑（逐字）**："Once sealed, every archived triplet is permanently frozen. Do not edit, translate, reformat, update, move, or delete it, and do not treat it as authority for current behavior."——归档即宣布它不再对当前行为负责；若仍可编辑就会与 implemented note「随代码同步」的义务冲突，变成第二份会过期的权威。故 gate 跳过 archived 源（含其出链）。归档唯一允许的内容改动：在 `Status: implemented` 正下方插入同一值的 `Archived: YYYY-MM-DD`（两个语言文件）。

**格式要求（全部由 gate 强制）**：

- 路径 `{lifecycle}/{class}/yyyy-mm-dd-topic-title.md`，日期取主题**首次提出日**（按 git 历史）。
- class 为封闭集合：feature / bug-fix / simplification / architecture / process / testing——architecture = 发布的源码结构；process = 源码周边工具与流程；**刻意没有 refactor**。
- 禁建中心化 INDEX.md。
- 头三行固定为 `# Agent Note: <title>`、空行、`Status: <status>`；Status 仅三形式（proposed / implemented / `rejected — <一行原因>`），不带日期与括号，且必须与所在目录一致（gate 交叉校验）。
- 正文必以 `## Problem` 开（能在没有方案的情况下独立成立）。
- proposed 章节：Problem / Proposal / … / Alternatives considered / Acceptance criteria / Risks；implemented：Problem / Decision / … / Alternatives considered / Consequences。gate 拒绝 implemented 中的 `## Proposal`、`## Plan`、`## Migration plan`、`## Acceptance criteria`（spec-speak）。
- `## Alternatives considered` **强制**且必为真替代：每个真替代一段加粗开头，或有争议的写 `### Why not <X>?`。
- 决策与架构约束（逐字）："An Agent Note is never edited into a *different decision*: supersede it with a new one, and keep both notes cross-linked."
- `.zh.md` 逐节镜像英文结构，机器校验的 header token（`# Agent Note: ` 与 Status 行）保持英文原样。

### A.3 可迁移点（原报告）

**个人**：① 固定四段模板（问题 → 决策 → 替代方案（为什么没赢，必填）→ 后果）；② 写前先问「这条属于哪一层」，一事实一家，重复规则 grep 特征短语合并；③ 当前状态进文档、理由进决策记录、事故进复盘、临时想法只进 Dev Note（"Dev Note is the only slop zone."）；④ "the only admissible evidence for an operation claim is having run it"——跑不了就写「未验证 + 验证 owner」；⑤ 决策变更用新记录取代旧记录 + 双向交叉链接。

**≤10 人团队最小可行**：`notes/{proposed,implemented,rejected,archived}/{class}/yyyy-mm-dd-title.md`；class 裁到 4 个（feature / bug-fix / architecture / process）；三条准入规则 = 非机械改动同 PR 必加或更新一条、每条必写 Alternatives considered、新建时做 supersession 扫描；归档即冻结、只作历史链接目标；给 AGENTS.md / README 设字数上限，超限按 relocate → condense → raise。

**未验证项**：①「audience-first hierarchy」精确定义；② `dsh-doc/references/review.md` 与 `dsh-prose-standard` 未读（后者由报告 C 补上）；③ `scripts/verify-archived-agent-notes.ts` 实现细节。

## 报告 B：性能与可靠性

**源文件**：`.agents/skills/dsh-speed-up-perf/SKILL.md`（92 行）、`.agents/skills/dsh-ci-test-reliability/SKILL.md`（131 行）

### B.1 定位（逐字）

- perf："Turn a broad “make it faster” request into reproducible user-path measurements and small, evidence-backed fixes."；"This is guidance, not a quota or a script: survey broadly, follow measured cost, and reject attractive changes that do not improve the workload users actually run."
- ci："Build tests that remain correct under the repository's real CI topology, not only when run alone on a quiet workstation."；"Process isolation does not isolate host ports, predictable filesystem paths, external services, databases, sockets, or inherited child processes."；"Do not serialize an entire suite merely because one fixture lacks isolation."

### B.2 性能七步

1. **定范围**：读 AGENTS/architecture/testing/defensive-patterns，约定五项——可见终点、负载范围、资源约束、可接受行为差异、**停止规则**。后端与浏览器端到端分开："a fast history iterator or Client fold does not prove fast transport, paint, scrolling, or input response"；本机开销须排除 model/网络延迟并声明。
2. **核对确切当前 base**（merged diff / 源头 / 测试 / 已解决线程）；PR 正文可能描述已废弃实现，历史证据 "not authority to reintroduce their implementations"。
3. **Survey 用户路径 → 排序候选**：冷启动与首读 / 多轮与工具重型历史 / 首绘·滚动·翻页·激活隐藏视图 / 流式与重连；区分独立成本驱动力（bytes / events / records / deltas / turns / tools / children / DOM nodes）。每个候选须写明：生产消费者、重复工作、期望复杂度、最小可伪证干预、必须稳定的行为。
4. **先建真实合成基准**：扩展现有 required lane，不另立基建；只能提取**聚合**负载特征。
5. **写 measurement card 后才实现**；Node 测构建后 JS（plain Node），浏览器用构建产物 + 支持的 profile；"Do not add a production export solely for measurement or copy the algorithm into a “benchmark implementation.”"；冷样本用 fresh child + 私有临时 root，warm 显式保留 cache，两侧输入/校验/完成条件一致。
6. **先证回归再删工作**：改前跑未优化负载，存「命令、revision、runtime/platform、fixture 维度、原始值、裁决」；缩小到仍触发真瓶颈，再排可伪证假设。
7. **一次一个因果因子**，重跑聚焦场景 + 端到端父场景，必须 negative control："the tightened assertion fails on the original implementation or a controlled reintroduction of the targeted cost."

**measurement card 七字段（逐字）**：

| 字段 | 要求 |
|---|---|
| User operation | "Exact action and externally observable completion condition" |
| Workload | "Fixed dimensions, distributions, construction seed/constants, and why they exercise ordinary and tail use" |
| Entry path | "Production calls/composition and built artifacts; mocked external boundaries" |
| Clock | "Included setup, cold/warm state, timing start/end, and excluded costs" |
| Memory | "Reachable endpoint objects, baseline, GC policy, retained versus transient limits" |
| Verdict | "Raw samples, chosen aggregate, calibrated absolute/ratio/memory limits, and negative control" |
| Behavior | "Owning functional tests/snapshots and permitted minor differences" |

**不算证据清单（完整）**：怀疑的循环 / 未用缓存 / 大文件（"A suspicious loop, unused cache, or large file alone is not evidence of a bottleneck."）；历史迭代器或 Client fold 快不代表传输、绘制、滚动、输入响应；"Node folds, fake DOMs, and custom heartbeat events alone cannot establish browser responsiveness."；"A parse-and-discard baseline is not comparable with validated retained history."；未区分 merged / closed-unmerged / superseded / estimated / newly-measured 的历史 PR 数字；调阈值——"Do not widen a budget or select a lucky run to hide a regression." 且 "A threshold so generous that the regression passes is not protection; a budget below a verified noise floor is not reliable either."；手工浏览器诊断**无阈值**，浏览器预算须先在真实 CI runner 重复测量才可落为源码常量。另一条底层原则："Faster execution with unbounded retention is not an automatic win."

**隐私红线（逐字）**："Never copy prompts, outputs, paths, identities, IDs, credentials, recordings, or recognizable snippets into fixtures, logs, screenshots, PRs, or artifacts. Generate fixed inputs from reviewed constants; no benchmark depends on the user's home, ambient repository, network service, or private data."

### B.3 CI 可靠性：分类与防护

先建模拓扑（可重叠）四层：同文件测试 / 不同 Vitest 文件或 worker 进程 / 同 job 内独立进程 / 共享一台宿主的不同 Actions job。每个已获取资源须点名：owner、原子分配机制、可观测就绪信号、登记清理、静默完成信号。

| 类别 | 防护 |
|---|---|
| 并发/隔离 | "Use the resource owner's allocator instead of checking availability and claiming it later."；不因单个 fixture 串行整套 |
| 端口/网络 | 回环 `listen(0)`，服务报 listening 后才读地址；"Never scan for a free port and bind it later." |
| 共享路径/资源 | `mkdtemp` per-test 私有根；db/socket/session/输出唯一命名空间；必须不存在时 exclusive creation；录制标识与临时地址分离并在 fixture 内翻译 |
| 进程全局态 | `process.env`、`cwd`、fake timers、locale/timezone、module mocks、registries、console hooks、`globalThis`、global `fetch` 拦截 = 独占可变资源；优先注入依赖；必须改时 capture 原值存在与否 → 恢复原状 → 立即登记 → `try/finally` 最小作用域 → `afterEach` 兜底 → 只拦最窄目标请求 |
| 平台语义 | 回写仅在断言容忍回写失败时安全；NTFS 100ns 滴答不给分数毫秒，依赖回写时取 fresh read；Windows 环境变量名大小写不敏感；Windows 句柄异步释放 → 按实测争用做有界重试；无 POSIX 权限/信号语义 → 显式平台 skip 并注明理由 |
| 超时预算 | `describe`/case timeout 覆盖 runner 的 `--testTimeout`（低于 lane 预算即收窄 CI 已给的）；进程创建型套件取 lane 预算；hook 预算随 test 预算同升 |
| 同步 | "A fixed sleep is not evidence that setup completed or cleanup settled."；等显式就绪事件/握手/状态转移/自有 promise；deferred/barrier 钉住竞态；"Use a timeout only to bound a wait, never as the condition that makes the assertion correct."；不断言调度器顺序 |
| 释放到静默 | 获取后立即登记清理；停止新回调、解绑监听、恢复全局钩子、终止自有工作，并 await 子进程退出/服务关闭/worker 终止；"Calling `abort()`, `close()`, or `kill()` without awaiting the owned completion signal is incomplete teardown." |

**「可靠」的判定（不是「多跑几次都过」）**：① 修复前能观察到普通回归失败，新 guard 临时引入被拒用例能观察到预期失败；② 竞态用 barrier 证重叠——"repeated execution alone is not a race test"；③ 端口/共享路径/子进程类改动须并发跑独立进程验证跨进程隔离；④ fixture 自设 deadline 时先断言无 signal/timeout 结束子进程；⑤ 验证外部状态/事件/文件/日志/退出/释放而非组件自报；⑥ "Stress runs supplement a deterministic regression; they do not replace one."；⑦ 证据按风险配：全局变更→恢复证据，生命周期/子进程→静默 teardown 证据，共享路径→并发独立进程证据，新 guard→negative control。报告 "do not describe retries, skipped tests, or pending CI as passing"。

**反模式（逐字，八条禁令）**："increasing a timeout without identifying the awaited state; adding retries; making all files serial; swallowing an error or unhandled rejection; weakening an assertion; normalizing away unstable behavior; adding a sleep before cleanup or assertion." 例外："Retries remain valid for documented transient external-provider tests under the real-API policy. Keep that exception at the external boundary."；"Restoring a budget is not masking."

**延伸阅读**：`dsh-ci-test-reliability` 引用的 `references/ci-flake-diagnosis.md`（诊断既有 flake 的只读工作流）未读。

## 报告 C：写作规范与推理痕迹

**源文件**：`.agents/skills/dsh-prose-standard/SKILL.md`（含 `references/examples.md`、`references/recall-batteries.md`）、`.agents/skills/dsh-trim-cot-leakage/SKILL.md`

### C.1 定位

- **prose-standard**：决定该写多少、写在哪、按位置必须覆盖哪些契约（不够要补写）——"This is not a one-way shortening pass."
- **trim-cot-leakage**：清掉视角停在「写作会话」而非仓库的推理残留（失效引用／变更叙事／对已离场评审辩解）。
- 两者是配套关系：trim 把 prose-standard 的 complete-proposition 规则作为前置依赖引用；单独用 trim 会过度删减，故后者专列 overcorrection traps。

### C.2 prose-standard 核心原则（逐字）

1. "Write enough to preserve the contract, then remove reasoning transcripts, repetition, and decoration."
2. "A smaller word count alone is not an improvement."
3. "One explanation has one home; essential contract facts may repeat locally."
4. "Keep non-obvious rationale when omitting it could plausibly cause misuse or an incorrect simplification."
5. "Comments describe non-obvious contracts or rationale that code cannot express; they do not restate what code already implies."
6. "Keep a complete local contract at the point of use"
7. "treat wording as behavior"
8. "This is not a one-way shortening pass."

### C.3 prose-standard 规则

**契约判据**：caller／callee／implementer／producer／consumer 依赖的 obligation、invariant、precondition、postcondition、compatibility promise；判据是「caller 推不出才写」。

**完整命题五要素**：actor and action；condition, timing, and ordering；modality（must / may / never）；negative guarantee and exception；ownership, side effect, failure mode, and consequence。修剪前提："Remove adjectives, repetition, and narration only when every factual clause survives"。

**按位置必须覆盖**：Public JSDoc（return distinctions、throws/rejections、side effects、ownership、timing、cancellation、durability）；Internal comments（invariants、race ordering、security boundaries）＋"Delete control-flow narration and code restatement"；其后依次点名 Module comments / Tests / Cookbooks / READMEs / Agent Notes / Postmortems / Skills / Examples / Prompts / Diagnostics 共 11 类（如 Tests 只解释 non-obvious test design，删 walkthroughs；Diagnostics 要点名 failing subject or path、violated rule、correction）。

**六分类动作**：keep, add, trim, restore, restructure, or defer；"do not manufacture edits to satisfy a deletion target"。borderline 定义 = 至少两版都满足完整命题、且本 skill 未化解取舍。

**反例对（`references/examples.md`）**：把 "serializes writes per session, flushes buffered events before disposal resolves, and reports backend failures" 砍成 "serializes persistence"；"normalizes provider errors" 丢光 failure categories；删掉 "Throws if initialization has not completed..." 即丢 caller-visible contract；收尾判据 "A package README is not a backlog dump."

**误报家族（逐条点名）**：instrumental "used to"（the key used to sign requests）、`/v1/` 协议路径、"This PR" 出现在流程文档、本版本 vs 本版、runtime "today"。

### C.4 trim-cot-leakage 规则

**定义（逐字）**："Chain-of-thought leakage is prose whose vantage is the authoring session rather than the repository"。

**单测判定（逐字）**："could a reader at HEAD, with no access to any session transcript, PR thread, or uncommitted draft, resolve every reference and verify every claim?"；"resolvability only clears this skill's bar"（在 README/docs/JSDoc 等 current-state 面仍属变更叙事）。

**修复方式（逐字）**："The fix is never deletion alone when a passage carries factual clauses — restate each so it stands at HEAD, then delete the transcript around it; a passage carrying none (an audit code, control-flow narration) is deleted outright."

**八类泄漏**：① 死设计会引用（`(decision 7)`、`(audit C2)`、`design §4.7`、phase labels 如 T4/W3/P-I）② stack/PR 视角（"a later PR in this stack"）③ 变更叙事与版本戳（"used to"、"no longer"、"this cut"、"today"）④ review choreography（"Rejected in review:"、draft ordinals）⑤ 为评审辩解（"the cast is safe — it simply…"）⑥ 复述与推导记录（"first we X, then we Y"、test walkthroughs）⑦ hedges（"probably fine for now"、"should be enough"）⑧ 作者语言滑落（端／设计稿／`---- 私有 ----` 混进英文 prose）。

**每条给「改成什么」**：固定回归写现在时反事实 "without X, Y happens"；延期挪 TODO/issue；hedge 提升为 TODO/FIXME 或写真实上界。

**keep 白名单（不得误删）**：issue 引用 `#1470`、`TODO(name)`、suppression 理由（oxlint-disable / coverage-ignore / 空 catch）、**measured 界**（"the provenance word 'measured' is load-bearing"）、runtime old/new、外部标准 §、note 的 Alternatives-considered。

**边界（逐字）**："the §-ban covers uncommitted internal drafts, not external standards or committed docs that own their §-numbering."

### C.5 可迁移点（原报告）

## 报告 D：审查、简化与提交

**源文件**：`.agents/skills/dsh-code-review/SKILL.md`、`.agents/skills/dsh-find-simplifications/SKILL.md`、`.agents/skills/dsh-pre-push-checks/SKILL.md`

### D.1 定位（逐字）

- code-review：DSH PR 审查导向器——接到仓库既有标准（AGENTS.md、防御性模式、ADR、质量门），并补上代码本身看不出的检查。
- find-simplifications：把「找简化点」的宽泛请求变成有证据的 Agent Note，真正删除/折叠既有表面积。
- pre-push-checks：推送/标 ready 前，选出覆盖本次 diff 的**最小**检查集，而非反射式跑全量套件。

**共同元原则**：三者都声明自己是导向不是清单——"This skill is guidance, not a complete checklist."（simplifications 版为 "It is guidance, not a checklist"）；pre-push 的等价声明是 "There is no universal local baseline beyond the hooks."

### D.2 code-review

**顺序**：核对 checkout 与分支 → 验证 live base/exact head → 跑 `pnpm --silent run change-scope --base <verified-base-ref>` → **再**读 diff 与足量周边码 → 按 SSoT 清单逐项过（AGENTS.md、packages/AGENTS.md、defensive-patterns.md、testing.md、Agent Notes、i18n）；该报告只给路径与脏层，"does not replace semantic review"；retarget/merge 后重建 base 并重跑范围报告。

**优先级（逐字）**："Prioritize correctness, lifecycle, security, and broken required behavior over style; **a short review with one substantiated blocker is better than a list of nits.**"

**分级**：7 条 Blocking requirements（新增文案必须语义审查；文档与代码同 diff 同步；核心类型与 type-equiv；注册可清理；不变量伴生必须语义化；必需证据存在；客户端 UI 文案归 locale）+ 一长串 Manual checks（接口两侧契约、生命周期与并发、能力与消费者匹配、范围与必要性、配置默认、模型视角、denial 路径、借用 vs 拥有、边界覆盖最终操作、真实入口路径、测试强度与可靠性、不变量负向控制、Agent Note 与已发布现实、transcript、双语文案）。

**分级处置（逐字）**："Separate blockers from suggestions and omit issues already enforced by a green gate." 局部缺陷 inline 贴最紧 diff 范围，跨切面用 PR 级评论；每条给 defect / location / impact / evidence。无合理关系的不变量伴生须整体删除（export、构建入口、专用测试）并在 README 记 package 专属理由："Reject empty installers and invented checks"。

**两条边界（逐字）**："Automated checks do not establish those properties."；"Coverage is necessary but not evidence that the scenario is correct."；对既定决策："Treat disagreement with an Agent Note as a design discussion, not an automatic veto."；收到 review 时 "verify each claim and fix or rebut it on technical grounds without performative agreement."

### D.3 find-simplifications

**判据（逐字）**："A strong simplification removes, folds, or demotes something real and has clear evidence that the current design costs more than it buys"；取舍 "prefer a few well-proven candidates over a pile of thin guesses"；"Do not let the first good candidate stop the survey."；替换净值 "A wrapper that relocates the same complexity is not a win."

**怎么找**：先读 AGENTS.md 的 pre-release stance 与两条 doctrine（tests-are-not-golden-truth、Agent Notes-are-not-golden-truth）与 architecture.md，**先标出有意架构与 protected seam**；用并行 subagent 分域（agent loop/session log、ACP+UI、LLM/tools/prompt、bash/工具执行、packages/scripts/tests），"require evidence, not guesses"，从生产代码最大 delta 起步；证据法为先 `rg` 精确 symbol / event name / config key（`.name(` 与 `name(` 两写）/ wire string，再读 call sites；消费者分 production / non-production / ambiguous 三类。

**非显而易见的强候选**：无生产消费者的公共方法/事件/配置项/注册通知/包/持久事件；"Tests or docs are the only consumers, and the behavior they pin is not load-bearing."；"Two representations mirror the same fact, especially across durable session events and transient `agent/*` events."；seam 有所有实现都必须支持却无人用的方法；独立 package 只服务测试并增加发布开销；推测性产品通用性（multi-session、background job rosters、live registry invalidation、tool-owned UI rendering）；只为保护无人调用 API 的不变量/回滚/期望输出；手写代码重实现了 Node builtin 或维护良好的 npm 包且替换能连实现与专用测试一起删。放宽条款："The simplified behavior may differ slightly, but the new behavior is still reasonable and easier to explain."

**反模式**：① "Thin candidates are not enough for an Agent Note: deleting one typo, running `knip` once, removing an intentionally documented backend/adapter, or flagging "this looks complex" without call-site proof."；② 四条 reject/downgrade——有生产调用方（属功能决策非清理）／被已实施 Agent Note 或来之不易的防御模式证成／只造成无关 churn 而不减公共 API 或必需行为／想法对但太小（改加定向 TODO/FIXME/XXX，"Do not add TODOs for speculative complaints or for behavior that needs an Agent Note-level decision."）；③ "Treat dual LLM adapters as intentional by default."，不把 twin adapter 或 persistence seam 当「低成本」删；④ 依赖替换须 "beat the recorded rationale, not just cite the policy"；⑤ 只有完全不出现在生产码/配置/格式/迁移中的特性才算 full supersession，否则留 partial 并交叉链接。

### D.4 pre-push-checks

**选择律（逐字）**："Every behavior change needs the narrowest available test or purpose-built check that would fail for its regression; add broader checks only for surfaces the diff actually reaches."

**为什么本地不跑全量**：hooks 故意窄（pre-commit 只修 staged lint、查 staged 空白、守 vendor 元数据；pre-push 只跑增量 typecheck），"CI owns exhaustive coverage and the platform matrix."

**怎么决定**：确认 checkout/分支 → 验证 live PR base 或 stack parent（该命令 "never guesses or fetches a base"）→ `change-scope --base <verified-base-ref>` → 按变更类型取最窄证据；merge 新 base 后重跑报告并**只重跑被 merge 失效的检查**。"Test selection and coverage selection are separate."：覆盖率须显式声明被测源范围；`vitest related` 发现不了只经配置、动态加载、子进程、worker、构建产物、外部 provider 到达的行为，须显式点出拥有者测试。

| 变更类型 | 应跑证据 |
|---|---|
| 包/脚本行为 | 拥有该行为的 Vitest 文件或 focused test name；共享契约加相邻包测试；仓库级留给 CI |
| Remote mock 类型 | `pnpm run typecheck`（unbuilt `any` 只是 "explicit local fallback, not strict evidence"） |
| 文档/Agent Note/catalog | `pnpm run doc-sync`，文档工作流要求时 full lint |
| 模型/编辑器/CLI/终端可见输出 | 拥有该输出的 focused keyless snapshot 或真实可运行示例 |
| 期望输出位置 | session 往返 → 顶层 `snapshots/`；其余 → 测试旁 `tests/expected/` |
| Profile/配置位置 | 跨包 → `apps/cli/tests/profiles/`；包内 → 该包 `tests/fixtures/`；用户 overlay → `apps/cli/config/examples/` |
| manifest/公开导出/构建配置/bin 入口 | `pnpm run build` + hygiene + 构建产物 smoke |
| 真实 provider/agent | 相关 `pnpm run test:e2e`（有凭据时）；"never print secrets" |

**全量本地排练**仅三种情形：用户明确要求、诊断 CI 失败、变更广到没有更窄集合可信；且 "Use the current workflow and package scripts as the inventory; do not recreate the removed `check:pre-push` aggregate."

**严禁**：重复已通过的检查（"do not run typecheck immediately before pushing solely to duplicate the pre-push hook"）；用 `--passWithNoTests`、降阈值、缩 include 掩盖未覆盖文件；"Raw `--force` is never allowed."（rewrite 用 `--force-with-lease=<branch>:<observed-oid>`）；push 后指望 CI 不同（"Do not push and hope CI differs."）；把平台失败含糊成环境问题（须记录精确命令、失败测试、平台差异，绕过 hook 仅在用户同意时）；`gh stack sync` 成功即称 stack ready；`gh pr checks` 报 "no checks reported" 就怀疑基础设施——PR 为 CONFLICTING/DIRTY 时 GitHub 不建 pull_request run，"total_count: 0" 即冲突，空提交 / `--allow-empty` / draft 切换 / revert 反弹都无效且污染历史。

### D.5 可迁移点（原报告）

**个人**：① 提交前自检按「回归时会失败的最窄测试」选证据，不习惯性全量；hook 故意窄是设计。② 不重复已通过的检查——重复不产生信息，只产生虚假确定性。③ 让 AI 审查的提示词：先给 base/head，要求**先出范围报告再读 diff**；要求"少而实"；blocker 与 suggestion 分栏、跳过已被绿灯门禁覆盖者；每条给 defect/location/impact/evidence；明说对已实施决策的分歧按设计讨论、不许一刀否决。④ 提简化请求的提示词：先列有意架构与 protected seam，分域并行调查并要求 call-site 证据，明令禁止 thin candidate 与「看起来复杂」。⑤ 收到 review：逐条验证，"fix or rebut it on technical grounds without performative agreement"。⑥ rewrite 纪律：lease 保护；rewrite 后旧 commit hash 与评论锚点不算证据，须重查 heads/线程/检查。

**工具**：① 移植 `change-scope`（显式 base → 变更路径 + 受影响包与脏层，作选检查的唯一入口；绝不猜 base）。② 固化「diff → 检查集」映射为脚本，输出应跑命令清单；全量排练需显式开关，缺省不跑。③ 覆盖率绑定门禁：选中测试必须声明覆盖源范围，禁 `--passWithNoTests` / 降阈值（可接 SSiD 的 L1 typecheck+test 门槛）。④ 「消费者证据」门禁：新增导出/配置项/事件须能列出生产调用方，否则拒收或降级为带稳定标签的 TODO。⑤ 可机械化的文档/文案门禁：对照 `verify-export-jsdoc`、`verify-doc-budgets`、`verify-client-ui-i18n`、`verify-cordis-config`、`doc-sync`。⑥ 不变量与负向控制：新增守卫须证明存在可独立分叉的观测，且每条变更的验收路径证明会拒绝无效输入。⑦ 推送规程：`--force-with-lease` 强制、raw `--force` 禁；「无检查运行」先读 mergeable 再怀疑基础设施。⑧ 决策记录：非平凡变更同 PR 带 Agent Note（proposed→implemented→archived、归档冻结、一事实一归属）。

**三份报告的公共骨架（原报告结语）**：「**先证据后判断**——范围报告先于阅读，call-site 先于结论，最窄证据先于全量；把「必须改」与「可以不改」显式分栏，把「已由绿灯门禁覆盖」排除在讨论之外。」
