## 二、兼容性检查结论

1. **插件 API 协议层 ✅**：rc.1/rc.2 官方 release notes 无插件破坏性变更；品牌槽位
   （`sidebar.brand.mark`/`conversation.hero.brand.mark`）、bundle patch 协议
   （cordis.patch.yml）、client 注入协议（dsh.client.platform/inject/immediately）
   在 0.1.1-rc.2 源码中逐一确认保留。插件框架包 rc.8→rc.2 仅 34 文件/376 行小改。
2. **内置 vendor 插件 ✅**：三插件 cordis.patch.yml 均为 profile 根纯 insert（不碰 DSH 源码）。
3. **插件 peer 版本范围 ⚠️**：全家桶 peer 钉在 `^0.1.0-rc.7`/`^0.1.0-rc.6`/`>=0.0.1-rc.x`，
   真实 node-semver 实测对 `0.1.1-rc.2` **全部不满足**（npm 预发布 tuple 规则：
   候选 prerelease 版本须与范围中某 comparator 的 major.minor.patch 相同）。
   pnpm 默认 strict-peer-dependencies=false → 仅告警不阻断，运行时风险低；
   各插件项目后续把 peer 升到 `^0.1.1-rc.1`。
4. **pnpm 11 发布年龄保护 ❌（阻断级）**：pnpm 11 默认 `minimumReleaseAge: 1440`（1 天），
   官方文档确认。`@deepseek-ai/dsh@0.1.1-rc.2` 及 60+ 个 `^0.1.1-rc.2` 官方闭包族全部
   发布 <24h，且 minimumReleaseAgeExclude 名单只有 @max-null 与社区插件。
   prepare-runtime 每次全新解析（profile-template 无 lockfile）→ 不豁免必装旧版/解析失败。

## 三、决策

1. **`minimumReleaseAge: 0`**（profile-template/pnpm-workspace.yaml）：
   - 理由：官方闭包 60+ 包同族 <24h，逐包维护 exclude 名单不可行（每个 rc 都要重来）；
     归档运行时版本由 pnpm-lock.yaml 固定、构建机可控，供应链风险可接受。
   - 保留既有 minimumReleaseAgeExclude 名单（作信任记录，无害）。
   - 附带收益：@max-null 全家桶新版本发布后 prepare-runtime 不再受年龄保护阻碍，
     记忆「发布三步」中的 a 步（豁免名单）不再必需（缓存清理与归档验证仍保留）。
2. **升级路径**：重跑 prepare-runtime.mjs（DSH_NODE/PNPM_CMD 显式指定）→
   解压归档静态验证 → 隔离冒烟（DSH_HOME=临时目录 + DSH_CHECKOUT=解压目录，
   boot-smoke.ts 验证 HTTP 200）→ 替换安装目录归档 → 用户重启思灵 →
   ensureProfile 自动原子重部署（main.mjs deployRuntime：.deploy.new → rename 原子切换）。
   不手动替换运行中 profile，避免文件占用与破坏运行中进程。
