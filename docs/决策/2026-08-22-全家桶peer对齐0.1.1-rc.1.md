# 全家桶 peer 对齐 DSH 0.1.1-rc.1 —— 决策与实施记录

- **日期**：2026-08-22
- **背景**：SSiD 内置 DSH 升级 0.1.1-rc.2 后，全家桶插件 peer 仍钉在 `^0.1.0-rc.x`/
  `>=0.0.1-rc.x`。npm semver 预发布 tuple 规则下这些范围对 0.1.1-rc.2 全部不满足
  （实测 false），虽 pnpm strict-peer-dependencies=false 下仅告警不阻断，但长期
  是隐患（后续内核再升级、其他用户 pnpm 严格模式会炸）。本次统一对齐。

## 决策

1. **统一范围**：所有 `@deepseek-ai/dsh-*`（排除 `@deepseek-ai/cordis` 与
   `@deepseek-ai/cordis-plugin-*`）的 peerDependencies / devDependencies 范围 →
   `^0.1.1-rc.1`（可匹配 0.1.1-rc.2）。`@deepseek-ai/cordis@^4.0.1`、`cordis-plugin-loader`
   不动；`@deepseek-ai/schemastery`（独立版本线 3.18.1）不动。
2. **版本策略**：peer 契约变化 → minor bump（0.x 语义）：
   chat-rail 0.2.0→0.3.0、chinese-thinking 0.2.0→0.3.0、draft-polish 0.1.0→0.2.0、
   guardian 0.1.0→0.2.0、habit 0.1.0→0.2.0、memory 0.4.1→0.5.0、
   node-appearance 0.2.3→0.3.0、plugin-center 0.1.7→0.2.0、skill-mcp-center 0.3.1→0.4.0
3. **流程**：批量脚本改 package.json（60 处范围）→ 各仓库 install（npm/pnpm 按 lock）→
   typecheck → test → build → commit → tag vX.Y.Z → push（GitHub 与 npm 版本对齐）
   → 给用户 npm publish 指令（2FA 无法代发，用户手动发布）
4. **发布后**：SSiD profile-template/package.json 依赖范围已是 ^（^0.2.0 等），
   prepare-runtime 重建归档自动收新版本（minimumReleaseAge: 0 已豁免）。

### 关键教训（2026-08-22）

1. **pnpm 11.21 自动改写 pnpm-workspace.yaml**：install 时自动追加 50+ 条
   minimumReleaseAgeExclude（@deepseek-ai/dsh-*@0.1.1-rc.1 系列），多个仓库触发，
   已还原/不提交。
2. **0.1.1-rc.2 内核 peer 网络收缩**：dsh-client-ui-primitives / ui-slots 不再被
   任何官方包 peer 引用——src import 它们的插件必须自行显式声明（chat-rail 原已
   声明；node-appearance 本次补齐）。
3. **dsh-better-sidebar（omdsh-dev/huanlin 社区包）peer 未对齐**：其 peer 仍为
   ^0.1.0-rc.x，与本轮 ^0.1.1-rc.1 声明无交集；pnpm 合并产生 `>=0.1.1 <0.2.0-0`
   （排除全部 prerelease）→ ERR_PNPM_NO_MATCHING_VERSION，9 种绕过方案实测无效，
   唯一可行是移除 peer 声明。上游对齐前，chat-rail 不再声明协作关系（README 说明）。
