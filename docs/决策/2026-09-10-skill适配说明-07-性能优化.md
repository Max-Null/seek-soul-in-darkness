## 一、为什么做这一个

### 1.1 它是一份「测量纪律」，不是一份「优化技巧」

上游开场就划清了界线：*把一个宽泛的"让它更快"请求变成**可复现的用户路径测量**与**小的、有证据的修复**……这是指导，不是配额也不是脚本：广泛普查、跟随实测成本、**并拒绝那些看起来诱人但没有改善用户真正运行的工作负载的改动**。*

它最有价值的产出不是那 7 条优化模式，而是**测量卡**（§3 的 7 个字段）：用户操作 / 工作负载 / 入口路径 / 时钟 / 内存 / 裁决 / 行为。**有了这张卡，"更快"才是一个可证伪的命题。**

### 1.2 SSiD 的现状：有性能面，但没有测量基建

SSiD 是 Electron 桌面壳，**有真实性能面**（启动到可用、大会话装载、导航条与面板响应、内核升级带来的影响）。但实测（§2.1）：**没有 benchmarks 目录、没有任何基准或性能脚本、手册里没有性能节**。

所以本 skill 在 SSiD 与 05 同类——**引入新能力**。差别在于：05 缺的是"提案纪律"，07 缺的是**测量基建本身**。上游 §3 那句 *"扩展现有的必需 lane，而不是创建竞争性的校准或报告基建"* 在 SSiD **无法照做**（没有可扩展的 lane），必须改成"**先建最小测量骨架，再谈优化**"。

## 三、逐条适配判断

上游共 **6 个部件**（6 个一级小节，无二级、无编号项）。

### 1. `## Establish scope and current authority` → **改写（引用换指向）**

**逐字保留的三条**：

1. **"同意"清单**：用户可见的端点、工作负载范围、资源约束、可接受的微小行为差异、**停止规则**。**"停止规则"要保留——它是防止性能工作无限蔓延的唯一闸门。**
2. **后端与浏览器端到端测量必须分开**：*"快的历史迭代器或 Client 折叠**不能证明**传输、绘制、滚动或输入响应快。"*
3. **测量本地开销时排除模型/网络延迟，并且要**陈述这个排除**，而不是把结果称为完整的产品延迟。**

**SSiD 本地化**：

- 上游的"后端 / 浏览器"两分 → SSiD 是**四层**：**主进程（`main.mjs`）/ 内核（`kernel.bundle.mjs` + DSH）/ 渲染进程（Web UI）/ 磁盘与归档（profile、`dsh-runtime.tar.gz`）**。跨层推断（"主进程快了所以界面快了"）与上游禁止的"Node 折叠证明浏览器响应"是同一类错误。
- **启动时间要定义终点**：SSiD 的启动有多个可观察点（进程起、splash 出现、splash 消失、首屏可交互、归档部署完成）。**不定终点就没法比较**——上游"用户可见端点"这条在 SSiD 尤其必要。
- 上游那段"检查确切当前 base 而非运行中的 checkout……PR 描述可能描述一个已放弃的实现"→ SSiD 版：**以仓库 HEAD 为准，不以本地 dev 进程为准**（dev 热更新会让本地状态偏离 HEAD）。

### 2. `## Survey user paths, then rank candidates` → **改写（领域清单全换）**

**保留骨架**：广度有帮助时委派独立域；**要求测量与生产调用点，不要猜测**；**独立成本驱动因素要分别变动**（字节、持久事件、紧凑记录、原始增量、回合、工具、子节点、可见 DOM 节点是**不同的量**）；**不要把一个"大量微小相同消息"的负载称为现实负载，除非检查过它压的是哪个用户操作**；包含典型与尾部负载，但**避免没有决策价值的组合矩阵**。

**排序依据逐字保留**：观察到的用户延迟、CPU/分配、保留内存、发生频率、置信度。**每条候选必须点名**：生产消费者、重复工作、预期复杂度、**最小的可证伪干预**、**必须保持稳定的行为**。

**保留那句防幻觉的**：*"可疑的循环、未使用的缓存、或大文件本身**不是**瓶颈的证据。"*

**4 个域全换**：

| # | SSiD 的域 |
|---:|---|
| 1 | **冷启动与热启动**：进程起 → splash → 归档部署（首启/升级）→ 首屏可交互 |
| 2 | **大会话**：多回合历史、工具密集、单条大结果、会话列表与切换、chat-rail 导航条与面板 |
| 3 | **渲染与交互**：首次绘制、滚动、面板展开/折叠、侧栏切换、隐藏视图激活 |
| 4 | **归档与部署**：`prepare-runtime.mjs` 耗时、`dsh-runtime.tar.gz` 解压与校验、vendor 同步（1.5 分钟级操作，用户可感知） |

### 3. `## Build realistic synthetic benchmarks first` → **保留（核心），基建从零**

**这是全篇最该保留的一节**，三个部分逐字保留：

**(a) 隐私纪律（对 SSiD 尤其重要）**

> 若用户授权检查本地语料，**只提取聚合的工作负载特征**。**绝不**把提示词、输出、路径、身份、ID、凭据、录制或可识别片段复制进 fixture、日志、截图、PR 或产物。用经复核的常量生成固定输入；**没有任何基准依赖用户的主目录、环境仓库、网络服务或私有数据。**

SSiD 的用户数据（会话日志、记忆库）**比 DSH 更敏感**，这条要**提权**并加一句："会话日志里含真实对话内容，聚合时**只取计数与长度分布**"。

**(b) 测量卡 7 字段** —— **逐字保留，一字不减**：

| 字段 | 必须给出的决定 |
|---|---|
| 用户操作 | 确切动作与**外部可观察的完成条件** |
| 工作负载 | 固定维度、分布、构造种子/常量，以及**为什么它压到普通与尾部使用** |
| 入口路径 | 生产调用/组合与构建产物；被 mock 的外部边界 |
| 时钟 | 纳入的 setup、冷/热状态、计时起止、**被排除的成本** |
| 内存 | 可达的端点对象、基线、GC 策略、保留 vs 瞬时上限 |
| 裁决 | 原始样本、选定的聚合、校准的绝对值/比例/内存上限、**负向控制** |
| 行为 | 属主功能测试/快照，以及**被允许的微小差异** |

**(c) 测量诚实性** —— 逐字保留：用**全新子进程与私有临时根**做冷启动/进程内存样本；热样本显式保留既定缓存；**绝不让 fixture 的 setup 悄悄预热一个冷场景**；两侧保持相同输入、校验、完成条件与可达输出；**"解析后丢弃的基线不能与经过校验的保留历史相比"**。

**SSiD 必须改写的一处**：上游 *"扩展现有的必需 lane，而不是创建竞争性的校准或报告基建"* → SSiD **没有 lane 可扩展**，改为：**"先建一条最小的测量 lane（一个脚本 + 一个输出格式），再开始优化"**，并**明确警告不要为每次优化各造一套脚本**。

**同步删除的**：Node 机器乘数、浏览器 CI 校准、共享时间校准、预算作为源码常量等——它们全部依赖 SSiD 不存在的基建。**但保留一句通用的**：*"不要把预算放宽或挑一次走运的运行来掩盖回归。"*

### 4. `## Prove the regression, then remove work` → **保留（含 7 条模式）**

**保留的流程**：改生产代码**之前**先跑未优化的负载；保存命令、版本、运行时/平台、fixture 维度、原始测量与裁决；**把失败场景缩减到仍然压到真实瓶颈**；在动手前**给可证伪假设排序**；用 profile、分配样本、工作计数或阶段计时来区分它们。

**7 条常见模式逐字保留**（它们是"值得测"，**不是自动处方**——上游原文强调）：

1. 让紧凑表示一路保持紧凑；消费者需要的是**已定内容或一个聚合**时，避免逐 delta 对象
2. 只有在**识别出真正的归属与信任转移之后**才移除重复的解析、拷贝、冻结与校验；**"同进程类型化借用不是削弱持久或 wire 解析的许可"**
3. 流式转换产物并**约束中间状态**，而不是保留每一代；在用户操作需要处**包含发布、校验与可写就绪义务**
4. **分离只读准备与写入/发布工作**，但**不要把被 await 的工作挪到一个正确性所要求的端点之后**
5. 延迟非活跃视图与折叠细节的工作；**同时测量首次激活与保留状态**；**"延迟不是删除，视口高亮不是完整虚拟化"**
6. **稳定标识、收窄订阅**，使一个变更节点不会让整段历史失效；保持更新顺序与即时事件行为
7. 用合适的数据结构替代反复移位/扫描/重建；**测量整个消费者路径**而不只是孤立的容器操作；**revision-keyed 复用或 singleflight 只在有显式失效、有界保留、独立等待者取消与拆除归属时才用**

**保留**：一次只改**一个因果因素**；重跑聚焦场景**与其端到端父场景**。

**保留负向控制的定义**（逐字）：*"一个宽到让回归通过的阈值**不是保护**；低于已验证噪声底的预算**也不可靠**。"*

### 5. `## Preserve behavior and resource ownership` → **保留**

**逐字保留**：性能测量**补充**功能证据，**不替代**它；跑或补最窄的属主测试（输出、排序、分页、流索引、错误、取消、并发、拆除）；**preserve 模型可见/已记录等价性、已发布代的不可变性、原子发布、必需校验与可写就绪**；**"不要为了达到一个数字而静默截断历史、跳过工具结果、禁用不变量或改变生命周期语义。"**

**SSiD 本地化**：模型可见/已记录等价性 → **DSH 会话日志的等价性**（SSiD 必须保持与 DSH 的会话格式契约）；产品可见 GUI 变更的浏览器证据 → **Playwright 截图基线**（`shell/tests/plugin-adapt/`）。

**四种拒绝优化的情形逐字保留**：端到端增益消失 / 典型负载实质性回退 / **复杂度超过小收益** / 取消·保留·持久性**无法解释与测试**。并保留：**"简短记录被否证的假设，而不是扩大范围来为它辩护。"**

### 6. `## Deliver a bounded, reviewable result` → **改写（删 stacks）**

**保留**：用 Agent Note 规则承载持久理由 → 改指向 `docs/决策/`；**检查相关记录是否被取代，但不要把性能工作变成全库行文清理**（这条与 05 §三.9 同源，逐字保留）；**可复用流程留在这里，场景相关的真相留在其基准或包属主处**。

**删除**：stacked PR / 官方 GitHub stacks / 独立 worktree 整段（SSiD 无 stacks）。**保留其中一句通用的**：*"在编辑前选好分层；每一层都要可合并"*——**若真需要分层，用分支而非 stacks**。

**保留**：应用 **06**（推送前检查）、**只报告执行过的证据**、**查看 CI 而不是假设本地计时能证明 runner 稳定性**（SSiD 版要加一句：**SSiD 的 CI 不跑测试，所以"本地计时"就是全部证据——这抬高了重复测量的必要性**）。

**保留**：标记 ready 后，用代码与可执行证据评估评审意见；**不要仅仅因为一份报告来自机器人就驳回它**。

**保留**最终摘要格式（逐字）：*工作负载 → 前后绝对值与比例 → 端点与内存语义 → 行为证据 → 负向控制 → 确切检查 → 排除项*；并**区分作者报告的历史数字、新的本地测量与 CI 证据**；**停在约定的场景/修复范围内，保留一份简短的排序后续清单，而不是追逐无关机会**。
