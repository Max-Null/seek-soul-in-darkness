# Header 按钮统一：调查结论与方案

> 日期：2026-08-17
> 状态：方案待确认（主方案：SSiD 标题栏统一按钮组；补丁已起草将改造；PR 降级）
> 范围：① 插件中心与 better-sidebar 右上角按钮的错位；② 插件中心按钮在 hero 页不可见
> 关联：`docs/设计/SSiD-技术设计方案.md`、`docs/设计/SSiD-壳级能力设计.md`

---

## 一、背景

SSiD 预制了插件中心（`@max-null/dsh-plugin-center`）与侧边栏（`dsh-better-sidebar`）两个插件，右上角各有一个按钮，但实现方式完全不同：

| | 插件中心 | 侧边栏 |
|---|---|---|
| 按钮注入方式 | `ctx.slots.inject("conversation.session.header.utilities", ...)`——DSH 官方 slot | 自绘浮层：`position: fixed; top: 3px; right: 10px`（`.toggleCluster`） |
| 与原生按钮关系 | 与 DSH 原生 Session log 下载按钮同 slot 并排，样式统一 | 不经过 slot，钉死在视口右上角，与 header 错位 |
| 语义定位 | 会话级工具 | 全局布局开关（无会话时也显示 disabled 按钮） |

用户感知：① 侧边栏按钮与 header 错位；② 初次打开/新会话（hero 页）时插件中心按钮不可见——而那时正是需要装插件的节点。

**新方向（用户提出）**：SSiD 标题栏是自绘的（非系统原生），完全可以在**最小化按钮左侧**做一个统一按钮组（插件中心 + 侧栏开关），天然全局可见、样式统一。

## 二、调查结论（读代码核实）

### 2.1 DSH 无"全局 header/toolbar"位置

DSH 全部 42 个 client slot（`cordis-client-runner/src/client/slot-catalog.ts`）中，header 类 slot（`conversation.session.header.actions` / `.utilities`）**全部 `scope: 'session'`**，只在会话页渲染。全局可用的仅 `sidebar.footer.action`（左栏底部）、`sidebar.*`、`shell.overlay`（浮层）、`conversation.hero.*`（hero 内容区）。**DSH 官方 UI 没有"全局右上角"扩展点。**

### 2.2 hero 页没有 header

`ui-conversation/src/client/skeleton/ConversationRoot.tsx`：`hero = sessionId === undefined`。hero 时渲染居中文案 + 输入框，不渲染 header——挂 `header.utilities` 的按钮在 hero 页必然不可见。

### 2.3 插件中心：按钮与面板解耦，未暴露跨插件 API

- `HeaderButton` 仅是 `onClick: openOverlay()`；面板挂全局 `shell.overlay`；打开状态是模块级变量 `overlayOpen`（`client.js`）——**未暴露**为 service/全局函数。
- 仓库：`Max-Null/dsh-plugin-center`（**自有**，改源码发新版无障碍）。`apply(ctx)` 内一行 `window.__pluginCenterOpen = openOverlay` 即可暴露全局触发。

### 2.4 better-sidebar：有对外 service

- `ctx.provide('betterSidebar', service)`，导出 `togglePanel` 等（`service.ts`），exports 含 `./client/api`——外部插件可集成。
- `.toggleCluster` 编译后类名保留原始段（`nArs4W_toggleCluster`）。
- 仓库：`omdsh-dev/DSH-better-sidebar`（第三方，只能提 PR）。

### 2.5 壳已具备"操作 DSH 页面"的成熟模式

`shell/main.mjs` 多处 `mainView.webContents.executeJavaScript(...)`：
- **侧边栏自动诊断**（793-820 行）：`document.querySelector('.nArs4W_toggleCluster')` + `btns[0].click()` **模拟点击 better-sidebar 按钮**——标题栏按钮触发 DSH 内动作的链路已有先例。
- 主题同步（835-862 行）：mainView 读 token → titleBar 写 CSS 变量（双向注入）。
- MutationObserver 注入（870-879 行）：注入长期驻留代码。

### 2.6 标题栏结构

- `titlebar.html`：`.titlebar` flex 布局 = `.brand`（logo + 思灵 + DSH 版本）+ `.spacer` + `.controls`（最小化/最大化/关闭，52px 宽按钮）。按钮组插在 `.controls` 内最小化按钮左侧即可。
- `titlebar-preload.cjs`：`window.ssidTitle`（invoke/handle 模式 IPC）。
- `main.mjs`：`ipcMain.handle('ssid:title:minimize' | 'toggle-maximize' | 'close')`——加新 IPC 成本低。

## 三、问题矩阵

| 场景 | 插件中心按钮 | better-sidebar toggle |
|---|---|---|
| 会话页 | ✅ header 右上角 | ❌ fixed 错位 |
| hero 页 / 新会话 | ❌ 不可见 | ✅ 原位置，无冲突（但无 header 相伴） |

## 四、决策

### D1：插件中心按钮 → 迁入 SSiD 标题栏（主方案，解决全部两个问题）

标题栏是自绘 BrowserView（SSiD 100% 控制），按钮组放最小化按钮左侧：

```
[logo 思灵 DSH版本]        [插件中心][侧栏] [—][□][✕]
```

- 永远可见（hero / 会话 / 设置页都在标题栏下方）。
- 统一样式（标题栏按钮组风格一致，跟随主题 token）。
- 不依赖 DSH slot 演进。

**触发链路**：标题栏按钮 → preload IPC → main → `mainView.webContents.executeJavaScript` 派发 `CustomEvent('ssid:titlebar')` → SSiD 内置 client 插件（`dsh-header-unify` 改造）监听执行：
- 插件中心 → `window.__pluginCenterOpen?.()`（plugin-center 新版暴露）
- 侧栏 → `ctx.betterSidebar.togglePanel()`（service 已有）

**DSH 内原按钮隐藏**（避免双份、消除错位）：`dsh-header-unify` 注入 CSS：
```css
[class*="pc-headerbtn"]  { display: none !important; }
[class*="toggleCluster"] { display: none !important; }
```
DSH 原生 Session log 按钮保留在 header。

### D2：better-sidebar 上游 PR（撤销）

按钮迁入标题栏后错位问题消失（DSH 内原 toggleCluster 被 CSS 隐藏），**不再提 PR**——better-sidebar 在 DSH header 场景下的错位是上游自己的布局决策，SSiD 不做无谓贡献。

### D3：备选方案（记录不采纳）

- **原 CSS 对齐方案**（`dsh-header-unify` 对齐 toggleCluster 到 header utilities 行）：解决会话页错位，但不解决 hero 页插件中心不可见；已起草的代码可作参考。
- 插件中心 `sidebar.footer.action` 入口 / body fixed 按钮：用户已评估"设置内已有插件中心 tab，非高频功能，可接受现状"——**除非做标题栏方案，否则保持现状**。

## 五、实施设计（标题栏统一按钮组）

### 5.1 改动清单

| # | 文件 | 改动 |
|---|---|---|
| 1 | `shell/titlebar.html` | `.controls` 前加按钮组（2 按钮：插件中心、侧栏），样式复用现有 hover/主题 token |
| 2 | `shell/titlebar.js` | 按钮 click → `window.ssidTitle.action('plugin-center' | 'sidebar')` |
| 3 | `shell/titlebar-preload.cjs` | `ssidTitle.action(id)` → `ipcRenderer.invoke('ssid:title:action', id)` |
| 4 | `shell/main.mjs` | `ipcMain.handle('ssid:title:action', ...)` → `mainView.webContents.executeJavaScript(派发 CustomEvent)`；DSH UI 未就绪时忽略（按钮点击发生在用户交互期，UI 必已就绪） |
| 5 | `plugins/dsh-header-unify/lib/client.js` | 改造：监听 `ssid:titlebar` CustomEvent → 执行插件中心/侧栏动作；注入隐藏 CSS（pc-headerbtn + toggleCluster） |
| 6 | `@max-null/dsh-plugin-center`（独立仓库） | `apply(ctx)` 暴露 `window.__pluginCenterOpen = openOverlay`（含页面卸载清理）→ 发新版 |

### 5.2 触发链路（时序）

```
用户点标题栏[插件中心]
 → titlebar renderer: window.ssidTitle.action('plugin-center')
 → preload: ipcRenderer.invoke('ssid:title:action', 'plugin-center')
 → main: ipcMain.handle → mainView.webContents.executeJavaScript(
     `window.dispatchEvent(new CustomEvent('ssid:titlebar', { detail: 'plugin-center' }))`)
 → dsh-header-unify (DSH 页面内): 监听事件 → window.__pluginCenterOpen?.()
 → plugin-center OverlayPanel (shell.overlay) 打开（hero/会话页均可）
```

### 5.3 状态反馈（可选增强，MVP 不做）

侧栏开/关 active 态：main 可定期 `executeJavaScript` 读面板 class（`panelHidden` 有无）→ `titleBar.webContents.send` 更新按钮样式。

### 5.4 风险与缓解

| 风险 | 缓解 |
|---|---|
| executeJavaScript 注入代码在 DSH 页面出错 | 包 try/catch；CustomEvent 无监听者时静默（插件未加载） |
| plugin-center 未升级（旧版无 `__pluginCenterOpen`） | `?.()` 可选调用；升级插件中心后生效 |
| better-sidebar 升级改类名段 | 隐藏 CSS 依赖 `toggleCluster`/`pc-headerbtn` 原始段；若变更则按钮重现（无破坏），再适配 |
| 标题栏空间有限 | 按钮组 ≤ 3 个；36px 高标题栏用 28-30px 按钮 |
