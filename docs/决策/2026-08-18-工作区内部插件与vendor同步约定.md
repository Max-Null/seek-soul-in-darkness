## 同步流程（以后插件更新）

1. `plugins/dsh-ssid-panels` 改代码 → `npm run build`（tsdown）。
   （dsh-node-appearance 同理：独立工作区改代码 → `npm run build`）
2. 复制 `lib/`（+ package.json/cordis.patch.yml 如变更）到
   `shell/profile-template/vendor/<插件名>/`——**用 `robocopy <ws>/lib <vendor>/lib /MIR`，
   不要用 PowerShell `Copy-Item` 覆盖已存在目录**（会生成 `lib\lib` 嵌套，
   破坏目录结构，pnpm 对结构异常的 file: 依赖会 fallback registry 解析，未发布包 404）。
3. `prepare-runtime` → 归档 boot 冒烟 → pack。
4. 构建产物需 MD5 对比确认（tsdown 输出确定性，一致即已同步）。

## pnpm file: 依赖快照坑（2026-08-19 实测）

- node_modules 里的 file: 依赖副本是 **pnpm store 的内容寻址快照（硬链接）**，
  不是 vendor 目录的实时复制；lockfile 指纹是 peer 组合指纹，与目录内容无关。
- vendor 内容更新后，`pnpm install`（含 `--force`/`update`/删缓存）**不会**重新打包 vendor，
  node_modules 副本停留在旧快照。dev 环境要立即生效需手动复制 lib 到 node_modules；
  发布版不受影响（全新环境直接打包新内容）。
