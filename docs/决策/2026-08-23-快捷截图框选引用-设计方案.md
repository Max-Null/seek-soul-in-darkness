# 快捷截图框选引用插件 — 设计方案（2026-08-23）

## 背景与目标

用户想引用屏上内容时，过去只能打字描述，LLM 理解准确性有限且费事。现在 DSH 已有多模态能力（图片消息走官方 admission 通道），因此做一个 **快捷截图 + 框选 + 送入消息框** 插件：从全屏冻结帧里框选一块区域，裁剪结果自动进入当前会话。

本方案放弃上一版 dsh-sidebar-preview-select 路线（全局 mouseup + 区域判定 + DSH 页面内浮层 + 文件类型解析），理由：侵入 DSH DOM、只限 DSH 内预览、生命周期复杂。新方案把「截屏 + 框选」放在**独立的 Electron 浮层窗口**（壳层），把「送入」走 DSH 官方图片 intake，互不侵入。

## 架构

```
触发（托盘菜单项「截图引用」 / 全局快捷键 Ctrl+Shift+A）
   ↓ 主进程
win.hide()（冻结帧不含 DSH 自身）→ ~250ms
desktopCapturer.getSources({types:['screen'], thumbnailSize=所有屏物理并集最大})
   → 每屏一张冻结帧 nativeImage → dataURL
   → 每屏一个全屏无边框置顶 overlay BrowserWindow（独立窗口，不碰 DSH DOM）
       渲染本屏冻结帧 + 十字准星；拖拽框选；Esc 取消；双击/Enter 确认
       选区逻辑 px × scaleFactor → canvas 物理像素裁剪 → PNG base64
   → 主进程关全部浮层 → win.restore()
   → mainView.webContents.executeJavaScript 派发 `ssid:screenshot` CustomEvent
   ↓ 客户端插件 @max-null/dsh-ssid-screenshot（profile 内置）
       监听 CustomEvent → dataURL→File（fetch(dataUrl).blob()）
       → 合成 drop（new DataTransfer + DragEvent）填入当前会话输入框草稿
         （官方 intake：可编辑/删除/加文字，回车后才发送）
```

### 分层职责

- **壳层（shell/main.mjs + overlay 页面）**：触发、截屏、框选浮层、裁剪、输送。Electron 独有的能力留在这里（desktopCapturer/globalShortcut/clipboard/nativeImage）。
- **client 插件（plugins/dsh-ssid-screenshot）**：接收事件、把 PNG 交给官方 intake、处理「无会话/不支持」反馈。只依赖官方 客户端服务（sessions）与浏览器事件，不 import DSH 包内部符号。

### 触发方式（已定：托盘菜单 + 全局快捷键）

- 托盘菜单项「截图引用」（托盘已存在，L1018-1033 菜单模板加一项）
- 全局快捷键 `Ctrl+Shift+A`（whenReady 注册 / 退出注销；避开微信/QQ 的 `Ctrl+Alt+A`；设置页改键留后续）
- 标题栏按钮暂不做（需要改 titlebar.html，后续需要时走 `ssid:title:action` 通道）

### 框选浮层细节（多显示器，v1 所有屏）

- 触发后先 `win.hide()`（冻结帧里不包含 DSH 自身），~250ms 后再抓帧，浮层关闭后恢复窗口。
- 抓帧：**逐屏调用** `desktopCapturer.getSources({ types: ['screen'], thumbnailSize: 该屏物理宽高 })`，按 `display_id` 匹配源（兜底枚举顺序）。*修正记录（2026-08-23 探针实测）*：单次调用统一 thumbnailSize 会把全部源等比缩放进同一请求盒（本机 2560x1440@1.0 被放大成 3840x2160，画面失真）；逐屏请求后返回像素级 1:1（3840x2162 请求 → 源返回 3840x2160，浮层换算以返回值为基准，无需依赖请求值）。
- 浮层：每屏一个 `BrowserWindow`（`frame:false, alwaysOnTop:true, skipTaskbar:true, resizable:false, movable:false, show:false` + preload），位置尺寸取 `screen.getAllDisplays()` 的 bounds（DIP）；每个浮层只渲染自己那屏的冻结帧（`<img>` 按逻辑像素铺满）。
- 选区：mousedown → mousemove 画矩形 → mouseup 定格；**裁剪在浮层渲染进程用 canvas 完成**（画布按物理像素、选区逻辑像素按 `thumbnail尺寸 / bounds` 比例换算成物理像素），避免 nativeImage.crop 的 DIP/scaleFactor 换算；Esc 取消（全部浮层）；双击/Enter 确认。
- 确认后浮层经自带 preload 把裁剪结果（PNG base64）回主进程：主进程关闭全部浮层 → `win.restore()` → 派发 `ssid:screenshot` CustomEvent 给 mainView。

### 注入渲染进程

沿用 `ssid:titlebar` 先例：`executeJavaScript` 派发 CustomEvent，插件监听。数据为 base64 PNG（框选区域通常几十 KB~几 MB，可接受；若后续变大可改为浮层窗口完成裁剪后直接把 dataURL 经 devtools 协议/临时文件通道送，v1 不做）。

## 边界与风险

- 无当前会话 / composer 未挂载：drop 不生效 → 插件检测 `sessions.list.current === undefined` 时（在浮层内或 toast）提示「先打开一个会话」；v1 简化为浮层提示 + 插件侧静默。
- 模型不支持图片：host 拒绝（`attachment-error`，官方中文文案），走 composer 的 promptError 展示，无需插件处理。
- 快捷键冲突：v1 固定一个低冲突组合，文档写明；设置页改键留待后续。
- 大图 admission 限制（像素/大小上限）与官方拖拽路径一致，超限提示同样生效。
- Windows 多屏缩放比：冻结帧按物理像素请求，选区坐标按 CSS px 换算 `scaleFactor`；v1 主屏通常 100% 缩放，仍需换算代码。

## 已定决策（2026-08-23 用户确认）

1. 送达方式：**填入输入框草稿**（不自动发送；可加文字后再回车）。
2. 触发方式：**托盘菜单项 + 全局快捷键**（标题栏按钮留后续）。
3. 屏幕范围：**所有显示器**。
4. （迭代追加，2026-08-23 用户反馈）确认框选后进入**标注阶段**：拖拽画红框强调
   重点（可多个），回车/完成发送；右键/Esc 与 Esc 同级逐级回退（撤框 → 重选 →
   退出）；浮层无交互 3 分钟自动取消（防卡屏）。
5. （迭代追加）截图设置并入 **设置 → 通用** 两行（隐藏窗口开关 + 快捷键，即改即存、
   壳内即时重注册；配置存 ~/.ssid/screenshot.json，主进程每次触发前读取）。
