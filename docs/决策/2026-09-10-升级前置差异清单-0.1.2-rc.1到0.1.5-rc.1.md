# 升级前置差异清单：0.1.2-rc.1 → 0.1.5-rc.1（2026-09-10 整理）

> 用途：周末「大改造」的升级前核对清单。
> 素材来源：`dsh-observations/` 三篇观察（2026-09-04 / 09-09 / 09-10）+ 官方 GitHub Release notes（经 API 核对）+ 本机实测。
> 状态：**素材已核对，标注「待查」的项尚未在本地验证**。

## 1. 升级范围

| 项 | 值 |
|---|---|
| 起点 | `0.1.2-rc.1`（当前 web 宿主 + SSiD profile，实测 32 个包全为 rc.1） |
| 终点 | `0.1.5-rc.1`（09-10 09:36 发布，**npm `latest` + `next`**） |
| 中间版本 | 0.1.3-alpha.1（未发 npm）、0.1.3-alpha.2、0.1.5-alpha.1、0.1.5-alpha.2、0.1.5-rc.1（**无 0.1.4**） |
| 提交量 | 1469（rc.1→alpha.2）+ 17（alpha.2→rc.1） |
| 新增包目录 | 20 个，删除 0 个（清单见 09-09 观察附录） |

与上次升级（alpha.2 → rc.1，同系列内）不同，**这次跨 0.1.2 → 0.1.5 两个系列**，破坏性变更显著更多。

## 2. 破坏性变更清单

| 变更 | 引入版本 | 影响层 | 本地需核查什么 |
|---|---|---|---|
| **会话格式 v2**（assistant streams 内嵌持久日志 + live stream frames） | 0.1.3-alpha.1 | 会话日志 | 会话日志读取工具（`.tmp-*.mts` 修复脚本、chat-rail 投影读取、标题修补脚本） |
| **会话格式 v3**（identity 迁移、PTC 词汇重命名、V2 prompts → V3 system surfaces） | 0.1.5-alpha.1 | 会话日志 | 同上；**升级后的会话不支持降级读取** |
| Session persistence API → 生命周期持有的 `SessionHandle`；`agentLoop.create()` 异步化；新增 session 锁（同 session 至多一个进程持有） | 0.1.3-alpha.1 | 内核 API | 插件是否直接调 session/agentLoop 内部 API |
| 移除 `ctx.agent`（调用方须显式传 Agent） | 0.1.5-alpha.1 | 插件 API | ✅ **已查**：`max-null-plugins/*` 无任何使用 |
| Inbox API：`Inbox` 改为类型接口，`hasPending` / `claim` 退出公共接口 | 0.1.5-alpha.1 | 插件 API | ✅ **已查**：无插件使用 `inbox.` / `hasPending` / `claim` |
| 插件面板 API：`sidebar.panellist` 与 `main` 注册全局面板；原 `conversation` Slot 迁移为 `main` 的 `conversation` key | 0.1.5-alpha.2 | 插件 API | ✅ **已查（结论：不受影响）**：5 个插件的 `conversation.input.right`（capture / draft-polish）/ `conversation.input.dock`（chat-rail）/ `conversation.session.header.utilities`（plugin-center）/ `conversation.input.for`（memory），以及 `dsh-ssid-panels` 的 `settings.section` / `sidebar.brand.mark` / `sidebar.brand.name` / `conversation.hero.brand.mark`——**在 0.1.5-rc.1 里全部仍存在**。release notes 那句指「全局面板」的注册方式，与这些输入区/品牌 Slot 无关 |
| **自定义 persona 配置拆分为前缀 + 后缀** | 0.1.3-alpha.2 | 配置 | ❌ **必须改（唯一确定风险）**：`presets/ssid-double-star/agent.cordis.yml` 用的是 `config.text`，而 0.1.5 的 `dsh-persona` schema 是 `prefix`（**required**）/ `suffix` / `complete` / `includeRuntimeContext`——**`text` 字段已不存在**，且缺 `prefix` 会校验失败 |
| 普通 subprocess handle 移除 `pid`（终端 handle 不受影响） | 0.1.3-alpha.2 | 内核 API | ✅ **已查**：无插件读取 subprocess pid |
| 默认工具调整：SDK / Headless / ACP 默认用 read/write/edit；minimal 系列保持 shell-only；`str_replace_editor` 移出默认 | 0.1.3-alpha.2 / 0.1.5 | 工具集 | ✅ **已查**：`str_replace_editor` 仅出现在 `dsh-guardian/src/engine.ts` 的注释与 `dsh-node-appearance/src/client/palette.ts` 的配色表键名，**无功能依赖** |
| `str_replace_editor` 移出默认工具集（代码仍在，需显式启用） | 0.1.5 | 工具集 | 同上 |

## 3. connection 能力变化（方案 B 的关键）

| | rc.1（当前） | 0.1.5-rc.1（目标） |
|---|---|---|
| `ConnectionFetchMethod` | `'GET' \| 'HEAD'` | `'GET' \| 'HEAD' \| 'POST'` |
| `ConnectionFetchRoute.requestBody` | 无 | 有（`buffered` / `streaming`） |
| connection 的 `inject` | `['webServer','credentials']` | `['credentials']` |
| 路由实现 | `ctx.webServer.register(route)` | carrier 直接分发 |
| 无 webServer 时 | connection 也不激活 | connection 仍可用 |

→ **升级后 §12 规范草案（host 侧用 `ctx.connection.fetch.register`）技术前提成立**。封存分支 `feat/connection-fetch-routes` 可在升级后启用。

## 4. 新增能力（升级后可用）

- **右侧边栏**：`ui-sidebar-right`（`ctx.sidebarRight` / `ctx.sidebarRightTabs`，extension 档可接管 builtin）、`ui-sidebar-files`、`ui-sidebar-documentpreview`
- **官方桌面端**：`apps/desktop` + `apps/desktop-host`（**仍未发布**：npm 无包、GitHub Release 无资产）
- **文件体系**：`api/workspace-files`（双面文件 API）、`fs` 有界字节窗口读取、`client/resources` 资源注册表、`host/open-in-app`
- **布局**：`ui-dockkit`（可逆停靠引擎，自述内部引擎、非稳定 API）

## 7. 风险与回滚

| 风险 | 说明 | 缓解 |
|---|---|---|
| **会话不可降级** | v3 迁移后旧版本读不了新日志 | 前置备份；先在小 profile 试迁 |
| 会话日志工具失效 | 自定义读取器需适配 v2/v3 | 升级前先跑一遍现有工具，确认基线 |
| 插件静默失效 | 静态 `inject` 缺失服务时不报错 | 升级后逐个核对插件是否真的挂载 |
| 性能回退 | 0.1.3-alpha.1 曾公告已知性能缺陷 | 本版应已修复，实测确认 |
| 回滚路径 | checkout 回 tag + 恢复归档 + 恢复会话备份 | 三样都要有备份才动手 |
