## 一、为什么做这一个

1. **它是 02 的地基**。02（推理痕迹修剪）的「删之前先枚举命题」依据的就是本 skill 的**完整命题规则**。若只装 02 不装 03，agent 会把真事实一并删掉——那是比不做更坏的结果。
2. **它管的不是"文风"，是"契约要不要写出来"**。上游定义：*contract* 是 caller/callee/implementer/producer/consumer 依赖的**义务、不变量、前置/后置条件或兼容承诺**。这跟"写得漂亮"无关，是**接口事实是否可被使用方读到**。
3. **SSiD 的主体是 AI 生成的代码与文档**，而 AI 的默认倾向是**过度叙述**（讲过程、讲变更、讲理由），恰好是这条 skill 从头到尾在修剪的东西。

### 2.2 `docs/决策/` 与 DSH 的 Agent Notes 不是一回事

| | DSH Agent Notes | SSiD `docs/决策/` |
|---|---|---|
| 位置 | `.agents/notes/{implemented,proposed,rejected}/` | `docs/决策/YYYY-MM-DD-标题.md` |
| 状态字段 | 有（目录即状态 + 归档冻结） | **无**（靠文件名日期与内容自述） |
| 编目 | 有 README 说明制度、有索引门禁 | **无索引、无门禁** |
| 读者 | agent（主要） | **人**（给用户回看决策） |

**这条差异决定适配时的两件事**：

1. **不能把上游的 Agent Note 规则整段搬过来**（如"implemented 用现在时"、"归档即冻结"）——SSiD 没有状态机，无从施加。**只保留对 SSiD 成立的部分**：保留独有理由、机制、备选方案、后果、已交付的验证证据、点名的覆盖空白。
2. **02 已定的「六个合法载体」在这里同样适用**：`docs/决策/` 是**变更叙事的合法主场**，行文标准**不要求它改写成 HEAD 视角**。

### 2.3 Prompts 与可见字符串：机制不同

上游：客户端 UI 文案归属**类型化 locale 字典**，经显式本地化 props 到达无 Cordis 依赖的原语，并有 `verify-client-ui-i18n` 门禁拒绝硬编码。

SSiD：`dsh-ssid-zh-ui` 用的是**运行时翻译表**（`lib/client.js` 里的 `TEXT_ZH`）＋ 自己的验证脚本 `verify-zh-ui.cjs`（10,952 B，含翻译表覆盖 / 中文替换 / 切英文恢复 / 防误传等断言）。

**所以判据保留、门禁换名**：把 `verify-client-ui-i18n` 换成 **`verify-zh-ui.cjs`**。措辞本身即行为的纪律（文案与 a11y 名称、tooltip、placeholder、格式模板一起看）**逐字保留**。

### 8. 从 `dsh-doc` 并入的 9 条判据（见 09 号说明）→ **新增**

> `dsh-doc`（861 行）被判 `⛔ 不单独适配`——它的制度部分（kind 系统 / 4 模板 / 双语配对 / 字数预算 / 网站投影 / 门禁）SSiD 一样都没有。**但它有 9 条判据的主题正是"行文"**，因此在 09 的合订理由里被明确移交到本节。**逐条列出，不做"大概有点用"的模糊移交。**

#### (a) 事实核对纪律（4 条，逐字保留）

上游出处：`dsh-doc` 的 "Fact-check procedure: test, do not assume" 节。

1. **对每条声称的操作，对着当前 checkout 真跑一遍。** 执行文档将展示的每个 CLI 命令、配置片段、profile/patch 示例的**原样**版本；**只写下你观察到的**，包括确切输出、警告与失败模式。若某断言依赖你没有的密钥或网络，**说明这一点并点名验证属主，而不是断言其行为**。
2. **★★★ 删掉你无法复现的东西。** *"**绝不**把命令、字段、默认值或行为从**记忆、类比或邻居包的 README** 搬过来。当一条断言无法复现时，**修那条断言——而不是修测试**。"*
   > **这条必须提权**：它逐字描述了本系列 01/02/03/09 犯的 **9 次**"数一数"错误。DSH 早已把它写成判据，而 SSiD 侧没有任何等价物。**它就是本说明《写作规则》§三 的存在理由**，两者应互相引用。
3. **对着最新 master 检查旧文档。** 修订既有页面之前先 `git fetch origin`，把该节与 `origin/master` 对照；配对 sidecar 可恢复任一侧最后确认的文本。**"master 上一句陈旧的陈述仍然是错的"——要对着代码改，不是对着旧散文改。**
4. **分类主题再写安装指引。** **读事实，不要读文件夹名**：看 `package.json` 的声明与入口文件的形态，而不是目录名暗示的类型。

#### (b) 语气规则（5 条，逐字保留）

上游出处：`dsh-doc` 的 "Voice rules" 节。这些规则管的是**陈述方式**，与文档制度无关。

1. **★ Summary 说的是主题能做什么。** 开篇 Summary 与用户向小节描述用户或 agent **能用它做什么**——结果、收益、何时选用、主要代价——**绝不是它的角色、类型或内部身份**。包 Summary 里的"它是什么"**仅指读者可见的能力**，不是它的 Cordis 角色、注册点或内部组件。*"'这个接缝注册 `ctx.x` 并追加 `x/event` 记录'是身份叙述；'你可以每条消息存一条笔记，重启后还在'才是它做什么。"*
   > **与 `writing-skills` 的「description 只写触发条件」同源**：两者都是"读者要能判断**该不该用它**，而不是被告知它内部走了几步"。**适配版的 description 规则应把两处合并成一条**，而不是各写一份。
2. **开发者小节解释，绝不枚举。** 折叠的实现内容覆盖整体设计概念、架构与挥手式数据流——**足够了理解它怎么工作**——并**链接代码**取确切细节；**不做完整 API 目录、穷举式字段清单、事件负载枚举或 JSDoc 复述**。
3. **★ Dev Note 是唯一的草稿区。** 半成品想法、草稿、未定方向、实测产物与工作假设**只**出现在末尾的 Dev Note 里，并**显式标注非权威**；**其他每一节都是打磨过的当前状态散文**。
4. **★ 只讲当前状态。** **Dev Note 之外没有兼容性垫片、迁移话术或历史**（`previously` / `now` / `no longer` / `renamed`）；**"今天这个代码库是唯一主题"。**
   > **这条与 02 的推理痕迹修剪同源**——**03 与 02 应互相引用它**，而不是各自造一份判据。
5. **用受控的技术英语。** 歧义会改变行为时，让每句话有**显式 actor 与一个主要动作**；一个概念复用一个术语；优先直接动词；拆开堆叠的指令与条件；**保留情态与例外**。（上游引用一份 ASD-STE100 启发的规范，SSiD 无对应文献 → **保留判据、删引用**。）

**并入的算术**：03 的判据总数由上游 7 部件的判定结果 + **9 条新增**构成；上游部件数（7）不变，因此 §四 的算术核对不受影响。
