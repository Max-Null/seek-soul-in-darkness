# 检查更新缺下载入口：v0.1.2 候选改进

日期：2026-08-17
状态：决策记录（v0.1.2 实施时执行）

## 现象

用户点「立即检查」看到「新版本可用：v0.1.1 补丁」，但卡片只有文案，
**没有任何可点击的下载入口**，用户不知道如何更新（2026-08-17 实测确认）。

## 根因（代码级确认）

`dsh-ssid-panels/lib/index.mjs` 的 `update-check` API 返回字段只有
`tag / name / body / publishedAt`，**丢弃了 GitHub release 的 `html_url` 与
资产 `browser_download_url`**；前端（client.js）更新卡片仅渲染文案 + 「立即检查」按钮。

## 方案（v0.1.2 实施）

1. `update-check` 返回补 `htmlUrl: release.html_url`（及可选
   `downloadUrl: 首个 exe 资产的 browser_download_url`）。
2. 前端更新卡片：新版本可用时渲染「下载」按钮 →
   `shell.openExternal(htmlUrl)` 打开 Releases 页（或直接指向资产 URL）。
3. 配套：`@max-null/dsh-ssid-panels` 发新版 → `profile-template/vendor` 同步 →
   重打包发 v0.1.2。

## 本次（v0.1.1 当值）应对

- 手动更新：下载 `Setup.0.1.1.exe`，NSIS 向导覆盖安装（保持原目录）。
- 安装包已下载至 `C:\Users\MaxNull\Downloads\Setup.0.1.1.exe`。
- 覆盖安装后 about 页 shellVersion 显示 0.1.1，检查更新回到「已是最新」。

## 决策备查

- 更新机制现状（v0.1.x）：提示式，不自动下载、不静默安装，符合「人工闸门」原则；
  但提示必须带下载入口，否则等于没提示。
