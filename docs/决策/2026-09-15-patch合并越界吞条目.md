# patch 合并越界吞掉 connection 条目（2026-09-15）

> 状态：**已修复**（`mergeUserPatch` 替换区间钳制 + 回归用例；修复随下一版出包）
> 关联：`docs/决策/2026-09-14-插件中心405诊断记录.md`（405 的机制与配置层修复）、
> 手册 §7 坑 #30、`shell/lib/profile-merge.mjs`、`shell/tests/profile-merge.spec.ts`

## 一、现象

0.3.0 → 0.3.1 升级部署后，安装版思灵启动失败，splash 报：

```
Error: kernel-child 启动失败：ssid: failed to parse overlay
C:\Users\21030442\.dsh\profiles\ssid\cordis.patch.yml:
YAMLException: bad indentation of a mapping entry (93:5)

 91 |   inject: [webRuntime, webServer]
 92 |
 93 |     - id: mcp-playwright-b
```

把该文件调成能解析的 YAML 后可以启动，但**插件中心 405 复发**（同路径 GET 404、`/api` 401，
与 2026-09-14 记录的判据一致）。

## 二、根因：`overridden` 替换区间越界

`mergeUserPatch` 的三方合并有一个「用户改过的出厂子条目」分支：base（上次部署的模板）里存在同 id
子条目、且用户文本与之不同时，用用户版本替换模板的该子条目。替换区间按
`e.start + c.start .. e.start + c.end` 计算（`e` 来自 `splitPatchEntries`，`c` 来自
`splitChildEntries`）。两个实现细节叠加后，这个区间会**跨过条目边界**：

1. `splitPatchEntries` 判定顶层条目只看「行首 `- ` 且无前导空白」，注释行归入**当前**条目。
   模板把 connection 的 26 行说明注释写在 insert 块之后、条目之前（缩进 0），于是这段注释被计入
   insert 条目，insert 条目范围一直延伸到注释块末尾。
2. `splitChildEntries` 的 `end = c.start + c.lines.length - 1`，而 `entryText` 以
   `lines.join('\n') + '\n'` 结尾——`split('\n')` 多出一个空元素，`end` 因此比真实末行**多 1**。

两者叠加：insert 块最后一个子条目（`mcp-codegraph`）的替换区间末端 `e.start + c.end`
正好落在下一个顶层条目 `- id: connection` 那一行上，整行被替换掉。

触发条件是该子条目被用户改过。本机升级报告 `upgrade-report-0.3.1-…json` 记录了
`patchMerged.overridden: ["mcp-codegraph"]`（用户在 MCP 管理页改过它的 cwd/args），条件成立。

## 三、后果链

`- id: connection` 整行消失后，只剩缩进 2 的 `inject: [webRuntime, webServer]`——YAML 把它解析成
insert 条目的**兄弟键**，与 `insert` 平级，因而：

- 文件本身成非法 YAML（缩进冲突）→ kernel-child boot 失败，思灵起不来；
- 把它手工调成合法 YAML 后，`connection` 的 `webServer` 注入仍然缺失 →
  `ctx.connection.rpc.handle` 读不到 `webServer` → 路由不入 webserver 路由表 →
  frontend-static 兜底 → **405 复发**。

即 2026-09-14 记录的 405 机制原样重现，但这次的成因是「配置里的条目被合并吞掉」，
不是「配置里没写这条」。

## 四、证据

用真实输入复现（脚本比对，非推断）：

| 输入 | 取值 |
|---|---|

| `templateText` / `baseText` | 两次发版的模板；`git diff eb90fc1 2ab2346 -- shell/profile-template/cordis.patch.yml` 为空，即两版模板逐字节相同 |

复现输出与真实坏文件**逐字符一致**（8364 字符 / 212 行，同在第 92 行报错）。

## 五、修复

`shell/lib/profile-merge.mjs` 的 overridden 分支把区间钳制在本条目内：

```js
edits.push({ start: e.start + c.start, end: Math.min(e.start + c.end, e.end), text: overridden.get(c.id) })
```

`shell/tests/profile-merge.spec.ts` 增加用例「insert 块后的注释块不得让替换区间吞掉下一个顶层条目」，
构造与真实模板同构（insert 块 + 缩进 0 注释块 + `- id: connection`）。判别力实测：未修复版本
`not ok`（pass 22 / fail 1），修复版本 pass 23 / fail 0。

**未采纳**：

- 改 `splitPatchEntries` 的注释归属（把条目之间的注释划给下一个条目）：头注释、条目间说明都依赖
  当前规则，影响面远超本次缺陷。
- 只修 `splitChildEntries` 的 `end` 越界：治标不全——注释块仍在条目范围内，区间仍可能压在下一个
  条目上。

## 六、影响面与遗留

命中需三条同时成立：① 模板在 insert 块之后、下一个顶层条目之前有缩进 0 的注释块；② 该注释块紧跟
insert 块的最后一个子条目；③ 用户在 MCP 管理页改过那个子条目（触发 overridden）。任一不成立则不
复现——本机修复后再次模拟升级即因第 ③ 条不成立而结果合法。

遗留：安装版 `app.asar` 内仍是未修复逻辑，**本次修复随下一版安装包生效**；在此之前，老用户升级
仍可能写出坏 patch。

## 七、恢复已损坏 profile 的要点

损坏后要恢复的**不只是缩进**：必须把 `- id: connection` 这条**顶层条目**补回（与 `insert:` 平级），
否则文件合法了、启动正常了，405 依旧。

校验方式（`yaml` 包在该 profile 的 `node_modules` 内）：

```js
// 顶层条目数必须为 2，且其中一条 id === 'connection'
const doc = YAML.parse(text.replace(/!!js\s+/g, ''))
doc.length === 2 && doc.some((e) => e?.id === 'connection')
```

本机实机验证：`bootKernel ok port=54854` → `loadURL ok` → `start() completed`，内核日志无
`without inject` / `cannot get property`，`GET /` 与 `GET /api` 均 401（服务就绪），插件中心恢复。
