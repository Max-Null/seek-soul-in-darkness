## 〇、决策（2026-08-16）

**押注 DSH。** fractal 的差异化功能以插件形式迁移到 DSH，采用「DSH 官方 GUI + 桌面壳 + 插件」形态，作为分形 2.0 的基座。

### 决策理由

1. **自主可控**：DSH 为 DeepSeek 生态（国产），与 fractal「仅 DeepSeek 唯一 Provider」的定位天然一致。
2. **技术适配**：DSH「一切皆插件」的基座，与 fractal「先插件、后 GUI」的演进路线同构，差异化功能可逐个落地。
3. **已验证**：`dsh-memory`（记忆）、`dsh-chinese-thinking`（语言）已跑通「独立插件 + npm + topic + PR」全链路；记忆引擎迁移路径已实测无空白。

### 护栏（防呆，非口号）

1. fractal（OC 版）**继续维护、继续交付**，作为稳定兜底，不因押注 DSH 而停更。
2. **渐进迁移**：按映射表「三分类」逐项搬，不一次性 all-in。
3. **退出条件**：若 DSH 长期无 tagged release 导致反复重写、或关键能力缺失且无法用插件补齐，回到 OC 基座，fractal 壳保留（EngineAdapter 边界不变）。

## 一、核心认知转变：从「切引擎」到「换基座形态」

08-14 决策否决的是「**切引擎**」——fractal 壳保留、把 OC serve 换成 DSH 引擎适配器。这条路要求 DSH 的 ACP/SDK 足够富，当时确实不成立（automation-only，无流式/会话管理/审批交互）。

今天重新审视，正确的思路是「**换基座形态**」：

```
旧思路：fractal 壳(Electron GUI) + DSH 引擎适配器   ← 要求 DSH 暴露富接口给 fractal 壳消费
新思路：DSH 官方 Web GUI + 桌面壳(exe) + 插件        ← fractal 的差异化功能做成插件，进 DSH
```

关键区别：**DSH 不是「引擎」（像 OC serve 那样被消费），DSH 是「自带完整富 GUI 的乐高基座」。** 所以不是「把 DSH 塞进 fractal 壳」，而是「把 fractal 的功能做成插件塞进 DSH」。

佐证：`dsh-skin`（换皮肤，设置页配置）验证了 GUI 外观可插件化；`dsh-web-ui`（2620★，task board / git graph / 远程 UI / 皮肤中心）验证了连面板级 UI 都能插件化。

## 二、08-14 决策「重评估条件」逐条对照（据实，2026-08-16）

| 08-14 重评估条件 | 今日现状 | 是否满足 |
|---|---|---|
| DSH 提供交互式对外接口（流式 + 审批交互 + 会话管理） | 已提供——不是 ACP/SDK，而是**官方 Web GUI 本体**（dsh-web-app bundle）及其 host 接口 | ✅ 以「官方 GUI」形态满足 |
| DSH 发布首个 tagged release、API 稳定 | 仍无 tagged release（截至 08-16），pre-release 段仍在 | ❌ 未满足 |
| OC 出现不可接受阻塞 | 无 | ❌ |

结论：**「官方 GUI」这条路让第一个条件实质满足**（无需等 ACP/SDK 变富，直接用官方 GUI + 插件）。但「无 tagged release」仍是硬风险，需单独评估。

## 四、真正要做的插件清单（增量工作）

按「能无缝搬 → 要补卡扣 → 别搬」三分类：

1. **已完成**：`dsh-memory`（记忆工具 + 闸门）、`dsh-chinese-thinking`（中文语言）。
2. **需补 UI**：`dsh-memory` 的记忆侧栏面板（浏览三层记忆 + BM25 搜索 + 确认操作）。
3. **需重做**：Guardian 状态引擎（触发线监控 → 映射到 DSH 的 `session/event` + 自建状态存储 + UI 面板）。
4. **已核实**：ui-trajectory 覆盖「回答时间线」且更强（直接用）；ui-plan 是「计划模式」非「计划文件面板」（fractal 计划面板需插件）。
5. **暂不做**：撤销/重做（DSH 无 revert，08-14 本就标「产品未接」）。

## 五、关键风险与待核实项

1. **DSH 无 tagged release**：pre-release 段仍在，`SESSION_FORMAT_VERSION=0` 无兼容承诺。押注前需接受「随 DSH 迭代反复调整」的成本。这是唯一未满足的硬条件。
2. **套壳无需自研**：社区已有现成桌面壳（anywhere-labs/deepseek-harness-desktop 5402★、bruc3van Electron「官方 UI 本体」、hairyf Tauri 等），fractal 应「选壳」而非「造壳」。
3. **已核实**：ui-trajectory 对应「回答时间线」且更强；ui-plan 是「计划模式」非「计划文件面板」。剩余 ⚠️ 仅「撤销/重做」等少数项。
4. **记忆 UI 面板**：dsh-memory 目前只有工具、无侧栏面板，这是 fractal 记忆体验搬到 DSH 的最大缺口。

## 六、下一步建议

1. 实测 DSH Web GUI 逐项核对映射表 ⚠️ 项（trajectory / plan / 设置页形态）。
2. 选定一个桌面壳（anywhere-labs 或 bruc3van）跑通「DSH GUI + 壳 + 你的插件」最小闭环。
3. 补 `dsh-memory` 的记忆 UI 面板（第一个增量插件）。
4. 按本表「三分类」排期，逐步把 fractal 差异化能力以插件形式搬入。
