# DSH 官方工程化范式调查（2026-09-10）

> 目的：DSH 的开发过程本身是 agent 驱动的（仓库大量 Agent Notes、AGENTS.md、skill 体系），其工程范式对 SSiD 的规范建设有直接参考价值。
> 素材来源：`DSHfork` @ `origin/master`（`c291e7961a`，2026-09-10）；查询命令见文末附录。
> 状态：**事实已逐条查证；「可移植清单」中的成本评估为判断，未实施**。

## 1. 三套机制总览

| 机制 | 层次 | 规模（实测） | 强制方式 |
|---|---|---|---|
| **AGENTS.md** | 规范文本 | 根 + 各包 + 各目录多份 | 靠阅读与自觉 |
| **Skills** | 方法论 | 12 个（9–60 KB/个） | 靠触发调用 |
| **Gates** | 执行 | 215 个脚本（约 50 个 `verify-*`） | **机器拒绝（CI 红）** |
| **Agent Notes** | 长期记忆 | 960 篇英文主文档（含双语共 2921 文件） | 由 `verify-agent-note-*` 部分强制 |

**关系**：AGENTS.md 说规则 → Skills 教怎么做 → Gates 检查有没有做 → Agent Notes 记录为什么这么做。

## 2. Agent Notes（长期记忆）

- **位置**：`.agents/notes/`
- **状态目录**：`proposed` / `implemented` / `archived` / **`rejected`**
- **规模**：英文主文档 proposed 21 篇、implemented 310 篇、archived 629 篇（合计 **960 篇**）；含 `.zh.md` 与 `.i18n.yaml` 共 2921 个文件
- **写入规则**（AGENTS.md 原文）："Non-trivial changes MUST include an Agent Note in the same PR; only mechanical/local edits are exempt"
- **归档策略**："Archived notes are frozen: never edit or treat them as current authority"
- **强制**：`verify-agent-note-format`、`verify-agent-note-classification`、`verify-archived-agent-notes` 三个 gate 检查格式与分类

**值得注意**：连**被否决的方案**也保留（`rejected/` 目录），供后人避免重复提出。

## 3. Skills（方法论）

- **位置**：`.agents/skills/<name>/SKILL.md`（单文件，YAML frontmatter：`name` + `description`）
- **时间线**：最早 `dsh-code-review`（2026-06-13，早于 0.1.0 发布两个月）；最新 `dsh-speed-up-perf`（2026-09-06）；最近修改 2026-09-08（`dsh-doc`、`dsh-pre-push-checks`、`record-browser-gif`）
- **清单与定位**：

| skill | 定位 |
|---|---|
| `dsh-archive-agent-notes` | Agent Notes 新增/审计/裁剪/归档 |
| `dsh-ci-test-reliability` | CI 并发、时钟、子进程、共享资源导致的非确定性失败 |
| `dsh-code-review` | PR 审查：对齐本仓规范 / 防御模式 / ADR / 质量门 |
| `dsh-doc` | 文档创建/重构/审计/迁移（受众优先层级、kind 映射 YAML 元数据） |
| `dsh-find-simplifications` | 找非显而易见的简化机会（含冗余注释与重文档） |
| `dsh-merging-stacked-prs` | stacked PR（A←B←C）落地 |
| `dsh-pre-push-checks` | 推送前选**最小必要证据** |
| `dsh-prose-standard` | 决定何处该有文档、何处该写注释（19 KB） |
| `dsh-speed-up-perf` | 把"再快点"变成可复现的用户路径测量 |
| `dsh-translate-docs` | 双语文档工作流 |
| `dsh-trim-cot-leakage` | 清除"推理痕迹泄漏"（残留 `(decision N)`、审计项代码、未提交草稿 §N） |
| `record-browser-gif` | 浏览器交互演示录为优化 GIF |

### 3.1 两个样本的范式提炼

**`dsh-pre-push-checks`**（10.4 KB）的核心主张：

- 推送前**选最小必要证据**，"without reflexively running the full repository suite"
- "There is no universal local baseline beyond the hooks"；"CI owns exhaustive coverage and the platform matrix"
- 提供专用工具：`pnpm run change-scope --base <ref>`（计算 outgoing 变更范围，且"never guesses or fetches a base"）
- 明确反模式：**"Do not manually repeat a passing check merely because commit or push follows"**
- 测试选择与覆盖度选择分离：用 `--coverage.include` 把覆盖度量限定到受影响源文件

**`dsh-speed-up-perf`**（12.2 KB，最新）的核心主张：

- "Turn a broad 'make it faster' request into reproducible user-path measurements and small, evidence-backed fixes"；"This is guidance, not a quota or a script"
- 先建立 scope（用户可见终点、负载范围、资源约束、停止规则），**backend 与 browser 端到端测量必须分开**
- 候选排序需要"production call site + 测量"，"A suspicious loop, unused cache, or large file alone is not evidence of a bottleneck"
- 实施前必须填 **measurement card**：User operation / Workload / Entry path / Clock / Memory
- 隐私红线：不得把 prompt、输出、路径、身份、ID、凭据、录制片段写进 fixture / 日志 / 截图 / PR

## 4. Gates（机器强制）

- **位置**：`scripts/`（215 个脚本，其中约 50 个 `verify-*`）
- **编排**：`scripts/run-gates.ts` —— "Run local and CI quality gates with bounded in-process scheduling"；每个 gate 有 `id` / `label` / 依赖关系
- **聚合模式（Mode，17 个）**：`ci-primary`、`ci-linux-primary`、`ci-static`、`ci-lint-contracts-ready`、`ci-coverage`、`ci-bench`、`ci-snapshot`、`ci-artifacts`、`ci-consumers`、`ci-windows-blocking`、`ci-windows-complete`、`ci-windows-observational`、`node-compat`、`check-all`、`hygiene`、`doc-sync`、`doc-quick`
- **组织约定**：一个脚本一个职责，多数配 `.spec.ts` 自测

### 4.1 分类清单（举例）

| 约束对象 | 脚本 | 拦住什么 |
|---|---|---|
| 文档 | `verify-md-links` / `-md-wrap` / `-doc-budgets` / `-doc-refs` | 死链、换行格式、字数超预算、文档引用失效 |
| 双语 | `verify-translation-pairing` | 中英文档配对缺失 |
| 包规范 | `verify-export-jsdoc` / `-package-readme-summaries` / `-readme-model-experience` / `-readme-limitations` | 导出无 JSDoc；README 必填章节缺失 |
| 架构约束 | `verify-application-entrypoints` / `-cordis-config` / `-client-domain-graph` / `-no-bare-dispatcher` | 绕过 dsh CLI 的应用入口；裸插件未声明依赖；Client 域依赖越界 |
| Agent 产物 | `verify-agent-note-format` / `-classification` / `-archived` / `-skill-invocation-metadata` | Note 格式/分类合规；skill 元数据完整 |
| UI | `verify-client-ui-i18n` | 硬编码文案（必须走 locale 字典） |

### 4.2 三个值得注意的设计

1. **`verify-application-entrypoints` 是"一切皆插件"的执法者**：架构文档声称"没有特权内核可改"，此 gate 拒绝任何绕过 `dsh` CLI 的 Node 应用入口。**约束写在文档里是愿望，写进 CI 才是规则。**
2. **README 有强制章节**：`-package-readme-summaries` / `-model-experience` / `-limitations` 分别校验三段必填内容，**包括 Known Limitations**——用机器强制诚实。
3. **`verify-skill-invocation-metadata` 是自举的**：skills 体系自身也要过格式门。

## 5. 可移植清单（对 SSiD 的价值）

| 项 | 我们的现状 | 移植成本 | 优先级 |
|---|---|---|---|
| **Agent Notes 状态机**（proposed → implemented → archived + rejected） | `docs/决策/` 为平铺结构，无状态流转 | 低（约定 + 目录） | 高 |
| **`check-rules` gate**（手册待办 #5） | 已有待办条目与检查项清单 | 中（脚本 + 编排） | 高 |
| **"最小证据"提交纪律**（手册 L1/L2/L3 已接近） | 已分级，但无 `change-scope` 类工具 | 低（纪律）/ 中（工具） | 中 |
| **measurement card 模板**（性能类改动） | 无 | 低（模板） | 中 |
| **CoT 泄漏检查**（残留 `(decision N)`、未提交草稿 §N） | 无；我们的产出物常见此类自引用 | 低（检查脚本） | 中 |
| **README 必填章节校验** | 手册 §9 有"截图演示"硬门槛；其余靠自觉 | 低—中 | 中 |
| **skill 元数据校验** | `ssid-release` 等 skill 已存在，但无格式门 | 低 | 低 |

## 6. 不可直接抄的部分

这些 skill 与 gates 是**为 DSH 仓库量身定做**的：其中命令（`pnpm run change-scope`、`pnpm run doc-sync`、`pnpm run hygiene` 等）都指向它自己的工具链，`verify-*` 的检查对象也是本仓目录结构。**可搬的是方法论与组织方式，不是命令与检查内容。**
