# v0.1.1 补丁发布决策：EPIPE 修复进安装包

日期：2026-08-17
状态：✅ 已完成（2026-08-17，Release v0.1.1 已发布）

## 背景

用户问「提交了吗？要重新打包吗？」。EPIPE 修复（`3584371`）只改了 `shell/main.mjs`，
v0.1.0 安装包仍是旧代码。是否重新打包需要决策。

## 决策：bump v0.1.1，发新 Release（不替换 v0.1.0 资产）

依据（检查更新逻辑实测，`profile-template/vendor/dsh-ssid-panels/lib/client.js`）：

```js
const newer = latest.tag !== `v${update.currentVersion}`
```

- 更新检查**只对比 tag 字符串与本地版本**。若静默替换 v0.1.0 资产（tag 不变），
  已安装用户永远判定「已是最新」，看不到修复版 → 必须发新 tag。
- EPIPE 是崩溃级 bug，语义上是 patch → 版本 0.1.1。
- 版本来源链：`shell/package.json` version → `SSID_SHELL_VERSION` 注入 →
  about API `currentVersion` → 检查更新对比。bump 该文件即可全链生效。
- v0.1.0 之后代码增量仅 EPIPE 防护一个 fix（其余两个提交是文档），0.1.1 范围干净。

## 动作清单

1. `shell/package.json` version → 0.1.1（`npm version patch --no-git-tag-version`，
   同步 package-lock root version，不让 npm 自动 commit/tag）。
2. 写 `docs/release-notes-v0.1.1.md`（修复说明）。
3. commit + push（tag 不打：由 `gh release create` 从 push 的 HEAD 建 tag，避免 tag 落后提交）。
4. `npm run pack` 重新打包（esbuild bundle-kernel + electron-builder NSIS，
   产物 `思灵 Setup 0.1.1.exe`）。
5. `gh release create v0.1.1`：正文用 v0.1.1 release notes，上传新安装包。
6. README 下载直链更新为 0.1.1 资产，收尾 commit + push。
7. 验证：Release 资产 200；v0.1.0 安装用户检查更新应显示「新版本可用：v0.1.1」。

## 已知注意点

- kernel.ts 未改动，bundle-kernel 重跑产物不变；修复仅随 main.mjs 进 asar。
- v0.1.0 Release 保留不动（用户可回退）。
- 更新机制只提示、不自动下载：用户仍需到 Releases 页手动下载安装（v0.1 现状）。
- **GitHub 会规范化资产名**：上传「思灵 Setup 0.1.1.exe」后资产实际名为
  `Setup.0.1.1.exe`（中文与空格被去除，v0.1.0 同）。README 直链必须用规范化名。
