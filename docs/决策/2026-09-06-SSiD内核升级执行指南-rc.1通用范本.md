# SSiD 内核升级执行指南（rc.1 适配通用范本 · 2026-09-06）

> 先例：v0.1.15 升级（2026-08-29 执行指南）、alpha.4 评估（2026-09-02 执行指南）。
> 本文把 v0.1.17(alpha.2) → v0.2.0(rc.1) 的完整适配过程固化为**可复制 SOP**：
> 下次内核升级（alpha.5 / 0.1.3 / rc.2…）按步骤改版本号即可；坑表逐条可查。
> 配套文档：`2026-09-04-SSiD内核升级-0.1.2-rc.1插件适配与测试体系方案.md`（前期方案）、
> `2026-09-05-rc.1适配执行日志与复盘.md`（过程记录）。

## 0. 决策与范围（先拍板再动手）

| 决策点 | 本次判据（复用于后续） |
|---|---|
| 版本号 | 内核换版 = 里程碑 → **minor 起步**；内核 rc/正式版 + 插件语义版本发布时评估 **0.2.0 级进位**（本次 0.1.17→0.2.0） |
| 未分发合并 | 上一版**无用户流量**（发布 <24h/自测未装）→ **删除旧 release+tag、合并重打**（v0.1.10/0.1.11 先例）；不浪费新版本号 |
| 平台策略 | mac = **单架构 arm64**（2020 后全 M 系）；双架构的 latest-mac.yml 互覆、增量更新缺架构条目——以后需要 Intel 再按「同 job 双 arch」设计重构 |
| 上游留言 | 官方缺陷若本地已完全规避 → **不留言**（升级即规避，除非影响长尾生态） |

## 1. 升级前准备

1. **定内核 tag**：`git tag` 查官方最新（如 `dsh-v0.1.2-rc.1`）；`git -C deepseek-harness checkout <tag>`。
2. **前置检查**：`git status` 干净、`git log v上版本..HEAD` 收集分组素材、安装目录归档备份。
3. **dev profile 洁净**：跑 `npm start` 前确认 profile 无半成品（`.deploy.*`/`node_modules.old*` 清理见坑表 K9）。

## 2. 内核接法（单一来源 + 全量锁版）

- **DSH_VERSION 单一来源** = `deepseek-harness/apps/cli/package.json`（prepare-runtime 自动读取；CI 用完整 clone 的同 tag）。
- **overrides 全量切版**：`shell/profile-template/pnpm-workspace.yaml` **214 条 @deepseek-ai/dsh-\* 全部换成新版本串**（**无混杂**——半切 = 闭包混版本必 boot 坏）。
- **聚合包**：prepare-runtime `[3/5]` 注入 `@deepseek-ai/dsh@<ver>` + 32 个丢失 peer（精确 pin，无 `^`）。
- **官方 rc 依赖范围缺陷规避**（K1）：官方子包依赖 `>=0.1.2 <0.2.0-0` 匹配不到 rc 预发布 → 靠 overrides 强制 + 插件 peer 侧精确 pin。

## 3. 插件适配

- **第三方升级规则**：升到 npm 最新；本地超前以本地为准；大跳版先核实 author/peer 再 install。
- **自研插件**（@max-null/*）：**L1 = typecheck + test 全绿**才能发；适配 rc.1 变化点优先看官方 settings 三段式（host `installSection` + client `settingsScope.bind` + `settings.plugin.item` keyed 卡片）。
- **双处声明**：profile-template/package.json pin（新 minor 必须显式改）+（vendor 化插件的）vendor/package.json 版本号。
- **vendor 三处同步**：plugins 源构建产物 → profile-template/vendor → dev profile vendor；`git diff --no-index` / MD5 双核对。
- **发布**：npm publish 用户手动（F2A）；**发布必须在归档重建前**（archives 按 pin 解析）。

## 4. 归档构建

```powershell
cd shell
node scripts/prepare-runtime.mjs   # 3-5 分钟；完成前不得动 ssid profile 的 pnpm
```
- **运行约束**：官方源（不设 SSID_REGISTRY）；归档约 147 MB（本版）；`.runtime-version = <ssidVer>-<dshVer>-<指纹>`。
- **验证指纹**：`0.2.0-0.1.2-rc.1-86e1fb66` 形态（ssidVer 与 shell/package.json 一致、dshVer 与 checkout 一致）。

## 5. 验证链（发版门槛，按序全过）

1. **守卫单测**：`node --test shell/updater-core.test.mjs`（7）+ `node --import tsx/esm --test plugins/dsh-ssid-panels/tests/release-notes.test.ts`（3）。
2. **归档抽查 8 项**（解包 dsh-runtime/ 后）：`.runtime-version` 前缀 / dream-skin 版本+lib / plugin-center pin / better-sidebar pin / capture lib==vendor 源 / dependencies 新 pin / vendor 三包版本 / release-notes 首行 `# vX.Y.Z`。
3. **打包版自检**（isPackaged 分支必须实测——v0.1.14 教训）：win-unpacked 启动 → 日志 `deploy → bootKernel ok` → 骨架断言。
4. **smoke-ui**：`node .agents/skills/ssid-release/smoke-ui.cjs --cdp <port>`（打包版用 `--remote-debugging-port=9334` + CDP 模式；裸 URL 撞认证页）。
5. **mac CI**：push tag 自动触发 build-mac（单 arm64 job）→ 成功后核对 Release 资产与 latest-mac.yml url 一致。

## 6. 交付（GitHub 五件事）

1. commit → push main → `git tag vX.Y.Z` → push tag（触发 mac CI）。
2. `gh release create`（--notes-file）+ 资产上传。
3. **资产命名**（K5）：electron-builder 产物中文名 → **英文名副本**上传（`ssid-shell-setup-<ver>.exe`），必须与 latest.yml/latest-mac.yml 的 url 完全一致。
4. **大文件上传**（K8）：gh CLI 传 256MB+ 会挂 → `curl --proxy http://127.0.0.1:7897 -F "file=@..."`（uploads API + 数字 release id）；慢但要完成。
5. 核对 `gh api releases/tags/vX.Y.Z` 资产清单、清理旧名残留（`gh api -X DELETE .../assets/<id>`）。

## 7. 坑表（本次全部，按触发频率排序）

| # | 坑 | 症状 | 处理 |
|---|---|---|---|
| K1 | 官方 rc 依赖范围缺陷 | 干净安装 NO_MATCHING | overrides 强制 + 插件 peer 精确 pin |
| K2 | DSH 版本漂移（CI sparse clone 默认分支） | 归档注入 `0.1.3-alpha.1` | clone 钉 `--branch dsh-vX.Y.Z` |
| K3 | pnpm shim（CI `.bin/pnpm` 是 shell） | `SyntaxError` | prepare-runtime 只收 `.cjs` 入口 + bundled pnpm 兜底 |
| K4 | esbuild 幽灵依赖 | mac `esbuild: command not found` 127 | bundle-kernel 的 esbuild 显式 devDep |
| K5 | GH 中文资产名剥离 | 资产名缺中文、与 yml url 不一致 | artifactName 全英文（`ssid-shell-${version}-${arch}.*`） |
| K6 | afterPack 钩子文件换行丢失 | `handler is not a function` | 提取仓库文件一律 node execSync 按字节（禁用 Out-File -NoNewline） |
| K7 | mac 双 job 的 latest-mac.yml 互覆 | 增量更新缺架构条目 | 单 arch（arm64）；需 Intel 时重构同 job 双 arch |
| K8 | gh 上传大文件挂死/404 | 256MB 上传无进展 | curl 直传（显式代理）+ 数字 release id |
| K9 | deploy EPERM `.deploy.old` | 打包版首装失败 | 清 profile 运行时残骸（node_modules/old/old2/.upgrade-backup）走首装路径 |
| K10 | vendor 根有非目录条目 | mac ENOTDIR | 清 vendor node_modules 前 `isDirectory()` 过滤 |
| K11 | 插件中心重复提示 | 同插件更新提示两次 | plugin-center checkUpdates 按包名去重（0.2.18） |
| K12 | 归档后插件的「过期感」 | 用户疑「归档为何不最新」 | **归档 = 发版时刻 pin 快照**；作者新发布走插件中心一键更新；模板 pin 同步下次发版自然带 |

## 8. 回滚

- **未分发**：`gh release delete <tag> --yes` + 删远端 tag（`git push origin :refs/tags/<tag>`）+ 本地 `git tag -d`；force tag 新 commit 重触发 CI。
- **已分发**：发补丁版本（合并重打原则：无用户流量才算未分发；有流量走新版本号）。
- **运行时**：版本指纹不一致 → 下次启动自动重部署；profile 坏 = 清残留走首装（K9）。

## 9. 固化的通用约定（本次拍板，后续遵循）

- 插件生态更新**不进 SSiD 版本**——插件中心一键更新 + 模板 pin 同步（下次发版归档自然最新）。
- MCP 管理列表 = mcp-client loader 条目（cordis.patch.yml `name: '@deepseek-ai/dsh-mcp-client'` 行）；模板预置 playwright（`@playwright/mcp@0.0.80`），纯净 profile 空列表是设计而非缺陷。
- dev 裸跑隔离：dev 跳过归档部署、就绪信号 = 内核实体（`@deepseek-ai/dsh`）——清预设不再触发回灌死循环。
