# SSiD 发版流程规范

> 适用范围：思灵（SSiD）安装包发布（`shell/` + 内置运行环境归档 + profile 预置插件）。
> 依据：v0.1.12 发布全流程复盘（2026-08-25），含期间踩坑与修复。
> 原则：**发版 = 版本号 + 内置插件对齐 + 归档 + 更新日志 + tag/Release 五件事一次做完**，
> 漏一项即视为未完成发版。

---

## 0. 版本决策

- **未外发版本合并重打**：上一版从未分发（无 GitHub Release）时，不单独发版，
  全部改动并入下一版本号重打（v0.1.10/v0.1.11 先例）。
- **版本号步进**：修复+攒小改 → patch；功能增强 → minor（dsh-capture 因截图标注
  增强/预览编辑闭环定 0.2.0 先例）；破坏性/大重构 → major。
- 定版日期写进发布说明；「更新说明」节必须包含给老用户的升级行为描述
  （自动重部署约 30 秒等）。

## 1. 内置插件对齐（发版前必做，本次主要踩坑区）

### 1.1 vendor 定制插件（dsh-capture / open-sea-skin tgz / ssid-panels 等）

- **源码 bump 后必须同步 vendor**：`lib/*`（构建产物）+ **`package.json` 版本号**
  （v0.1.12 案例：dsh-capture bump 0.2.0 时只同步了 lib，deploy 后插件中心持续
  误报更新）。
- open-sea-skin：定制用 `scripts/repack-open-sea-skin-vendor.mjs` 重打 tgz
  （幂等补丁），**改完跑一遍脚本确认产物与说明一致**。
- 校验清单：
  - `git diff --no-index <plugins 源>/lib <vendor>/lib` 一致；
  - 无 src 的纯产物包跑各自 `verify-*.cjs`；
  - 源仓库 git 状态干净（未提交的源码改动不进包）。

### 1.2 npm 预置插件（profile-template/package.json）

- **0.x 的 caret 不跨 minor**：`^0.15.2` 不会装 0.16.0——想要新 minor 必须显式
  改 pin（v0.1.12 side bar 案例）。
- 更新 pin 后核对 npm 最新版；**插件 npm 发布必须在归档重建之前**完成
  （归档按 pin 解析，晚了就装旧版，需重打）。
- 插件中心（dsh-plugin-center）走 `^0.2.x` 自动解析；host 侧修复必须发布 npm
  后重打归档才能进安装版。

## 2. 更新日志（docs/release-notes-vX.Y.Z.md）

- 每版本一份，格式沿用现有惯例（内置升级 / 新增 / 调整 / 修复 / 更新说明）。
- **未外发版本也要追记**（标注「vX.Y.Z 本地构建验证版，未对外分发，内容并入
  下一版」）——本次 v0.1.10/v0.1.11 漏写后按 git log 补记。
- 分组依据从 git log 提炼（`git log --oneline --grep 版本号` 回溯），不凭记忆。
- 发布说明随 tag/Release 使用（见 §6）。

## 3. 版本号同步点（四处）

| 位置 | 动作 |
|---|---|
| `shell/package.json` `version` | bump（prepare-runtime 的 ssidVer 来源） |
| `.runtime-version`（归档内） | prepare-runtime 自动生成（ssidVer-dshVer-指纹），勿手改 |
| profile 内 `.runtime-version` | 由启动 deploy 自动对齐，勿手改 |
| GitHub tag `vX.Y.Z` | 与 package.json 严格一致 |

## 4. 归档重建（prepare-runtime）

- 命令行：`node scripts/prepare-runtime.mjs`（shell/ 目录；约 3-5 分钟）。
- **运行约束**：完成前**不要**在 ssid profile 上做任何 pnpm 操作（会扰动
  lockfile；vendor 定制依赖 archive 一致性）。
- 完成后**完整性检查**：归档约 **185 MB**（明显偏小 = 被中断/损坏，如绿屏案例
  7.4MB 半成品，必须重跑）；`tar -tzf` 可列出。
- 产物不入库（`.gitignore: shell/dsh-runtime.tar.gz`），由安装包内嵌。

## 5. 归档内容抽查清单（解包验证，发布前必须全过）

```powershell
# 完整解包后核对：
# 1) .runtime-version == <ssidVer>-<dshVer>-<指纹>
# 2) open-sea-skin/plugin/client.js 含 "enabled: false"（SSiD 定制默认关闭）
# 3) @max-null/dsh-plugin-center/package.json version == npm 最新（含 hot/no-op 逻辑）
# 4) dsh-better-sidebar/package.json version == pin 预期
# 5) @max-null/dsh-capture/lib/client.js 含最新功能标记（如 dsh-img-edit-btn）
# 6) package.json dependencies 含本轮新增（如 @playwright/mcp…）
# 7) vendor 包 package.json 版本号与源仓库一致
```

## 6. 打包与发布

1. `npm run bundle-kernel` + `npm run pack`（electron-builder NSIS）：
   - 日志出现 `[after-pack] dsh-runtime.tar.gz OK (185.0 MB)` = 归档已内嵌；
   - 产物 `dist-electron/思灵 Setup <ver>.exe`（签名 + blockmap）。
2. 本机 dev 验证：重启思灵 → 日志 `runtime deploy needed (archive=<ver> proxy=<old>)`
   → deploy 成功 → boot 正常（MCP/热键/侧栏诊断），抽查关键插件版本。
3. **GitHub 交付**：
   ```powershell
   git add -A; git commit -m "release: vX.Y.Z ..."; git push
   git tag vX.Y.Z; git push origin vX.Y.Z
   gh release create vX.Y.Z -R Max-Null/seek-soul-in-darkness `
     --title "思灵 vX.Y.Z：..." --notes-file docs/release-notes-vX.Y.Z.md --latest
   gh release upload vX.Y.Z "shell/dist-electron/思灵 Setup X.Y.Z.exe" `
     -R Max-Null/seek-soul-in-darkness
   ```
4. 未外发版本：打追溯 tag（可），不建 Release（惯例）。

## 7. 常见坑（累积）

- vendor `package.json` 版本号漏同步 → 安装版首启插件中心持续误报「可更新」。
- `^0.x.y` pin 不跨 minor → 显式改 pin，否则归档悄悄装旧版。
- 插件 npm 发布晚于归档重建 → 归档旧版（需重打归档 + 重打安装包，两趟）。
- 归档被进程/电源中断 → 体积异常必重跑；tar 有 partial 列表但仍损坏。
- SSiD 内 pnpm add 可能静默 no-op（exit 0 未落盘）→ plugin-center 已有版本核对
  防护（v0.2.12），升级说明中提示手动命令兜底。
- **`cordis.patch.yml` 的 insert 子条目必须带显式 `id`**（如 `- id: mcp-playwright`）：
  无 id 时 loader 在启动时分配随机 id（`Math.random()`），plugin-center 禁用写入
  的 `- id: <随机id>` 行重启后永远匹配不到（warn 后静默跳过）→ 禁用失效 +
  垃圾行累积（2026-08-25 vuln 实证：dsh-web-preview-panel 禁用无效）。插件中心
  修复前，社区插件（`dsh plugin add` 标准格式无 id）禁用同样受影响。
- 绿屏/断电后：先检查归档与后台任务再继续，不要直接复用疑似半成品。
