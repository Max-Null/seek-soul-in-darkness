## 直接死因

`kernel-child.log` 中的退出堆栈：

```
Error: EPERM: operation not permitted, rename
  'C:\Users\21030442\.dsh\storages\guardian\.1d66850a-…-114606ce2286.tmp'
  -> 'C:\Users\21030442\.dsh\storages\guardian\guardian.json'
    at async rename (node:internal/fs/promises:1426:10)
    at async writeAtomic (…/@deepseek-ai/dsh-storage-json/lib/index.js:35:3)
  errno: -4048, code: 'EPERM', syscall: 'rename'
```

`writeAtomic`（`@deepseek-ai/dsh-storage-json` 0.1.5-rc.2，`lib/index.js:25-41`）的协议是：写同目录 `.tmp` → `fsync` → `rename` 覆盖目标。libuv 把 `rename` 映射为 `MoveFileExW(..., MOVEFILE_REPLACE_EXISTING)`；当目标或源文件被**另一个进程**打开且未共享 `FILE_SHARE_DELETE` 时，该调用返回 `ERROR_ACCESS_DENIED`，Node 映射为 `EPERM`。

## 因果链

**触发**：`edit` 工具成功 → `@max-null/dsh-guardian` 0.2.0 的 `engine.js` 在 `tool/result` 分支调用 `enqueueReview` 与 `flushQueue()`，随后 `turn/end` 再调用 `flushSession()`，两者都写 `$DSH_HOME/storages/guardian/guardian.json`（`single` 布局，每次整文件重写）。

**放大**：写入失败后错误沿 `flushSession` → `handleEvent` 冒泡，而事件入口用 `void this.handleEvent(session, event)`（`engine.js:117`）丢弃了返回的 promise —— 该 rejection 无人接管。同时 `writeChain`（`engine.js:176-188`）一旦 reject 便保持 rejected，链上后续写入会立即失败。

**致命**：Node 26 默认把未处理的 rejection 当作致命错误。存储写失败因而终止**整个内核进程** —— 没有隔离、没有降级、没有重试，一个 unit 的一次写盘即可带走所有会话。

`ERR_IPC_CHANNEL_CLOSED` 是独立的次生故障：壳 relaunch 时父进程退出、IPC 通道关闭，`kernel-child.bundle.mjs:617` 的 `process.send` 抛出的 `'error'` 事件同样未被捕获。

## 根因实测证据

崩溃来自**环境层的进程外文件锁**，与 DSH 代码并发无关。用探针复现同一协议（写 `.tmp` → `fsync` → `close` → `rename` 覆盖已存在目标），**单进程串行**循环：

| 位置 | 次数 | EPERM 次数 | 失败率 |
|---|---|---|---|
| `C:\Users\21030442\.dsh` | 1500 | 45 | 3.0% |
| `C:\Users\21030442\Documents` | 1500 | 19 | 1.3% |
| `C:\Users\21030442\.ssid` | 1500 | 9 | 0.6% |
| `C:\Users\21030442\AppData\Local\Temp` | 1500 | 6 | 0.4% |
| `D:\Project\ssid\.build`（对照） | 3000 | 0 | 0% |

探针为单进程串行，任何失败都只能来自进程外的持有者。**C 盘（系统盘）普遍受影响，D 盘 3000 次零失败。**

失败呈两种形态，决定了修法：

| 重试策略 | 样本 | 结果 |
|---|---|---|
| 无重试 | 1500 | 3.0% 失败 |
| 立即重试（无延迟，最多 5 次） | 800 | 3 次 1 次即成功；**8 次连续 6 次仍失败** |
| 带退避重试（10/30/100/300/1000 ms） | 2000 | 11 次触发重试，**全部恢复，0 次最终失败** |

即：锁绝大多数是瞬时的，但**不带延迟的立即重试吸收不了**。带退避的重试吸收了样本内的全部失败，零硬失败。

## 未确证部分

**锁的持有者身份未取得直接证据。** 本机常驻奇安信天擎（`TQDefender` / HIPS / `AntiRansom`，其 `defender\*` 组件时间戳为 2026-09-16 11:32）与深信服 SSL；Windows Defender 已关闭（`AMServiceEnabled=False`）。天擎日志目录（`Program Files (x86)\Qianxin\Tianqing\Log`）不可读，未能取到扫描记录。已确证的是「存在进程外瞬时锁」这一事实本身，持有者归属停留在嫌疑层面。

探针以每秒约 100 次 `rename` 施压，失败率被放大；真实业务写入稀疏，因此表现为「偶发崩溃」而非必崩 —— 崩溃概率随写盘密度上升，密集编辑的会话暴露面最大。

## 修复方向

| 层面 | 动作 | 效果 |
|---|---|---|
| 内核（上游） | `writeAtomic` 增加带退避的重试（同类问题见 npm/write-file-atomic #227） | 消除触发源；实测样本内零硬失败 |
| 插件（guardian） | 写链与事件入口各自兜底，见下 | 写失败降级为「丢一次状态」，内核不受影响 |
| 环境 | 给安全软件加白名单（`node.exe` 或 `.dsh` 目录），或将数据目录置于 D 盘 | 消除触发源（D 盘实测零失败） |

插件侧的两处改动可独立生效，且在其它走 `storages` 的插件上同样适用：

```js
// 1. 写链自愈：失败不得让 writeChain 保持 rejected（否则后续写入全部立即失败）
writeChain = this.writeChain
    .then(async () => { await this.unit?.putRecord(SESSIONS_TABLE, sessionId, state); })
    .catch((error) => { /* 记录并吞掉：本次状态未落盘，链保持可用 */ });

// 2. 事件入口兜底：rejection 不得逃逸到进程（当前是 void this.handleEvent(...)）
this.ctx.on('session/event', (session, event) => {
    this.handleEvent(session, event).catch((error) => { /* 同上 */ });
});
```

审查队列是**可重建的提示性状态**，落盘失败的正确后果是丢失一次入队，而非终止承载全部会话的内核进程。

## 复现方法

探针核心（Node，单进程串行；目标文件须已存在以走替换路径）：

```js
import { open, rename, rm, mkdir } from 'node:fs/promises';
import { join } from 'node:path';
import { randomUUID } from 'node:crypto';

const dir = process.argv[2], rounds = Number(process.argv[3] ?? 3000);
const target = join(dir, 'probe-target.json');
await mkdir(dir, { recursive: true });
let ok = 0, failed = 0;
for (let i = 0; i < rounds; i++) {
  const tmp = join(dir, `.${randomUUID()}.tmp`);
  const handle = await open(tmp, 'wx', 0o600);
  try { await handle.writeFile('{"i":1}\n', 'utf8'); await handle.sync(); }
  finally { await handle.close(); }
  try { await rename(tmp, target); ok++; }
  catch (error) { failed++; await rm(tmp, { force: true }).catch(() => {}); }
}
console.log({ dir, rounds, ok, failed });
```

2026-09-17 实测所用的三个探针（频率统计、立即重试、退避重试）留在 `D:\Project\ssid\.build\` 下的 `tmp-probe-rename.mjs`、`tmp-probe-retry.mjs`、`tmp-probe-backoff.mjs` —— `.build` 为临时目录，上面的片段可独立复跑；会话日志解压脚本为 `.build\tmp-dump-session.mjs`（`session.v3.jsonl.zstd` 为多帧追加，须按 zstd magic `28 B5 2F FD` 逐帧切分解压）。
