# 排查记录：切换应用后 SSID 不定时跳出（抢焦点）

> 2026-08-20 · 状态：**待反馈者复现定位**（诊断日志 + 日志基建修复已就位，随下次打包生效）· 来源：其他用户反馈（本人未复现）

## 现象

SSID 的内置 DSH 会话输出过程中，用户切换到其他应用后，SSID 会不定时跳出（反馈者确认：**整个窗口跳到最前面/抢焦点**）。

补充确认（2026-08-20 二轮问询）：
- 跳出时**没有**弹出"选择文件夹"对话框；
- 跳出**伴随文件编辑操作**（AI 正在编辑文件时发生）；
- 反馈者本人当前无法复现（非高频/环境相关）。

## 已排查并排除的路径

| 路径 | 结论 |
|---|---|
| 主进程 `win.show()/focus()` 调用点（启动 splash L230、start 末尾 L1037、托盘 L987/1004、second-instance L1032-1033） | 全部为**手动/启动触发**，无会话相关自动调用 |
| `setAlwaysOnTop` / `flashFrame` / `setSkipTaskbar` | 全仓无调用 |
| kernel.ts / kernel.bundle.mjs（cordis 宿主） | 无任何窗口操作；未向 DSH host 暴露 electron/窗口能力 |
| 内置插件（dsh-ssid-panels / dsh-header-unify / dsh-ssid-zh-ui） | 无窗口操作（panels 只有通知配置面板） |
| `maybeNotify` 通知体系（main.mjs L938-970） | 只弹系统通知 + 提示音（Asterisk），**Electron 通知不抢窗口焦点**；输出中每次工具授权/提问/完成会触发（切走后 isFocused=false），观感为"右下角横幅+声音"，与"整窗跳出"不符 |
| worker 模式（main.mjs L74-142） | worker 用**纯 node.exe** 执行（明确排除 execPath），不触发 second-instance |
| `before-input-event`（F12 devtools）/ `dom-ready`（主题同步）/ `console-message` | 与窗口焦点无关 |

## 强嫌疑（未验证）

**DSH 目录选择器（dsh-host-directory-picker-native）的 Win32 文件夹对话框**：

- AI 在会话输出中调用目录选择工具时，host `spawn(process.execPath, [worker.cjs])`（win32-dialog-host.ts L28，execPath = 思灵.exe）
- worker 分支再 spawn 纯 node.exe → koffi 调 `IFileDialog`（Win32 文件夹对话框）
- **Win32 模态对话框弹出时 Windows 会将其激活到前台**——用户在别的应用时突然弹框，感知为"SSID 跳出"
- "不定时"吻合：AI 输出中不定时调用目录选择（选工作区/文件夹）

## 已加诊断（v0.1.x 分支，随下次打包生效）

`shell/main.mjs`：
- `win.on('focus' | 'show' | 'restore' | 'minimize')` → `safeLog('ssid: win <event> event @ <ts>')`
- `app.on('browser-window-focus')` → `safeLog('ssid: browser-window-focus @ <ts>')`
- `second-instance` handler → `safeLog('ssid: second-instance triggered @ <ts>')`
- **日志基建修复**：`safeLog` 原实现不建目录，`~/.ssid` 不存在时首次 `appendFileSync` ENOENT → `logFileDead=true` **整个会话日志静默丢失**（本次排查中实测 `~/.ssid` 目录不存在、日志为空）。已改为写入前 `mkdirSync(dirname, {recursive:true})` 兜底。

## 复现定位步骤（给反馈者）

1. 安装带诊断日志的新版后复现：会话输出中切走 → 等跳出；
2. 跳出后收集 `~/.ssid/ssid.log`（**新版才有日志**，旧版因基建 bug 可能为空）：
   - 跳出时刻附近有 `win focus/show/restore event` → 窗口确实被激活，往前翻对照同时间段的 `notify` / `[worker]` 记录找触发源；
   - 有 `second-instance triggered` → 第二个实例来源（对照任务管理器 electron 进程数变化）；
   - 两者皆无 → 系统级行为（此时重点核对：跳出时**是否弹出文件夹选择对话框**、或任务栏是否有新图标闪烁）；
3. 反馈者补充信息：跳出瞬间**任务管理器 electron 进程数**是否瞬时增加（6→7 之类）。

## 候选修复方向（待确认根因后实施）

| 方向 | 说明 |
|---|---|
| 对话框附着主窗口 | worker 弹框前通过 IPC 传主窗口 HWND 作所有者（IFileDialog 的 owner），对话框不再独立跳出（但模态仍会打断） |
| 通知引导 | 目录选择器触发时先发通知"请回到思灵选择目录"，由用户主动回 SSID 再弹框（改动大，涉及 DSH host 侧） |
| second-instance 静默化 | 若根因是 second-instance：`win.show()` 改 `win.showInactive()` 或仅任务栏闪烁，不抢焦点 |
| maybeNotify 降噪（若反馈者实际感知为通知打扰） | approval 场景通知去提示音/可单独关闭，减少"输出中被反复打扰"的观感 |
