# 思灵控制台持续报 `plugins/??…404`：页面手上的插件批已过期

> 状态：**根因已定位，影响面已界定**（2026-09-29）
> 影响面：**功能不受影响**（客户端会降级到每个插件自己的单行 URL，实测 29/29 返回 200）；代价是控制台噪声（每行最多 3 次请求）
> 处置：刷新页面即取当前清单；**不需要重启、不需要改 profile**
> 相关：`2026-09-29-1.1.0启动失败-插件peer与内核脱钩.md`（同一次升级的另一条线）· 记忆里的 dev 侧同形故障（覆盖插件落点后 `client.js` 404，判据一律「重启 host」）

## 一、症状

装版思灵（1.1.1，内核 `0.2.0-rc.1`）的 DevTools 控制台持续报同一批客户端插件请求失败：

```
dsh-app://app/plugins/??@max-null/dsh-ssid-zh-ui/client.js,…（29 个插件）…&rev=c2f052c87159
```

## 二、判据：404 是怎么产生的

`ClientModuleRegistry.bundleResource()`（`packages/client/modules/src/index.ts`）对 `/plugins` 下的一切请求**只服务三种 URL**：

1. **当前广播的批**（`responses`，键是 `路径+查询`，即 `<插件列表顺序>+rev` 的完整字面量）；
2. **上一批**（`previousBatchResponses`，只为 HMR 过渡保留一批）；
3. 精确匹配当前 rev 的**包内 chunk**。

其余一律 `404`。因此**组合与 rev 两者都必须逐字一致**——同 rev 换组合、同组合换 rev，都是 404。

`rev` 是内容寻址的：批的 rev 由各行的构建指纹合成（`comboRevision`），行的 rev 由该 `client.js` 的 `mtime/ctime/size` 算出（`artifactRevision`）。所以**插件集一变（哪怕只是多一个包），批的 rev 与组合同时变**。

## 三、取证

探针：`node shell/scripts/ssid-host-probe.mjs manifest`（用 `$DSH_HOME/.credentials.yaml` 里的浏览器会话密钥自签 cookie，只读地问 Host；壳平时就是靠这枚 cookie 转发请求的，裸 curl 只会得到 401/404 的混合噪声）。

**Host 当前广播**（连续三次请求 `/` 结果一致，清单不抖）：

| 批 | rev | 项数 |
|---|---|---|
| A | `76b40999fb48` | 58 |
| B | `e197aed779c8` | 32 |
| 单行引用 | 每包一条 | 92 |

**控制台报的那份不在其中**，且它与当前批 B 的关系是：

- 报的 29 项 = 批 B 的 32 项 **减去** 3 个官方实验插件的客户端半球：
  `@deepseek-ai/dsh-experimental-client-ui-agent-team`、`@deepseek-ai/dsh-client-ui-schedule`、`@deepseek-ai/dsh-experimental-client-ui-voice-input`；
- 报的那 29 项**全部仍在批 B 里**（无移除项）。

**四组对照**（同一端口、同一 cookie）：

| 请求 | 结果 |
|---|---|
| 报的（29 项 + `c2f052c87159`） | **404** |
| 29 项 + 当前 rev `e197aed779c8` | **404** |
| 当前 32 项 + 当前 rev | **200 / 27.9 MB** |
| 当前 32 项 + 报的 rev | **404** |

Host 服务本身完全正常；**404 只因为这份组合已经不在广播里**。

**降级路径健康**：`rows` 子命令逐条验证每个插件的单行 URL（`plugins/??<id>/client.js&rev=<rowRev>`），**92/92 返回 200**；其中报的那 29 个插件 **29/29 返回 200**。且插件实体全部是安装时刻（17:31:58）写入的，实例启动（18:24）之后**没有任何插件文件被改动**——所以行的 rev 没有变，页面降级时用的行 URL 与 Host 当前的一致。

## 四、根因

页面手上的批，是它**加载那一刻** Host 广播的批；此后插件集变化会让 Host 重算批，旧批从「当前」落入「上一批」之外，随即 404。

这次插件集的变更是**配置文件在运行中被改写**：

| 时刻 | 事件 |
|---|---|
| 17:31:58 | 安装 1.1.1（安装目录全部文件写入） |
| 18:24:00 | 启动实例（主进程、页面 renderer、Host 同在 18:24:00–02） |
| **18:41:04** | **`~/.dsh/profiles/ssid/package.json` 被改写**——实例启动后 17 分钟，且这是启动后**唯一**被改动的 profile 文件（`node_modules`、`pnpm-lock.yaml` 都停在 9/28，没有跑过包管理） |
| 18:32:40 | 另有一个 renderer 启动（第二个页面/窗口） |

改写后的声明末尾是 4 个官方骨架 bundle（`@deepseek-ai/dsh-experimental-agent-team-profile` / `-auto-review` / `-schedule-bundle` / `-voice-input-bundle`），其中 3 个有客户端半球——正好是批 B 比报的那份多出来的 3 项。这 4 个**不在**随包插件集清单里（`resources/ssid-plugins/ssid-plugins.json` 的 `bundles`），所以它们来自**官方 profile 骨架**，由壳侧的骨架/接入逻辑写进声明：

- `apps/desktop/src/project-manager.ts` 的 `createRuntimeProjectMetadata` / `applyRelease`：写 `dsh.profile.bundles: [...WEB_PROFILE.bundles]`（官方骨架）；
- `apps/desktop/src/ssid/profile-seed.ts` 的 `seedProfilePlugins`：幂等地**追加**思灵的随包插件集（`bundles` 与 `dependencies` 只补缺失项）。

**推断链（非直接观测改写前内容）**：profile 声明被改写 → Host 的 `ClientModuleRegistry` 重算客户端插件表 → 批从 29 项重分为 32 项 → 18:24 加载的页面手上那份批成为「未广播组合」→ 它的请求 404，且**页面没有重新导航**（没有走内核重启那条会「连导航一起重来」的路径），于是一直用旧批重试。

## 五、影响与处置

**影响：功能面没有损失。** 客户端对一个失效批的处理是（`packages/client/modules/src/client/system.ts:arrive`）：同一 URL 重试一次 → 记入 `failedBundleUrls`（本批后续不再重复请求）→ 降级到该行自己的单行 URL，而 Host 对每个包都提供单行 URL。实测 29/29 单行 URL 返回 200，所以这 29 个插件都加载成功；控制台看到的红色记录属于**噪声**。

**处置：刷新页面**（`Ctrl+R`）。页面重新取 Host 的 index 文档，拿到当前的批（32 项 + `e197aed779c8`），404 消失。不需要重启思灵，也不需要动 profile。

**下次启动是否复发**：取决于启动后是否还会改写 profile 声明。若声明已是最终形态（本机现在稳定，连续观测 mtime 不变），则不复现。判据：下次启动后看 `~/.dsh/profiles/ssid/package.json` 的 mtime 是否晚于启动时刻——晚于，就是同一条链又走了一遍。

## 六、可复用的判据

1. **控制台报 `plugins/??…` 失败，第一步是取状态码**——431（cookie 累积超 16KB 头限）、404（组合未被广播）、503（协议层 Host 未就绪）指向完全不同的三处，别猜内容。
2. **分不清「路由没注册」与「组合没广播」时，用探针带认证问 Host**，看它此刻广播了哪些批；裸 curl 的 401/404 不具备区分力。
3. **`rev` 与组合必须同时一致**：把报的 URL 与当前广播逐字段比（项数与 rev 各比一次），比"看起来差不多"可靠。
4. **报的批是当前批的子集** ⇒ 页面比 Host 旧（插件集在页面加载后变化），刷新即恢复；**报的批与当前批交叉**（各有对方没有的项）⇒ 是两次不同的分组，要查插件启用条件而不是刷新。
5. **判「功能坏没坏」看单行 URL**，而不是批 URL——批是优化（并行加载），单行才是每条记录的保底通道。
6. 排查这类问题前先 `git status`（本仓约定）：本次读的是 `.ssid-build/checkout`（开发主轴）的实现，而装版内核在 `resources/app.asar/dsh/` 里；两者版本可能不同，机制一致但行号会漂。
