## 三、根因：会话根隔离是**三层契约**，fork 只落了一层

`dsh-ssid-panels` 的设计文档明确要求三层：

1. **env 注入** —— 壳启动时写 `SSID_SESSION_ISOLATED_ROOT` / `SSID_SESSION_SHARED_ROOT` / `SSID_PROFILE_DIR`
2. **patch 覆盖 `session-persistence-jsonl.root`** —— 真正改内核读哪个根
3. **状态回写** —— `kernel.ts` 把本次 boot 实际生效值写进 `~/.ssid/session-root.json` 的 `applied`

**实际只做了第 1 层。** 第 2 层是会话根错乱的真正根因，而它**从未落到任何一份 profile patch 里**：

- `seek-soul-in-darkness/shell/profile-template/cordis.patch.yml` 全文仅 7 行，只有 `- insert: [- id: ssid-panels, name: '@max-null/dsh-ssid-panels']`；整个 `profile-template/` 目录搜不到 `session-persistence-jsonl`
- 而设计文档 `profile-template/vendor/dsh-ssid-panels/docs/2026-08-22-会话存储隔离开关-设计方案.md:20` 白纸黑字写着「`session-persistence-jsonl` 的 `root: ~/.dsh/sessions-ssid` 覆盖 patch」
- 官方基座侧供给点在 `packages/bundle/base/cordis.patch.yml:130-133`（`root: !!js dshHomePath('sessions')`），`:147-148` 明确写了覆盖方式："later patch layer (profile `cordis.patch.yml` or a `--patch` overlay)"
- `dsh-ssid-panels` 只**读**这两个根（做 UI 与 `sessionRoot.import/.clear/.get/.set/.restart` API，`src/index.ts:386,395-412,520-602`），它**改不了内核的根**

另有一个空白：`2026-09-24-内核0.1.7适配-壳侧方案.md` 通篇没提会话根（按 `session|root|patch|storages|工作区` 检索零命中）—— 0.1.7 适配的破坏点清单里缺了这一项。

### 三层契约在壳里的落点

- `apps/desktop/src/ssid/profile-name.ts:68-69` 是 `apps/desktop/src` 下**唯一**碰 `SSID_SESSION_ISOLATED_ROOT` / `SSID_SESSION_SHARED_ROOT` 的地方
- `apps/desktop/src/main.ts:651-677` 的启动顺序（已确认顺序正确，`installSsidMcpEnv` 的插入没有破坏 MCP 注入）：
  `installSsidMcpEnv`(659) → 日志 `ssid: mcp ready …`(665) → `installSessionRootEnv`(671) → 日志 `ssid: session roots isolated=… shared=…`(672) → `await host.start()`(673)
- `SSID_PROFILE_DIR` 注入与 `session-root.json` 的 `applied` 回写**都还没做**（第 3 层缺失）

### 3.2 更深一层：profile 交付链漏了 `cordis.patch.yml` 整层

会话根只是症状之一。顺着 `ssid/mcp-env.ts` 往上游查交付链，发现**fork 版只补 `package.json`，整个 `cordis.patch.yml` 层没人补**：

| 交付层 | 0.4.0（自建壳） | 1.0.0（fork 基座） |
|---|---|---|
| 内核 + 插件实体 | `dsh-runtime.tar.gz` 解包铺入 | `ssid-plugins` + junction |
| `package.json`（bundles / 依赖） | 归档整体覆盖 | `profile-seed.ts` 补 ✅ |
| `cordis.patch.yml`（MCP / connection / 会话根） | `profile-merge.mjs` 条目级合并 ✅ | **没人补** ❌ |

证据（每条都能定位）：

- `apps/desktop/src/ssid/profile-seed.ts` 全文只读写 `profileDir/package.json`（`mergeProfileManifest`），不碰 patch；文件头自述 `initProfile()` 那一步「只写骨架」。
- DSH 自己的断言：骨架就是空数组 —— `apps/desktop/tests/project-manager.spec.ts:185` 期望 `cordis.patch.yml` 内容含 `[]`。
- 0.4.0 侧有 `shell/lib/profile-merge.mjs:12`「cordis.patch.yml 条目级合并（纯文本，不解析 `!!js`，失败保模板）」，且 `shell/scripts/prepare-runtime.mjs:118` 把模板四件套打进归档。
- 本机 0.4.0 的 profile patch 是 172 行、含 MCP 与 connection —— 正是归档部署的结果。
- `profile-seed.ts` 文件头自述「fork 的打包链不带该归档」。

**一因多果**（同一台新装机器上同时成立）：3 条预制 MCP 条目缺失 → MCP 服务器列表空；`connection` 的 `inject: [webRuntime, webServer]` 缺失 → 插件中心 405 回归；`session-persistence-jsonl` 的 `root` 覆盖缺失 → 历史会话看不见、工作区全空。

**修复形态的取舍**：曾考虑「让条目随 bundle 自带 patch 走」（`dsh.bundle.patch` 是官方机制，`dsh-ssid-panels` 就这么用，见 `packages/boot/app-boot/src/profile.ts:10-13` 与 `:665-678`）。**放弃** —— `insert` 是追加语义，0.4.0 升上来的机器 profile 里已有归档部署的同名 MCP insert，bundle 再追加一条就撞 `duplicate loader entry id`，内核起不来（同一条账记在 `plugins/dsh-ssid-panels/docs/DSH插件中英切换适配-方案.md:120`）。改为：**条目仍由壳写进 profile（单一来源），合并语义取「出厂条目以模板为准，用户条目原样保留」**，与 0.4.0 侧已验证过的语义一致。

## 六、踩到的坑

1. **安装报「思灵无法关闭」** —— 根因是**目录句柄锁**，不是进程。诊断命令把 PowerShell 窗口的工作目录留在了 `%LOCALAPPDATA%\Programs\ssid-shell`，于是整个目录被锁住，卸载器（`installUtil.nsh:219`，静默 `/S` + `/SD IDOK`）重试 5 次后弹 `appCannotBeClosed`。**给用户的诊断命令必须带收尾动作**（移出 CWD / 关窗）。进程列表看着干净是有欺骗性的：锁在目录句柄上，不在进程上。
   - 附：`appCannotBeClosed` 在 app-builder-lib 26.15.3 里有 3 个调用点（`allowOnlyOneInstallerInstance.nsh:156`、`installUtil.nsh:219`、`extractAppPackage.nsh:116`），zh_CN 文案与思灵自己的 `INSTALLER_RUNNING` 不同，据此可分辨来源。
2. **`ERR_PNPM_IGNORED_BUILDS`（pnpm 11）**：装成功了也退非零。`ignoredBuiltDependencies` 不被内置 pnpm 11.7.0 识别；要在脚本的内联 staging config 里加 `allowBuilds`。模板 `pnpm-workspace.yaml` 的改动是**惰性的**（脚本自己写配置）。
3. **`ELECTRON_MIRROR` 必须设**（`https://npmmirror.com/mirrors/electron/`），且不能写进 `.env.windows`。不设会在 `download:electron` 阶段 `HTTP/2 stream timeout after 300000`。
4. **微信发文件会被限流**（`delivery deferred by WeChat rate limiting`）—— 给用户的脚本不能只依赖这条路，要准备"纯粘贴即可跑"的命令作为兜底。

```powershell
(Get-Process -EA SilentlyContinue | Where-Object { $_.Path -like '*ssid-shell*' }).Count
```

### 7.3 临时补 session root 覆盖（单机）

备份后追加到 profile 的 `cordis.patch.yml`（用字面 here-string，避免 PowerShell 吃掉转义）：

```powershell
$p = "$env:USERPROFILE\.dsh\profiles\ssid\cordis.patch.yml"
Copy-Item $p "$p.bak" -Force
@'
- id: session-persistence-jsonl
  config:
    root: !!js 'process.env.SSID_SESSION_ISOLATED_ROOT || (process.env.USERPROFILE + "\\.dsh\\sessions")'
'@ | Add-Content -Path $p -Encoding UTF8
```

重启后，来自共享根的那批「未分组」条目会消失 —— **这是预期行为，不是新 bug**。不对就还原 `.bak`。
