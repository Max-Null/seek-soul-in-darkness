# 内核 0.1.7 适配：自制插件评估

> 日期：2026-09-24 ｜ 状态：**评估稿，未改任何代码** ｜ 评估范围：`max-null-plugins/`（16）+ `seek-soul-in-darkness/plugins/`（4）= **20 个插件**
> 基线：DSH **0.1.5-rc.2**（当前内核，`deepseek-harness/` 实测 version 即此）→ 目标：**0.1.7-rc.2**（工作树 `%TEMP%\dsh-017-src`）
> 关联：`dsh-anatomy/版本对比/2026-09-24-0.1.7-rc.2-vs-0.1.6-alpha.2.md`（上游观察）、`docs/排查/2026-09-24-内核0.1.7适配-壳侧方案.md`（壳侧前置）

## 结论速览

| 档位 | 数量 | 插件 |
|---|---|---|
| **会坏** | **4** | `dsh-node-appearance` · `dsh-chat-rail` · `dsh-draft-polish` · `dsh-ssid-achievements` |
| **需评估** | **4** | `dsh-capture` · `dsh-plugin-center` · `dsh-ssid-panels` · `dsh-allostasis` |
| **核验通过** | **12** | `dsh-memory` · `dsh-quick-toolbar` · `dsh-skill-mcp-center` · `dsh-skills` · `dsh-guardian` · `dsh-habit` · `dsh-chinese-thinking` · `dsh-tone-layer` · `dsh-ssid-zh-ui` · `dsh-ssid-env` · `dsh-ssid-pwsh-retry` · `dsh-assistant-center`（非插件） |
| 横切项 | 5 个插件 | 裸 `cordis` peer 名会阻塞 typecheck/发版（见 §五） |

**两个结论出乎预期**：

1. **破坏面高度集中**：20 个插件里真正会坏的只有 4 个，且其中 3 个是同一根因（settings 体系重写）。这偏离了「内核大版本升级 → 插件普遍坏掉」的直觉——原因是我们多数插件只依赖 host 侧的稳定服务（`storage` / `systemPrompt` / `tools` / `webServer`），这些在 0.1.7 都没动。
2. **但「会坏」的后果比字面重**：`node-appearance` 与 `chat-rail` 是 client `inject` 缺服务 → cordis 语义下**整个 client apply 静默不激活**，丢的不是设置卡片，而是这两个插件的全部前端功能。

## 一、前置条件：壳必须先适配

本文所有 settings 面结论都建立在「设置体系已激活」之上，而 0.1.7 的 `settings` 与 `config-editor` 两行由 `profileContext` 门控（`bundle/base/cordis.patch.yml:99` / `:103`），壳当前**未提供**该服务 → 设置页整体不渲染。

**因此实施顺序是：壳侧 P0 三件 → 本文的 4 个「会坏」→ 4 个「需评估」→ 清理项。** 壳侧方案见 `docs/排查/2026-09-24-内核0.1.7适配-壳侧方案.md`。

## 二、会坏（4）

### 2.1 `dsh-node-appearance` —— 中改

**根因**：client `inject = ['slots','connection','remote','settingsScope']`（`src/client/index.ts:23`）含已被删除的服务 `settingsScope` → **整个 client 半侧不激活**（调色板绘制、思考展示等全部前端功能消失）。

**改动清单**

| 文件:行 | 改法 |
|---|---|
| `src/index.ts:89-94` | `installSection` → `ctx.settings.configure({auto:false}, ctx.fiber)` |
| `src/index.ts:61-78` | Config 的**标量字段**逐个标 `.volatile()`；注意 `colors`(object) 与 `toolColors`(dict) **不能标**（见下） |
| `src/client/index.ts:23` | inject 去掉 `settingsScope`、加 `configForms` |
| `src/client/index.ts:44` | `ctx.settingsScope.bind({namespace})` → `configForms.get(NS)` |
| `src/client/index.ts:81-87` | 旧槽注册 → `plugins.item`，卡片加 `view` 分支 |
| `src/client/settings-card.tsx:17,47` | `SettingsScope`/`SettingsScopeSnapshot` → 新类型；`PropsRuntime<'settings.plugin.item'>` 换成 `plugins.item` 的 owner props |
| `package.json` | 移除 `@deepseek-ai/dsh-client-ui-settings-plugins` 依赖，改 `ui-plugin-manager` + `ui-primitives` |

**关键约束**：`SettingsFormModel` 只能编辑**顶层标量**（path 恒为 `[field]`，`form-model.ts:114-115,342,349`）→ `colors` 与 `toolColors` 不适用，应保留其自建 face 直接 `form.mutate()` 写路径。

### 2.2 `dsh-chat-rail` —— 中改

与 2.1 同源同改法，另有一处架构障碍：

| 文件:行 | 改法 |
|---|---|
| `src/client/index.tsx:32` | inject 去 `settingsScope`、加 `configForms` |
| `src/client/index.tsx:354-371` | **删掉模块级 `railSettingsScope` 单例**，改持 `ConfigForm` |
| `src/client/index.tsx:1412-1416, 2054-2057` | 两处绕开 inject face 直接订阅 `railSettingsScope` 的调用点一并改 |
| `src/client/index.tsx:2036-2037` | 旧槽 → `plugins.item` |
| `src/index.ts:25 / :217` | NS 常量与注释同步 |

### 2.3 `dsh-draft-polish` —— **大改**（四个里最重，且最隐蔽）

**根因**：`src/index.ts:77-99` 的 `settings.register` 在 0.1.7 已不存在，调用抛 TypeError，而它被 `:96-98` 自己的 **try/catch 吞掉** → 静默退回 `DRAFT_POLISH_DEFAULTS`，只留一行 `console.warn`。**用户全部润色设置失效，且没有任何可见症状。**

| 文件:行 | 改法 |
|---|---|
| `src/index.ts:77-99` | `settings.register` → `configure` + 从 plugin config 读值；**去掉吞错的 try/catch**（否则问题继续不可见） |
| `src/config.ts:60-72` | **11 个字段全部标 `.volatile()`**，类型改 `Volatile<T>` |
| `src/context-types.ts:98-126` | 自建类型收窄为 `{configure; describe; update}` |
| `src/client/index.tsx:41` | `settings.section` 注册**不动**（该槽 0.1.7 仍在） |

### 2.4 `dsh-ssid-achievements` —— 小改，但影响明确

**根因**：`src/index.ts:21` 的 `ctx.on('agent/session-start', ...)` —— 该事件在 0.1.7 全树 **0 命中**（0.1.5 在 `core/agent/src/runtime-types.ts:316`），能力并入 `agent/created`（`:261`，且 emit → **serial**）。

**不崩，但计数归零**：cordis 对未知事件名静默（`vendor/cordis/src/events.ts:299` 惰性建表不校验名）。该 handler 只做 `recordSession()` → `store.bump('sessions')`（`engine.ts:183`）；而原本以为能兜底的 `engine.ts:278` 的 `session/start` 分支，经核查**两版都不存在该事件类型**——是**从头就死**的代码。故 `sessions` 唯一活路径被切断 → 恒为 0 → `first-session`（`rules.ts:50`，target 1）**永久不解锁**。

**改法**：改监听 `agent/created` 并取 payload 的 `source`。⚠️ 它已变 **serial 且返回 Promise，抛错会否决 agent 创建**（原来是 emit，不可否决）→ handler 内**必须 try/catch**。或更稳：改在 `session/event` 里按 `turn/start` 首现记账。

## 三、需评估（4）

### 3.1 `dsh-capture` —— 小改，但有一处需业主决策

配置真身在 `~/.ssid/screenshot.json`（`src/index.ts:49,62-78`），`installSection`（`:171-179`）只是占位 → 删掉即可。client `inject=['slots']` **不含 `settingsScope`**，故截图按钮与投递**不受影响**。

| 文件:行 | 改法 |
|---|---|
| `src/client/index.ts:111-114` | 旧槽 → `plugins.bundle.config`（key `@max-null/dsh-capture#dsh-capture`）或 `plugins.item`，并加 `view` 分支 |
| `src/index.ts:171-179` | 删掉占位 `installSection` |

**⚠️ 决策点**：**不要给它标 volatile**。否则 settings 会把配置写进 `cordis.patch.yml`，而代码读 `screenshot.json` → 两层存储分叉。既然配置真身在自有 JSON，就保持「不进设置表单」。

### 3.2 `dsh-plugin-center` —— API 无破坏，冲突在功能面

`connection.fetch.register` 的 route 形状与 0.1.7 逐字一致（`client/connection/src/rpc.ts:138-162`），且 0.1.7 connection **有** `fetch`（`rpc-host.ts:96-101`）→ 走首选 fetch 路径；fallback 的 `rpc.handle` 也在（`:89`）。`FiberState` 六成员两版一致。

**与官方 `ui-plugin-manager` 无技术冲突**：它走 Typert Remote、**不注册 HTTP 路由**；服务名也不撞（官方 `pluginManager` vs 本插件 `pluginCenter`）。

**冲突在写入面**：两者都做「装 / 更 / 开关」，且**都写同一份 profile 状态**——plugin-center 写 `<profileDir>/cordis.patch.yml`（`toggle.ts:215,292`）、`package.json`（`reconcile.ts:77`）、跑 `pnpm add -w`（`update.ts:593,709`），而双方缓存互不感知（plugin-center 的 5min `updatesCache` 只对自己 invalidate）。

**需决策**：保留哪个作为用户入口；或让 plugin-center 监听官方写入。

### 3.3 `dsh-ssid-panels` —— 运行时 API 逐项存活，但有一个既存缺陷

`webServer.register` 与 `{kind:'prefix',path,handler}` 形状不变（`host/webserver/src/index.ts:39/:42-48/:166`）、`webRuntime.trustedHosts`（`bundle/web-app/src/index.ts:68-73/:231`）、4 个槽全存活、`priority:-1` 语义未变（`ui-slots/src/index.ts:771`）、`[role="dialog"] nav button` 锚点仍成立。

**既存缺陷（非升级引入）**：`session.events`（`index.ts:616`）在**所有版本都不存在**（`Session` 公共面只有 `snapshotEvents`/`ownEvents`）→ `interruptedTurnClosers(undefined)` 在 `repair.ts:69` 抛 TypeError，该 HTTP 分支返回 500。既然要动适配，建议顺手修。

### 3.4 `dsh-allostasis` —— 运行时不坏，但已进官方废弃路径

`agent/pre-step` 逐字不变（`runtime-types.ts:320`）。但 `session.snapshotEvents()` 在 0.1.7 **新增 `@deprecated`「new calls are prohibited」**（`core/session/src/index.ts:643-649`；0.1.5 同位置无此标记，`ownEvents()` :666 同样）。

**结论**：本次升级**不用改**，但下次适配要规划迁移（改用 `session/event` 增量或 `eventAt`）。

## 五、横切项：裸 `cordis` peer 名（5 个插件）

`dsh-quick-toolbar`、`dsh-ssid-env`、`dsh-ssid-pwsh-retry`、`dsh-ssid-zh-ui`、`dsh-ssid-panels` 的 `peerDependencies` 写裸 **`cordis`**（如 `^4.0.0-rc.7`），而 DSH 树里该包名是 `@deepseek-ai/cordis`（**注意 0.1.5 的 vendor 也叫这名**，所以这不是源码层改名）。

- **影响面仅 typecheck**（`import type` 运行时被擦除，插件加载不受影响）
- 但 **L1 门槛要求 typecheck 全绿 → 会阻塞发版**
- 改法：peer 名统一改 `@deepseek-ai/cordis`（`dsh-skills` / `dsh-memory` 已是正确写法）
- **待实测**：profile 里裸 `cordis` 是否还能解析——建议跑一次 typecheck 定论

## 六、修复顺序建议

1. **壳侧 P0 三件**（`healProfilesModuleFallback` / `PluginPackages` 注入 / `profileContext`）—— 否则设置体系整体不亮，下面第 2 步没有落点
2. **settings 面 3 个会坏**：`node-appearance`、`chat-rail`、`draft-polish`（可复用同一套机械改法，见 §七）
3. **`ssid-achievements`**（独立根因，改动小）
4. **4 个需评估**：`capture`（改槽 + 决策不标 volatile）、`plugin-center`（决策分工）、`ssid-panels`（顺手修既存 bug）、`allostasis`（仅记录）
5. **横切**：5 个插件的 peer 名（可与第 2 步合并）
6. **清理**：壳 `tsconfig` 11 条断路径、`agent-presets` root 注入改写

## 七、可复用的统一改法（settings 面）

1. **`settingsScope.bind({namespace})` → `configForms.get(NS)` 是机械替换**：`getSnapshot().value` / `subscribe` / `set` / `unset` 四个成员**同名同形**，消费点几乎不动。
2. **卡片注册模板**抄官方 `ui-settings-web-search/src/client/index.ts:57-59` 的 `whileServed` + `plugins.item`，卡片首行加 `if (props.view === 'summary') return <一行>;`。
3. **type import 三件套**：`@deepseek-ai/dsh-client-ui-settings/client`、**`@deepseek-ai/dsh-client-ui-primitives`（主入口，无 `./settings-form` 子路径）**、`@deepseek-ai/dsh-client-ui-plugin-manager/client`。
4. **`plugins.item` 的 `id` 不必等于 namespace**（官方 4 个注册者大多不等，它们自建 `SettingsFormModel` 再 inject actions，`id` 仅是页面锚点）。
5. **可抽 `migrateSettingsScope(ctx, ns)` 收敛 bind→get 与 inject 改名**；但**注册块不能抽公共函数**——client bundle 的 purity gate 禁止跨插件值导入。
6. **白捡**：四个 settings 面插件的 `cordis.patch.yml` entry id 与代码里的 NS 常量**恰好全等**，而 0.1.7 的 namespace 正是 `entry.options.id`（`settings/src/index.ts:315,317,326,382`）→ **namespace 字符串一个都不用改**。

## 八、方法与证据说明

- 评估方式：先对 20 个插件做两维机械扫描（破坏面关键词 × cordis 服务面），再分两片深入（settings 面四插件 / 其余 16 个），关键断言交叉核实。
- **服务面结论**：0.1.5→0.1.7 唯一被删除的 cordis 服务是 **`settingsScope`**；`loader` / `webRuntime` / `webServer` / `connection` / `storage` / `agents` / `systemPrompt` / `tools` / `llm` / `locale` / `slots` / `sessions` / `conversation` / `sessionQuery` / `remote` 全部存在（`loader` 60 处、`webRuntime` 18 处命中，先前一次扫描因口径漏报，已修正）。
- **两条被推翻的中间结论**（记录以免重复踩）：① `dsh-allostasis` 的 `snapshotEvents` 曾被判「0.1.6 已弃用」→ 实际 0.1.7 仍存在（61 处官方在用），只是新增了 `@deprecated` 标记；② `dsh-quick-toolbar` 的 `sidebarRightTabs` 命中是**注释**，不是调用。
- **未验证项**：① 五个插件的裸 `cordis` peer 是否真的阻塞 typecheck（建议实测）；② 0.1.7 的 Web 前端**构建产物**未核验，本文 DOM 结论基于源码；③ 所有改动清单均为设计，未编译、未运行。
