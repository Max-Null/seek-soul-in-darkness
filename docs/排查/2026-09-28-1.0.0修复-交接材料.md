## 三、关键机制（排查时最容易走错的地方）

### 3.1 v4 消息来源格式（#9 的根因）

- 内核从 `0.1.5-rc.2` 升到 `0.1.7-rc.2` 时，**会话格式 v3 → v4**。
- 准入规则在 `packages/session/session-format-v3-to-v4/src/message-sources.ts:9-11`：`kind` 必须是非空字符串**且不等于 `'plugin'`**（v3 的旧写法）。
- **运行时的消息不走迁移器**（迁移器只处理已发布的 v3 文件）→ 插件一注入就抛错，整轮请求失败。
- 正确形状：`source: { kind: 'plugin:<插件名>', ...其余字段 }`，**且不再有 `plugin` 字段**。
  - 依据：`session-format-v3-to-v4/src/sources.ts:59-90` 的 `producerKind` 兜底 `plugin:${plugin}`。
  - 官方测试 `tests/message-sources.spec.ts:30` 拿 `'plugin:acme'` 当正例。
- `@deepseek-ai/dsh-llm` 的 `MessageSourceMap` 是 **merge-extensible 的 interface**，但只列官方生产者；第三方自述 kind 只能断言 —— 既有实践见 `third-party-plugins/dsh-genui/src/plugin/fence-feedback.ts:175`（`as unknown as UserMessage`）。

### 3.2 安装器的目录事务（#4）

- 安装器**不再是**「解压到暂存目录再改名就位」，而是 **先让路、直接解压到最终目录**。
- 旧设计多一次改名，而失败的往往是改名本身；现在失败会在**解压 427 MB 之前**就报出来。
- 让路失败会重试 3 次（每次间隔 `Sleep 700` 并结束从安装目录启动的进程）。
- 原子性由 `dshRollbackDirectories` 保住：解压失败 → 删半成品 → 把 `.old-<guid>` 改回。
- **注意**：`installer-directories.nsh` 与 `installer.nsh` **必须带 UTF-8 BOM**（见第五节坑）。

### 3.3 profile patch 合并（#10）

- 语义：**出厂条目以模板为准，用户条目原样保留**，判据粒度是**子条目**。
- 出厂条目排在前面、用户条目在后 —— 后者优先，与 patch 层覆盖方向一致。
- 内容没变就不写盘；写盘前备份 `cordis.patch.yml.bak-<时间戳>`。

### 六个必须记住的坑

1. **`npx tsc --noEmit -p apps/desktop/tsconfig.json` 会假绿** —— 它漏报错误（实测 `title` 字段的 TS2352 它报 0 错）。**一律以 `tsc -b` 为准**。
2. **NSIS 脚本（含非 ASCII）必须 UTF-8 带 BOM**，否则 makensis 直接 `Bad text encoding`。用 write **或 edit** 工具改这类文件**都会**丢 BOM（2026-09-28 两次实测）——改完必须复查前 3 字节是不是 `EF BB BF`，丢了就用 `[System.IO.File]::WriteAllText($f, $t, [System.Text.UTF8Encoding]::new($true))` 补回。
3. **electron-builder 把 makensis 的 warning 当 error**（`warning treated as error`）。典型触发：宏里引用了该展开点尚未定义的 define（如 `${APP_EXECUTABLE_FILENAME}`），用 `!ifdef` 包住即可。
4. **排查打包失败别用 `Select-Object -Last N` 截断输出** —— warning 与编码错误都会被切掉，只剩调用栈。真因在 `.desktop-build\packaging-runs\<run>\stdout.log`（**不是** `events.jsonl`）。
5. **pnpm 11 的 `allowBuilds` 占位符**：`pnpm-workspace.yaml` 里若写着 `esbuild: set this to true or false`，那是**没填完的模板**，pnpm 当字符串处理、不生效，构建会以 `ERR_PNPM_IGNORED_BUILDS` 失败。
6. **semver 的预发布陷阱**：`^0.1.1-rc.1` 只匹配 `0.1.1-*`，**不会**升到 `0.1.7-rc.2` —— 依赖声明必须显式改。

## 九、本次修复中「我判断错过的」记录（供新会话避坑）

这些不是成果，是**方法教训**，比结论更该带走：

- **报错文案可能与真实原因无关**。安装器 96% 报「思灵无法关闭」，真因是 `dshPromoteDirectories` 里 `RMDir` 对空目录静默失败 → 后续 `Rename` 必败。文案是从 `appCannotBeClosed` 复用的。
- **比较两组数据前先确认口径一致**。用两条不同正则（一条允许缩进、一条只顶层）扫同一个文件，然后互相比较，得出了「出厂条目只落了三条」的错误结论。
- **「重启即恢复」否证了配置缺失类假设**。配置是持久的，重启不会把它变回来 —— 凡「重启能修」的现象，优先怀疑运行时状态/时序，而不是配置。
- **给新行为配一条测试**。`meta-resolve.test.ts` 抓出了我自己写的「提前 `return null` 短路了新代码」—— 只跑原有测试会看到全绿并打出一个带 bug 的包。
